# Decision: Migration from Obsidian Journal to ADR System

Date: 2025-01-17

## Context

The project previously tracked architectural decisions in Obsidian journal files under `obsidian/Journal/sprint-3/`. This included documents like:
- Pipeline Architecture.md
- New Pipeline Architecture.md
- Refined Two-Stage Pipeline - Quality First Then Length.md
- Visual Awareness Layer.md
- Word-Level Selection Plan.md
- Three-Stage Pipeline Analysis.md
- Narrative Role Assignment & Implementation Strategy.md

While Obsidian provided good note-taking capabilities, it had several limitations:
- No integration with Claude Code workflow
- Easy to forget documenting decisions
- No automatic detection of architectural decisions
- Decisions scattered across dated journal entries
- No structured format for capturing decision rationale
- Difficult for team members to discover past decisions

With the introduction of the ADR system (ADR-0001), the project needed to decide whether to maintain both systems or consolidate to a single source of truth.

## Options Considered

- **Option A: Keep Obsidian for Journal, ADRs for Architecture**
  - Maintain Obsidian for daily notes and sprint planning
  - Use ADRs only for major architectural decisions
  - Pros: Separation between ephemeral notes and permanent decisions
  - Cons: Duplication, unclear boundaries, two places to search

- **Option B: Migrate Everything to Obsidian with ADR Format**
  - Use Obsidian's file system but adopt ADR template
  - Keep familiar Obsidian interface
  - Pros: Single tool, familiar workflow
  - Cons: Still no Claude Code integration, manual ADR creation

- **Option C: Full Migration to ADR System**
  - Convert existing Obsidian architectural decisions to ADRs
  - Use Claude Code's built-in TodoWrite for task tracking
  - Retire Obsidian journal for this project
  - Pros: Single source of truth, automatic detection, Claude Code integration, industry-standard format
  - Cons: Loss of journal-style workflow, requires discipline

## Decision

Chose **Option C** - Full migration to ADR system.

**Migration approach:**

1. **Extract architectural decisions from Obsidian**
   - Reviewed all sprint-3 journal entries
   - Identified major architectural decisions:
     - Pipeline architecture choice (Human-Equivalent approach)
     - Three-pass editing system
     - Two-stage quality-first pipeline
     - Sentence vs word-level granularity
     - Visual awareness layer phased approach

2. **Create ADRs for each decision**
   - ADR-0002: Pipeline Architecture - Human-Equivalent Approach
   - ADR-0003: Three-Pass Editing System
   - ADR-0004: Two-Stage Quality-First Pipeline
   - ADR-0005: Sentence-Level Granularity for Stage 1
   - ADR-0006: Visual Awareness Layer - Phased Approach
   - ADR-0007: Migration from Obsidian to ADR System (this document)

3. **Update ADR-0001**
   - Removed references to Obsidian integration
   - Simplified to pure Claude Code workflow

4. **Preserve Obsidian files**
   - Keep `obsidian/` directory as historical reference
   - Do not delete (useful for understanding evolution)
   - Mark as archived/deprecated

5. **Future workflow**
   - Use TodoWrite for task tracking
   - Use ADR system for architectural decisions
   - Use git commit messages for implementation details
   - No new Obsidian entries for this project

**Rationale:**
- ADR system provides better integration with development workflow
- Automatic detection prevents forgetting to document decisions
- Industry-standard format makes decisions discoverable
- Single source of truth reduces confusion
- Claude Code skill automatically prompts for ADR creation
- `/adr` and `/adr-list` commands provide easy access

## Consequences

**Positive:**
- Single source of truth for architectural decisions
- Automatic ADR detection via Claude Code skill
- Industry-standard format (portable, discoverable)
- Easy access via `/adr-list` command
- Better integration with git workflow
- Reduced cognitive overhead (one less tool to maintain)
- Historical decisions now properly documented with full context

**Negative:**
- Loss of journal-style workflow for daily notes
- All architectural decisions from Obsidian needed migration (one-time cost)
- Team members need to adopt new workflow
- Less free-form than Obsidian (strict ADR template)

**Affected Areas:**
- Documentation workflow (switch from Obsidian to ADRs)
- Existing Obsidian files (archived, not deleted)
- ADR directory (now contains 7 ADRs covering all major decisions)
- Team onboarding (need to explain ADR system instead of Obsidian)
- Historical reference (Obsidian files remain as evolution history)

**Migration completed:**
- 6 architectural decisions extracted from Obsidian
- 7 total ADRs created (including workflow and migration ADRs)
- `docs/adr/index.md` auto-maintained
- Obsidian directory preserved for historical reference
- All major pipeline decisions now properly documented
