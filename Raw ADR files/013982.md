# PNG Export via resvg and tiny-skia

## Context and Problem Statement

The `pikchr` CLI currently renders Pikchr diagrams to SVG only. Users often need PNG output for embedding in documentation systems, chat applications, or contexts where SVG support is limited. How should we add PNG export while keeping the binary small and avoiding external system dependencies?

## Decision Drivers

* **Pure Rust** — avoid system library dependencies (Cairo, librsvg) for portability
* **Binary size** — keep the CLI lightweight; currently ~3MB
* **Quality** — output should match SVG fidelity
* **Simplicity** — minimize new dependencies and code paths

## Considered Options

* **resvg + tiny-skia** — pure Rust SVG renderer with PNG output
* **cairo-rs** — Rust bindings to Cairo (requires system library)
* **rsvg** — Rust bindings to librsvg (requires system library)
* **image crate only** — manual SVG parsing and rasterization

## Decision Outcome

Chosen option: **resvg + tiny-skia**, because it's the only pure-Rust option that provides high-quality SVG rendering without external dependencies. The resvg ecosystem (usvg for parsing, tiny-skia for rendering) is battle-tested with 500k+ monthly downloads.

### Consequences

* Good, because no external system dependencies — works on all platforms including WASM
* Good, because binary stays relatively small (~3MB additional for resvg stack)
* Good, because high-quality anti-aliased output
* Good, because actively maintained by the linebender project
* Bad, because adds ~15 transitive dependencies
* Neutral, because text rendering requires the `text` feature (we'll enable it)

### Confirmation

Validate with: `pikchr render test.pikchr --png` produces valid PNG output matching SVG dimensions.

## Pros and Cons of the Options

### resvg + tiny-skia

Pure Rust SVG rendering library with PNG export via tiny-skia's `Pixmap::save_png()`.

* Good, because pure Rust — no FFI, no system dependencies
* Good, because portable to any target Rust supports (including WASM)
* Good, because well-maintained, 500k+ monthly downloads
* Good, because small binary footprint (~3MB)
* Good, because handles complex SVG features Pikchr might use
* Bad, because adds dependency tree (~15 crates)

### cairo-rs

Rust bindings to the Cairo graphics library.

* Good, because mature, battle-tested rendering
* Good, because fast native performance
* Bad, because requires Cairo system library installation
* Bad, because complicates cross-compilation
* Bad, because not available on all platforms (e.g., WASM)

### rsvg

Rust bindings to librsvg (GNOME's SVG library).

* Good, because extremely accurate SVG rendering
* Good, because handles edge cases well
* Bad, because requires librsvg and its dependencies (glib, pango, etc.)
* Bad, because heavy system dependency chain
* Bad, because complicates distribution and cross-compilation

### image crate only

Use the `image` crate for PNG encoding, implement custom SVG rasterization.

* Good, because minimal dependencies
* Bad, because SVG rasterization is complex — we'd reinvent resvg poorly
* Bad, because would miss many SVG features
* Bad, because significant development effort

## More Information

Key crates:
- [resvg](https://github.com/linebender/resvg) — SVG rendering library
- [tiny-skia](https://docs.rs/tiny-skia/) — 2D rendering with PNG support
- [usvg](https://docs.rs/usvg/) — SVG simplification/preprocessing

The CLI will expose PNG export via:
- `--png` flag to output PNG instead of SVG
- `--formats svg,png` to output both formats simultaneously (the "clever flag")
