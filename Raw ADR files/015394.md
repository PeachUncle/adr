# ADR-001: Frontend Topology (Portal + Field, Mobile-Ready)

## Context
- Current surfaces: Next.js report builder under `report-builder/`; no dedicated field PWA. Goal: Android/iOS apps eventually.
- Constraints: offline-first capture (photos/media), shared workspace state machine, shared API/client types, branding and portal/report editing on web.
- Future mobile: likely a PWA that can be wrapped (Capacitor/React Native WebView) or a native client that reuses the same API/workspace contracts.

## Options Considered
1) Single app (Next.js) with portal + capture routes.
2) Two apps: portal/report builder (web) + field capture (PWA/offline-first), sharing packages.
3) Native-first mobile now (React Native/Flutter) plus web portal.

## Decision
- Choose **Option 2**: two apps sharing packages, optimized for offline capture now and mobile-wrappability later.
  - `apps/web`: portal + report builder (Next.js or similar).
  - `apps/field`: capture PWA with IndexedDB/outbox/sync model; designed to wrap in Capacitor if/when native shells are needed.
- Shared packages: `packages/ui`, `packages/workspace` (state machine + sync adapters), `packages/api-client` (generated types), `packages/domain` (contracts).

## Rationale
- Offline-first capture benefits from a PWA/data-layer tailored to device storage and background sync without complicating the portal.
- Portal/report builder keeps its own cadence and can stay web-optimized.
- Future native wrappers can host the PWA or call the same API/client and workspace package; no lock-in to a single framework.

## Consequences
- Need shared design tokens/components (`packages/ui`) to avoid divergence.
- Sync/mutation log client code lives in `packages/workspace` and is used by both apps.
- Build/deploy pipelines must handle two app targets; auth/session handling should be shared.
- If native shells are later required, prioritize PWA-wrappable patterns (no browser-only APIs without fallbacks).

## Open Questions
- Which framework for `apps/field` (React/Vite vs Next static export) given PWA needs?
- Auth strategy shared across web/PWA/native wrappers (Firebase, tokens).
- Media handling constraints on iOS/Android when wrapped (camera, storage quotas).
