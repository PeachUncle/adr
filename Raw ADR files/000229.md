# ADR-003: Multi-Criteria Decision Analysis for Vacation Optimization

## Status
Accepted

## Context
The Personal Vacation Optimizer needs sophisticated algorithms to evaluate and optimize vacation plans based on multiple user preferences including budget, activities, climate, accessibility, and personal priorities. The system must provide meaningful recommendations while being computationally efficient.

## Decision
We will implement Multi-Criteria Decision Analysis (MCDA) using weighted scoring algorithms with the following components:

1. **Weighted Additive Model** for overall vacation scoring
2. **Collaborative Filtering** for destination recommendations
3. **Budget Optimization** using constraint satisfaction
4. **Activity Matching** with semantic similarity

## Rationale

### Multi-Criteria Decision Analysis Benefits:
- **Comprehensive Evaluation**: Considers all user preferences simultaneously
- **Transparent Scoring**: Clear breakdown of how scores are calculated
- **Configurable Weights**: Users can prioritize different factors
- **Scalable**: Efficient computation even with many criteria
- **Proven Methodology**: Well-established decision science approach

### Algorithm Components:

#### 1. Weighted Additive Model
```
Overall Score = Σ(wi × normalized_scorei)

Where:
- wi = user-defined importance weight for criterion i
- normalized_scorei = criterion score normalized to [0,1]
- Σwi = 1 (weights sum to 1)
```

#### 2. Budget Optimization
```
Optimize: max(satisfaction_score)
Subject to: total_cost ≤ max_budget
Variables: accommodation_cost, activity_cost, food_cost, transport_cost
```

#### 3. Activity Matching
```
Activity Score = |preferred_activities ∩ available_activities| / |preferred_activities|
Enhanced with semantic similarity for related activities
```

## Implementation Details

### Core Optimization Service:
```java
@Service
public class VacationOptimizationService {
    
    public OptimizationResult validateVacationPlan(String userId, VacationPlan plan) {
        UserPreferences prefs = getUserPreferences(userId);
        
        // Calculate individual criterion scores
        BigDecimal budgetScore = calculateBudgetScore(plan, prefs);
        BigDecimal activityScore = calculateActivityScore(plan, prefs);
        BigDecimal climateScore = calculateClimateScore(plan, prefs);
        BigDecimal accessibilityScore = calculateAccessibilityScore(plan, prefs);
        
        // Apply weighted combination
        BigDecimal overallScore = calculateWeightedScore(
            budgetScore, activityScore, climateScore, accessibilityScore, prefs);
        
        return OptimizationResult.builder()
            .overallScore(overallScore)
            .budgetScore(budgetScore)
            .activityScore(activityScore)
            .climateScore(climateScore)
            .accessibilityScore(accessibilityScore)
            .valid(overallScore.compareTo(MINIMUM_THRESHOLD) >= 0)
            .build();
    }
}
```

### Scoring Criteria:

#### Budget Scoring:
```java
private BigDecimal calculateBudgetScore(VacationPlan plan, UserPreferences prefs) {
    BigDecimal cost = plan.getEstimatedCost();
    BigDecimal maxBudget = prefs.getMaxBudget();
    
    if (cost.compareTo(maxBudget) > 0) {
        return BigDecimal.ZERO; // Over budget = 0 score
    }
    
    // Optimal cost is 80% of max budget
    BigDecimal optimalCost = maxBudget.multiply(BigDecimal.valueOf(0.8));
    
    if (cost.compareTo(optimalCost) <= 0) {
        return BigDecimal.ONE; // Under optimal = perfect score
    }
    
    // Linear decrease from optimal to max budget
    BigDecimal excess = cost.subtract(optimalCost);
    BigDecimal range = maxBudget.subtract(optimalCost);
    return BigDecimal.ONE.subtract(excess.divide(range, 4, RoundingMode.HALF_UP));
}
```

#### Activity Matching:
```java
private BigDecimal calculateActivityScore(VacationPlan plan, UserPreferences prefs) {
    Set<String> preferred = new HashSet<>(prefs.getPreferredActivities());
    Set<String> available = new HashSet<>(plan.getActivities());
    
    // Direct matches
    Set<String> directMatches = Sets.intersection(preferred, available);
    
    // Semantic matches (beach ↔ swimming, culture ↔ museums)
    int semanticMatches = calculateSemanticMatches(preferred, available);
    
    int totalMatches = directMatches.size() + semanticMatches;
    
    return BigDecimal.valueOf(totalMatches)
        .divide(BigDecimal.valueOf(preferred.size()), 4, RoundingMode.HALF_UP);
}
```

#### Climate Suitability:
```java
private BigDecimal calculateClimateScore(VacationPlan plan, UserPreferences prefs) {
    String planClimate = plan.getClimate();
    String preferredClimate = prefs.getClimatePreference();
    
    // Climate compatibility matrix
    Map<String, Map<String, BigDecimal>> climateMatrix = Map.of(
        "tropical", Map.of("tropical", BigDecimal.ONE, "temperate", BigDecimal.valueOf(0.7)),
        "temperate", Map.of("temperate", BigDecimal.ONE, "tropical", BigDecimal.valueOf(0.8)),
        "cold", Map.of("cold", BigDecimal.ONE, "temperate", BigDecimal.valueOf(0.6))
    );
    
    return climateMatrix.getOrDefault(preferredClimate, Map.of())
        .getOrDefault(planClimate, BigDecimal.valueOf(0.5));
}
```

### Collaborative Filtering:
```java
@Service
public class DestinationRecommendationService {
    
    public List<DestinationRecommendation> getRecommendations(String userId) {
        UserPreferences userPrefs = getUserPreferences(userId);
        List<UserPreferences> similarUsers = findSimilarUsers(userPrefs);
        
        // Weighted recommendation based on similar users
        Map<String, BigDecimal> destinationScores = new HashMap<>();
        
        for (UserPreferences similarUser : similarUsers) {
            BigDecimal similarity = calculateSimilarity(userPrefs, similarUser);
            // Weight destinations by user similarity
            updateDestinationScores(destinationScores, similarUser, similarity);
        }
        
        return destinationScores.entrySet().stream()
            .map(this::createRecommendation)
            .sorted(Comparator.comparing(DestinationRecommendation::getMatchScore).reversed())
            .limit(10)
            .collect(Collectors.toList());
    }
}
```

## Performance Optimizations

### Caching Strategy:
- **User Preferences**: Cache for 1 hour to reduce database calls
- **Similar Users**: Cache for 24 hours, update when preferences change
- **Destination Scores**: Cache popular destinations for 6 hours
- **Climate Data**: Cache seasonal climate information

### Algorithm Efficiency:
- **Parallel Processing**: Independent criteria calculated in parallel
- **Early Termination**: Stop calculation if critical criteria fail
- **Batch Processing**: Process multiple plans efficiently
- **Memory Management**: Minimize object creation in hot paths

### Database Optimization:
```sql
-- Indexes for common queries
CREATE INDEX idx_user_preferences_activities ON user_preferences USING GIN(preferred_activities);
CREATE INDEX idx_user_preferences_budget ON user_preferences(max_budget);
CREATE INDEX idx_similar_users_lookup ON user_preferences(budget_importance, activity_importance);
```

## Consequences

### Positive:
- **Objective Scoring**: Consistent, repeatable vacation evaluations
- **User Control**: Configurable weights for personal preferences
- **Transparency**: Clear breakdown of scoring factors
- **Scalability**: Efficient algorithms handle many criteria
- **Accuracy**: Considers multiple factors simultaneously

### Negative:
- **Complexity**: More complex than simple rule-based systems
- **Tuning Required**: Weights and thresholds need calibration
- **Data Dependency**: Requires accurate input data for all criteria
- **Computational Cost**: More CPU intensive than simple filtering

### Mitigation Strategies:
- **Default Weights**: Sensible defaults for new users
- **Performance Monitoring**: Track algorithm execution times
- **Gradual Rollout**: A/B testing for algorithm improvements
- **Fallback Mechanisms**: Simple algorithms for edge cases

## Future Enhancements

### Machine Learning Integration:
- **Preference Learning**: Automatically adjust weights based on user behavior
- **Outcome Prediction**: Learn from vacation satisfaction feedback
- **Seasonal Adjustments**: Adapt recommendations based on time of year

### Advanced Algorithms:

- **Fuzzy Logic**: Handle uncertain or imprecise preferences
