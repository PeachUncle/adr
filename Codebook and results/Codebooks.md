| B05 Transportation, Logistics, and Mobility                  | Transportation, delivery, warehousing, fleet management, and mobility scheduling. Merely using a map API does not qualify a repository for this category.                                                                                                                                                                                 | Adapted from NAICS 48–49.                                                                                                                                                                        |

| B07 Industry, Manufacturing, and Engineering                 | Business control or management of factory production, industrial equipment, manufacturing processes, and engineering facilities. | B08 Agriculture, Energy, and Environment                     | Agricultural production, energy supply, utilities, and environmental operations. | B09 Real Estate, Accommodation, and Tourism                  | Property sales and rentals, property management, accommodation booking, and tourism operations. | B10 Media, Content, and Entertainment                        | Content publishing, news media, music, film, gaming, and entertainment applications. | B11 Scientific Research and Professional Services            | Software supporting clearly defined professional workflows in scientific research, law, professional consulting, and related fields. | B99 Insufficient Evidence / Undetermined                     | Repository descriptions are missing, or available evidence is insufficient to establish the target business domain. ## Repository Software Types (T)

| Code and Original Category Name            | Inclusion Criteria and Boundaries                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T01 Application Software                   | Software that directly provides functionality to end users, such as web browsers, text editors, and business applications. A repository must not be classified as T03 merely because it implements a web application.                                                                                                  |
| T02 System Software                        | Software providing runtime environments and foundational services for other systems, including operating systems, middleware, servers, and databases. General-purpose database systems are preferentially classified here unless the repository primarily provides an embeddable database programming library.         |
| T03 Web Libraries and Frameworks           | Reusable libraries and frameworks specifically intended for web development or runtime environments, such as web UI libraries and web application frameworks. Web applications directly serving end users are classified as T01.                                                                                       |
| T04 Non-Web Libraries and Frameworks       | Reusable libraries and frameworks whose primary purpose is not web development. Repositories primarily providing developer toolchains are classified as T05.                                                                                                                                                           |
| T05 Software Tools                         | IDEs, package managers, compilers, and similar tools supporting software development tasks. Database servers and other software providing general-purpose runtime services are classified as T02.                                                                                                                      |
| T06 Documentation                          | Repositories whose primary deliverables are tutorials, documentation, or source code examples rather than executable software products. Ordinary software repositories containing documentation are not classified in this category.                                                                                   |
| T99 Insufficient Evidence / Pending Review | Repository descriptions, README files, and other available evidence are insufficient for classification, or the repository contains multiple primary deliverables without a clearly identifiable dominant type. This is a missing-value code introduced in this study, not a seventh category in the original dataset. |

## ADR Decision Topics (D)

| Code | Name                                                                  | Inclusion Criteria and Boundaries                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01  | Allocation of Responsibilities                                        | Assignment of responsibilities to modules, services, components, or layers. Decisions concerning how components interact are classified as D02.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| D02  | Coordination Model                                                    | Runtime interactions, messaging, synchronization, asynchronous communication, and communication patterns. Decisions solely concerning the selection of a named product are classified as D07.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D03  | Data Model                                                            | Entities, relationships, state, data ownership, and the organization of data persistence. Decisions solely concerning the selection of a database product are classified as D07.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D04  | Management of Resources                                               | Acquisition, reuse, limitation, scheduling, and release of computing resources, storage, connections, threads, and caches.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D05  | Mapping Among Architecture Elements                                   | Mapping modules, services, and processes to nodes, containers, or other architectural views and deployment locations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D06  | Binding Time Decisions                                                | Decisions about whether something is determined at design time, build time, deployment time, startup time, or runtime. The mere presence of a configuration file is insufficient for assigning this code.                                                                                                                                                                                                                                                                                                                                                                                                      |
| D07  | Choice of Technology                                                  | Adoption or replacement of programming languages, frameworks, databases, middleware, cloud services, protocols, or products, where technology selection is the primary focus of the decision.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D98  | Confirmed Architectural Decisions Not Covered by the Seven Categories | The decision and its context must be examined to identify the specific architectural subject and explain why none of the related predefined categories applies. This code must not serve as a fallback for unclear or uncertain cases.                                                                                                                                                                                                                                                                                                                                                                         |
| D99  | Unidentifiable Architectural Topic or Insufficient Evidence           | A specific architectural subject cannot be established from the Decision, Context, and Options sections. Cases include blank records or templates, records containing only goals or evaluation criteria, non-architectural decisions concerning documentation, governance, or functional scope, and records with genuinely insufficient information. Decisions concerning proposed, rejected, deferred, or superseded alternatives must not be classified as D99 if their architectural topics remain identifiable. Record the specific evidence gap or reason for considering the decision non-architectural. |

## Product Quality Attributes (Q)

| Code and Main Characteristic               | Subcharacteristics Listed on the Public Standard Page                                                                                                  | Inclusion Guidance and Common Classification Boundaries                                                                                                                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q01 Functional Suitability                 | Functional completeness, functional correctness, functional appropriateness                                                                            | The decision addresses functional coverage, correctness of outputs, or suitability of functions for intended tasks. Statements merely proposing to implement a feature require further review if no product quality concern is expressed.                               |
| Q02 Performance Efficiency                 | Time behaviour, resource utilization, capacity                                                                                                         | Explicit concerns about response time, throughput, resource consumption, or capacity. “Scalability” may instead correspond to Q08; distinguish adaptability to increasing demand from explicit capacity limits based on the text, and assign both codes when justified. |
| Q03 Compatibility                          | Co-existence, interoperability                                                                                                                         | The ability of different products to operate together, exchange information, and use exchanged information. Support for multiple execution platforms primarily concerns Q08 Adaptability.                                                                               |
| Q04 Interaction Capability                 | Appropriateness recognizability, learnability, operability, user error protection, user engagement, inclusivity, user assistance, self-descriptiveness | The extent to which human users can recognize, learn, operate, and interact with a product, including accessibility and assistance. API interactions between software systems generally belong to Q03 rather than Q04.                                                  |
| Q05 Reliability                            | Faultlessness, availability, fault tolerance, recoverability                                                                                           | Explicit concerns about preventing failures, service availability, fault tolerance, or recovery. Prevention of safety hazards primarily concerns Q09.                                                                                                                   |
| Q06 Security                               | Confidentiality, integrity, non-repudiation, accountability, authenticity, resistance                                                                  | Protection against attacks, access control, information integrity, identity authenticity, and related concerns. Distinguish information security from Q09, which concerns risks to human life, property, and the environment.                                           |
| Q07 Maintainability                        | Modularity, reusability, analysability, modifiability, testability                                                                                     | Modularity, reuse, change analysis, modification, and testability. The mere appearance of the term “module” is insufficient for assigning this code.                                                                                                                    |
| Q08 Flexibility                            | Adaptability, scalability, installability, replaceability                                                                                              | The ability to adapt, scale, install, or replace software in response to changing requirements and environments. Improvements in execution speed must not automatically be classified as scalability.                                                                   |
| Q09 Safety                                 | Operational constraint, risk identification, fail safe, hazard warning, safe integration                                                               | Prevention of operational hazards that could threaten human life, health, property, or the environment. This category may co-occur with Q06 Security and Q05 Reliability, but each assigned code requires independent supporting evidence.                              |
| Q99 No Explicit Quality Attribute Evidence | Not a tenth characteristic in the standard                                                                                                             | Used when an ADR merely records technology selection or organizational process decisions without verifiable quality requirements. One of the nine quality characteristics must not be assigned without supporting evidence.                                             |

## Explicit Trade-offs (TR)

| Code | Meaning                                          | Classification Rules                                                                                                                                     |
| ---- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TR00 | No Recorded Trade-off                            | The summary is empty, and no explicit comparison is recorded.                                                                                            |
| TR01 | Product Quality vs. Product Quality              | Explicit comparison between two product quality dimensions, without a non-quality factor.                                                                |
| TR02 | Product Quality vs. Non-Quality Factor           | Explicit comparison between a product quality concern and factors such as cost, effort, complexity, schedule, or licensing.                              |
| TR03 | Non-Quality Factor vs. Non-Quality Factor        | Comparison exclusively between non-quality factors, such as development effort and vendor dependency.                                                    |
| TR04 | Alternative Comparison with Unclear Dimensions   | Benefits and drawbacks of alternative solutions are compared, but the corresponding quality and/or non-quality factors cannot be reliably identified.    |
| TR99 | Conflicting Information or Insufficient Evidence | The summary conflicts with an explicit trade-off indicator, or the available evidence does not support the claimed trade-off. Manual review is required. |
