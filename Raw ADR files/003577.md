# ADR-004: Use Azure CDN for Image Storage

## Status
**Status:** Approved

## Context and Problem Statement
We are currently facing issues with database performance due to the storage of large media files (images) directly in the database. Storing images as base64 encoded strings or as BLOBs in the database is increasing the size of our database and causing slower query performance, especially when retrieving media-related information. Our primary goal is to reduce the impact on database performance and ensure scalability as the number of media items grows.

### Problem being solved:
- The database is becoming bloated with large image data.
- Image retrieval is slowing down query performance and overall user experience.

### Driving forces behind this decision:
- **Database performance**: Large images in base64 or BLOB format negatively impact query performance.
- **Scalability**: As the volume of media items increases, storing images in the database will not scale efficiently.
- **Cost-effective storage**: Cloud-based storage solutions like Azure CDN are optimized for serving large media files with low latency and can be more cost-effective than storing them in a traditional database.
- **Separation of concerns**: Storing images separately in an efficient storage system like Azure CDN allows the database to focus solely on structured data, improving maintainability.

## Decision Drivers
The decision drivers for choosing the most appropriate solution include:
- **Performance**: Reducing the load on the database and improving media retrieval times.
- **Scalability**: Supporting a growing number of media items without performance degradation.
- **Cost**: Choosing a solution that provides an efficient way to store and serve large media files without excessive costs.
- **Ease of integration**: Selecting a solution that can be easily integrated with existing systems and workflows.

## Options Considered
- **Option 1: Store images as base64 encoded strings in MySQL database**  
  - This option would involve storing base64 encoded images directly in the database. This option would cause the database to grow significantly in size, leading to slower query performance.
  
- **Option 2: Store images as BLOBs in MySQL database**  
  - Using the BLOB data type in MySQL allows storing raw binary image data in the database. However, this would still lead to database bloat and affect performance, especially as the number of images increases.
  
- **Option 3: Use file system storage for images**  
  - This approach would involve storing the images on a local file system and storing file paths in the database. While this reduces database bloat, it may not scale well in cloud environments or when handling large volumes of traffic and media files.
  
- **Option 4: Use Azure CDN for image storage**  
  - Azure CDN (Content Delivery Network) offers a scalable solution for storing and serving media files like images. This option provides low-latency image delivery globally, offloads the storage and delivery from the database, and integrates well with cloud-based infrastructure. It also reduces database bloat and ensures efficient image delivery across different regions.

## Decision Outcome
We have decided to use **Azure CDN** for storing and serving images.

### Why is this the best option?
- **Performance**: Azure CDN is specifically designed for delivering static content like images, and it ensures low-latency, high-performance access to images globally.
- **Scalability**: Azure CDN can scale automatically based on demand, handling a large number of media files and high traffic without impacting database performance.
- **Cost-effective**: Using a CDN for media storage reduces the load on the database and minimizes operational costs associated with maintaining large image data in the database.
- **Separation of concerns**: This solution allows the database to focus on structured data and metadata, while images are handled by a specialized content delivery service.

## Consequences
### Positive Outcomes:
- Improved database performance by offloading image storage to Azure CDN.
- Faster image retrieval times due to Azure CDN's global distribution and caching capabilities.
- Easier to manage and scale media storage with cloud-native solutions.
- Reduced database size, leading to faster backups, restores, and less database maintenance.

### Negative Outcomes:
- Initial setup and configuration of Azure CDN for image storage may require time and effort.
- Potential learning curve for team members unfamiliar with Azure CDN integration.
- Dependence on an external service for image storage could introduce risks related to uptime and external service reliability (though this is mitigated by Azure's reliability).

### What will be affected:
- **Codebase**: The application code will need to be updated to reference images stored in Azure CDN rather than retrieving them from the database.
- **Performance**: Positive impact on database and query performance, while the impact on image retrieval time will be minimized.

### How does this decision affect future systems:
- Future systems will continue to leverage cloud storage solutions like Azure CDN for media files, ensuring scalability and high performance as the system grows.

### Mitigation Strategy:
- We will monitor Azure CDN usage and performance to ensure that it meets our scalability needs.
- The integration with Azure CDN will be tested thoroughly before full implementation, ensuring smooth transition and minimal disruption to users.

## Confirmation
We will validate this decision by conducting performance testing on image retrieval times, monitoring the impact on database performance, and comparing costs between different storage solutions over time.

## Pros and Cons

### Pros:
- **Improved performance**: Faster media retrieval and reduced load on the database.
- **Scalability**: Easily scales to accommodate large numbers of media items.
- **Cost-effective**: Offloads image storage to a cloud-based solution optimized for delivery.
- **Global content delivery**: Low-latency access to media from users around the world.

### Cons:
- **Initial setup time**: Some configuration and integration effort are required to move images to Azure CDN.
- **External dependency**: We rely on Azure's availability and performance, which could be impacted by outages or service degradation.
- **Learning curve**: The team may need to get up to speed on how to integrate and use Azure CDN effectively.
