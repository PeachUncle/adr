# DEC-0010 Decision Summary

**Date:** 2025-12-20  
**Status:** ✅ DECIDED  
**Decision:** Keep strict exact version matching for v1.0.0

---

## Quick Summary

**Question:** Should we relax determinism enforcement during development (draft mode)?

**Answer:** No, keep strict for v1.0.0. Can add flexibility later if needed.

---

## Decision

**For v1.0.0:** **Keep exact version matching (Status Quo)**

```yaml
dependencies:
  - package: prompt-gen.common
    version: "1.0.0"  # Exact version - ALWAYS
```

---

## Rationale

### Why Keep Strict?

1. **✅ Already Implemented** - Working, tested, proven
2. **✅ Simple to Explain** - Clear guarantees, no complexity
3. **✅ Ship Stable v1.0.0** - Avoid premature optimization
4. **✅ Non-Breaking Evolution** - Can add features in v1.1.0+
5. **✅ Real Feedback First** - Don't solve hypothetical problems

### Trade-Offs Accepted

- ⚠️ Manual version updates required (acceptable)
- ⚠️ Can't auto-benefit from bug fixes (acceptable)
- ⚠️ Some DX friction (acceptable for v1.0.0)

### Why Not Draft Mode Now?

- Would add complexity (two validation modes)
- No real user feedback yet on DX friction
- Can add in v1.1.0 if users need it (non-breaking)
- Better to ship simple v1.0.0 first

### Why Not Lock Files Now?

- 1-2 weeks implementation (delays v1.0.0)
- Better suited for M12 marketplace milestone
- M12 already plans package registry (needs resolution anyway)
- Can implement lock files alongside registry

---

## Future Path

### v1.1.0 (Post-M10 - If Needed)
**Evaluate draft mode based on feedback**

If users say: "Manual version management is really painful!"
→ Implement draft mode (1-2 days work)

If users say: "Exact versions are fine"
→ Keep as-is

### M12 Marketplace (Weeks 9-12)
**Implement lock files with package registry**

This is the "proper" long-term solution:
- Industry-standard pattern (npm/yarn model)
- Flexible constraints + determinism guarantees
- Marketplace needs resolution algorithm anyway
- Perfect architectural alignment
