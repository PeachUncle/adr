# ADR-013: Azure Blob Storage for File Management

## Status

Accepted

## Context

Trama needs to store user-generated content:
- **Profile pictures** and artist portfolio images
- **Document uploads** (contracts, certificates)
- **Media files** for artwork listings
- **Backup data** and archives

Requirements:
- Scalable storage that grows with the platform
- Cost-effective for varying access patterns
- Secure access control with time-limited URLs
- Integration with .NET backend
- CDN capabilities for global content delivery

The key tension is between using a managed cloud storage service (Azure Blob Storage) versus self-hosted solutions (MinIO, local filesystem).

## Decision

We will use **Azure Blob Storage** as our primary file storage solution.

**Architecture:**
```
Client Upload Request
    ↓
API generates SAS token
    ↓
Client uploads directly to Azure Blob Storage
    ↓
API stores blob URL in PostgreSQL
    ↓
Client retrieves via CDN or SAS token
```

## Consequences

### Positive

- **Virtually Unlimited Storage**: Scales automatically as the platform grows
- **Cost-Effective Tiers**: Hot ($0.018/GB), Cool ($0.01/GB), Archive ($0.002/GB) per month
- **High Availability**: 99.9% SLA with geo-redundancy options (LRS, GRS, RA-GRS)
- **Secure Access**: SAS tokens provide time-limited, granular access control
- **Native .NET Integration**: Azure.Storage.Blobs SDK with excellent documentation
- **CDN Ready**: Easy integration with Azure CDN for global content delivery
- **Lifecycle Management**: Automated policies to move/delete old files
- **Data Protection**: Soft delete and versioning prevent accidental data loss
- **Monitoring**: Built-in metrics and Azure Monitor integration

### Negative

- **Vendor Lock-In**: Tight coupling to Azure (mitigated by `IFileStorageService` abstraction)
- **Cost Complexity**: Pricing varies by region, tier, operations, and egress
- **Egress Costs**: Data transfer out can be expensive at scale ($0.087/GB after 100GB)
- **Learning Curve**: Team needs Azure-specific knowledge (SAS tokens, storage tiers)
- **Archive Latency**: Archive tier has hours of retrieval delay
- **Regional Limits**: Some features unavailable in certain Azure regions

### Neutral

- Requires Azure subscription and account management
- Need cost monitoring and alerting
- Must establish container naming conventions
- Backup strategy beyond Azure's built-in redundancy

## Alternatives Considered

**Self-Hosted MinIO:**
- Pros: S3-compatible, no vendor lock-in, full control
- Cons: Infrastructure management, backup responsibility, scaling complexity
- Rejected: Adds operational burden, not cost-effective for showcase project

**AWS S3:**
- Pros: Industry standard, mature, similar features to Azure Blob Storage
- Cons: Requires AWS account, similar vendor lock-in, team already familiar with Azure
- Rejected: No significant advantage over Azure Blob Storage

**Local Filesystem:**
- Pros: Simple, no external dependencies, no cost
- Cons: Not scalable, no redundancy, difficult backups, no CDN
- Rejected: Not suitable for production or showcase deployment

**DigitalOcean Spaces:**
- Pros: S3-compatible, simple pricing, cheaper egress
- Cons: Less mature, fewer features, smaller ecosystem
- Rejected: Azure provides better integration with existing .NET stack

**Cloudflare R2:**
- Pros: Zero egress fees, S3-compatible, good pricing
- Cons: Newer service, less mature, limited regions
- Rejected: Azure Blob Storage more proven and better .NET support
