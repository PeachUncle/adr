# ADR-008: Hybrid Feed Algorithm

## Status
Accepted

## Context

Social Flow needs a feed algorithm that:
- Shows relevant and engaging content to users
- Balances chronological freshness with quality
- Provides personalization without filter bubbles
- Maintains user engagement and session time
- Scales to millions of users and posts

Pure chronological feeds miss good content from less active followed users, while pure algorithmic feeds can create echo chambers.

## Decision

We will implement a **hybrid feed algorithm** that combines:
1. **Chronological component** (30%): Recent posts from followed users
2. **Recommended component** (70%): ML-powered personalized recommendations

Users can also switch to pure chronological or pure recommended modes.

## Consequences

### Positive

- **Best of both worlds**: Fresh content + personalized recommendations
- **User control**: Can switch between algorithms
- **Better engagement**: More relevant content keeps users active
- **Discovery**: Helps users find new interesting content/creators
- **Flexibility**: Can tune ratio based on user behavior

### Negative

- **Complexity**: Requires ML infrastructure and training
- **Cold start**: New users have no personalization data
- **Computational cost**: Real-time ML inference adds latency
- **Maintenance**: Models need retraining and monitoring
- **Transparency concerns**: Users may not understand why they see content

### Risks

- **Filter bubbles**: Algorithm might create echo chambers
  - *Mitigation*: Diversity injection, serendipity factor
- **Engagement gaming**: Content creators might game the algorithm
  - *Mitigation*: Multiple ranking signals, spam detection
- **Latency**: ML inference could slow feed loading
  - *Mitigation*: Pre-compute recommendations, caching

## Algorithm Design

### Phase 1: Candidate Generation

Generate 1000+ candidate posts:

```typescript
async generateCandidates(userId: string): Promise<Post[]> {
  const candidates = await Promise.all([
    // 1. Posts from followed users (last 24h)
    this.getFollowingPosts(userId, { hours: 24 }),
    
    // 2. Trending posts
    this.getTrendingPosts({ limit: 100 }),
    
    // 3. Collaborative filtering (users similar to you liked)
    this.getCollaborativeFilteringPosts(userId),
    
    // 4. Content-based (similar to posts you liked)
    this.getContentBasedPosts(userId),
    
    // 5. Explore (random popular posts)
    this.getExplorePosts({ limit: 50 })
  ]);
  
  return deduplicateAndShuffle(candidates);
}
```

### Phase 2: Ranking

Rank candidates using ML model:

```typescript
interface RankingFeatures {
  // Content features
  postAge: number;
  contentType: 'text' | 'image' | 'video';
  contentLength: number;
  hasMedia: boolean;
  
  // Author features
  authorFollowerCount: number;
  authorVerified: boolean;
  userFollowsAuthor: boolean;
  
  // Engagement features
  likeCount: number;
  commentCount: number;
  shareCount: number;
  engagementRate: number;
  
  // User features
  userInterestMatch: number;
  userLanguageMatch: boolean;
  userPastEngagement: number;
  
  // Temporal features
  timeOfDay: number;
  dayOfWeek: number;
}

async rankPosts(posts: Post[], user: User): Promise<RankedPost[]> {
  // Extract features
  const features = posts.map(post => 
    extractFeatures(post, user)
  );
  
  // ML model inference
  const scores = await this.mlModel.predict(features);
  
  // Combine with chronological score
  return posts.map((post, i) => ({
    post,
    score: 0.7 * scores[i] + 0.3 * chronologicalScore(post)
  })).sort((a, b) => b.score - a.score);
}
```

### Phase 3: Diversity & Filtering

Apply post-processing:

```typescript
async postProcess(rankedPosts: RankedPost[]): Promise<Post[]> {
  let feed = rankedPosts;
  
  // 1. Remove duplicate authors (max 2 posts per author in top 20)
  feed = removeDuplicateAuthors(feed, { maxPerAuthor: 2, topN: 20 });
  
  // 2. Inject diversity (ensure variety of content types)
  feed = injectDiversity(feed);
  
  // 3. Inject serendipity (10% random popular posts)
  feed = injectSerendipity(feed, { ratio: 0.1 });
  
  // 4. Apply user filters (muted users, keywords)
  feed = applyUserFilters(feed, user);
  
  // 5. Add freshness boost to recent posts
  feed = applyFreshnessBoost(feed);
  
  return feed.map(r => r.post);
}
```

## ML Model

### Model Architecture

We use a **two-tower neural network**:

- **User tower**: Embeds user features
- **Post tower**: Embeds post features
- **Interaction**: Dot product + MLP for final score

```python
class FeedRankingModel(nn.Module):
    def __init__(self):
        self.user_tower = nn.Sequential(
            nn.Linear(user_features, 256),
            nn.ReLU(),
            nn.Linear(256, 128)
        )
        
        self.post_tower = nn.Sequential(
            nn.Linear(post_features, 256),
            nn.ReLU(),
            nn.Linear(256, 128)
        )
        
        self.interaction = nn.Sequential(
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 1),
            nn.Sigmoid()
        )
    
    def forward(self, user_features, post_features):
        user_emb = self.user_tower(user_features)
        post_emb = self.post_tower(post_features)
        interaction = user_emb * post_emb
        return self.interaction(interaction)
```

### Training Data

- **Positive examples**: Posts user engaged with (like, comment, share, long view)
- **Negative examples**: Posts user scrolled past
- **Features**: 50+ features covering content, author, engagement, user preferences
- **Training frequency**: Daily batch training on previous day's data

### Metrics

- **CTR (Click-Through Rate)**: % of posts clicked
- **Engagement rate**: % of posts liked/commented/shared
- **Session time**: Time spent in feed
- **Return rate**: % of users returning next day
- **Diversity score**: Content type variety in feed

## Implementation

### Caching Strategy

```typescript
class FeedService {
  async getFeed(userId: string, algorithm: FeedAlgorithm) {
    // Check cache (15 min TTL)
    const cached = await this.cache.get(`feed:${userId}:${algorithm}`);
    if (cached) return cached;
    
    // Generate feed
    const feed = await this.generateFeed(userId, algorithm);
    
    // Cache result
    await this.cache.set(`feed:${userId}:${algorithm}`, feed, { ttl: 900 });
    
    return feed;
  }
}
```

### Real-time Updates

```typescript
// Invalidate cache on new post from followed user
onPostCreated(post: Post) {
  const followers = await this.getFollowers(post.authorId);
  
  followers.forEach(followerId => {
    // Invalidate cache
    this.cache.del(`feed:${followerId}:*`);
    
    // Send real-time update
    this.pubsub.publish('postCreated', { post, userId: followerId });
  });
}
```

## Alternatives Considered

### Pure Chronological

**Pros:**
- Simple to implement
- Transparent to users
- No ML infrastructure needed
- No filter bubble concerns

**Cons:**
- Misses good content from less active users
- No personalization
- Lower engagement
- Rewards posting frequency over quality

**Why not chosen:** Engagement data shows users prefer personalized feeds.

### Pure Algorithmic

**Pros:**
- Maximum personalization
- Highest engagement
- Best content discovery

**Cons:**
- Filter bubble concerns
- Less transparency
- Misses breaking news/real-time events
- Users lose control

**Why not chosen:** Users want option to see latest posts from people they follow.

### Interest-Based (Twitter Communities style)

**Pros:**
- Strong interest alignment
- Good discovery
- Clear categories

**Cons:**
- Requires explicit interest selection
- Limits cross-pollination
- More complex UX

**Why not chosen:** Better as complementary feature, not primary feed.
