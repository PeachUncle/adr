# ADR-0001: Use CustomData with Parquet for LEAN Tick Data

**Status**: Accepted

**Date**: 2025-10-08

**Context**: We need to feed high-frequency tick data from multiple providers (Dukascopy, TrueFX, Binance, custom CSVs) into QuantConnect LEAN for backtesting. LEAN has native data formats, but our data sources are heterogeneous and stored in Parquet for efficiency.

## Decision

We will use **LEAN CustomData** to read Parquet files directly during backtests, with an optional path to convert to LEAN native formats later.

### Approach

1. **Primary Path** (Implemented Now):
   - Store normalized tick data in Hive-partitioned Parquet (`data/silver/symbol=/date=/`)
   - LEAN strategies use Python `polars.scan_parquet()` to read data in `Initialize()` or `OnData()`
   - Resample ticks to desired resolution (second/minute) within strategy
   - Feed to LEAN's internal data pipeline

2. **Secondary Path** (Future Optimization):
   - Build offline converter: `silver/` → LEAN native directory structure
   - Leverage LEAN's native data reader for ~10x speed on repeated backtests
   - Converter script: `scripts/lean/convert_to_lean_format.py` (TODO)

## Rationale

### Pros
- **Flexibility**: Support any data format via normalization pipeline
- **Storage Efficiency**: Parquet with zstd is 5-10x smaller than CSV
- **Query Performance**: Column pruning, predicate pushdown, lazy evaluation
- **No Vendor Lock-in**: Keep data in open format, not tied to LEAN structure
- **Unified Pipeline**: Same Parquet files used for research notebooks and backtests

### Cons
- **Slower than Native**: LEAN native format is optimized for sequential reads
  - Mitigation: Use lazy loading, cache frequently accessed data
- **Memory Overhead**: Loading ticks in Python before LEAN ingestion
  - Mitigation: Batch processing, streaming from Parquet

## Alternatives Considered

### 1. Convert all data to LEAN native format upfront
- **Pros**: Fastest backtest execution
- **Cons**:
  - Rigid structure, harder to version/update
  - Large storage footprint (uncompressed CSV-based)
  - Difficult to integrate new sources

### 2. Use LEAN SubscriptionDataSource API
- **Pros**: Official LEAN approach for custom data
- **Cons**:
  - Still requires format conversion
  - Less flexible than direct Polars access
  - Harder to debug data issues

## Consequences

- **Initial Development**: Strategies must handle Parquet reads (template provided)
- **Performance**: Accept 20-30% slower backtests vs native format (acceptable for research phase)
- **Future Work**: Build converter once strategy patterns stabilize
- **Documentation**: Provide clear examples of CustomData usage in strategy templates

## Implementation Notes

**Strategy Template Pattern**:

```python
class MyStrategy(QCAlgorithm):
    def Initialize(self):
        # Load tick data from Parquet
        import polars as pl
        self.tick_data = pl.scan_parquet(
            f"/data/silver/symbol={self.symbol}/date={self.date}/*.parquet"
        ).collect()

        # Resample to desired resolution
        self.bars = self.tick_data.group_by_dynamic("ts", every="1m").agg(...)
```

**Converter Script** (Future):
```bash
python scripts/lean/convert_to_lean_format.py \
  --input data/silver \
  --output /Lean/Data \
  --format tick
```
