# Design: Add RaBitQ Vector Query

## Context
RaBitQ uses asymmetric quantization for queries: dataset vectors are quantized to 1-bit (binary), while query vectors use higher precision (4-bit or 8-bit). This asymmetry provides better distance estimation accuracy at negligible query processing cost, since queries are processed once while data is stored persistently.

## Goals / Non-Goals

### Goals
- Implement mathematically correct RaBitQ distance estimation
- Support configurable query precision (4-bit, 8-bit) via comptime
- Efficient top-k nearest neighbor selection
- SIMD optimization for dot products where possible
- Clean API: single function call returns top-k results

### Non-Goals
- Not implementing index structures (IVF, HNSW) - linear scan only
- Not supporting batch queries initially (can add later)
- Not optimizing for specific k values (general solution)

## Decisions

### Decision 1: QuantizedData Structure Update

Add projection matrix storage:

```zig
pub const QuantizedData = struct {
    hypercube_vectors: Matrix,  // N × d
    corrective_1: []f32,        // N values
    corrective_2: []f32,        // N values
    centroid: []f32,            // D dimensions
    projection: Matrix,         // D × d (NEW)
    dimension: usize,           // d
    allocator: Allocator,
};
```

**Rationale**: Query processing requires the same projection matrix P used during quantization.

### Decision 2: QueryResult Structure

```zig
pub const QueryResult = struct {
    index: usize,     // Vector index in dataset
    distance: f32,    // Estimated distance
    
    pub fn lessThan(context: void, a: QueryResult, b: QueryResult) bool {
        _ = context;
        return a.distance < b.distance;
    }
};
```

### Decision 3: Main Query API

```zig
pub fn queryTopK(
    comptime B: u8,                    // Query precision: 4 or 8 bits
    quantized_data: QuantizedData,
    query_vector: []const f32,         // D dimensions
    k: usize,                          // Number of results
    allocator: Allocator,
) ![]QueryResult
```

**Comptime B**: Allows compiler to optimize quantization levels (2^B - 1) and eliminate branches.

## Algorithm: RaBitQ Query

### Step 1: Query Preprocessing

```zig
// Input: q (raw query vector, D dimensions)
// Output: q_rotated (projected normalized query, d dimensions)

q_residual = q - centroid
norm_q_residual = ||q_residual||  // L2 norm
q_norm = q_residual / norm_q_residual
q_rotated = P^T * q_norm  // Project using transpose
```

**SIMD**: Use SIMD for centering, norm computation, normalization, and projection dot products.

### Step 2: Asymmetric Quantization (B-bit)

```zig
// Determine quantization range
q_lower = min(q_rotated)  // Minimum value
q_upper = max(q_rotated)  // Maximum value
width = (q_upper - q_lower) / ((2^B) - 1)

// Quantize to B-bit integers
q_bar[i] = floor((q_rotated[i] - q_lower) / width)  // Range: [0, 2^B - 1]
q_bar_sum = Σ q_bar[i]
```

**Example (B=4)**:
- Range: [0, 15] (4 bits)
- If q_rotated values in [-0.5, 0.8]
- width = 1.3 / 15 ≈ 0.0867
- q_rotated[i] = 0.2 → q_bar[i] = floor((0.2 - (-0.5)) / 0.0867) = floor(8.07) = 8

### Step 3: Distance Estimation Loop

For each dataset vector v (index i):

```zig
// Retrieve quantized data
hyper_cube = quantized_data.hypercube_vectors.getRow(i)  // d values: ±1/√d
corrective_1 = quantized_data.corrective_1[i]            // ||v_residual||
corrective_2 = quantized_data.corrective_2[i]            // dot(v_rotated, hyper_cube)

// Count 1's in hypercube (positive values = 1, negative = 0)
pop_count_hyper = countIf(hyper_cube[j] > 0 for j in 0..d)

// Compute dot product term
dot_term = 0.0
for j in 0..d:
    dot_term += q_bar[j] * hyper_cube[j]

// Estimate <v_norm, q_norm>
term1 = (2.0 * width / sqrt(d)) * dot_term
term2 = (2.0 * q_lower / sqrt(d)) * pop_count_hyper
term3 = (width * q_bar_sum / sqrt(d))
term4 = sqrt(d) * q_lower

inner_product_est = (term1 + term2 + term3 - term4) / corrective_2

// Final distance estimate (Euclidean)
distance_sq = corrective_1² + norm_q_residual² - 
              2 * corrective_1 * norm_q_residual * inner_product_est
distance = sqrt(max(0, distance_sq))  // Clamp to avoid sqrt(negative)
```

**Note**: The `max(0, ...)` clamp handles numerical errors in approximation.

### Step 4: Top-K Selection

**Algorithm**: Min-heap of size k

```zig
// Initialize heap with first k results
heap = MinHeap(QueryResult, k)
for i in 0..k:
    heap.insert({.index = i, .distance = distances[i]})

// Process remaining vectors
for i in k..N:
    if distances[i] < heap.peek().distance:
        heap.pop()
        heap.insert({.index = i, .distance = distances[i]})

// Extract results (sorted by distance)
results = heap.toSortedSlice()
```

**Complexity**: O(N*d) for distance computation + O((N-k)*log(k)) for heap operations

**Alternative for small k**: Could use partial sort, but heap is more cache-friendly.

## SIMD Optimization Strategy

### 1. Query Preprocessing
- **Centering**: SIMD subtraction (q - centroid)
- **Norm**: SIMD multiply-add for sum of squares
- **Normalization**: SIMD division
- **Projection**: SIMD dot products (P^T columns × q_norm)

### 2. Distance Loop
- **Dot product**: SIMD multiply-add for q_bar × hyper_cube
- **Pop count**: Use SIMD compare and reduce (count positive values)

### 3. When to Use SIMD
- Power-of-2 dimensions >= 8
- Use @Vector(8, f32) for consistency with existing code

## Memory Layout

### Per-Query Allocations
```
q_residual:     D floats (temporary)
q_norm:         D floats (temporary)
q_rotated:      d floats (temporary)
q_bar:          d integers (temporary)
distances:      N floats (or streaming)
results:        k QueryResults
```

**Total**: ~(2D + 2d + N + k) allocations

**Optimization**: Could stream distances instead of storing all N, but adds complexity.

## Performance Estimates

### Query Time (SIFT-1M, D=128, d=64, k=10)

```
Preprocessing:     ~10 µs (centering, norm, projection)
Quantization:      ~5 µs (min/max, quantize d values)
Distance loop:     ~50 ms (1M vectors × 64 dims)
Top-k selection:   ~200 µs (heap operations)
Total:             ~50 ms
```

**Throughput**: ~20 queries/second (single-threaded)

## Risks / Trade-offs

### Risk: Numerical Stability
- **Issue**: Distance squared could be negative due to approximation errors
- **Mitigation**: Clamp to zero before sqrt

### Risk: Projection Matrix Memory
- **Issue**: Adds D×d floats to QuantizedData
- **Impact**: For SIFT (128×64), adds 32 KB per index
- **Acceptable**: Small compared to hypercube storage

### Trade-off: B Parameter
- **B=4**: Faster (16 levels), less accurate
- **B=8**: Slower (256 levels), more accurate
- **Decision**: Support both via comptime, let user choose
