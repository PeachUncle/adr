# ADR-031: Comprehensive Testing Framework

**Status**: Accepted  
**Date**: 2025-10-16  
**Decision Makers**: Architecture Team, QA Team, Trading Operations  
**Related ADRs**: ADR-023 (Testing Strategy), ADR-018 (GitHub Actions CI/CD), ADR-004 (BigQuery Analytics), ADR-016 (Cloud Run)  
**Supersedes**: ADR-023 (expands with comprehensive implementation details)

## Context

The multi-agent options trading system requires comprehensive testing to ensure correctness, reliability, and safety before deploying capital at risk. While ADR-023 established the foundational testing strategy, this ADR provides detailed implementation specifications for all 85 testing requirements, including test organization, tooling, CI/CD integration, and quality gates.

### Business Requirements

1. **Capital Protection**: No untested code executes trades with real money
2. **Regulatory Compliance**: Audit trail of test results for system validation
3. **Continuous Deployment**: Fast test execution (<5 minutes) enables rapid iteration
4. **Risk Mitigation**: Comprehensive coverage (>80% unit, >70% integration) reduces production failures
5. **Strategy Validation**: Backtesting and forward testing prove profitability before live deployment

### Technical Challenges

1. **Distributed Coordination**: Testing asynchronous multi-agent workflows
2. **External Dependencies**: Mocking third-party APIs (Alpha Vantage, Polygon, broker)
3. **Stateful Operations**: Testing trading session state machines
4. **Financial Calculations**: Validating Greeks to 6+ decimal precision
5. **Time-Based Behavior**: Testing market hours, expirations, time-to-expiry

## Decision

We adopt a **comprehensive multi-layered testing framework** with:

1. **Unit Tests** (80%+ coverage): Isolated function/class testing with pytest
2. **Integration Tests** (70%+ coverage): Agent communication, database, Pub/Sub
3. **End-to-End Tests**: Full workflow validation from stock selection to order generation
4. **Backtests**: 3+ years historical performance validation
5. **Forward Tests**: 1 month paper trading before live deployment
6. **Performance Tests**: Load testing and latency validation

### 2. Unit Testing Framework

**Tools**:
- `pytest`: Test framework (simple syntax, powerful fixtures)
- `pytest-cov`: Coverage measurement (<80% fails CI)
- `pytest-mock`: Dependency mocking
- `pytest-asyncio`: Async code testing
- `hypothesis`: Property-based testing for financial calculations
- `freezegun`: Time mocking

**Coverage Requirements**:

| Component | Target | CI Gate |
|-----------|--------|---------|
| Greeks Calculator | 95% | <90% fails |
| Risk Validator | 95% | <90% fails |
| Portfolio Hedging | 90% | <85% fails |
| Strategy Agents | 85% | <80% fails |
| Orchestrator | 85% | <80% fails |
| Repositories | 80% | <75% fails |
| ML Models | 75% | Warning <70% |

**Test Pattern (AAA)**:

```python
def test_calculate_portfolio_delta_multiple_positions():
    """Test portfolio delta with multiple positions."""
    # Arrange
    positions = [
        Position(symbol="AAPL", quantity=100, delta=0.6),
        Position(symbol="MSFT", quantity=-50, delta=0.45),
    ]
    calculator = GreeksCalculator()
    
    # Act
    portfolio_delta = calculator.calculate_portfolio_delta(positions)
    
    # Assert
    assert portfolio_delta == pytest.approx(37.5, abs=0.01)
```

**Example**:

```python
def test_stock_analysis_message_flow(pubsub_emulator):
    """Test message from orchestrator to stock selection."""
    publisher = pubsub.PublisherClient()
    topic_path = publisher.topic_path(PROJECT, "stock-analysis-tasks")
    
    task_message = {"task_id": "task_123", "max_symbols": 50}
    future = publisher.publish(topic_path, json.dumps(task_message).encode())
    future.result(timeout=5)

    subscriber = pubsub.SubscriberClient()
    response = subscriber.pull(subscription_path, max_messages=1, timeout=5)
    assert len(response.received_messages) == 1
```

### 7. CI/CD Integration

**GitHub Actions Workflow**:

```yaml
name: Test Suite
on: [push, pull_request]

jobs:
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
        with: { python-version: '3.11' }
      - run: pip install -r requirements.txt
      - run: pytest tests/unit/ --cov=src --cov-fail-under=80
  
  integration-tests:
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:15 }
      pubsub: { image: google/cloud-sdk }
    steps:
      - run: pytest tests/integration/ --cov-fail-under=70
  
  e2e-tests:
    if: github.ref == 'refs/heads/main'
    steps:
      - run: pytest tests/e2e/ --environment=staging
```

**Quality Gates**:
- ✅ All tests pass (100%)
- ✅ Unit coverage ≥80%
- ✅ Integration coverage ≥70%
- ✅ No critical vulnerabilities
- ✅ Code style compliance (Black, isort, flake8)
- ✅ Type checking passes (mypy strict)

## Consequences

### Positive
1. High confidence from 80%+ coverage
2. Fast feedback (<5 min CI)
3. Regression prevention
4. Financial safety via backtesting
5. Performance assurance

### Negative
1. Maintenance overhead for large test suite
2. 10-15 minute full suite execution
3. Mock complexity for external APIs
4. Flaky async tests

### Risks
1. Coverage gaps despite high percentage
2. Mock drift from real APIs
3. Staging != production load
4. Backtest overfitting

### Mitigation
1. Mandatory code reviews
2. Quarterly mock validation
3. Production monitoring (ADR-029)
4. Walk-forward testing
5. Test quarantine for flaky tests
