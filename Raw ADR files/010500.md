# ADR-004: Communication Protocols

**Status**: Accepted  
**Date**: 2025-06-30  
**Decision Makers**: AI Society Communication Team  

## Context

Agents need structured ways to communicate and collaborate. Rather than free-form communication, we need patterns that enable efficient collective problem-solving while maintaining order and traceability.

## Decision

Implement structured communication protocols:

1. **Message Structure**
   ```typescript
   interface AgentMessage {
     id: string;
     timestamp: Date;
     fromAgent: string;
     toAgent: string | 'all';
     type: 'proposal' | 'review' | 'decision' | 'knowledge' | 'query' | 'response';
     content: any;
     requiresResponse?: boolean;
     priority?: 'urgent' | 'high' | 'normal' | 'low';
   }
   ```

2. **Communication Patterns**

   **Design Circle**: Structured deliberation for major decisions
   - Initiator presents proposal
   - All agents provide perspective
   - Guiding circle synthesizes
   - Consensus or guided decision

   **Problem Swarm**: Self-organizing for complex challenges
   - Problem broadcast
   - Interested agents self-select
   - Parallel exploration
   - Solution synthesis
   - Swarm dissolution

   **Code Review**: Quality assurance pattern
   - Builder submits code
   - Required reviewers respond
   - Iterative improvement
   - Final approval

   **Knowledge Propagation**: Asynchronous learning
   - Agent discovers pattern
   - Broadcasts to all
   - Others integrate if relevant
   - Collective intelligence grows

   **Ambient Awareness**: Passive learning
   - Monitor all messages
   - Extract patterns
   - Build context
   - Emergent understanding

3. **Communication Bus**: Central message routing
   - Priority queues per agent
   - Message history retention
   - Subscription system
   - Channel-based organization

## Rationale

### Why Structured Protocols?

- **Efficiency**: Clear patterns reduce overhead
- **Traceability**: Decisions have clear lineage
- **Quality**: Built-in review processes
- **Scalability**: Patterns work with many agents

### Why These Specific Patterns?

- **Design Circle**: Ensures thoughtful architecture
- **Problem Swarm**: Leverages collective intelligence
- **Code Review**: Maintains code quality
- **Knowledge Propagation**: Enables learning
- **Ambient Awareness**: Captures emergent insights

### Why Priority System?

- **Resource Allocation**: Handle urgent tasks first
- **Flow Control**: Prevent agent overwhelm
- **Responsiveness**: Critical issues addressed quickly

## Consequences

### Positive

- Clear communication pathways
- Reduced message chaos
- Better decision quality
- Audit trail for all decisions
- Emergent collaboration patterns

### Negative

- Initial protocol overhead
- Learning curve for patterns
- Potential rigidity
- Message queue management

### Neutral

- Requires protocol evolution
- Need for pattern metrics
- Documentation important
- Training new agents

## Implementation Details

### Message Flow

1. **Send**: Agent creates message
2. **Route**: Bus determines recipients
3. **Queue**: Priority-based queuing
4. **Process**: Agent handles message
5. **Respond**: Optional response

### Protocol Execution

```typescript
// Example: Design Circle
const decision = await protocol.executePattern('design-circle', {
  bus: communicationBus,
  initiator: systemArchitect,
  participants: allAgents,
  topic: 'New Feature Design',
  data: proposalData
});
```

### Channel Types

- `design-circle`: Major decisions
- `build-coordination`: Development tasks
- `knowledge-sharing`: Learning propagation
- `ethics-review`: Ethical validation

## Anti-Patterns to Avoid

- **Message Flooding**: Too many low-priority messages
- **Decision Paralysis**: Over-deliberation
- **Echo Chambers**: Agents reinforcing biases
- **Protocol Rigidity**: Not adapting patterns

## Monitoring and Metrics

- Message volume by type and agent
- Response times
- Protocol success rates
- Knowledge propagation speed
- Emergent pattern detection
