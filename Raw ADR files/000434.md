# ADR-004: Hybrid ML/Heuristic Systems for Real-Time Detection

**Status**: Accepted
**Date**: December 2024
**Author**: Vincent
**Implementation**: [Sentinel](https://github.com/BugVanquisher/Sentinel)

---

## Context

When building real-time detection systems (abuse, safety, fraud), there's a fundamental tension:

**Machine Learning**:
- Excellent at nuanced pattern recognition
- Can generalize to novel variations
- But: 10-500ms latency, requires training data

**Heuristics (Rules/Regex)**:
- Sub-millisecond latency
- Deterministic, explainable
- But: Brittle, requires manual updates

### The Wrong Question

"Should we use ML or rules?" is the wrong question.

### The Right Question

"Which technique should handle which cases, and how do they interact?"

---

## Decision

**Implement a hybrid system where heuristics handle clear cases and ML handles ambiguous cases:**

```
┌──────────────────────────────────────────────────────────────┐
│                 HYBRID DETECTION PIPELINE                    │
├──────────────────────────────────────────────────────────────┤
│  INPUT                                                       │
│    │                                                         │
│    ▼                                                         │
│  ┌────────────────────────┐                                  │
│  │ Heuristic Layer        │ <1ms                             │
│  │ • Regex patterns       │ "Is this obviously bad?"         │
│  │ • Block lists          │                                  │
│  │ • Format validators    │                                  │
│  └───────────┬────────────┘                                  │
│              │                                               │
│    ┌─────────┴─────────┐                                     │
│    │ Match?            │                                     │
│    └─────────┬─────────┘                                     │
│         YES  │  NO                                           │
│         ▼    ▼                                               │
│    ┌─────┐  ┌────────────────────┐                           │
│    │BLOCK│  │ ML Layer           │ 20-50ms                   │
│    └─────┘  │ • BERT classifiers │ "Is this subtly bad?"     │
│             │ • NER models       │                           │
│             │ • Embedding search │                           │
│             └───────────┬────────┘                           │
│                         │                                    │
│               ┌─────────┴─────────┐                          │
│               │ Confident?        │                          │
│               └─────────┬─────────┘                          │
│              YES        │  NO                                │
│              ▼          ▼                                    │
│         ┌─────────┐  ┌─────────┐                             │
│         │ DECIDE  │  │ ESCALATE│                             │
│         └─────────┘  │(human/LLM)│                           │
│                      └─────────┘                             │
└──────────────────────────────────────────────────────────────┘
```

### Design Principles

1. **Heuristics First**: Cheap checks before expensive ones
2. **ML for Ambiguity**: Use ML where patterns can't decide
3. **Confidence Routing**: Route uncertain cases to higher-cost systems
4. **Continuous Learning**: ML failures become heuristic patterns

## Implementation in Sentinel

### Heuristic Layer

```python
# sentinel/detectors/heuristics.py

class HeuristicDetector:
    """
    Fast pattern-based detection for obvious cases.

    Design Philosophy:
    - If we KNOW it's bad (exact pattern), heuristics handle it
    - If we're UNSURE (no pattern match), ML decides
    - Heuristics are FAIL-FAST: one match = done

    Performance: <1ms for 100+ patterns
    """

    def __init__(self):
        # Pre-compile patterns for speed
        self.injection_patterns = self._compile_patterns(INJECTION_PATTERNS)
        self.toxic_keywords = self._load_blocklist("toxic_keywords.txt")
        self.secret_patterns = self._compile_patterns(SECRET_PATTERNS)

    def detect(self, text: str) -> HeuristicResult:
        start = time.perf_counter()

        # Check injection patterns (most common attack)
        for pattern in self.injection_patterns:
            if pattern.search(text):
                return HeuristicResult(
                    detected=True,
                    type="injection",
                    confidence=0.95,  # High confidence for exact match
                    latency_ms=(time.perf_counter() - start) * 1000
                )

        # Check toxic keywords (simple cases)
        text_lower = text.lower()
        for keyword in self.toxic_keywords:
            if keyword in text_lower:
                # Keyword match = medium confidence (context matters)
                return HeuristicResult(
                    detected=True,
                    type="toxic_keyword",
                    confidence=0.7,  # Lower confidence, ML should verify
                    latency_ms=(time.perf_counter() - start) * 1000
                )

        # Check secrets
        for pattern in self.secret_patterns:
            if pattern.search(text):
                return HeuristicResult(
                    detected=True,
                    type="secret",
                    confidence=0.99,  # Very high confidence
                    latency_ms=(time.perf_counter() - start) * 1000
                )

        return HeuristicResult(
            detected=False,
            latency_ms=(time.perf_counter() - start) * 1000
        )

    def _compile_patterns(self, patterns: List[str]) -> List[re.Pattern]:
        """
        Pre-compile and optimize patterns.

        Optimization: Combine into alternation group where possible
        """
        return [re.compile(p, re.IGNORECASE) for p in patterns]
```

### ML Layer

```python
# sentinel/detectors/ml_detectors.py

class MLDetectorEnsemble:
    """
    ML-based detection for nuanced cases.

    Called when:
    1. Heuristics didn't match (need deeper analysis)
    2. Heuristic confidence is low (need verification)

    Models:
    - ToxicityClassifier: BERT-based toxicity scoring
    - PIIDetector: NER-based PII extraction
    - IntentClassifier: Harmful intent detection
    """

    def __init__(self):
        self.toxicity = ToxicityClassifier(model="unitary/toxic-bert")
        self.pii = PIIDetector(engine="presidio")
        self.intent = IntentClassifier(model="custom-intent-v2")

    async def detect(self, text: str, context: dict) -> MLResult:
        start = time.perf_counter()

        # Run detectors in parallel
        results = await asyncio.gather(
            self.toxicity.score(text),
            self.pii.extract(text),
            self.intent.classify(text, context),
            return_exceptions=True
        )

        toxicity_score, pii_entities, intent_result = results

        # Aggregate results
        detections = []
        max_confidence = 0

        if toxicity_score > 0.7:
            detections.append(Detection(
                type="toxicity",
                confidence=toxicity_score,
                details={"score": toxicity_score}
            ))
            max_confidence = max(max_confidence, toxicity_score)

        if pii_entities:
            detections.append(Detection(
                type="pii",
                confidence=max(e.score for e in pii_entities),
                details={"entities": [e.to_dict() for e in pii_entities]}
            ))
            max_confidence = max(max_confidence, max(e.score for e in pii_entities))

        if intent_result.is_harmful:
            detections.append(Detection(
                type="harmful_intent",
                confidence=intent_result.confidence,
                details={"intent": intent_result.intent}
            ))
            max_confidence = max(max_confidence, intent_result.confidence)

        return MLResult(
            detected=len(detections) > 0,
            detections=detections,
            confidence=max_confidence,
            latency_ms=(time.perf_counter() - start) * 1000
        )
```

### Hybrid Orchestrator

```python
# sentinel/engine/hybrid.py

class HybridDetector:
    """
    Orchestrates heuristic and ML detection.

    Decision Logic:
    1. Run heuristics first (always)
    2. If heuristic confidence >= 0.9: use heuristic decision
    3. If heuristic confidence 0.6-0.9: run ML to verify
    4. If heuristic confidence < 0.6 or no match: run ML
    5. If ML confidence < threshold: escalate to human/LLM

    Why this order?
    - Most traffic (80%+) is legitimate, heuristics say "pass" quickly
    - Clear violations caught fast without ML overhead
    - ML resources reserved for ambiguous cases
    """

    def __init__(self):
        self.heuristics = HeuristicDetector()
        self.ml = MLDetectorEnsemble()
        self.confidence_thresholds = {
            "high": 0.9,    # Heuristic alone sufficient
            "medium": 0.6,  # ML verification recommended
            "low": 0.3      # Escalate if below this
        }

    async def detect(self, text: str, context: dict = None) -> DetectionResult:
        # Step 1: Heuristics (always run, <1ms)
        heuristic_result = self.heuristics.detect(text)

        if heuristic_result.detected:
            if heuristic_result.confidence >= self.confidence_thresholds["high"]:
                # High-confidence heuristic match: done
                return DetectionResult(
                    verdict="block",
                    source="heuristic",
                    confidence=heuristic_result.confidence,
                    reason=heuristic_result.type,
                    latency_ms=heuristic_result.latency_ms
                )

            # Medium-confidence: verify with ML
            elif heuristic_result.confidence >= self.confidence_thresholds["medium"]:
                ml_result = await self.ml.detect(text, context)

                # ML confirms heuristic
                if ml_result.detected and ml_result.confidence >= 0.7:
                    return DetectionResult(
                        verdict="block",
                        source="hybrid",
                        confidence=(heuristic_result.confidence + ml_result.confidence) / 2,
                        reason=f"{heuristic_result.type} (ML confirmed)",
                        latency_ms=heuristic_result.latency_ms + ml_result.latency_ms
                    )

                # ML disagrees: use ML (more nuanced)
                elif not ml_result.detected:
                    return DetectionResult(
                        verdict="pass",
                        source="ml_override",
                        confidence=1 - ml_result.confidence,
                        reason="ML override of heuristic",
                        latency_ms=heuristic_result.latency_ms + ml_result.latency_ms
                    )

        # Step 2: ML for no heuristic match or low confidence
        ml_result = await self.ml.detect(text, context)

        if ml_result.detected:
            if ml_result.confidence >= self.confidence_thresholds["medium"]:
                return DetectionResult(
                    verdict="block",
                    source="ml",
                    confidence=ml_result.confidence,
                    reason=ml_result.detections[0].type,
                    latency_ms=heuristic_result.latency_ms + ml_result.latency_ms
                )

            # Low ML confidence: escalate
            elif ml_result.confidence < self.confidence_thresholds["low"]:
                return DetectionResult(
                    verdict="escalate",
                    source="uncertain",
                    confidence=ml_result.confidence,
                    reason="Low confidence, human review needed",
                    latency_ms=heuristic_result.latency_ms + ml_result.latency_ms
                )

        # Nothing detected
        return DetectionResult(
            verdict="pass",
            source="clear",
            confidence=1 - max(heuristic_result.confidence, ml_result.confidence if ml_result else 0),
            latency_ms=heuristic_result.latency_ms + (ml_result.latency_ms if ml_result else 0)
        )
```

### Feedback Loop: ML to Heuristics

```python
# sentinel/engine/feedback.py

class FeedbackProcessor:
    """
    Convert ML detections into heuristics for future speed.

    When ML catches something repeatedly:
    1. Extract pattern from examples
    2. Validate pattern doesn't over-match
    3. Promote to heuristic layer

    This continuously shifts work from ML to heuristics.
    """

    async def process_ml_detection(self, detection: MLResult, text: str):
        """
        Analyze ML detection for pattern extraction.
        """
        # Track detection
        await self.detection_store.record(
            type=detection.detections[0].type,
            text=text,
            confidence=detection.confidence
        )

        # Check if pattern emerges
        similar_detections = await self.detection_store.get_similar(
            type=detection.detections[0].type,
            min_count=10,  # Need 10+ examples
            days_back=7
        )

        if similar_detections:
            # Extract common pattern
            pattern = self.pattern_extractor.extract(
                [d.text for d in similar_detections]
            )

            if pattern and pattern.precision >= 0.95:
                # Validate on held-out data
                validation = await self.validate_pattern(pattern)

                if validation.false_positive_rate < 0.01:
                    # Promote to heuristics
                    await self.heuristics.add_pattern(
                        category=detection.detections[0].type,
                        pattern=pattern.regex,
                        metadata={
                            "source": "ml_promotion",
                            "examples": len(similar_detections),
                            "precision": pattern.precision
                        }
                    )

                    logger.info(f"Promoted ML detection to heuristic: {pattern.regex}")
```

## Performance Analysis

### Latency Breakdown

| Scenario | Heuristic | ML | Total | % of Traffic |
|----------|-----------|------|-------|--------------|
| Clear pass (no match) | 0.3ms | - | 0.3ms | 75% |
| Heuristic block (high conf) | 0.5ms | - | 0.5ms | 15% |
| Heuristic + ML verify | 0.5ms | 35ms | 35.5ms | 5% |
| ML only (no heuristic match) | 0.3ms | 40ms | 40.3ms | 4% |
| Escalate | 0.3ms | 40ms | 40.3ms + queue | 1% |

**Weighted Average**: 3.5ms (because 75% of traffic is clear pass)

### Cost Analysis

| Layer | Cost per Request | % of Traffic | Weighted Cost |
|-------|-----------------|--------------|---------------|
| Heuristics only | $0 | 90% | $0 |
| ML (local models) | $0 | 9% | $0 |
| LLM escalation | $0.02 | 1% | $0.0002 |

**Total cost**: $0.0002 per request (vs. $0.02 for LLM-only)

## Consequences

### Benefits

1. **Speed**: 90% of requests handled in <1ms
2. **Cost**: 100x cheaper than LLM-only approaches
3. **Explainability**: Heuristic matches are deterministic
4. **Continuous Improvement**: ML findings become heuristics

### Trade-offs

1. **Maintenance**: Two systems to maintain
   - Mitigation: Clear boundaries, automatic promotion
   - Benefit: Each system is simpler than unified approach

2. **Consistency**: Different paths may give different results
   - Mitigation: ML override capability, unified confidence scores
   - Acceptable: Edge cases handled by escalation

3. **Coverage Gap**: New attacks may evade both initially
   - Mitigation: Logging for analysis, rapid pattern updates
   - Reality: No system is perfect, but hybrid catches more

## Alternatives Considered

### 1. ML-Only Detection

**Rejected because**:
- 40ms minimum latency for all requests
- High cost at scale
- Overkill for obvious patterns

### 2. Heuristics-Only Detection

**Rejected because**:
- Misses nuanced toxicity (sarcasm, coded language)
- Can't detect novel attacks
- High maintenance burden

### 3. Sequential (Heuristics → ML always)

**Rejected because**:
- Always pays ML latency
- Heuristics become bottleneck for ML
- No early exit optimization
