# ADR-0002: Use Regina REXX

## Status

🟢 Active

## Context

We need a REXX interpreter that...
- supports the classic dialect of REXX
  - we want to be able to run this framework on Linux/MacOS as well as MVS 3.8k
    and z/OS without change.
- is free and open source
- has resilient and active community support

## Decision

The target REXX interpreter for this project is Regina REXX.

https://regina-rexx.sourceforge.io/index.html

## Rationale

- Regina REXX's project [aims to be ANSI Standard](https://regina-rexx.sourceforge.io/#:~:text=become%20100%25%20compliant%20with%20the%20ANSI%20Standard).
  - as of Regina 3.1, the author claims this is now true.
  - at the time of writing, there is no ANSI test suite for REXX.
- At the time of writing, Regina REXX is (one of) the most widely-used REXX interpreters.
- While [ooRexx](#open-object-rexx-oorexx) is a reasonable option, Regina is
  more popular and more specifically designed for our purposes: use classic REXX
  that likely runs unchanged on the mainframe as well.
 

## Alternatives Considered

### Open Object REXX (ooRexx)

https://www.oorexx.org/

- This is one of the most popular REXX interpreters, today.
- This interpreter is designed to be backwards compatible with classic REXX
  with _extensions_ to support OO features.

This makes this interpreter an acceptable choice.


### NetRexx

https://www.netrexx.org/

Written by the creator of REXX, Mike Cowlishaw, and running on the JVM (where
JUnit and friends live) is very tempting.

However:
- NetRexx's goal is to embrace the OO features provided on the JVM which
  runs counter to our goal of supporting a classic dialect of REXX.


### BREXX

https://github.com/vlachoudis/brexx

This is also a tempting option because it aims to emulate REXX on the mainframe.

However,
- this project is no longer actively maintained and has identified bugs.
