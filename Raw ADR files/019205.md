# ADR-008: React with TypeScript Frontend

## Status

Accepted

## Context

The Trama platform requires a modern, interactive frontend for users to discover artists, browse portfolios, and manage profiles. We want to use current industry-standard technologies that provide:

- **Type Safety**: Catch errors at compile time, not runtime
- **Developer Experience**: Fast feedback, autocomplete, refactoring support
- **Modern Tooling**: Fast build times, hot module replacement
- **Component Reusability**: Build UI from composable components
- **State Management**: Handle complex client-side state
- **API Integration**: Seamless communication with backend
- **Performance**: Fast initial load and smooth interactions
- **Mobile Responsiveness**: Work well on all device sizes

The frontend must integrate with our JWT-based authentication, handle geolocation for proximity search, and provide a smooth user experience for browsing artist portfolios with images.

## Decision

We will use **React 19 with TypeScript, Vite, and TanStack Query** for the frontend:

**Core Stack:**
- **React 19**: Component-based UI library with hooks
- **TypeScript 5.x**: Static typing for JavaScript
- **Vite 6**: Fast build tool with HMR
- **TanStack Query v5**: Server state management and caching
- **React Router v7**: Client-side routing
- **Tailwind CSS 4**: Utility-first CSS framework
- **Zustand**: Lightweight client state management

**Key Libraries:**
- **Axios**: HTTP client with interceptors
- **React Hook Form**: Form handling with validation
- **Zod**: Schema validation
- **date-fns**: Date manipulation
- **Leaflet**: Interactive maps for location selection

**Why This Stack:**
- **React**: Most popular UI library, huge ecosystem, excellent documentation
- **TypeScript**: Industry standard for type-safe JavaScript
- **Vite**: 10-100x faster than Webpack, excellent DX
- **TanStack Query**: Best-in-class server state management, automatic caching/refetching
- **Tailwind**: Rapid UI development, consistent design system

## Consequences

### Positive

- **Type Safety**: TypeScript catches errors before runtime, reducing bugs
- **Developer Experience**: Fast HMR, autocomplete, refactoring support
- **Performance**: Vite provides instant server start and fast builds
- **Modern React**: Hooks-based architecture, no class components
- **Automatic Caching**: TanStack Query handles API caching and invalidation
- **Component Reusability**: Build once, use everywhere
- **Large Ecosystem**: Extensive libraries and community support
- **Learning Value**: Industry-standard technologies with transferable skills
- **Mobile-First**: Tailwind makes responsive design straightforward
- **SEO-Ready**: Can add SSR later with Next.js if needed

### Negative

- **Learning Curve**: TypeScript adds complexity for beginners
- **Build Step Required**: Cannot run directly in browser (needs transpilation)
- **Bundle Size**: React + dependencies add ~150KB gzipped
- **Type Definitions**: Must maintain TypeScript types for API responses
- **Tooling Complexity**: Multiple tools (Vite, TypeScript, ESLint, Prettier)
- **Breaking Changes**: React/ecosystem updates may require migration
- **Over-Engineering Risk**: Easy to add unnecessary abstractions

### Neutral

- **SPA Architecture**: Client-side routing (no SSR in MVP)
- **No State Management Library Initially**: Use React Context + TanStack Query
- **CSS-in-JS**: Using Tailwind instead of styled-components/emotion
- **Testing**: Jest + React Testing Library (not included in MVP)

## Alternatives Considered

**Vue.js with TypeScript:**
- Pros: Simpler learning curve, excellent documentation, composition API
- Cons: Smaller ecosystem than React, fewer job opportunities
- Rejected: React has larger community and more learning resources

**Angular:**
- Pros: Full framework, built-in TypeScript, opinionated structure
- Cons: Steeper learning curve, more boilerplate, heavier bundle
- Rejected: Overkill for MVP, prefer lighter solution

**Next.js (React with SSR):**
- Pros: SEO benefits, server-side rendering, API routes
- Cons: More complex deployment, overkill for SPA, learning curve
- Rejected: SSR not needed for MVP, can migrate later if needed

**Svelte:**
- Pros: No virtual DOM, smaller bundle, simpler syntax
- Cons: Smaller ecosystem, fewer jobs, less mature tooling
- Rejected: Prefer more established ecosystem for learning

**Plain JavaScript (no TypeScript):**
- Pros: Simpler, no build step for types, faster initial development
- Cons: Runtime errors, no autocomplete, harder refactoring
- Rejected: Type safety is worth the investment

**Create React App:**
- Pros: Official React starter, zero config
- Cons: Slow build times, Webpack-based, less flexible
- Rejected: Vite is significantly faster and more modern
