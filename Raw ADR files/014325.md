# TASK-011: Ollama client adapter
> Source: tasks/tasks.md

## Context
- Create a robust OllamaClient adapter with chat and classification functionality
- Support both Python ollama package and HTTP fallback
- Implement strict JSON classification with proper error handling
- Align with existing llm_simple.py categories and patterns

## Options Considered
- Option A: Pure Python ollama package integration (Pros: Native integration, Cons: Dependency requirement)
- Option B: Pure HTTP client with requests (Pros: No dependencies, Cons: More complex implementation)
- Option C: Hybrid approach with automatic fallback (Pros: Best of both worlds, Cons: Slightly more complex)

## Decision
- Chosen approach: Hybrid OllamaClient with automatic fallback detection
- Uses Python ollama package when available, falls back to HTTP requests
- Implements custom exception hierarchy for proper error handling
- Robust JSON parsing with fallback classification logic

## Impacts
- Performance: Native package faster, HTTP fallback adds ~100ms overhead
- Complexity: Medium complexity with dual-path implementation
- Security/Privacy: No additional security concerns, uses existing Ollama setup
- Compatibility: Works with or without ollama package installed
- Risks & Mitigations: 
  - Risk: Model returns non-JSON responses
  - Mitigation: Robust parsing with regex and fallback classification logic
