# BFF to Process Orchestrator Migration

## Status
Proposed

## Context
The current BFF service primarily acts as a simple passthrough layer, with limited orchestration capabilities and no process tracking. As the system grows more complex, we need better handling of distributed transactions, process state management, and error compensation.

## Decision
We will transform the BFF into a Process Orchestrator that manages complex workflows across multiple services. This involves:

1. Process State Management
   - Implement ProcessDefinition and ProcessInstance entities
   - Add process tracking tables
   - Maintain process context and state

2. Orchestration Logic
   - Create ProcessOrchestrator service
   - Implement process definition and execution layers
   - Add compensation handling for failed processes

3. Enhanced Service Communication
   - Implement process-aware NATS patterns
   - Add event correlation and tracking
   - Enable process context propagation

### Core Components

#### Process Definition
```typescript
interface ProcessDefinition {
  id: string;
  name: string;
  steps: ProcessStep[];
  compensation: CompensationStep[];
  timeout: number;
  parameters?: ProcessParameter[];  // Define expected input parameters
}

interface ProcessStep {
  id: string;
  service: string;
  endpoint: string;
  method: string;
  timeout: number;
  compensation: string;
  parameters?: {                   // Map process parameters to step inputs
    [key: string]: StepParameter;
  };
  resultMapping?: {               // Map step results to process state
    [key: string]: string;
  };
}

interface CompensationStep {
  stepId: string;
  service: string;
  endpoint: string;
  method: string;
}

interface ProcessParameter {
  name: string;
  type: 'string' | 'number' | 'boolean' | 'object';
  required: boolean;
  defaultValue?: any;
  validation?: {
    pattern?: string;
    min?: number;
    max?: number;
    enum?: any[];
  };
}
```

#### Process Context & Parameters
```typescript
interface ProcessContext {
  params: Record<string, any>;        // Input parameters
  state: Record<string, any>;         // Process state
  stepResults: Record<string, any>;   // Results from each step
  metadata: {
    startTime: Date;
    lastUpdated: Date;
    attempts: number;
    retries: number;
  };
}

interface StepParameter {
  source: 'input' | 'state' | 'stepResult';
  path: string;                       // e.g., "params.userId" or "stepResults.createHost.id"
  transform?: (value: any) => any;    // Optional transformation
  validation?: {                      // Step-specific validation
    required: boolean;
    rules: any[];
  };
}

interface ProcessInstance {
  id: string;
  definitionId: string;
  status: ProcessStatus;
  currentStep: number;
  context: ProcessContext;
  startTime: Date;
  lastUpdated: Date;
}
```

#### Process Orchestrator
```typescript
@Injectable()
class ProcessOrchestrator {
  async startProcess(
    definition: ProcessDefinition,
    params: Record<string, any>
  ): Promise<ProcessInstance>;

  async executeStep(
    instance: ProcessInstance,
    step: ProcessStep
  ): Promise<StepResult>;

  async handleCompensation(
    instance: ProcessInstance
  ): Promise<void>;

  async trackProgress(
    instanceId: string
  ): Observable<ProcessStatus>;
}
```

### Implementation Phases

1. Infrastructure Setup (2-3 weeks)
   - Create process management entities
   - Implement core orchestration services
   - Set up event tracking system

2. Process Migration (4-6 weeks)
   - Convert host registration flow

3. Enhanced Features (2-3 weeks)

## Consequences

### Positive
1. Better error handling through compensation flows
2. Improved process visibility and monitoring
3. Consistent state management across services
4. Simplified maintenance and process modifications
5. Enhanced system reliability
6. Better scalability for complex workflows

### Negative
1. Increased complexity in the BFF layer
2. Additional database tables and storage requirements
3. Learning curve for developers
4. Migration effort for existing processes

### Neutral
1. Changes to service communication patterns
2. New monitoring and operational requirements
3. Process definition maintenance

## Implementation Examples

### Example 1: Host Registration Process with Parameters
```typescript
const hostRegistrationProcess: ProcessDefinition = {
  id: 'host-registration',
  name: 'Host Registration Process',
  parameters: [
    {
      name: 'userId',
      type: 'string',
      required: true,
      validation: {
        pattern: '^[0-9a-f]{24}$'  // MongoDB ObjectId pattern
      }
    },
    {
      name: 'hostData',
      type: 'object',
      required: true,
      validation: {
        // Custom validation can be added
      }
    },
    {
      name: 'documents',
      type: 'object',
      required: true
    }
  ],
  steps: [
    {
      id: 'create-host',
      service: 'user-service',
      endpoint: 'host',
      method: 'POST',
      timeout: 5000,
      compensation: 'delete-host',
      parameters: {
        userId: {
          source: 'input',
          path: 'params.userId'
        },
        hostData: {
          source: 'input',
          path: 'params.hostData'
        }
      },
      resultMapping: {
        'state.hostId': 'result.id',
        'state.status': 'result.status'
      }
    },
    {
      id: 'verify-documents',
      service: 'verification-service',
      endpoint: 'documents',
      method: 'POST',
      timeout: 10000,
      compensation: 'cancel-verification',
      parameters: {
        hostId: {
          source: 'stepResult',
          path: 'stepResults.create-host.id'
        },
        documents: {
          source: 'input',
          path: 'params.documents'
        }
      },
      resultMapping: {
        'state.verificationId': 'result.verificationId',
        'state.verificationStatus': 'result.status'
      }
    },
    {
      id: 'activate-host',
      service: 'user-service',
      endpoint: 'host/activate',
      method: 'PUT',
      timeout: 5000,
      compensation: 'deactivate-host',
      parameters: {
        hostId: {
          source: 'state',
          path: 'state.hostId'
        },
        verificationId: {
          source: 'state',
          path: 'state.verificationId'
        }
      }
    }
  ],
  compensation: [
    {
      stepId: 'delete-host',
      service: 'user-service',
      endpoint: 'host',
      method: 'DELETE'
    },
    {
      stepId: 'cancel-verification',
      service: 'verification-service',
      endpoint: 'documents/cancel',
      method: 'POST'
    },
    {
      stepId: 'deactivate-host',
      service: 'user-service',
      endpoint: 'host/deactivate',
      method: 'PUT'
    }
  ],
  timeout: 30000
};

// Usage example in controller
@Controller('hosts')
class HostController {
  constructor(
    private readonly processOrchestrator: ProcessOrchestrator
  ) {}

  @Post('register')
  async registerHost(@Body() data: HostRegistrationDto) {
    const process = await this.processOrchestrator.startProcess(
      hostRegistrationProcess,
      {
        userId: data.userId,
        hostData: {
          name: data.name,
          email: data.email,
          phone: data.phone,
          // ... other host data
        },
        documents: data.documents
      }
    );

    return process;
  }
}
```

### Example 2: Parameter Transformation
```typescript
// Example of a step with parameter transformation
{
  id: 'create-payment',
  service: 'payment-service',
  endpoint: 'payments',
  method: 'POST',
  parameters: {
    amount: {
      source: 'input',
      path: 'params.amount',
      transform: (value) => value * 100, // Convert dollars to cents
      validation: {
        required: true,
        rules: [(val) => val > 0]
      }
    },
    currency: {
      source: 'input',
      path: 'params.currency',
      transform: (value) => value.toUpperCase(),
      validation: {
        required: true,
        rules: [(val) => ['USD', 'EUR'].includes(val)]
      }
    }
  }
}
```
