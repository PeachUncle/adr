## Context
InstaGrants is an AI-powered grant writing platform that automates the end-to-end grant application process for small to mid-sized nonprofits. The system integrates Dewlyn Nonprofit Services' proven 8-section methodology with AI capabilities to match organizations with funders and generate compelling proposals.

### Stakeholders
- **Nonprofit Organizations** - Primary users seeking grants
- **Dewlyn Team** - Expert reviewers providing human oversight
- **Grant Writers** - Professional writers using the platform
- **Funders** - Foundations and government agencies (indirect)

### Constraints
- Must handle sensitive organizational data (financials, EIN)
- AI generation must be reviewable and editable
- Must integrate with external grant databases (Grants.gov, etc.)
- Expert review workflow required before submission

## Goals / Non-Goals

### Goals
- Reduce grant writing time by 70%+ through AI automation
- Increase grant success rate through better funder matching
- Provide accessible grant writing for small nonprofits without dedicated staff
- Maintain quality through expert review workflow

### Non-Goals
- Fully automated submission (human approval always required)
- Replace grant writers entirely (augment, not replace)
- Real-time grant database (batch updates acceptable)
- Multi-language support (English only for v1)

## Decisions

### Architecture: Next.js Full-Stack with Supabase
**Decision**: Use Next.js App Router with Supabase for database and auth.
**Rationale**:
- Already have Next.js 16 + React 19 setup
- Supabase provides PostgreSQL, Auth, and Storage in one platform
- Server Components for secure API calls to OpenAI
- Row Level Security for multi-tenant data isolation

**Alternatives considered**:
- Separate backend (Python FastAPI) - Rejected: adds complexity
- Firebase - Rejected: less SQL flexibility for complex queries
- Prisma + PlanetScale - Viable but Supabase has built-in auth

### AI Provider: OpenAI GPT-4o
**Decision**: Use OpenAI GPT-4o-mini for drafts, GPT-4o for final generation.
**Rationale**:
- Best quality for long-form writing
- Good at following structured templates
- Already have API key configured

**Alternatives considered**:
- Claude - Excellent but API limits for long documents
- Local LLM - Quality not sufficient for professional grants

### Grant Data Sources
**Decision**: Multi-source aggregation with caching.
**Sources**:
1. Grants.gov API (federal)
2. SAM.gov API (federal contracts)
3. Foundation Directory Online API (private)
4. Manual entry for state/local

**Caching**: Daily refresh, stored in Supabase

### File Storage
**Decision**: Supabase Storage with customer-based buckets.
**Rationale**: Integrated with auth, RLS support, S3-compatible.

### Data Structure

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| AI generates inaccurate content | Human review required before submission |
| Grant databases go offline | Cache data locally, graceful degradation |
| Sensitive data exposure | RLS, encryption at rest, audit logging |
| OpenAI rate limits | Queue system, retry logic, fallback to mini model |
| Proposal quality inconsistent | Templates + expert review workflow |
