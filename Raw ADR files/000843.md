# ADR-012: Deployment Architecture and Infrastructure

## Status
**Accepted** (October 7, 2025)

## Context

### Business Drivers
BahariWatch is a community-driven illegal fishing monitoring system for Kenya's coastal regions, with a **final presentation deadline in October 2025** (current date: October 7, 2025). The system must be operational, reliable, and cost-effective within the project's **KSh 59,500 budget** while supporting the following critical requirements:

**System Requirements:**
- **Availability:** 99.5% uptime for community reporting functionality
- **Performance:** Sub-5-second alert delivery to enforcement officers
- **Scalability:** Support 10,000+ coastal users with spike loads during peak fishing seasons
- **Security:** End-to-end encryption, anonymous reporting, GDPR compliance
- **Geographic Coverage:** Pilot deployment in Kwale, Mombasa, and Kilifi counties
- **Timeline:** May-October 2025 (6-month development and deployment window)

### Technical Constraints
Per ADR-001 (Microservices Architecture), the system comprises:
- **Report Service** (community report submission)
- **Matching Service** (AIS/VMS correlation)
- **Alerting Service** (notification delivery)
- **User Service** (authentication and authorization)
- **Geospatial Service** (hotspot mapping and spatial analysis)
- **Analytics Service** (survey and research data)
- **PostgreSQL + PostGIS** (monolithic database with logical separation per ADR-003)
- **Message Broker** (event-driven choreography per ADR-002)
- **Redis Cache** (external API caching per ADR-011)

### Architecture Characteristics Affected
(Reference: Fundamentals of Software Architecture, Chapters 4-6)
- **Deployability:** Automated, frequent releases for iterative feedback (Agile deployment strategy)
- **Availability:** 99.5% uptime SLO with automated failover and disaster recovery
- **Scalability:** Elastic scale for spike loads (elastic scale as discussed in "Fundamentals" Chapter 1 - Pets.com case study)
- **Testability:** CI/CD pipeline with automated testing before production deployment
- **Cost:** Budget-conscious infrastructure within KSh 59,500 project constraints
- **Observability:** Distributed tracing, centralized logging, performance monitoring
- **Maintainability:** Infrastructure as Code for reproducible environments

### Integration with Other ADRs
- **Depends on:** ADR-001 (Microservices), ADR-002 (Event-driven Communication), ADR-003 (Database), ADR-011 (External Integration)
- **Supports:** ADR-010 (Fitness Functions require CI/CD automation), ADR-008 (Security in production environments)
- **Related to:** ADR-005 (API Gateway deployment configuration)

## Decision

We will adopt a **containerized cloud-native deployment architecture** using **Docker + Docker Compose** for development/staging and **DigitalOcean App Platform** for production hosting, with **GitHub Actions** for CI/CD automation.

### Deployment Strategy Components:

#### 1. Containerization: Docker + Docker Compose
- **All microservices containerized** with multi-stage Docker builds (minimize image size)
- **docker-compose.yml** for local development environment orchestration
- **docker-compose.staging.yml** for staging environment (mimics production)
- **Shared base images** for Python services (Django) to reduce build times

#### 2. Cloud Provider: DigitalOcean App Platform
- **Primary hosting:** DigitalOcean App Platform (Platform-as-a-Service)
- **Database:** Managed PostgreSQL with PostGIS extension (automatic backups, read replicas)
- **Caching:** Managed Redis cluster (high availability configuration)
- **Object Storage:** DigitalOcean Spaces (GPS-stamped photos, encrypted at rest)
- **CDN:** Spaces CDN for static asset delivery (React frontend, public documentation)

#### 3. CI/CD Pipeline: GitHub Actions
- **Continuous Integration:**
  - Automated testing on every pull request (pytest, Jest, integration tests)
  - Static code analysis (ESLint, Flake8, Black)
  - Security scanning (OWASP Dependency-Check, Trivy container scanning)
  - Fitness function execution (per ADR-010)
- **Continuous Deployment:**
  - Automated Docker image builds on merge to `main` branch
  - Push images to DigitalOcean Container Registry
  - Automated deployment to staging environment
  - Manual approval gate for production deployment
  - Automated rollback on health check failures

#### 4. Monitoring and Observability
- **Application Performance Monitoring (APM):** Prometheus + Grafana
- **Distributed Tracing:** Jaeger with OpenTelemetry instrumentation
- **Centralized Logging:** DigitalOcean Managed Logging (or ELK stack alternative: Loki + Grafana)
- **Alerting:** PagerDuty integration for critical incidents (availability SLO violations)
- **Uptime Monitoring:** UptimeRobot (external synthetic monitoring)

#### 5. Infrastructure as Code (IaC)
- **Docker Compose files** for service orchestration (version-controlled in Git)
- **GitHub Actions workflows** as code (`.github/workflows/`)
- **Database migrations** managed via Django migrations (versioned)
- **Configuration management** via environment variables (12-factor app methodology)

#### 6. Disaster Recovery and Backup Strategy
- **Database Backups:** Daily automated backups with 30-day retention (DigitalOcean Managed PostgreSQL)
- **Point-in-Time Recovery:** 7-day PITR window for database restoration
- **Object Storage Replication:** Cross-region replication for GPS photo archives
- **Deployment Rollback:** Automated rollback to previous Docker image on deployment failure
- **RTO (Recovery Time Objective):** 2 hours for critical services
- **RPO (Recovery Point Objective):** 24 hours (acceptable data loss window)

## Rationale

### Alternatives Considered

#### Alternative 1: AWS Elastic Beanstalk (Rejected)
**Pros:**
- Enterprise-grade reliability and scalability
- Native integration with AWS services (RDS, ElastiCache, S3, CloudWatch)
- Auto-scaling and load balancing out-of-the-box
- Mature ecosystem with extensive documentation

**Cons:**
- **Higher cost:** AWS pricing exceeds project budget (~$50-100/month minimum vs DigitalOcean ~$25-40/month)
- **Complexity:** Steeper learning curve for student developer (IAM policies, VPC configuration, security groups)
- **Overkill for pilot scale:** Over-engineered for 10k user pilot deployment
- **Vendor lock-in concerns:** Migration complexity if scaling down needed

#### Alternative 2: Self-Managed Kubernetes (GKE, EKS, DigitalOcean Kubernetes) (Rejected)
**Pros:**
- Maximum flexibility and portability across cloud providers
- Native support for microservices orchestration (service discovery, load balancing)
- Industry-standard for large-scale deployments
- Advanced features (rolling updates, canary deployments, horizontal pod autoscaling)

**Cons:**
- **Operational overhead:** Requires dedicated DevOps expertise to manage cluster
- **Time investment:** Steep learning curve conflicts with October 2025 deadline
- **Cost:** Kubernetes control plane costs + worker nodes exceed budget
- **Over-engineering:** Unnecessary complexity for 6-service architecture
- **Development velocity:** Slows iteration speed during critical pilot phase

#### Alternative 3: Heroku (Rejected)
**Pros:**
- Simplest deployment model (git push to deploy)
- Excellent developer experience with minimal configuration
- Built-in CI/CD and review apps for pull requests
- Strong PostgreSQL addon ecosystem

**Cons:**
- **Cost at scale:** Pricing increases rapidly beyond free tier (~$75/month for production-grade setup)
- **PostGIS limitations:** Limited PostGIS version support in standard Heroku Postgres addons
- **Docker support limitations:** Heroku's container runtime less flexible than native Docker
- **Sunset concerns:** Heroku acquired by Salesforce, future uncertain post-2022 security incident

#### Alternative 4: On-Premises Deployment (Rejected)
**Pros:**
- Complete control over infrastructure
- No recurring cloud costs (after initial hardware investment)
- Data sovereignty (data remains in Kenya)

**Cons:**
- **Capital expenditure:** Hardware costs exceed project budget
- **No elastic scale:** Cannot handle spike loads without over-provisioning
- **Operational burden:** Requires physical server maintenance, power/network management
- **Disaster recovery complexity:** No automated backups or geographic redundancy
- **Availability risk:** Single point of failure (99.5% SLO unattainable without redundancy)

### Why DigitalOcean App Platform?

1. **Budget Alignment:** Fits within KSh 59,500 project budget (~$25-40/month for pilot deployment)
2. **PostGIS Native Support:** Managed PostgreSQL includes PostGIS extension out-of-the-box (critical for ADR-003 spatial queries)
3. **Docker-First Philosophy:** Native Docker support aligns with containerization strategy
4. **Developer Velocity:** Simple deployment model accelerates iteration during 6-month project window
5. **Managed Services:** Reduces operational burden (database backups, Redis clustering, load balancing)
6. **Kenyan Market Presence:** DigitalOcean has strong presence in African developer community
7. **Educational Resources:** Extensive tutorials and documentation for student developer
8. **Migration Path:** Low vendor lock-in enables future migration to AWS/GCP if scaling beyond pilot

### Why Docker + Docker Compose (Not Kubernetes)?

Per "Fundamentals of Software Architecture" Chapter 1 (DevOps intersection with architecture):
> "Microservices freely leverage former solely operational concerns... while microservices handled [elastic scale] less painfully via a liaison between architects and DevOps."

**Docker + Docker Compose provides:**
- **Local development parity:** "It works on my machine" eliminated via containerization
- **Service isolation:** Each microservice runs in isolated container (fault tolerance per ADR-001)
- **Dependency management:** Explicit service dependencies in docker-compose.yml (matches ADR-002 event-driven communication)
- **Environment consistency:** Development, staging, production use identical container images
- **Resource efficiency:** Lower overhead than Kubernetes for 6-service architecture
- **12-Factor App Compliance:** Externalized configuration, stateless processes, disposable instances

**Kubernetes deferred because:**
- **Premature optimization:** Pilot deployment (10k users) doesn't require Kubernetes orchestration complexity
- **Time constraint:** October 2025 deadline prioritizes working system over infrastructure sophistication
- **Operational maturity:** Student developer lacks Kubernetes operations expertise
- **Future-proofing:** Docker containers provide smooth migration path to Kubernetes if scaling beyond pilot

### Why GitHub Actions (Not Jenkins, GitLab CI, CircleCI)?

1. **Native GitHub Integration:** Source code already hosted on GitHub (no tool context switching)
2. **Zero infrastructure cost:** GitHub Actions included with GitHub repository (no separate CI server)
3. **YAML-based configuration:** Declarative pipeline as code (`.github/workflows/`)
4. **Docker-native:** First-class Docker support (build, push to registries)
5. **Marketplace ecosystem:** Reusable actions for testing, security scanning, deployment
6. **DigitalOcean integration:** Official DigitalOcean GitHub Action for deployment automation

## Architecture Characteristics Impact

(Reference: Fundamentals of Software Architecture, Chapters 4-6)

### ↑ Positive Impact

- **Deployability: ↑↑↑** (Automated CI/CD enables frequent releases every 1-2 weeks per Agile strategy)
- **Testability: ↑↑↑** (CI pipeline enforces automated testing before deployment per ADR-010 fitness functions)
- **Availability: ↑↑** (Managed PostgreSQL with automatic failover, Redis high availability, multi-zone deployment)
- **Scalability: ↑↑** (DigitalOcean App Platform auto-scaling for microservices, read replicas for database)
- **Observability: ↑↑** (Prometheus + Grafana + Jaeger provide comprehensive monitoring and tracing)
- **Cost: ↑↑↑** (Budget-friendly infrastructure ($25-40/month) enables project sustainability within KSh 59,500)
- **Maintainability: ↑↑** (Infrastructure as Code ensures reproducible environments, Docker eliminates configuration drift)

### ↓ Negative Impact

- **Performance: ↓** (Network latency from cloud hosting vs on-premises; acceptable trade-off for pilot scale)
- **Data Sovereignty: ↓** (Data stored in DigitalOcean data centers outside Kenya; mitigated by encryption at rest/transit per ADR-008)

### → Neutral Impact

- **Security: →** (Cloud provider security vs self-managed trade-offs; DigitalOcean provides SOC 2 Type II compliance, encryption at rest/transit)
- **Fault Tolerance: →** (Managed services improve availability but introduce external dependency on DigitalOcean SLA)

## Consequences

### Positive

1. **Rapid Time-to-Market:** Docker + DigitalOcean App Platform enables production deployment within 1-2 weeks (meets October 2025 deadline)
2. **Budget Sustainability:** $25-40/month hosting cost fits within KSh 59,500 project budget, enabling 12+ months of operation
3. **Developer Productivity:** Docker local development parity eliminates "works on my machine" issues, accelerating iteration
4. **Automated Quality Gates:** GitHub Actions CI/CD enforces testing, security scanning, fitness function validation before production (per ADR-010)
5. **Elastic Scale:** DigitalOcean App Platform auto-scaling handles spike loads during peak fishing seasons (addresses Pets.com failure mode from "Fundamentals" Chapter 1)
6. **Operational Simplicity:** Managed PostgreSQL, Redis, backups reduce operational burden for student developer
7. **Low Vendor Lock-In:** Docker containers provide migration path to AWS, GCP, Azure, or on-premises if needed beyond pilot
8. **12-Factor App Compliance:** Containerization enforces stateless processes, externalized configuration, disposable instances
9. **Disaster Recovery:** Automated daily backups, point-in-time recovery, cross-region object storage replication ensure data durability
10. **Observability:** Prometheus + Grafana + Jaeger enable real-time monitoring of availability SLO (99.5% uptime) and alert latency (<5s)

### Negative

1. **Cloud Dependency:** Production system depends on DigitalOcean availability (mitigated by 99.99% SLA and disaster recovery plan)
2. **Network Latency:** Cloud hosting introduces network latency vs on-premises deployment (acceptable for pilot scale)
3. **Data Sovereignty:** GPS photo data stored in DigitalOcean data centers outside Kenya (mitigated by encryption per ADR-008)
4. **Kubernetes Migration Cost:** If scaling beyond pilot requires Kubernetes, migration effort needed (deferred optimization)
5. **GitHub Actions Limitations:** 2,000 minutes/month free tier may require paid plan if CI/CD usage increases
6. **PostGIS Version Lock-In:** Managed PostgreSQL may lag behind latest PostGIS releases (acceptable for current spatial query requirements)

### Neutral

1. **Docker Learning Curve:** Student developer must learn Docker containerization (offset by extensive online resources and tutorials)
2. **Monitoring Complexity:** Prometheus + Grafana + Jaeger require configuration and maintenance (necessary for ADR-010 fitness functions)
3. **DigitalOcean Limitations:** App Platform less feature-rich than AWS/GCP (sufficient for pilot deployment requirements)

### Security Implications

1. **Container Image Security:**
   - Trivy vulnerability scanning in CI pipeline blocks deployment of images with critical CVEs
   - Base images updated weekly for security patches
   - Non-root user in Docker containers (least privilege principle)

2. **Secrets Management:**
   - GitHub Actions encrypted secrets for API tokens (DigitalOcean, Prometheus, PagerDuty)
   - No hardcoded credentials in docker-compose.yml (environment variable injection)
   - Secrets rotation policy: 90-day mandatory rotation for production tokens

3. **Network Security:**
   - TLS 1.3 enforcement for all external API endpoints (per ADR-011)
   - DigitalOcean VPC (Virtual Private Cloud) isolates database and Redis from public internet
   - Firewall rules restrict database access to application containers only

4. **Compliance:**
   - **GDPR (per ADR-008):** Encryption at rest (DigitalOcean Spaces AES-256), encryption in transit (TLS 1.3)
   - **Audit Logging:** Centralized logging captures all deployment events, configuration changes, secret access
   - **Data Residency:** GPS photo data encrypted and stored in DigitalOcean FRA1 (Frankfurt) region

### Data Privacy Implications

1. **Anonymous Reporting Protection (per ADR-008):**
   - Application logs sanitized in CI/CD pipeline (PII detection fitness function per ADR-010)
   - GPS photo metadata stripped before storage (except coordinates required for matching)
   - User IDs hashed in logs and monitoring dashboards

2. **Right to be Forgotten (GDPR):**
   - Database backup retention: 30 days (GDPR-compliant deletion window)
   - Object storage lifecycle policy: GPS photos auto-deleted after retention period
   - Deployment pipeline includes GDPR compliance fitness function (per ADR-010)

3. **Data Encryption:**
   - **At Rest:** DigitalOcean Spaces AES-256 encryption, PostgreSQL transparent data encryption
   - **In Transit:** TLS 1.3 for all API calls, end-to-end encryption for community reports (per ADR-008)
   - **Backup Encryption:** Database backups encrypted with customer-managed keys

### Cost Optimization Strategies

1. **Right-Size Instances:** Start with `basic-xs` ($5/month per service), scale up only if needed
2. **Database Read Replicas:** Defer until query load exceeds single-instance capacity
3. **Autoscaling:** Enable for Report Service and Matching Service (handle spike loads)
4. **Object Storage Lifecycle:** Auto-delete GPS photos after 90-day retention period (GDPR compliance)
5. **CDN Caching:** Cache static assets (React bundle) at edge for 24 hours (reduce bandwidth costs)
6. **GitHub Actions Optimization:** Cache Docker layers, npm packages to reduce CI build time

### Migration Path Beyond Pilot

If BahariWatch scales beyond 10,000 users:

**Option 1: Stay on DigitalOcean, Upgrade Resources**
- Increase App Platform instance sizes (`basic-xs` → `professional-m`)
- Add database read replicas for query load distribution
- Enable Redis high availability cluster (automatic failover)
- **Cost:** $75-150/month (still budget-friendly)

**Option 2: Migrate to Kubernetes (DigitalOcean Kubernetes)**
- Export Docker Compose to Kubernetes manifests (Kompose tool)
- Deploy to DigitalOcean Kubernetes (DOKS) for advanced orchestration
- Leverage Horizontal Pod Autoscaling, Ingress controllers, StatefulSets
- **Cost:** $120-200/month (Kubernetes cluster + nodes)
- **Migration Effort:** 2-3 weeks (container images remain unchanged)

**Option 3: Migrate to AWS Elastic Beanstalk**
- Docker containers deploy directly to Elastic Beanstalk (minimal changes)
- Leverage RDS PostgreSQL with PostGIS, ElastiCache Redis, S3 for photos
- **Cost:** $150-300/month (enterprise-grade reliability)
- **Migration Effort:** 3-4 weeks (update environment variable injection, IAM roles)

**Low Vendor Lock-In Guarantee:** Docker containerization ensures portability across cloud providers
