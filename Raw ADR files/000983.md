# Use Golang for CLI

## Context and Problem Statement

CAIRA requires a command-line interface (CLI) for generating deployment files based on the choice of a particular reference architecture and a set of choices for configuring that as needed (input parameters).

We need to determine which language to use for the CLI code.

## Decision Drivers

Ordered by decreasing importance:

* Familiarity for teams working in AI/ML
* Integration with existing tooling
* Ease of initial implementation
* Ease of maintenance
* Platform independence
* Ease of use for our customers (e.g. "just install the JRE first" is not an option)
* Consistency with other CLI choices within the community
* Likelihood of language-aware resources (e.g. "x"-lang experts) in the organization

## Considered Options

* Python
* Golang

## Decision Outcome

Chosen option: Python
Due to being one of the most popular languages for AI/ML, the ease of use and the enormous community, Python is the best choice for the CLI code. As the language is already included in our repository, the barrier to set up a dev environment is low.

## Pros and Cons of the Options

### Powershell cmdlet in CSharp

* Good, because Powershell (posh) scripts are common for DevOps professionals at our customers
* Good, because posh cmdlets provide built-in help, examples, and other affordances for ease of use
* Good, because posh cmdlets can be "UX"'d easily with existing powershell interactive components
* Bad, because Powershell expertise within ISE is not common
* Bad, because deployment of Powershell cmdlets can be a highly restricted operation in many of our customers
* Bad, because for customers that don't use Powershell already, this will be a barrier to entry
* Bad, because although posh works on non-Windows platforms it is still not a common choice for them

### TypeScript

* Good, because ISE contains many TypeScript experts
* Bad, because TypeScript CLIs are not self-contained (e.g. requiring Node.js)
* Bad, because Node.js CLIs can bring in many dependencies resulting in a more significant SBOM and supply-chain attack surface
* Bad, because the CLI code can easily be compromised post-deployment

### Go

* Good, because Go is a compiled language, so the CLI could be distributed as a single binary (which we don't want to do)
* Bad, because it would add a new language to the repository
* Bad, because Go is not as common in the AI/ML community as Python
* Bad, because Go is not as common in the ISE as Python
* Bad, because Go is not as common in the community as Python
