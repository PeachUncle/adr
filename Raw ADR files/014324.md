# TASK-010: Self-hosted LLM runtime (Ollama)
> Source: tasks/tasks.md

## Context
- Implement Ollama integration for local LLM inference
- Add health probe endpoint for LLM service monitoring
- Support configurable model selection via environment variables
- Provide comprehensive documentation for setup and deployment

## Options Considered
- Option A: Use OpenAI API (Pros: Easy integration, high quality; Cons: Cost, privacy, internet dependency)
- Option B: Use Hugging Face Transformers (Pros: Free, local; Cons: Complex setup, resource intensive)
- Option C: Use Ollama (Pros: Easy setup, good performance, local, free; Cons: Model quality varies)

## Decision
- Chosen approach: Ollama with deepseek-r1:1.5b as default model
- Rationale: Best balance of ease of setup, local deployment, and performance for financial applications

## Impacts
- Performance: Local inference reduces latency, ~2-4GB RAM usage for default model
- Complexity: Minimal - simple HTTP API integration
- Security/Privacy: All data stays local, no external API calls
- Compatibility: Works on macOS, Linux, Windows; Docker support included
- Risks & Mitigations: 
  - Model quality varies → Document model selection guidelines
  - Resource usage → Provide minimum requirements documentation
  - Service availability → Implement proper health checks and error handling
