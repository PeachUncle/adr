# ADR-001: Use Rust for Core Agent System

**Status**: Accepted
**Date**: 2025-11-08
**Deciders**: Yuri Krupnik, Claude Code
**Tags**: architecture, language-choice, performance

## Context

The Mac management system requires multiple agents running concurrently with:
- Low resource overhead (memory and CPU)
- High reliability and type safety
- Integration with Kubernetes APIs
- Cross-platform support (macOS initially, Linux/Windows future)
- Async I/O for HTTP APIs and K8s client operations

User's CLAUDE.md explicitly states preference for Rust applications over other languages.

Alternatives considered:
- Python (existing expertise, extensive libraries)
- Go (Kubernetes ecosystem standard)
- TypeScript/Node.js (existing in monorepo)

## Decision

All core agent binaries will be implemented in Rust:
- **agent-system**: Supervisor agent (Axum HTTP server)
- **credential-vault**: Credential management CLI
- **k8s-orchestrator**: Cluster management CLI

Supporting scripts and workflows will use Nushell (already established pattern in dotconfig).

### Key Technologies
- **kube-rs**: Kubernetes client library
- **tokio**: Async runtime
- **axum**: HTTP server framework
- **clap**: CLI argument parsing
- **tracing**: Structured logging

## Consequences

### Positive Consequences
- **Performance**: Low memory footprint, fast startup times
- **Safety**: Compile-time guarantees prevent many runtime errors
- **Concurrency**: Tokio async runtime handles concurrent operations efficiently
- **Type safety**: Strong typing catches errors at compile time
- **Alignment**: Matches user's stated preference in CLAUDE.md
- **Ecosystem**: Excellent Kubernetes client (kube-rs) and cloud SDK support
- **Binary deployment**: Single binary distribution, no runtime dependencies

### Negative Consequences
- **Learning curve**: Team members unfamiliar with Rust need ramp-up time
- **Compilation time**: Longer build times compared to interpreted languages
- **Dependency management**: Cargo dependency resolution can be slow initially
- **Smaller ecosystem**: Fewer libraries compared to Python/JavaScript

### Neutral Consequences
- **Borrow checker**: Requires different thinking about ownership
- **Release optimization**: Binary size reduction requires careful profile tuning

## Alternatives Considered

### Alternative 1: Python
**Description**: Implement agents in Python with asyncio
**Pros**:
- Fast development iteration
- Extensive library ecosystem
- Easy prototyping
- Good cloud provider SDK support
**Cons**:
- Higher memory usage (Python interpreter overhead)
- GIL limitations for true parallelism
- Runtime errors vs compile-time safety
- Dependency management complexity (virtualenvs, pip)
- Contradicts user's Rust preference
**Reason for rejection**: User explicitly prefers Rust; performance concerns; type safety

### Alternative 2: Go
**Description**: Use Go (de facto standard for Kubernetes tooling)
**Pros**:
- Native Kubernetes ecosystem language
- Excellent client-go library
- Fast compilation
- Built-in concurrency (goroutines)
- Static binary compilation
**Cons**:
- Less memory-safe than Rust (nil pointers, data races possible)
- No structured concurrency patterns
- Weaker type system (no algebraic data types)
- Does not match user's stated preference
**Reason for rejection**: User prefers Rust; Rust provides better safety guarantees

### Alternative 3: TypeScript/Node.js
**Description**: Leverage existing Nx monorepo and TypeScript infrastructure
**Pros**:
- Already in use in playground monorepo
- Fast prototyping
- Extensive npm ecosystem
- Team familiarity
**Cons**:
- Runtime overhead (V8 engine)
- No compile-time memory safety
- Larger binary size (bundling required)
- Async complexity (promises, callbacks)
- Not user's preferred language
**Reason for rejection**: Performance and safety concerns; contradicts preference
