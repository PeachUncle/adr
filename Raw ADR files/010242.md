# ADR 005: TypeScript Adoption Across Project

**Status:** Accepted

**Date:** 2025-10-13

**Deciders:** Development Team

## Context

The Latera project spans multiple environments and contexts:
- Electron main process (Node.js)
- Electron preload scripts (Node.js + Chromium APIs)
- Renderer process (Browser environment with React)
- Shared packages (utilities, types)
- Landing page (Next.js)

We need to choose between JavaScript and TypeScript, considering:
- Type safety across IPC boundaries
- Developer experience and productivity
- Maintainability for a side project
- Refactoring safety as project evolves
- Integration with React and Electron ecosystems
- Build complexity and tooling requirements

## Decision

We will use **TypeScript 5.0+** throughout the entire codebase with strict mode enabled.

### Configuration Strategy:

**Shared Base Config** (`@latera/tsconfig`):
```json
{
  "compilerOptions": {
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noUncheckedIndexedAccess": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

**Main Process** extends base + Node.js types
**Renderer Process** extends base + DOM types
**Preload** extends base + Electron types
**Shared Packages** extends base with library-specific needs

## Consequences

### Positive

- **Type Safety**: Catch errors at compile time, especially across IPC boundaries
- **Better DX**: IntelliSense, autocomplete, inline documentation
- **Refactoring Confidence**: Rename, move, and restructure safely
- **Self-Documenting Code**: Types serve as inline documentation
- **IPC Contract Safety**: Strongly typed communication between main/renderer
- **Shared Types**: Single source of truth for data structures across processes
- **Fewer Runtime Errors**: Many bugs caught during development
- **Ecosystem Alignment**: React, Electron, and Node.js have excellent TS support
- **Tooling Integration**: ESLint, Prettier, bundlers all support TypeScript
- **Future-Proof**: JavaScript moving toward type annotations (TC39 proposal)

### Negative

- **Learning Curve**: Requires TypeScript knowledge (mitigated by existing expertise)
- **Build Step Required**: Can't run raw .ts files (need tsc or bundler)
- **Compilation Time**: Adds 5-10s to build process (acceptable for side project)
- **Type Wrestling**: Occasionally need complex types or `as` assertions
- **Library Types**: Not all npm packages have good type definitions
- **Configuration Complexity**: Multiple tsconfig files for different environments
- **Bundle Size**: Slightly larger with emitted JS (minimal impact with minification)

### Mitigation Strategies

- Use `skipLibCheck: true` to speed up compilation
- Leverage `isolatedModules` for faster transpilation
- Use shared `@latera/tsconfig` package to reduce duplication
- Add `// @ts-expect-error` with explanation for unavoidable edge cases
- Use `unknown` instead of `any` to maintain type safety
- Create custom type definitions for untyped libraries in `src/types/`

## Alternatives Considered

### JavaScript with JSDoc
- **Pros**: No build step, gradual typing, works with existing tools
- **Cons**: Verbose syntax, limited type inference, no compile-time checking, harder refactoring, poor IDE support compared to TS

### JavaScript Only
- **Pros**: Simplest setup, no compilation, direct execution
- **Cons**: No type safety, runtime errors, poor refactoring support, harder to maintain as project grows

### Flow
- **Pros**: Similar to TypeScript, gradual typing, Facebook-backed
- **Cons**: Smaller ecosystem, less community support, React moving to TypeScript, declining adoption

### ReScript/Rescript-React
- **Pros**: Strong type system, functional paradigm, compiles to JS
- **Cons**: Different syntax, small ecosystem, steep learning curve, not suitable for side project

### IPC Type Safety

Define shared types in `@latera/shared`:

```typescript
// packages/shared/src/types/article.ts
export interface Article {
  id: string;
  url: string;
  title: string | null;
  description: string | null;
  imageUrl: string | null;
  domain: string;
  readingTime: number | null;
  isRead: boolean;
  isFavorite: boolean;
  isArchived: boolean;
  createdAt: number;
  updatedAt: number;
  readAt: number | null;
  archivedAt: number | null;
}

export interface CreateArticleInput {
  url: string;
  title?: string;
  description?: string;
  imageUrl?: string;
}

export interface UpdateArticleInput {
  title?: string;
  isRead?: boolean;
  isFavorite?: boolean;
  isArchived?: boolean;
}
```

Define IPC API contract:

```typescript
// packages/shared/src/types/ipc.ts
import type { Article, CreateArticleInput, UpdateArticleInput } from './article';

export interface ElectronAPI {
  articles: {
    getAll: () => Promise<Article[]>;
    getById: (id: string) => Promise<Article | null>;
    create: (input: CreateArticleInput) => Promise<Article>;
    update: (id: string, input: UpdateArticleInput) => Promise<Article>;
    delete: (id: string) => Promise<void>;
    search: (query: string) => Promise<Article[]>;
  };
  settings: {
    get: <T = unknown>(key: string) => Promise<T | null>;
    set: (key: string, value: unknown) => Promise<void>;
  };
  onArticleAdded: (callback: (article: Article) => void) => () => void;
  onArticleUpdated: (callback: (article: Article) => void) => () => void;
}

declare global {
  interface Window {
    electron: ElectronAPI;
  }
}
```

Implement in preload script:

```typescript
// apps/desktop/src/preload/index.ts
import { contextBridge, ipcRenderer } from 'electron';
import type { ElectronAPI } from '@latera/shared/types/ipc';

const api: ElectronAPI = {
  articles: {
    getAll: () => ipcRenderer.invoke('articles:getAll'),
    getById: (id) => ipcRenderer.invoke('articles:getById', id),
    create: (input) => ipcRenderer.invoke('articles:create', input),
    update: (id, input) => ipcRenderer.invoke('articles:update', id, input),
    delete: (id) => ipcRenderer.invoke('articles:delete', id),
    search: (query) => ipcRenderer.invoke('articles:search', query),
  },
  settings: {
    get: (key) => ipcRenderer.invoke('settings:get', key),
    set: (key, value) => ipcRenderer.invoke('settings:set', key, value),
  },
  onArticleAdded: (callback) => {
    const subscription = (_: unknown, article: Article) => callback(article);
    ipcRenderer.on('article:added', subscription);
    return () => ipcRenderer.removeListener('article:added', subscription);
  },
  onArticleUpdated: (callback) => {
    const subscription = (_: unknown, article: Article) => callback(article);
    ipcRenderer.on('article:updated', subscription);
    return () => ipcRenderer.removeListener('article:updated', subscription);
  },
};

contextBridge.exposeInMainWorld('electron', api);
```

### Strict Mode Configuration

We enable all strict checks for maximum safety:

```json
{
  "compilerOptions": {
    // Strict type checking
    "strict": true,                           // Enable all strict checks
    "noUncheckedIndexedAccess": true,         // Add undefined to index signatures
    "noUnusedLocals": true,                   // Error on unused locals
    "noUnusedParameters": true,               // Error on unused parameters
    "noFallthroughCasesInSwitch": true,       // Error on fallthrough cases
    "noImplicitReturns": true,                // Error on missing returns
    "noImplicitOverride": true,               // Require 'override' keyword

    // Module resolution
    "moduleResolution": "bundler",            // Modern resolution
    "resolveJsonModule": true,                // Import JSON files
    "allowImportingTsExtensions": true,       // Import .ts files (with bundler)

    // Code quality
    "forceConsistentCasingInFileNames": true, // Prevent casing issues
    "isolatedModules": true,                  // Each file can be compiled separately
    "skipLibCheck": true,                     // Skip type checking of .d.ts files

    // Output
    "target": "ES2022",                       // Modern JS features
    "module": "ESNext",                       // ES modules
    "lib": ["ES2022"]                         // Standard library
  }
}
```

### Type Utilities

Create reusable type utilities in `@latera/shared`:

```typescript
// packages/shared/src/types/utils.ts

/** Make specific properties required */
export type RequireProps<T, K extends keyof T> = T & Required<Pick<T, K>>;

/** Make specific properties optional */
export type OptionalProps<T, K extends keyof T> = Omit<T, K> & Partial<Pick<T, K>>;

/** Extract promise type */
export type Awaited<T> = T extends Promise<infer U> ? U : T;

/** Extract array element type */
export type ArrayElement<T> = T extends (infer U)[] ? U : never;

/** Deep partial (all nested properties optional) */
export type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P];
};

/** Require at least one property */
export type RequireAtLeastOne<T, Keys extends keyof T = keyof T> =
  Pick<T, Exclude<keyof T, Keys>> &
  { [K in Keys]-?: Required<Pick<T, K>> & Partial<Pick<T, Exclude<Keys, K>>> }[Keys];
```

### Error Handling Types

```typescript
// packages/shared/src/types/errors.ts

export class AppError extends Error {
  constructor(
    message: string,
    public code: string,
    public statusCode: number = 500
  ) {
    super(message);
    this.name = 'AppError';
  }
}

export type Result<T, E = AppError> =
  | { success: true; data: T }
  | { success: false; error: E };

// Usage
export const safeInvoke = async <T>(
  fn: () => Promise<T>
): Promise<Result<T>> => {
  try {
    const data = await fn();
    return { success: true, data };
  } catch (error) {
    return {
      success: false,
      error: error instanceof AppError ? error : new AppError(
        error instanceof Error ? error.message : 'Unknown error',
        'UNKNOWN_ERROR'
      )
    };
  }
};
```

## Build Process

### Main Process
- Compiled with `tsc` to `dist/main/`
- Target: Node.js 18+
- Module: CommonJS (for Electron compatibility)

### Renderer Process
- Bundled with Vite (uses esbuild internally)
- Target: Chrome/Electron's Chromium version
- Module: ESNext
- Fast HMR during development

### Preload Scripts
- Compiled with `tsc` to `dist/preload/`
- Target: Electron's Node.js + Chromium environment
- Module: CommonJS

### Shared Packages
- Compiled with `tsc` to `dist/`
- Module: ESNext (consumed by bundlers)
- Dual package (ESM + CJS) if needed for compatibility

## Notes

- Always use `unknown` instead of `any` for truly unknown types
- Prefer interfaces for object shapes, types for unions/intersections
- Use const assertions (`as const`) for literal types
- Avoid type assertions (`as`) unless absolutely necessary
- Document complex types with JSDoc comments
- Run `pnpm typecheck` before committing
- Use TypeScript's strict mode from day one
- Create type definitions for third-party libraries if missing

## Future Considerations

- **TypeScript 5.x Features**: Decorators, const type parameters
- **Type-only Imports**: Use `import type` for type-only imports
- **Project References**: For faster incremental builds in monorepo
- **Path Mapping**: Cleaner imports with `@/` aliases
- **Type Coverage**: Monitor type coverage with tools like `type-coverage`
