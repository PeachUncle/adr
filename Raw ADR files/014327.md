# TASK-013: Chat orchestration mapped to endpoints
> Source: tasks/tasks.md

## Context
- Create ChatOrchestrator service to route user messages through intent classification to service calls
- Map intent categories to underlying service calls without calling HTTP endpoints
- Generate contextual responses using LLM with facts from service calls
- Provide unified chat API endpoint with proper error handling

## Options Considered
- Option A: Direct HTTP endpoint calls from orchestrator (Pros: Simple, Cons: Network overhead, circular dependencies)
- Option B: Direct service calls with route hints (Pros: Efficient, clean architecture, Cons: More complex mapping)
- Option C: Hybrid approach with service calls and optional HTTP fallback (Pros: Flexible, Cons: Increased complexity)

## Decision
- Chosen approach: Direct service calls with route hints
- ChatOrchestrator calls underlying services directly (not HTTP endpoints)
- Route hints provided for frontend integration
- Comprehensive error handling with proper HTTP status codes

## Impacts
- Performance: Direct service calls ~6-7s latency (mainly LLM processing)
- Complexity: Medium complexity with service orchestration and error handling
- Security/Privacy: No additional security concerns, uses existing service patterns
- Compatibility: Works with existing service architecture
- Risks & Mitigations: 
  - Risk: Service dependencies and error propagation
  - Mitigation: Comprehensive error handling with fallback responses
