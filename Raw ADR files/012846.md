# ADR-0003: Use Pinecone Vector Database

## Status

Accepted

## Context

We need to store and search document embeddings for semantic similarity. The system requires:

- **Vector Storage**: Store 1536-dimensional embeddings from OpenAI
- **Semantic Search**: Find similar document sections based on meaning
- **Metadata Filtering**: Filter results by document, section, tags, etc.
- **Real-time Performance**: Fast query response for chat interactions
- **Scalability**: Handle multiple documents and concurrent users
- **Production Ready**: Reliable, managed service with good uptime

The main contenders are:
- **Pinecone**: Managed vector database with excellent performance
- **Weaviate**: Open-source vector database with rich features
- **Qdrant**: High-performance vector database with filtering
- **Chroma**: Open-source embedding database
- **Self-hosted**: Custom solution with PostgreSQL + pgvector

## Decision

We will use **Pinecone** as our vector database for storing and searching document embeddings.

## Consequences

### Positive

- **Performance**: Optimized for vector similarity search with sub-second query times
- **Managed Service**: No infrastructure management, automatic scaling, and high availability
- **Rich Metadata**: Support for complex metadata filtering and indexing
- **Production Ready**: Battle-tested in production with 99.9% uptime SLA
- **Developer Experience**: Simple API, good documentation, and SDKs
- **Cost Effective**: Pay-per-use pricing for development and production
- **Integration**: Excellent integration with OpenAI embeddings and LangChain
- **Filtering**: Advanced metadata filtering for precise search results

### Negative

- **Vendor Lock-in**: Proprietary service with potential migration challenges
- **Cost**: Can become expensive with high usage volumes
- **Latency**: Network calls to external service add latency
- **Data Privacy**: Data stored in cloud service (though Pinecone has enterprise options)
- **Limited Control**: Less control over infrastructure and configuration
- **Dependency**: Relies on external service availability

### Neutral

- **Learning Curve**: Team needs to learn Pinecone-specific APIs and concepts
- **Ecosystem**: Growing but smaller than traditional database ecosystems
- **Documentation**: Good but evolving documentation

## Implementation

### Pinecone Setup

```bash
# Install Pinecone SDK
bun add @pinecone-database/pinecone

# Environment variables
PINECONE_API_KEY=your_api_key
PINECONE_INDEX_NAME=your_index_name
PINECONE_NAMESPACE=your_namespace
```

### Index Configuration

```typescript
// Create Pinecone index
const pc = new Pinecone({
    apiKey: process.env.PINECONE_API_KEY!
});

const index = pc.index(process.env.PINECONE_INDEX_NAME!)
    .namespace(process.env.PINECONE_NAMESPACE!);

// Index configuration
const indexConfig = {
    name: "document-embeddings",
    dimension: 1536,           // OpenAI embedding dimensions
    metric: "cosine",          // Similarity metric
    podType: "p1.x1",          // Pod configuration
    metadataConfig: {
        indexed: [
            "sessionId",       // Document session
            "filename",        // Document filename
            "level",           // Section level
            "keywords",        // Extracted keywords
            "tags",            // Section tags
            "sectionType"      // Section classification
        ]
    }
};
```

### Vector Storage

```typescript
// Store document section embeddings
const vectorRecord = {
    id: `${sessionId}-${filename}-section-${chunkIndex}`,
    values: embedding,         // 1536-dimensional vector
    metadata: {
        sessionId,
        filename,
        sectionId: section.identifier,
        title: section.title,
        level: section.level,
        text: section.content,
        keywords: section.keywords,
        tags: section.tags,
        pageNumber: section.metadata?.pageNumber,
        totalPages: document.totalPages,
        // ... additional metadata
    }
};

await index.upsert([vectorRecord]);
```

### Semantic Search

```typescript
// Query for similar sections
const queryResponse = await index.query({
    vector: queryEmbedding,    // User query embedding
    topK: 150,                 // Number of results
    includeMetadata: true,     // Include full metadata
    filter: {
        $and: [
            { sessionId: { $eq: sessionId } },
            { filename: { $eq: filename } },
            { level: { $lte: 2 } }  // Top-level sections only
        ]
    }
});
```

## Monitoring and Evaluation

### Success Metrics

- **Query Performance**: < 100ms average query time
- **Uptime**: > 99.9% availability
- **Cost**: < $100/month for typical usage

- **Index Size**: Monitor and optimize index dimensions

## Risk Mitigation

### Vendor Lock-in
- **Data Export**: Regular exports of vector data
- **Migration Plan**: Document migration path to alternatives
- **Abstraction Layer**: Use service abstraction for easy switching

### Cost Management
- **Usage Monitoring**: Track usage and costs
- **Optimization**: Implement query optimization and caching
- **Budget Alerts**: Set up cost alerts and limits

### Availability
- **Fallback Plan**: Implement fallback to local storage
- **Retry Logic**: Robust retry mechanisms for API failures
- **Monitoring**: Comprehensive monitoring and alerting

## Alternatives Considered

### Weaviate
- **Pros**: Open-source, rich features, good performance
- **Cons**: Requires self-hosting, more complex setup
- **Decision**: Chose Pinecone for managed service benefits

### Qdrant
- **Pros**: High performance, good filtering capabilities
- **Cons**: Requires self-hosting, smaller community
- **Decision**: Chose Pinecone for managed service and integration

### Self-hosted PostgreSQL + pgvector
- **Pros**: Full control, no vendor lock-in, familiar technology
- **Cons**: Requires infrastructure management, less optimized for vectors
- **Decision**: Chose Pinecone for performance and managed service benefits
