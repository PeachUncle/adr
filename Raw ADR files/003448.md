# Gateway and Process Orchestrator Consolidation

## Status
Proposed

## Context
Currently, our architecture includes separate Gateway and BFF services, leading to:
- Multiple service hops
- Duplicated logic
- Complex context sharing
- Increased network overhead

## Decision
We will consolidate the Gateway Service and Process Orchestrator (formerly BFF) into a single service that handles both API gateway responsibilities and process orchestration.

### Core Components

#### Gateway Orchestrator
```typescript
interface GatewayOrchestrator {
  // Gateway Features
  handleAuth(): Promise<void>;
  validateRequest(): Promise<void>;
  routeRequest(): Promise<void>;

  // Process Orchestration
  startProcess(definition: ProcessDefinition, params: any): Promise<ProcessInstance>;
  executeStep(instance: ProcessInstance, step: ProcessStep): Promise<StepResult>;
  handleCompensation(instance: ProcessInstance): Promise<void>;
}
```

#### Unified Context
```typescript
interface RequestContext {
  auth: AuthContext;        // From gateway auth
  request: RequestMetadata; // From gateway routing
  process: ProcessContext;  // From orchestration
  tracing: TracingContext; // Shared tracking
}

interface AuthContext {
  userId: string;
  roles: string[];
  permissions: string[];
  token: string;
}

interface RequestMetadata {
  path: string;
  method: string;
  headers: Record<string, string>;
  query: Record<string, string>;
  body: any;
}

interface TracingContext {
  requestId: string;
  parentSpanId?: string;
  timestamp: Date;
  source: string;
}
```

### Implementation Example

```typescript
@Injectable()
class GatewayOrchestratorService implements GatewayOrchestrator {
  constructor(
    private readonly authService: AuthService,
    private readonly validationService: ValidationService,
    private readonly processManager: ProcessManager,
    private readonly contextManager: ContextManager
  ) {}

  async handleRequest(req: Request): Promise<Response> {
    // Create unified context
    const context = await this.contextManager.createContext(req);

    try {
      // Gateway responsibilities
      await this.handleAuth(context);
      await this.validateRequest(context);

      // Determine if request needs process orchestration
      if (this.requiresOrchestration(req.path)) {
        const process = await this.handleProcessRequest(context);
        return this.createResponse(process);
      }

      // Direct service routing if no orchestration needed
      return await this.routeRequest(context);
    } catch (error) {
      return this.handleError(error, context);
    }
  }

  private async handleProcessRequest(
    context: RequestContext
  ): Promise<ProcessInstance> {
    // Get process definition based on request
    const definition = this.getProcessDefinition(context.request.path);

    // Start process with context
    return this.startProcess(
      definition,
      {
        ...context.request.body,
        auth: context.auth,
        metadata: context.request
      }
    );
  }

  private getProcessDefinition(path: string): ProcessDefinition {
    // Map API paths to process definitions
    const definitions = {
      '/hosts/register': hostRegistrationProcess,
      '/spaces/create': spaceCreationProcess,
      '/reservations/book': bookingProcess
    };

    return definitions[path];
  }
}
```

### Example Process with Gateway Context
```typescript
const hostRegistrationProcess: ProcessDefinition = {
  id: 'host-registration',
  name: 'Host Registration Process',
  parameters: [
    {
      name: 'userId',
      type: 'string',
      required: true,
      // Use authenticated user ID from gateway context
      defaultValue: (context) => context.auth.userId
    },
    {
      name: 'hostData',
      type: 'object',
      required: true
    }
  ],
  steps: [
    {
      id: 'validate-permissions',
      service: 'auth-service',
      endpoint: 'permissions/validate',
      method: 'POST',
      parameters: {
        userId: {
          source: 'context',
          path: 'auth.userId'
        },
        requiredPermissions: ['host.create']
      }
    },
    {
      id: 'create-host',
      service: 'user-service',
      endpoint: 'host',
      method: 'POST',
      parameters: {
        userId: {
          source: 'context',
          path: 'auth.userId'
        },
        hostData: {
          source: 'input',
          path: 'params.hostData'
        },
        metadata: {
          source: 'context',
          path: 'request'
        }
      }
    }
    // ... other steps
  ]
};
```

## Consequences

### Positive
1. **Simplified Architecture**
   - Reduced number of services
   - Fewer network hops
   - Centralized request handling

2. **Enhanced Context Sharing**
   - Auth context available to processes
   - Request metadata feeds into process context
   - Single point for logging and monitoring

3. **Improved Performance**
   - Reduced latency
   - Fewer service-to-service calls
   - Better resource utilization

4. **Better Development Experience**
   - Single codebase for gateway and orchestration
   - Unified context management
   - Simplified deployment

### Negative
1. **Increased Service Complexity**
   - More responsibility in single service
   - Larger codebase
   - More complex testing

2. **Higher Resource Requirements**
   - Increased memory usage
   - Higher CPU utilization
   - More complex scaling

### Neutral
1. Service boundary changes
2. Deployment strategy updates
3. Monitoring adaptation needed
