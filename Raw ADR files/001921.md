# Configuration management tools

* Status: proposed
* Deciders: Oihana Elizagoyen, Xabier Mikel Gutierrez and Aimar Uriarte
* Date: 2025/02/18

## Context and problem statement

We need to decide on the most suitable tools for managing the project's configuration and version control. The tool selected should facilitate collaboration, help maintain organization, and be familiar to the team.

## Decision drivers

* **Familiarity and expertise** – The team should be comfortable using the tool to reduce the learning curve.
* **Version control and organization** – The tool must support version control and allow for proper organization of the project’s codebase.
* **Integration** – The tool should integrate smoothly with the project management tool (GitHub Issues + Projects) to streamline workflows.

## Considered options

* **Git**
* **Manual version naming**
* **Google Drive**
* **OneDrive**

## Decision outcome

Chosen option: **Git**

### Justification:

Git was chosen because the team already has a solid understanding of it, and it integrates seamlessly with GitHub. Git is a widely used version control system that allows for efficient collaboration, tracking of changes, and management of different versions of the project. Additionally, we will use **Git flow**, which is a branching strategy that helps organize development, staging, and production environments effectively.

### Positive consequences

* Git is the industry standard for version control and integrates well with GitHub.
* Using Git flow helps structure the development process and ensures that code changes are well-organized.
* The team is already familiar with Git, which will save time and avoid the need for extensive training.
* Git is a highly flexible tool that allows for easy collaboration among team members.

### Negative consequences

* Requires discipline and a solid understanding of Git workflows, such as Git flow, to avoid mistakes like merge conflicts or unorganized branches.
* If not used properly, branching strategies can become complex and lead to confusion.


## Pros and Cons of the Options

### Git

* Good, because it is an industry-standard tool for version control.  
* Good, because it integrates seamlessly with GitHub and supports collaboration.  
* Good, because it allows structured branching and workflow management.  
* Bad, because it requires discipline and adherence to a workflow (e.g., Git flow) to avoid mismanagement.  

### Manual Version Naming

* Good, because it is simple and does not require additional tools.  
* Good, because it allows manual control over versioning.  
* Bad, because it is prone to human error and inconsistencies.  
* Bad, because it does not provide automated version tracking or rollback functionality.  

### Google Drive

* Good, because it is easy to use and widely accessible.  
* Good, because it provides automatic backups and version history for documents.  
* Bad, because it is not designed for source code version control.  
* Bad, because collaboration on code files is not as efficient as using Git.  

### OneDrive

* Good, because it integrates well with Microsoft products.  
* Good, because it provides cloud-based storage and backup.  
* Bad, because it is not intended for software version control.  
* Bad, because tracking changes in code files is difficult compared to Git.
