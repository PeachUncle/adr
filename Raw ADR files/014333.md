# TASK-019: Full-stack dev compose
> Source: tasks/tasks.md

## Context
- docker-compose.yml to run frontend, backend, and LLM together
- frontend: env API_BASE_URL, binds to source for hot reload
- backend: env for DB and OLLAMA_HOST, mounts source for reload
- llm: Ollama service with model pulled. Share a models volume
- Make targets: make up, make down, make logs, make seed
- Healthchecks: frontend (GET /), backend (GET /health), llm (simple generate or /api/tags)

## Options Considered
- **Option A**: Single docker-compose.yml (Pros: Simple setup; Cons: Less flexible)
- **Option B**: Separate dev/prod compose files (Pros: Environment-specific configs; Cons: More files)
- **Option C**: Docker Swarm (Pros: Production-ready; Cons: Overkill for development)

## Decision
- **Chosen approach**: Option B - Separate dev/prod compose files
- **Rationale**: Better separation of concerns, development vs production configurations, easier maintenance

## Impacts
- **Performance**: Good - Optimized for development with hot reload and source mounting
- **Complexity**: Moderate - Well-structured with clear separation of dev/prod configs
- **Security/Privacy**: Good - Isolated network, local-only access in development
- **Compatibility**: High - Works across different platforms, supports mock LLM for teammates
- **Risks & Mitigations**: 
  - Risk: Resource usage; Mitigation: Memory limits and resource constraints
  - Risk: Model download failures; Mitigation: Health checks and retry logic
