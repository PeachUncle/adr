# ADR-002: Streaming Responses in llm4s

**Status**: Proposed

## Question

Does llm4s support streaming responses?

## Context

The Tripper application uses synchronous LLM calls that wait for complete responses. For better user experience, we may want:
- Real-time streaming of LLM outputs
- Progressive rendering of travel plans
- Reduced perceived latency for long generations
- Server-Sent Events (SSE) integration

## Decision

llm4s **does support streaming** via `streamComplete()`, but implementation is **provider-dependent**. We will create an **FS2-based wrapper** for functional streaming with proper integration into our Cats Effect IO architecture.

### Current State of llm4s Streaming

From llm4s documentation:

```scala
trait LLMClient {
  /** Stream a completion with callback for chunks */
  def streamComplete(
    conversation: Conversation,
    options: CompletionOptions = CompletionOptions(),
    onChunk: StreamedChunk => Unit
  ): Either[LLMError, Completion]
}

case class StreamedChunk(
  id: String,
  content: Option[String],                // Incremental text
  toolCall: Option[ToolCall] = None,      // Incremental tool call
  finishReason: Option[String] = None     // "stop", "length", "tool_calls"
)
```

**Limitations**:
- Uses callback pattern, not FS2 streams
- **Not fully implemented** in all providers (some fall back to `complete()`)
- No built-in backpressure or cancellation
- Requires wrapping for functional use

### Proposed Solution: FS2 Stream Wrapper

Create a functional streaming adapter that converts callback-based streaming to FS2:

```scala
package io.github.llm4s.tripper.llm

import cats.effect.IO
import cats.effect.std.Queue
import fs2.Stream
import org.llm4s.llmconnect.LLMClient
import org.llm4s.llmconnect.model._

object StreamingLLM {
  
  /**
   * Stream LLM completions using FS2.
   * Falls back to non-streaming if provider doesn't support streaming.
   */
  def streamCompletion(
    client: LLMClient,
    conversation: Conversation,
    options: CompletionOptions = CompletionOptions()
  ): Stream[IO, StreamedChunk] = {
    Stream.eval(Queue.unbounded[IO, Option[StreamedChunk]]).flatMap { queue =>
      val enqueueChunks: IO[Either[LLMError, Completion]] = IO.delay {
        client.streamComplete(
          conversation,
          options,
          chunk => queue.offer(Some(chunk)).unsafeRunSync()
        )
      }.flatTap(_ => queue.offer(None)) // Signal completion
      
      Stream.eval(enqueueChunks.start) >> 
        Stream.fromQueueNoneTerminated(queue)
    }
  }
  
  /**
   * Stream with fallback to non-streaming if streaming not supported.
   */
  def streamCompletionWithFallback(
    client: LLMClient,
    conversation: Conversation,
    options: CompletionOptions = CompletionOptions()
  ): Stream[IO, String] = {
    streamCompletion(client, conversation, options)
      .collect { case StreamedChunk(_, Some(content), _, _) => content }
      .handleErrorWith { error =>
        // Fallback to non-streaming
        Stream.eval(IO.delay(client.complete(conversation, options)))
          .collect { case Right(completion) => completion.message.content }
      }
  }
  
  /**
   * Accumulate chunks into complete response.
   */
  def streamAndCollect(
    client: LLMClient,
    conversation: Conversation,
    options: CompletionOptions = CompletionOptions()
  ): IO[Either[LLMError, String]] = {
    streamCompletion(client, conversation, options)
      .collect { case StreamedChunk(_, Some(content), _, _) => content }
      .compile
      .foldMonoid
      .attempt
      .map {
        case Right(text) => Right(text)
        case Left(error) => Left(LLMError.UnknownError(error.getMessage))
      }
  }
}
```

### Integration with workflows4s

Stream processing within workflows:

```scala
import io.github.llm4s.tripper.llm.StreamingLLM

case class StreamingEvent(chunk: String) extends Event
case class CompletionEvent(fullText: String) extends Event

val streamLLMCall: WIO[State, Nothing, State] = WIO
  .runIO[State] { state =>
    StreamingLLM
      .streamCompletionWithFallback(
        client,
        buildConversation(state),
        options
      )
      .compile
      .foldMonoid
      .map(fullText => CompletionEvent(fullText))
  }
  .handleEvent { (state, event) =>
    state.copy(generatedPlan = event.fullText)
  }
  .named("Stream Travel Plan Generation")
```

### Progressive Rendering with SSE

For web UI integration:

```scala
import org.http4s._
import org.http4s.dsl.io._
import org.http4s.server.ServerSentEvents

def streamPlanEndpoint(tripId: String): HttpRoutes[IO] = HttpRoutes.of[IO] {
  case GET -> Root / "trips" / id / "plan" / "stream" =>
    val state = getTripState(id)
    val stream = StreamingLLM
      .streamCompletionWithFallback(client, buildConversation(state))
      .map(chunk => ServerSentEvent(data = Some(chunk)))
    
    Ok(stream)
}
```

### Backpressure and Cancellation

FS2 provides built-in support:

```scala
// With timeout
StreamingLLM
  .streamCompletionWithFallback(client, conversation)
  .timeout(30.seconds)
  .compile
  .foldMonoid

// With rate limiting
StreamingLLM
  .streamCompletionWithFallback(client, conversation)
  .metered(100.millis) // Max 10 chunks/second
  .compile
  .foldMonoid

// With cancellation
val fiber = StreamingLLM
  .streamCompletionWithFallback(client, conversation)
  .compile
  .drain
  .start

// Later: cancel if needed
fiber.flatMap(_.cancel)
```

## Consequences

### Positive

1. **Functional streaming**: Pure FP approach with FS2
2. **Backpressure**: Built-in via FS2 streams
3. **Cancellation**: Easy to cancel ongoing streams
4. **Composability**: Integrate with other FS2 streams
5. **SSE integration**: Direct http4s support
6. **Fallback handling**: Graceful degradation for non-streaming providers
7. **Type-safe**: Full compile-time checking
8. **Resource safety**: Automatic cleanup via FS2

### Negative

1. **Complexity**: More complex than direct callback usage
2. **Performance overhead**: Queue-based bridging adds latency
3. **Provider-dependent**: Not all providers support streaming
4. **Testing complexity**: Need to mock streaming behavior
5. **Memory usage**: Queue buffering for chunks

### Trade-offs

- **Use streaming for**: Long-running plan generation, user-facing UI
- **Use non-streaming for**: Short responses, background processing
- **Fallback strategy**: Always provide non-streaming fallback
- **Buffer size**: Tune queue size based on expected chunk rate

### 3. Monitoring and Metrics

Track streaming performance:

```scala
def streamWithMetrics(
  client: LLMClient,
  conversation: Conversation
): Stream[IO, StreamedChunk] = {
  StreamingLLM
    .streamCompletion(client, conversation)
    .evalTap { chunk =>
      IO.delay {
        metrics.incrementChunkCount()
        chunk.content.foreach(c => metrics.recordChunkSize(c.length))
      }
    }
}
```

### 4. Error Recovery

Handle streaming errors gracefully:

```scala
def streamWithRetry(
  client: LLMClient,
  conversation: Conversation,
  maxRetries: Int = 3
): Stream[IO, String] = {
  Stream.retry(
    StreamingLLM.streamCompletionWithFallback(client, conversation),
    delay = 1.second,
    nextDelay = _ * 2,
    maxAttempts = maxRetries,
    retriable = {
      case _: java.net.SocketTimeoutException => true
      case _: java.io.IOException => true
      case _ => false
    }
  )
}
```

### 5. Workflow Integration Pattern

Standard pattern for LLM calls in workflows:

```scala
def llmStep(name: String)(
  buildConversation: State => Conversation
): WIO[State, Nothing, State] = WIO
  .runIO[State] { state =>
    StreamingLLM
      .streamAndCollect(client, buildConversation(state))
      .map {
        case Right(text) => LLMResponseEvent(text)
        case Left(error) => LLMErrorEvent(error.message)
      }
  }
  .handleEvent {
    case (state, LLMResponseEvent(text)) => 
      state.updateWithLLMResponse(text)
    case (state, LLMErrorEvent(msg)) => 
      state.copy(error = Some(msg))
  }
  .named(name)
```

## Alternative Considered

### Alternative: Use Callback Directly

Stay with callback pattern from llm4s:

```scala
var chunks = List.empty[String]
client.streamComplete(conversation, options, chunk => {
  chunk.content.foreach(c => chunks = chunks :+ c)
})
val result = chunks.mkString
```

**Rejected because**:
- Not functional (mutable state)
- No backpressure
- Difficult to cancel
- No integration with IO/FS2
- Not composable
