# Design: RaBitQ Binary Quantization

## Context
RaBitQ quantization is the final step in the compression pipeline. It takes preprocessed vectors (normalized, projected) and produces a binary quantized representation on the unit hypercube with corrective factors for accurate similarity search.

## Goals / Non-Goals

### Goals
- Implement RaBitQ binary quantization algorithm
- Produce hypercube vertex representations (±1/√d)
- Compute second corrective factor via dot product
- SIMD optimization for performance
- Modular, testable functions
- Memory-efficient storage

### Non-Goals
- Not implementing compressed binary storage (future optimization)
- Not implementing similarity search (separate module)
- Not supporting non-binary quantization levels

## Decisions

### Data Structure Design

```zig
pub const QuantizedData = struct {
    hypercube_vectors: Matrix,     // N × d (±1/√d values)
    corrective_1: []f32,          // N values (||v - centroid||)
    corrective_2: []f32,          // N values (dot(p_rotated, p_hypercube))
    dimension: usize,             // d
    allocator: Allocator,
    
    pub fn deinit(self: *QuantizedData) void {
        self.hypercube_vectors.deinit();
        self.allocator.free(self.corrective_1);
        self.allocator.free(self.corrective_2);
    }
};
```

**Rationale:**
- Uses Matrix for hypercube vectors (reuses existing structure)
- Stores both corrective factors for reconstruction
- Tracks dimension for hypercube scale factor
- Clean memory management with deinit()

### Algorithm: Binary Quantization

```
Input: p_rotated (normalized, projected vector)
Output: p_binarized (binary vector)

for each dimension i:
    if p_rotated[i] >= 0:
        p_binarized[i] = 1
    else:
        p_binarized[i] = 0
```

**Implementation:**
- Simple threshold at 0
- Edge case: 0.0 maps to 1 (>= threshold)
- Can use SIMD comparison operations

**Complexity:** O(d) time per vector

### Algorithm: Hypercube Mapping

```
Input: p_binarized (binary vector), d (dimension)
Output: p_hypercube (hypercube vertex)

scale = 1 / sqrt(d)

for each dimension i:
    if p_binarized[i] == 1:
        p_hypercube[i] = +scale
    else:
        p_hypercube[i] = -scale
```

**SIMD Optimization:**
```zig
// Create scale vectors
const pos_scale = @splat(1.0 / sqrt(d))
const neg_scale = @splat(-1.0 / sqrt(d))

// Conditional select based on binary mask
p_hypercube = @select(f32, binary_mask, pos_scale, neg_scale)
```

**Properties:**
- All vectors lie on unit hypercube: {-1/√d, +1/√d}^d
- Unit norm: ||p_hypercube|| = √(d * (1/d)) = 1
- Vertices of d-dimensional hypercube scaled to unit sphere

**Complexity:** O(d) time per vector, SIMD parallelizable

### Algorithm: Second Corrective Factor

```
Input: p_rotated (original normalized vector), p_hypercube (quantized)
Output: d_corrective_2 (scalar)

d_corrective_2 = dot(p_rotated, p_hypercube)
             = Σ(p_rotated[i] * p_hypercube[i])
```

**SIMD Optimization:**
- Reuse existing vectorNorm-style dot product
- 8-wide SIMD multiplication and accumulation
- Horizontal reduction for final sum

**Interpretation:**
- Measures projection of original onto quantized direction
- Used for similarity score adjustment
- Combined with d_corrective_1 for full reconstruction

**Complexity:** O(d) time per vector, SIMD optimized

### Complete Pipeline

```zig
pub fn quantizeVectors(
    preprocessed: PreprocessedData,
    allocator: Allocator,
) !QuantizedData {
    const N = preprocessed.rotated_vectors.rows;
    const d = preprocessed.rotated_vectors.cols;
    
    // Allocate output
    var hypercube = try Matrix.init(allocator, N, d);
    errdefer hypercube.deinit();
    
    var corrective_2 = try allocator.alloc(f32, N);
    errdefer allocator.free(corrective_2);
    
    // Compute scale factor once
    const scale = 1.0 / @sqrt(@as(f32, @floatFromInt(d)));
    
    // Process each vector
    for (0..N) |i| {
        const p_rotated = getRow(preprocessed.rotated_vectors, i);
        const p_hyper = getRow(hypercube, i);
        
        // Binarize and map to hypercube
        binarizeAndMap(p_rotated, p_hyper, scale);
        
        // Compute second corrective factor
        corrective_2[i] = dot(p_rotated, p_hyper);
    }
    
    return QuantizedData{
        .hypercube_vectors = hypercube,
        .corrective_1 = preprocessed.corrective_factors,  // Transfer ownership
        .corrective_2 = corrective_2,
        .dimension = d,
        .allocator = allocator,
    };
}
```

### Memory Layout

**Per Vector Storage:**
- Hypercube representation: d × 4 bytes (float32)
- First corrective factor: 4 bytes
- Second corrective factor: 4 bytes
- **Total: (d + 2) × 4 bytes per vector**

**For SIFT (d=128):**
- 130 × 4 = 520 bytes per vector
- vs original 128 × 4 = 512 bytes
- Small overhead for quantization metadata

**Future Optimization:**
- Binary representation: ⌈d/8⌉ bytes + 8 bytes = 24 bytes for d=128
- ~21× compression with binary storage

### SIMD Optimization Strategy

1. **Hypercube Mapping** (Critical Path):
```zig
// Power-of-2 dimensions >= 8
const VecSize = 8;
const Vec = @Vector(VecSize, f32);
const pos_vec: Vec = @splat(scale);
const neg_vec: Vec = @splat(-scale);
const zero_vec: Vec = @splat(0.0);

for (0..d by VecSize) |i| {
    const vals: Vec = p_rotated[i..][0..VecSize].*;
    // Create mask: true where vals >= 0
    const mask = vals >= zero_vec;
    // Select pos or neg scale
    const result = @select(f32, mask, pos_vec, neg_vec);
    p_hyper[i..][0..VecSize].* = result;
}
```

2. **Dot Product** (Already Optimized):
- Reuse SIMD dot product from vector_preprocessing
- 8-wide multiply-accumulate
- Horizontal reduction

## Testing Strategy

### Modular Tests (No Monoliths)

**Binary quantization:**
1. Positive values → 1
2. Negative values → 0
3. Zero edge case → 1
4. Mixed positive/negative

**Hypercube mapping:**
1. Scale factor correct (1/√d)
2. All binary 1 → all +scale
3. All binary 0 → all -scale
4. Mixed binary → mixed ±scale
5. Unit norm verification

**Second corrective factor:**
1. Known vector pairs → expected dot product
2. Orthogonal vectors → 0
3. Parallel vectors → ±norm
4. SIMD path verification

**Complete pipeline:**
1. Small dataset (2-3 vectors)
2. Output structure correct
3. Memory cleanup
4. SIFT-sized (128D)
5. Integration with PreprocessedData

## Risks / Trade-offs

### Trade-off: Float vs Binary Storage
- **Current**: Store as float32 (±1/√d values)
- **Upside**: Direct access, no decode overhead
- **Downside**: 32× larger than binary
- **Justification**: Matches paper, optimization later

### Risk: SIMD Complexity
- **Issue**: SIMD @select may have edge cases
- **Mitigation**: Comprehensive tests, scalar fallback
- **Testing**: Verify SIMD == scalar for all inputs

### Trade-off: Memory Ownership
- **Choice**: Transfer corrective_1 ownership from PreprocessedData
- **Upside**: Single QuantizedData structure owns all data
- **Downside**: PreprocessedData becomes invalid after quantization
- **Justification**: Natural pipeline progression
