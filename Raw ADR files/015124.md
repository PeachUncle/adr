# Design: Vector Preprocessing Pipeline

## Context
RaBitQ quantization preprocessing transforms raw vectors through multiple steps: centering, normalization, and projection. This design ensures modularity, memory efficiency, and SIMD optimization.

## Goals / Non-Goals

### Goals
- Modular functions for each preprocessing step
- Memory-efficient in-place operations
- SIMD optimizations for power-of-2 dimensions
- Clear separation of concerns
- Comprehensive standalone tests for each function

### Non-Goals
- Not supporting non-power-of-2 dimensions (Matrix constraint)
- Not batching/streaming (full dataset in memory)
- Not GPU acceleration (CPU/SIMD only)

## Decisions

### Data Structure Design

```zig
pub const PreprocessedData = struct {
    rotated_vectors: Matrix,     // N × d (projected dimension)
    corrective_factors: []f32,   // N values (d_corrective = ||v_residual||)
    centroid: []f32,             // D-dimensional dataset centroid
    allocator: Allocator,
    
    pub fn deinit(self: *PreprocessedData) void {
        self.rotated_vectors.deinit();
        self.allocator.free(self.corrective_factors);
        self.allocator.free(self.centroid);
    }
};
```

**Rationale:**
- Uses existing Matrix structure for rotated vectors
- Separate array for corrective factors (per-vector scalar)
- Stores centroid for potential later use
- All memory owned by structure, cleaned up in deinit()

### Algorithm 1: Compute Centroid

```
Input: Matrix(N, D)
Output: centroid[D]

for each dimension d:
    sum = 0
    for each vector v:
        sum += v[d]
    centroid[d] = sum / N
```

**SIMD Optimization:**
- Process D values in 8-wide vectors when D is power-of-2 and ≥ 8
- Accumulate sums in vector registers
- Use @reduce for final summation

**Complexity:** O(N*D) time, O(D) space

### Algorithm 2: Mean-Center and Normalize

```
Input: Matrix(N, D), centroid[D]
Output: corrective_factors[N], Matrix modified in-place

for each vector v:
    // Step 1: Mean-center
    v_residual = v - centroid  (in-place)
    
    // Step 2: Compute norm
    d_corrective = ||v_residual||
    corrective_factors[i] = d_corrective
    
    // Step 3: Normalize
    if d_corrective > 0:
        v /= d_corrective  (in-place)
```

**SIMD Optimization:**
- Vector subtraction using @Vector
- Dot product using SIMD (reuse from matrix.zig)
- Division by scalar using vector splat

**Complexity:** O(N*D) time, O(N) space

### Algorithm 3: Apply Orthogonal Projection

```
Input: Matrix(N, D), Projection(D, d)
Output: Matrix(N, d)

// For orthogonal P: P^-1 = P^T
P_transpose = transpose(P)  // (d, D)

// Matrix multiplication
result = P_transpose * vectors  // (d, D) * (D, N)^T = (d, N)^T = (N, d)

Actually: result[i] = P^T * v[i] for each vector
```

**Implementation:**
- Transpose projection matrix first
- Multiply each vector by transposed projection
- Result stored in new Matrix(N, d)

**Complexity:** O(N*D*d) time, O(N*d) space

### Complete Pipeline

```zig
pub fn preprocessVectors(
    allocator: Allocator,
    vectors: Matrix,      // Will be modified in-place
    projection: Matrix,   // Orthogonal projection P (D × d)
) !PreprocessedData {
    // Step 1: Compute centroid
    const centroid = try computeCentroid(vectors, allocator);
    errdefer allocator.free(centroid);
    
    // Step 2: Mean-center and normalize (in-place)
    const corrective_factors = try meanCenterAndNormalize(&vectors, centroid, allocator);
    errdefer allocator.free(corrective_factors);
    
    // Step 3: Apply projection
    const rotated = try applyOrthogonalProjection(vectors, projection, allocator);
    errdefer rotated.deinit();
    
    return PreprocessedData{
        .rotated_vectors = rotated,
        .corrective_factors = corrective_factors,
        .centroid = centroid,
        .allocator = allocator,
    };
}
```

### Memory Optimization Strategy

1. **In-place mean-centering**: Modify input matrix directly
2. **Single-pass operations**: No redundant iterations
3. **SIMD where applicable**: Power-of-2 dimensions use vectorized operations
4. **Minimal allocations**:
   - centroid: O(D)
   - corrective_factors: O(N)
   - rotated_vectors: O(N*d)
   - Total: O(N*max(D,d)) = O(N*D) typically

### Orthogonal Projection Property

**Key insight**: For orthogonal matrices, P^-1 = P^T

This means:
- No expensive matrix inversion needed
- Simple transpose operation
- Multiplication complexity remains O(N*D*d)
- Numerically stable (no division/conditioning issues)

## Testing Strategy

### Modular Tests (No Monoliths)

**computeCentroid tests:**
1. Known vectors → expected centroid
2. Single vector → centroid = vector
3. Power-of-2 SIMD path
4. Zero vectors edge case

**meanCenterAndNormalize tests:**
1. Mean-centering correctness
2. Norm extraction (d_corrective)
3. Unit normalization verification
4. Known centroid values

**applyOrthogonalProjection tests:**
1. Identity projection (P = I)
2. Dimension transformation
3. Simple orthogonal matrix
4. Orthogonality preservation

**preprocessVectors integration tests:**
1. Complete pipeline with small data
2. Output structure verification
3. Memory cleanup (deinit)
4. SIFT-sized vectors (128D)
5. Dimension reduction (128 → 64)

## Risks / Trade-offs

### Risk: In-Place Modification
- **Issue**: Input matrix is destroyed
- **Mitigation**: Document clearly, design expects this
- **Acceptable**: Preprocessing is one-way transformation

### Risk: Large Memory for Projection
- **Issue**: Projection matrix (D × d) can be large
- **Mitigation**: Passed by reference, not copied
- **Future**: Could explore streaming/tiling

### Trade-off: Modularity vs Performance
- **Choice**: Separate functions for each step
- **Upside**: Testability, composability, clarity
- **Downside**: Potential for redundant passes
- **Justification**: Single preprocessing pass is acceptable cost
