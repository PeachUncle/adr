# ADR-003: OpenAPI Generation Policy

**Date**: 2025-11-01  
**Status**: Accepted  
**Related**: ADR-001 (Hexagonal Architecture), ADR-002 (Architecture Validation)

---

## Context

The monorepo includes an OpenAPI specification generated from NestJS decorators and an `@pkg/openapi-client` package containing TypeScript types. We need a clear policy on whether generated code should be committed to version control.

### Current Situation

- OpenAPI spec: `apps/api/openapi/openapi.json`
- Client types: `packages/openapi-client/src/generated/`
- Both directories in `.gitignore` (not committed)
- Similar pattern exists for Prisma Client

### The Problem

Without a clear policy:

- **Merge Conflicts**: Generated code conflicts when multiple PRs modify the API
- **Review Noise**: Generated diffs pollute PR reviews
- **Inconsistency**: Developers may forget to regenerate
- **CI Brittleness**: Must enforce generation policy

---

## Decision

**Generated OpenAPI code will NOT be committed to version control.**

Includes:

- `apps/api/openapi/openapi.json`
- `packages/openapi-client/src/generated/**`

Implementation:

1. CI/CD generates on every build
2. Developers generate locally via `pnpm openapi:generate`
3. CI enforces no drift via git status check

---

## Rationale

## Rationale

### Advantages

- **Consistency**: Same pattern as Prisma Client (not committed)
- **No Merge Conflicts**: Multiple developers can modify API without conflicts
- **Clean PRs**: Reviews focus on source code, not generated types
- **Single Source of Truth**: Generated code always derived from source
- **Smaller Repository**: No history of generated file changes

### Trade-offs

- **CI Generation Required**: ~15-30 seconds per CI run (acceptable)
- **Local Setup**: Developers must run `pnpm openapi:generate` after clone

---

## Implementation

### CI Enforcement

`.github/workflows/ci.yml` includes check:

```yaml
- name: Check for uncommitted generated files
  run: |
    if [ -n "$(git status --porcelain)" ]; then
      echo "::error::Generated code should not be committed"
      exit 1
    fi
```

### Type Generation

`packages/openapi-client/package.json`:

```json
{
  "scripts": {
    "generate": "openapi-typescript ../../apps/api/openapi/openapi.json -o src/generated/types.ts",
    "build": "pnpm generate && tsc --build"
  }
}
```

**Tool**: `openapi-typescript` - generates clean TypeScript types from OpenAPI 3.x

---

## Developer Workflow

### Initial Setup

```bash
pnpm install                # Shows reminder to generate
pnpm prisma:generate
pnpm openapi:generate
pnpm build
```

### Daily Development

```bash
pnpm dev                    # Pre-flight check runs automatically
# ... modify controllers/DTOs ...
pnpm openapi:generate       # Regenerate after API changes
```

### Safeguards to Prevent Forgetting

**1. Postinstall Reminder**

- After `pnpm install`, displays: "⚠️ Remember to run: pnpm prisma:generate && pnpm openapi:generate"

**2. Pre-dev Checks** (`predev` hook)

- Running `pnpm dev` automatically checks if generated files exist
- Warns if OpenAPI spec missing (doesn't block, 3-second delay)
- Blocks if Prisma Client missing (critical)

**3. VS Code Tasks**

- Task: "Setup: Generate All" - One-click generation
- Task: "Dev: Start with Checks" - Auto-generates before starting
- Access via: Terminal → Run Task... (Ctrl+Shift+P)

**4. CI Enforcement**

- CI regenerates on every build
- Fails if generated files were accidentally committed
- Safety net ensuring consistency

## Alternatives Considered

| Approach          | Pros                                  | Cons                                | Decision      |
| ----------------- | ------------------------------------- | ----------------------------------- | ------------- |
| **Not Committed** | No conflicts, clean PRs, always fresh | Must generate locally               | ✅ **Chosen** |
| **Committed**     | Works immediately                     | Conflicts, review noise, drift risk | ❌ Rejected   |
