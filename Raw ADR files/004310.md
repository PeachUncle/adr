Summary
- Dedicate Sprint-003 to performance, resilience, and UI component-library hardening on existing tools, keeping privacy and accessibility gates intact.

Decision
- Set and monitor budgets: target <1.5s first interaction for tool UIs and <800ms for common actions; add lightweight client metrics (latency/error counts) without sending payload data.
- Perf/Error budgets per tool (targets, cold desktop 4G-equivalent; mobile-friendly later pass):
  - Base64, Hash, JWT: render <1.0s; action <800ms; progress shown >5MB; keep synchronous unless input >5MB (progress already wired).
  - Format Converter: render <1.2s; convert <1.2s for <3MB; show progress >5MB; consider worker if main-thread blocks >800ms.
  - Markdown-to-PDF: render <1.2s; convert <2.0s for 5MB; workerize if main-thread blocking >1s; always show progress >5MB.
  - Favicon Generator: render <1.2s; generation <1.5s single, <3s batch of 5; show progress for large/ batch; prefer worker for heavy batch.
- Lightweight client metrics plan (privacy-preserving):
  - Capture per action: tool slug, action type (load, convert, hash, decode, generate), duration ms, success/failure, error category, input size bucket (<1MB, 1-5MB, >5MB, >9MB rejected), offline/online, workerUsed flag.
  - Sampling: 100% for dev, 10% for prod until stable; no payload/content logged.
  - Transport: client-side buffering + POST to `/api/tools/metrics` (to be added) with zod schema; fall back to `navigator.sendBeacon` and drop on failure (no retries to avoid leakage).
  - Display: console debug in dev; optional aria-live “metrics collected” for debugging disabled in prod.
- Harden the UI kit: audit `@/components/ui` exports (remove placeholders), align design tokens and aria/useId coverage, add missing unit/visual tests for FileUpload/MultiSelect/ToolPageTemplate, and refresh `DEVELOPER_CHEAT_SHEET.md` guidance.
- Harden offline/privacy defaults: ensure all tools degrade gracefully without `DATABASE_URL`, cache translations/assets where safe, and keep the 10MB cap with >5MB progress feedback.
- Workerize heavy paths where needed (e.g., PDF generation, large conversions) to keep the main thread responsive; maintain aria-live progress updates.
- Expand regression coverage: add unit tests for parsing/decoding edge cases and Playwright smokes for new tools (format-converter, jwt-decoder) and any workerized flows.

Rationale
- Performance and resilience guardrails reduce regressions before adding more tools and keep the client-side privacy promise credible under load and offline/poor-network conditions.
- Strengthening the shared component library protects UX consistency and accelerates future tool delivery.

Out of scope
- New tool creation; design rebrands.
- Server-dependent features or lifting the 10MB ceiling.

Risks/Mitigations
- Risk: instrumentation creep leading to data leakage; mitigation: collect only synthetic metrics (durations/error counts) without payload data.
- Risk: workerization regressions; mitigation: gated rollout with tests and fallbacks to synchronous paths if workers fail.
- Risk: UI regressions from library refactors; mitigation: snapshot/unit coverage on shared components and spot-check representative tool pages (e.g., ImportPanel + ToolPageTemplate).
