# ADR 002: Multi-Cloud Strategy with AWS and Azure

**Date**: 2025-10-23  
**Status**: Proposed  
**Decision Makers**: Infrastructure & ML Engineering Team  
**Tags**: #multi-cloud #aws #azure #architecture

---

## Context and Problem Statement

The USPS ML Classification System is currently architected for AWS as the sole cloud provider. As the system matures, we need to decide:

1. Should we remain AWS-only, or adopt a multi-cloud approach?
2. If multi-cloud, which secondary provider (Azure vs GCP)?
3. What is the implementation strategy to avoid complexity explosion?

### Business Drivers

- **Vendor Leverage**: USPS has existing Azure EA agreements; multi-cloud provides negotiation leverage
- **Avoid Lock-In**: Reduce dependency on single vendor for mission-critical ML inference
- **Best-of-Breed Services**: Azure strengths (Entra ID, OpenAI, M365 integration) complement AWS strengths (SageMaker depth, S3 ecosystem)
- **Disaster Recovery**: Multi-cloud provides true vendor-independent DR capability
- **Organizational Reality**: Different USPS divisions have cloud preferences; potential M&A scenarios

### Technical Drivers

- **Azure OpenAI Access**: GPT-4 models for LLM fallback (Phase 5 requirement)
- **Identity Integration**: Entra ID is USPS enterprise identity provider
- **Compliance**: Azure Government regions for specific workloads
- **Geographic Distribution**: Reduce latency for West Coast operations

---

## Decision

**We will adopt a pragmatic multi-cloud approach with AWS as primary and Azure as secondary.**

### Core Principles

1. **AWS Primary, Azure Secondary**: Deploy all components to AWS first; add Azure selectively for specific benefits
2. **Portable Architecture**: Use cloud-agnostic patterns (HuggingFace models, OpenTelemetry, provider-neutral APIs)
3. **Minimal Shared Services**: Limit cross-cloud services to DNS, CI/CD, observability, identity
4. **Co-Located Data and Compute**: Avoid cross-cloud inference calls; replicate data selectively
5. **Strong Guardrails**: Policy-as-code, cost monitoring, golden templates

### Implementation Pattern

**Split by Function**:
- **Data + BI**: Azure (ADLS Gen2, Fabric/Power BI) for USPS reporting teams
- **ML Training/Inference**: AWS SageMaker (primary) + Azure ML (secondary/DR)
- **GenAI/LLM**: Azure OpenAI for GPT-4 fallback
- **API Gateway**: Cloudflare global routing → AWS API Gateway (90%) + Azure APIM (10%)

## Considered Alternatives

### Alternative 1: AWS Only (Single Cloud)

**Pros**:
- ✅ Simplest architecture, lowest operational overhead
- ✅ No cross-cloud data transfer costs
- ✅ Team has AWS expertise already
- ✅ SageMaker feature depth (Pipelines, Feature Store, Model Monitor)

**Cons**:
- ❌ Vendor lock-in for mission-critical inference
- ❌ No access to Azure OpenAI (GPT-4 models)
- ❌ Limited negotiation leverage
- ❌ Single point of failure (cloud-wide outage)
- ❌ Doesn't leverage USPS Azure EA agreements

**Why Rejected**: Business drivers (vendor leverage, Azure OpenAI access) outweigh operational simplicity for production system.

### Alternative 2: Azure Only (Switch Clouds)

**Pros**:
- ✅ Leverages existing USPS Azure EA
- ✅ Entra ID native integration
- ✅ Azure OpenAI access for GenAI features
- ✅ M365/Fabric integration for BI

**Cons**:
- ❌ Rework all existing AWS infrastructure (VPC, S3, SageMaker)
- ❌ Azure ML less mature than SageMaker (Pipeline orchestration, Model Monitor)
- ❌ Team retraining required
- ❌ Throws away AWS investment (Terraform modules, Lambda functions)
- ❌ S3 ecosystem migration complex (Parquet, data lake)

**Why Rejected**: High migration cost, loss of AWS SageMaker maturity, team expertise in AWS.

### Alternative 3: Multi-Cloud with GCP

**Pros**:
- ✅ GCP Vertex AI competitive with SageMaker
- ✅ BigQuery for data warehousing
- ✅ TPU availability for large models

**Cons**:
- ❌ No existing USPS GCP relationship or EA
- ❌ Less mature FedRAMP support than AWS/Azure
- ❌ Entra ID integration less seamless
- ❌ Three-cloud complexity (AWS + Azure + GCP)

**Why Rejected**: No business driver for GCP; Azure provides better USPS integration (Entra ID, EA agreements).

### Alternative 4: Multi-Cloud Everything (AWS + Azure Parity)

**Pros**:
- ✅ True cloud-agnostic deployment
- ✅ Maximum redundancy and failover options

**Cons**:
- ❌ 2x operational overhead (duplicate everything)
- ❌ High data egress costs (continuous replication)
- ❌ Complex CI/CD (deploy to both clouds always)
- ❌ Team expertise spread thin across two clouds

**Why Rejected**: Complexity explosion without proportional business benefit; pragmatic approach (primary/secondary) sufficient.

---

## Decision Rationale

### Why AWS + Azure (Hybrid)?

**Best of Both Worlds**:
- **AWS**: Mature ML services (SageMaker depth), S3 ecosystem, team expertise
- **Azure**: Entra ID integration, OpenAI access, USPS EA agreements, M365/Fabric
- **Combined**: Vendor leverage, DR capability, best-of-breed services

**Pragmatic Approach**:
- Start with AWS (Phases 1-4, Weeks 1-16)
- Add Azure incrementally (Phases 5-10, Weeks 17-52)
- Validate each step before expanding
- 90/10 traffic split (AWS primary, Azure canary/DR)

**Measured Risk**:
- Multi-cloud adds ~20-30% operational overhead
- Data egress costs ~$0.09/GB (AWS) + $0.087/GB (Azure)
- Mitigated by co-locating data and compute, selective replication
- Benefit: 10-15% vendor discount, DR capability, Azure OpenAI access

---

## Implementation Details

### Phase 1: AWS Only (Weeks 1-16) ✅
- Deploy VPC, S3, SageMaker, Lambda, API Gateway
- Establish baseline metrics (cost, latency, reliability)
- **Status**: Complete (current state)

### Phase 2-4: Azure Preparation (Weeks 17-28)
- Set up Azure subscription, Entra ID, VNet, ADLS Gen2
- Deploy Azure ML workspace and endpoint (no production traffic)
- Implement data replication (S3 → ADLS)
- **Deliverable**: Azure infrastructure ready, model deployed, validated

### Phase 5-6: Global Routing (Weeks 29-36)
- Deploy Cloudflare DNS + Load Balancer
- 99/1 weighted routing (1% Azure canary)
- Expand to 90/10 after validation
- **Deliverable**: Production traffic on both clouds

### Phase 7: Azure OpenAI Integration (Weeks 37-40)
- Integrate GPT-4 for low-confidence fallback
- Hybrid routing: BERT (AWS) → GPT-4 (Azure) for edge cases
- **Deliverable**: LLM fallback operational

### Phases 8-10: Optimization and DR (Weeks 41-52)
- Geo-routing, cost optimization, DR testing
- **Deliverable**: Production-ready multi-cloud system

## Technical Architecture

### Identity: Entra ID as Root of Trust

```
Entra ID (IdP)
    ├─── SAML ──► AWS IAM Identity Center ──► IAM Roles
    ├─── RBAC ──► Azure Resources (native)
    └─── OIDC ──► GitHub Actions ──► Both Clouds (no secrets)
```

### Data: Selective Replication

```
AWS S3 (Primary)              Azure ADLS (Mirror)
├── raw/ (local)              ├── raw/ (local)
├── curated/ (sync)    ◄──►   ├── curated/ (sync)
├── feature/ (sync)    ◄──►   ├── feature/ (sync)
└── models/ (sync)     ◄──►   └── models/ (sync)
```

### ML Inference: Dual Endpoints with Global Routing

```
Cloudflare DNS/LB (Global Edge)
    ├─── 90% ──► AWS API Gateway ──► Lambda ──► SageMaker (ml.m5.large)
    └─── 10% ──► Azure APIM ──► Function ──► Azure ML (Standard_DS3_v2)
```

### Observability: OpenTelemetry to Datadog

```
AWS Lambda ──┐
Azure Func ──┼──► OTLP ──► Datadog (Unified Dashboard)
```

## Consequences

### Positive

1. **✅ Vendor Leverage**: Negotiate 10-15% discounts on both AWS and Azure
2. **✅ Best-of-Breed Services**: SageMaker depth + Azure OpenAI
3. **✅ DR Capability**: True multi-cloud failover (<5 min RTO)
4. **✅ Identity Integration**: Entra ID as USPS enterprise IdP
5. **✅ Geographic Optimization**: Reduce latency for West Coast (Azure West US 2)
6. **✅ Compliance Coverage**: FedRAMP on both clouds

### Negative

1. **❌ Increased Complexity**: 20-30% operational overhead
2. **❌ Data Egress Costs**: ~$0.09/GB for cross-cloud replication
3. **❌ Team Expertise**: Need skills in both AWS and Azure
4. **❌ Monitoring Overhead**: Two clouds to monitor and maintain
5. **❌ CI/CD Complexity**: Deploy to two clouds (mitigated by GitHub OIDC)

### Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| **Cost Overrun** | Track data egress; co-locate compute and data; monthly cost reviews |
| **Complexity Explosion** | Guardrails: limit shared services, golden templates, policy-as-code |
| **Team Skill Gap** | Training on Azure; hire platform engineer with multi-cloud experience |
| **Model Drift** | Weekly validation of model parity (AWS vs Azure); <2% accuracy delta |
| **Cross-Cloud Latency** | Avoid cross-cloud calls; replicate data; use Cloudflare edge routing |

## Cost Analysis

### Current (AWS Only)
- Infrastructure: $40-80/month (VPC, NAT, S3, CloudWatch)
- SageMaker Endpoint: $83/month (ml.m5.large, 24x7)
- **Total**: ~$150-200/month (dev), ~$2500-4000/month (prod)

### With Azure (Multi-Cloud)
- AWS Infrastructure: $40-80/month
- Azure Infrastructure: $50-90/month (VNet, NAT, ADLS, Monitor)
- AWS SageMaker: $83/month (primary)
- Azure ML: $50-75/month (Standard_DS3_v2, lower utilization)
- Data Egress: $20-50/month (feature sync, model replication)
- Cloudflare: $20/month (Pro plan)
- Datadog: $30/month (2 hosts)
- **Total**: ~$300-400/month (dev), ~$3500-5000/month (prod)

**Incremental Cost**: +$150-200/month (dev), +$1000-1500/month (prod)  
**ROI**: 10-15% vendor discounts (~$300-600/month at scale), DR capability, Azure OpenAI access

## Compliance and Security

### FedRAMP Compliance
- **AWS**: FedRAMP High (us-east-1, us-west-2)
- **Azure**: FedRAMP High (Azure Government regions)
- **Status**: Architecture supports both; deployment to FedRAMP regions Phase 8+

### Encryption
- **At Rest**: AES-256 (S3, ADLS, EBS, Azure Disks)
- **In Transit**: TLS 1.2+ (all cross-cloud communication)
- **Keys**: AWS KMS (AWS resources), Azure Key Vault (Azure resources)

### Audit Logging
- **AWS**: CloudTrail, VPC Flow Logs
- **Azure**: Activity Log, NSG Flow Logs
- **Centralized**: Datadog for unified log aggregation

## Review and Reevaluation

### Review Triggers
1. **After Phase 1 Complete** (Week 16): Validate AWS baseline before adding Azure
2. **After Phase 5 Complete** (Week 32): Review canary results (99/1 split)
3. **After Phase 10 Complete** (Week 52): Comprehensive multi-cloud review
4. **Quarterly**: Cost analysis, vendor negotiations, architecture refinement

### Reevaluation Criteria
- If cost overhead >30%, reassess Azure components
- If model parity >5% accuracy delta, investigate deployment differences
- If DR failover >10 minutes, revisit architecture (DNS TTL, health checks)
- If team overhead unsustainable, consider scaling team or simplifying
