# Decision: Claude Code Workflow System with ADRs, Skills, and Approval Checkpoints

Date: 2025-01-17

## Context

The project needed a systematic approach to:
- Break down large tasks into trackable checklist items
- Maintain overall project backlog and roadmap
- Capture architectural decisions for future reference
- Enforce human approval checkpoints before critical operations (commits, deployments)
- Prevent loss of design rationale and decision context

Without this system, architectural decisions were scattered across conversations, commits lacked proper review gates, and complex tasks had no structured tracking mechanism.

## Options Considered

- **Option A: Custom orchestrator with separate planning/execution agents**
  - Build custom multi-agent system with explicit planner and executor roles
  - Pros: Maximum control, clear separation of concerns
  - Cons: Over-engineered for current needs, high maintenance overhead

- **Option B: Claude Code native features (Skills, Commands, Hooks, ADRs)**
  - Use built-in TodoWrite for task-level tracking
  - Create ADR skill for automatic decision detection
  - Add slash commands for manual workflows
  - Configure hooks for approval checkpoints
  - Maintain ADRs in `/docs/adr/`
  - Pros: Leverages existing tools, low maintenance, industry-standard ADRs, extensible
  - Cons: Requires learning Claude Code configuration

## Decision

Chose **Option B** - Claude Code native features with ADR system.

**Implementation:**

1. **Task Management**
   - Built-in `TodoWrite` for feature implementation checklists and task tracking
   - Provides real-time progress visibility

2. **Architectural Decision Tracking**
   - ADR skill: Auto-detects architectural decisions and proposes creating ADRs
   - `/adr` command: Manual ADR creation
   - `/adr-list` command: View all ADRs with summaries
   - Storage: `/docs/adr/` with auto-maintained `index.md`

3. **Approval Checkpoints (Future Phase)**
   - Hooks on `git commit` to require explicit approval
   - Stop hooks to prevent premature completion
   - Edit hooks to remind about plan approval

4. **Workflow Commands (Future Phase)**
   - `/plan`: Enter exploration mode without making changes
   - `/implement`: Execute approved plan

## Consequences

**Positive:**
- Architectural decisions are automatically captured and indexed
- Clear separation between exploration and implementation
- Human retains control over all critical operations
- Industry-standard ADR format ensures long-term maintainability
- Extensible system can grow with project needs
- TodoWrite provides real-time progress visibility

**Negative:**
- Requires discipline to approve ADR creation when prompted
- Initial setup overhead for hooks and commands
- Team members need to learn Claude Code configuration syntax

**Affected Areas:**
- Development workflow (all feature development now follows: explore → plan → approve → implement → explain → commit)
- Documentation structure (ADRs become source of truth for architectural decisions)
- Git workflow (commits require explicit approval via hooks)
- Task tracking (TodoWrite provides task-level tracking, ADRs provide architectural context)
