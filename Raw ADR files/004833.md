# ADR-002: Error Handling Strategy

## Status
**ACCEPTED** - 2025-09-22

## Context
The design document specified functional-style error handling using Result types:

```python
@dataclass(frozen=True)
class Success(Generic[T]):
    value: T

@dataclass(frozen=True)  
class Failure(Generic[E]):
    error: E

Result = Union[Success[T], Failure[E]]
```

However, our implementation uses standard Python exception handling. We needed to decide which approach to adopt consistently.

## Decision
**Use Python's idiomatic exception handling** rather than functional Result types.

## Rationale
1. **Python Idioms**: Exceptions are the Pythonic way to handle errors
2. **Ecosystem Integration**: Third-party libraries (ActivityWatch, LLM providers) use exceptions
3. **Simplicity**: Less cognitive overhead than Result type pattern matching
4. **Async Compatibility**: Exception handling works naturally with async/await
5. **Team Familiarity**: Standard Python error handling is well-understood

## Implementation Approach
```python
try:
    activities = await extract_activities(time_range)
    narrative = await generate_narrative(activities)
except ActivityWatchError as e:
    logger.error(f"ActivityWatch connection failed: {e}")
    # Graceful degradation to mock data or user guidance
except LLMProviderError as e:
    logger.error(f"LLM provider failed: {e}")
    # Fallback to basic summary generation
```

## Consequences

### Positive
- Consistent with Python ecosystem and community practices
- Natural integration with existing libraries and async code
- Simpler error handling logic without pattern matching
- Better stack traces and debugging experience
- Automatic error propagation through call stack

### Negative
- No compile-time guarantees about error handling (unlike Result types)
- Possible unhandled exceptions if not properly caught
- Less explicit about what errors functions can raise

### Implementation Requirements
- Define custom exception classes for domain errors
- Implement graceful degradation patterns
- Add comprehensive error logging
- Update design.md to reflect exception-based approach
