# ADR-001: Shadow Doc Standard — Co-located `*.ref.md`

## Context
Shadow docs were historically stored in `docs/architecture/`, causing orphaning and discoverability issues. Contributors and automation agents have created duplicates and inconsistent naming (`.ref.md`, `.shadow.md`). A clear, enforced standard reduces drift, improves discoverability, and simplifies CI checks.

## Decision
Adopt co-located shadow docs using the file extension `.ref.md` placed adjacent to the source file. Each shadow doc must include frontmatter with at least:

- `title:` short descriptive title
- `date:` creation or migration date
- `source:` relative path to the source file

Shadow docs will not be stored centrally; `docs/architecture/` (legacy) is being deprecated and will retain only this ADR until the final migration report is archived elsewhere (e.g. `docs/adr/` or `docs/archives/`).

## Alternatives considered
- Central directory `docs/architecture/` (legacy): easier central discovery, but high drift and orphan risk.
- Suffix `.shadow.md`: considered, but `.ref.md` aligns better with existing `.ref.md` stubs and tooling.

## Rationale
Co-location ensures the shadow doc travels with the source file during moves/renames and reduces orphaning. The `.ref.md` suffix is consistent with existing stubs and is easy for scripts to detect.

## Consequences
- Update automation scripts: `scripts/shadow-doc-sync.py`, `scripts/shadow_doc_audit.py`, and `scripts/migrate_shadow_docs.py` to prefer co-located `*.ref.md` and reject central copies except migration reports.
- Add CI check to fail on new shadow docs placed outside the co-located pattern.
- Run a migration script (dry-run succeeded) and commit migrated files with a temporary report (`migration-report.md`) slated for relocation out of `docs/architecture/`.
