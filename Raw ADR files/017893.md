# ADR-002: CSS Selector Matching Direction

## Status
Accepted

## Context
CSS selectors like "parent child" or "ancestor descendant" read left-to-right but must be matched right-to-left. This creates confusion when implementing selector matching logic.

For example, the selector "section title" should find all `title` elements that are descendants of `section` elements, not sections that have title descendants.

## Decision
Implement selector matching using a right-to-left approach:

1. Parse selectors into a chain of parts (left-to-right as written)
2. When matching an element:
   - First check if the element matches the rightmost selector part
   - Then traverse up/sideways through the tree to verify combinator relationships
   - Work backwards through the selector chain

## Implementation Details

### Selector Structure
```typescript
// "section title" parses to:
{
  type: 'Tag',
  value: 'section',
  combinator: 'descendant',
  next: {
    type: 'Tag', 
    value: 'title'
  }
}
```

### Matching Algorithm
```typescript
function matchesSelector(element, selector) {
  // 1. Extract all parts of the selector chain
  const parts = extractSelectorChain(selector);
  
  // 2. Check if element matches rightmost part
  if (!matchesSimple(element, parts[parts.length - 1])) {
    return false;
  }
  
  // 3. Verify combinator relationships working backwards
  for (let i = parts.length - 2; i >= 0; i--) {
    element = findMatchingElement(element, parts[i], combinator);
    if (!element) return false;
  }
  
  return true;
}
```

## Consequences

### Positive
- Correctly implements CSS selector semantics
- Supports complex selectors with multiple combinators
- Works with compound selectors (tag.class#id[attr])

### Negative  
- More complex than naive left-to-right matching
- Requires careful handling of selector chain extraction
- Performance overhead of splitting and reconstructing selectors

## Lessons Learned
The key insight is understanding that CSS selectors describe a path through the DOM tree, where:
- The rightmost part describes what we're looking for
- The left parts describe the context/relationships
- Matching must verify these relationships from the element upwards/sideways
