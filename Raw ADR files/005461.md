## Context

ADR-013 established Alpha Vantage as the primary tool for news and sentiment analysis. However, a critical data gap remains: Alpha Vantage does not provide access to official SEC filings (10-Ks, 10-Qs) or the deep fundamental data derived from them. Furthermore, relying on a single third-party API for a critical function like news/sentiment introduces a single point of failure. The system requires a provider for deep financial data and a resilient, multi-provider strategy for news and market data.

## Decision

We will integrate **Finnhub** into the `MarketAnalysisAgent` with a dual role, creating a multi-provider data strategy alongside Alpha Vantage.

1.  **Finnhub's Primary Role: Financial Data Provider**
    *   The `MarketAnalysisAgent` **must** use Finnhub as the primary, authoritative source for all data related to official company financials. This includes:
        *   SEC Filings (10-K, 10-Q, 8-K).
        *   Parsed Financial Statements (Income, Balance Sheet, Cash Flow).
        *   Basic company fundamentals.

2.  **Finnhub's Secondary Role: Backup Provider**
    *   Finnhub will serve as the secondary, failover provider for news, sentiment, and general market data. The agent's workflow will be:
        *   **For News/Sentiment**: First, attempt to fetch data from Alpha Vantage (per ADR-013). If the API call fails, returns no data, or times out, the agent **must** then attempt to fetch the data from Finnhub's news API.
        *   **For Market Data**: The primary source for real-time market data remains the `IBGatewayAgent` (per ADR-006). Both Alpha Vantage and Finnhub will act as secondary and tertiary backups for non-real-time price checks or in case of a broker connection failure.

## Rationale

This hybrid, multi-provider approach delivers a complete and resilient data solution.

1.  **Fills a Critical Data Gap**: Finnhub directly provides the SEC filing and fundamental data that Alpha Vantage lacks. This is essential for the deep, qualitative analysis required by the `StockSelectionAgent`.
2.  **Exceptional Cost-Effectiveness**: Finnhub's free tier is extremely generous (60 API calls/minute), which is sufficient for all development, testing, and even low-frequency production use. This allows us to add a significant amount of critical data and redundancy for little to no additional cost, offering an outstanding cost/functionality ratio.
3.  **Increased Resilience and Redundancy**: The system is no longer dependent on a single third-party API for news. By implementing a primary/secondary failover pattern, the agent can continue to function even if one provider is temporarily unavailable, making the system more robust.
4.  **Best Tool for the Job**: This decision uses each service for its primary strength. We use Alpha Vantage for its simple, integrated `NEWS_SENTIMENT` endpoint as the "fast path," and we use Finnhub for its deeper, more comprehensive financial data.

## Consequences

-   **Increased Implementation Complexity**: The `MarketAnalysisAgent` will become more complex. It must now manage clients for two different APIs (Alpha Vantage and Finnhub) and contain the failover logic to try the primary and then the secondary source.
-   **Configuration Management**: A second API key (for Finnhub) must be securely stored and managed by the system's configuration and secrets service.
-   **Data Standardization**: The agent will be responsible for normalizing the data from both APIs into a single, consistent internal data model (e.g., a Pydantic `NewsArticle` model). This is crucial to ensure that downstream agents receive data in a predictable format, regardless of the source.
-   **New Dependency**: A new dependency on the Finnhub API will be introduced.

## Alternatives Considered

-   **Using a Single, More Expensive Provider (e.g., Polygon.io)**: While some premium providers offer all the required data in one package, the combined cost of the Alpha Vantage and Finnhub paid tiers (if needed) is significantly lower. This hybrid approach provides comparable data coverage for a better price.
-   **Building a Direct SEC EDGAR Parser**: This was rejected due to the immense complexity and high maintenance overhead of parsing raw XBRL and HTML from the SEC. Using a provider like Finnhub, which handles this parsing, is far more efficient from a development perspective.

## Implementation Strategy

### Phase 1: Finnhub Client Setup (Week 1)
**Deliverables**:
- Install Finnhub Python client library (`finnhub-python`)
- Configure API key in Secret Manager (ADR-022)
- Implement base client wrapper with error handling
- Unit tests for API client initialization
- Rate limiting configuration (60 calls/minute free tier)

**Dependencies**: ADR-022 (Secrets Management)

### Phase 2: Financial Data Integration (Week 1-2)
**Deliverables**:
- Integrate SEC filings API endpoints (10-K, 10-Q, 8-K)
- Implement financial statements parsing (income, balance sheet, cash flow)
- Add company fundamentals API integration
- Create normalized data models for financial data
- Redis caching layer (24-hour TTL for filings, 7-day for fundamentals)
- Unit tests for data parsing and normalization

**Dependencies**: Phase 1 complete, Redis infrastructure (ADR-001)

### Phase 3: Failover Logic Implementation (Week 2-3)
**Deliverables**:
- Implement primary/secondary failover pattern in `MarketAnalysisAgent`
- Add retry logic with exponential backoff
- Configure timeout thresholds (5s Alpha Vantage, 5s Finnhub)
- Implement data source tracking and logging
- Integration tests for failover scenarios
- Performance testing for failover latency

**Dependencies**: Phase 2 complete, ADR-013 (Alpha Vantage) implementation

### Phase 4: Market Data Backup Integration (Week 3-4)
**Deliverables**:
- Integrate Finnhub quote API as tertiary data source
- Implement market data failover chain (IB Gateway → Alpha Vantage → Finnhub)
- Add data quality validation and staleness checks
- Configure alerting for data source failures
- End-to-end tests for complete failover chain

**Dependencies**: Phase 3 complete, ADR-006 (IB Gateway) integration

### Phase 5: Monitoring and Optimization (Week 4-5)
**Deliverables**:
- Configure API usage dashboards
- Set up quota monitoring and alerting (60 calls/minute)
- Implement intelligent caching strategies
- Performance benchmarking across all data sources
- Documentation for data source selection logic

**Dependencies**: Phase 4 complete, ADR-021 (Observability) implementation

## Cost Analysis

### Monthly Operational Costs

**Finnhub API**:
- Free tier: 60 API calls/minute, comprehensive endpoints
- Paid tier: $59.99/month for enhanced features and higher limits
- Estimated usage: 100-200 calls/day (SEC filings, fundamentals, failover)
- **Cost**: $0/month (free tier sufficient for MVP)
- **Upgrade threshold**: Sustained failover usage >1000 calls/day

**Redis Caching**:
- Financial data cache storage: <200MB
- Included in existing Redis instance (ADR-001)
- **Cost**: $0/month (covered by base allocation)

**Data Processing**:
- SEC filing parsing compute (Cloud Run): $2-5/month
- Storage for cached filings: Included in Redis
- **Subtotal**: $2-5/month

**Total Estimated Monthly Cost**: $2-5/month

### Cost Optimization Strategies

1. **Aggressive Caching**:
   - 24-hour TTL for SEC filings (updated quarterly)
   - 7-day TTL for company fundamentals
   - 1-hour TTL for market data backups
   - Estimated savings: 85-90% API call reduction

2. **Smart Failover Logic**:
   - Finnhub only called when Alpha Vantage fails (<5% of requests)
   - Market data from IB Gateway primary (99% of requests)
   - Minimizes Finnhub API usage to SEC filings and fundamentals
   - Free tier sufficient for years of operation

3. **Batch Processing**:
   - Fetch fundamentals for multiple stocks in parallel
   - Pre-cache SEC filings for watchlist stocks overnight
   - Reduces real-time API pressure during trading hours

### ROI Comparison

**vs Premium Provider (Polygon.io)**:
- Polygon.io: $199/month for comparable data
- Finnhub + Alpha Vantage: $0/month (free tiers)
- **Cost Savings**: 100% reduction

**vs Bloomberg Terminal**:
- Bloomberg Terminal: $2,000/month per user
- Finnhub for fundamentals: $0/month
- **Cost Savings**: 100% reduction for fundamental data

**vs Building SEC EDGAR Parser**:
- Development: 8-12 weeks engineering time
- Maintenance: 30% ongoing engineering allocation
- Infrastructure: $50-100/month
- Finnhub approach: 1 week, minimal maintenance, $0/month
- **Cost Savings**: 95%+ vs in-house solution

## Risk Assessment

| Risk | Severity | Likelihood | Impact | Mitigation |
|------|----------|------------|--------|------------|
| Finnhub API quota exceeded | Low | Low | Degraded failover capability | Rate limiting, caching, quota monitoring, paid tier upgrade if needed |
| SEC filing data quality issues | Medium | Low | Incorrect fundamental analysis | Data validation, cross-reference with Alpha Vantage, manual review for large positions |
| Failover chain complete failure | High | Very Low | Blocked stock selection | Manual analyst review, delay trades until data available, hard-coded safety limits |
| API latency in failover scenario | Low | Medium | Slower stock selection during Alpha Vantage outage | Async processing, timeout handling, cached data fallback |
| Data normalization errors | Medium | Medium | Inconsistent data across providers | Comprehensive unit tests, integration tests, data validation layer |
| API key exposure | High | Low | Unauthorized usage, quota exhaustion | Secret Manager storage (ADR-022), key rotation, usage monitoring |
| Free tier rate limiting | Medium | Medium | Temporary data unavailability | Backoff logic, request queuing, paid tier upgrade threshold |

## Monitoring and Success Criteria

### Key Metrics

**Finnhub API Performance**:
1. API call success rate: >99%
2. API latency: <800ms p95, <1.5s p99
3. Daily API usage: <500 calls
4. Failover trigger rate: <5% of total data requests

**Financial Data Quality**:
1. SEC filing freshness: <24 hours from SEC publication
2. Fundamental data accuracy: 100% (validated against SEC filings)
3. Data normalization success rate: >99%
4. Cache hit rate: >80% for fundamentals

**Failover Effectiveness**:
1. Failover success rate: >95% when Alpha Vantage unavailable
2. Failover latency overhead: <2 seconds p95
3. Data consistency across providers: >95%
4. Zero-downtime during single provider outage

### Alerting Thresholds

**Critical Alerts (PagerDuty)**:
- Finnhub API down for >5 minutes
- All data providers unavailable simultaneously
- API key unauthorized or expired
- Failover chain completely failing

**Warning Alerts (Email)**:
- Failover trigger rate >20% (indicates Alpha Vantage degradation)
- Daily API usage >400 calls (80% of free tier)
- API latency >3 seconds p95
- Data quality validation failures >5%

**Informational Alerts (Dashboard)**:
- Daily API usage summary by endpoint
- Failover events log
- Cache performance metrics
- Data source availability trends

### Success Criteria

**Functional Requirements**:
- SEC filings accessible within 24 hours of publication
- Fundamental data complete for all stocks in selection pool
- Failover completes successfully in >95% of Alpha Vantage failures
- Zero data loss during provider transitions

**Performance Requirements**:
- Combined availability (Alpha Vantage + Finnhub): >99.9%
- Financial data fetch latency: <3 seconds p95
- Failover adds <2 seconds latency
- Cache hit rate: >80% for repeat queries

**Cost Requirements**:
- Remain on Finnhub free tier for first 12 months
- Total monthly cost <$10 (including Cloud Run processing)
- No upgrade to paid tier unless trading volume >50 stocks/week

**Operational Requirements**:
- Zero manual intervention for failover operations
- Automated data source health checks every 5 minutes
- Self-healing retry mechanisms
- Quarterly data quality audits
