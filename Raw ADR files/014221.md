# Decision: bootstraptest `test_literal_suffix.rb`

## Context

`vendor/ruby/ruby/bootstraptest/test_literal_suffix.rb` exercises numeric literal suffix parsing and a small slice of control flow/error handling:

- `0r`, `1.2r`, `-1.2r` → `Rational`
- `1i`, `1ri`, `1.2ri`, `1e1i` → `Complex`
- modifier `if` (`1if true`)
- rescue modifier (`1rescue nil`)
- `begin ... rescue SyntaxError => e; e.message[/(...)/, 1]; end` around `eval(...)` syntax errors

This file is a good early conformance target because it stays mostly within literal parsing + minimal exception plumbing.

## Decision

Implement the minimum Prism-node → bytecode support needed for this file:

- Compile `RationalNode` into `Value::Rational { numerator, denominator }` using Prism’s already-reduced numerator/denominator integers.
- Compile `ImaginaryNode` into `Value::Complex { real: 0, imag: <numeric> }`, supporting numeric sub-nodes: `IntegerNode`, `FloatNode`, and `RationalNode`.
- Add minimal control-flow/exceptions:
  - `IfNode` (modifier form) compiled via `JUMP_IF_FALSE`.
  - `RescueModifierNode` compiled via `PUSH_RESCUE`/`POP_RESCUE` and a handler that evaluates the rescue expression.
  - `BeginNode` with a single `RescueNode` clause compiled similarly.
- Keep `eval` a no-op for non-literal inputs, but when the first argument is a plain string literal:
  - parse it with Prism during compilation
  - on parse errors, raise `SyntaxError` with message `": syntax error, <prism message>"`

For `e.message[/(...)/, 1]`, add a dedicated bytecode helper `STRING_REGEX_CAPTURE` that extracts a capture group from a string with a regexp + integer index (just enough for this one pattern).

## Notes / follow-ups

- This is intentionally not a full Ruby exception/object/method model; it is a bootstrap stepping stone. Full exception classes, `raise`, and backtraces must be designed when the real call-frame model lands.
- The current `Regexp` story is split: `=~` is still a substring matcher, while `STRING_REGEX_CAPTURE` uses Rust’s `regex` crate for capture extraction. This mismatch is tracked in `COMPAT.md` and should be unified later.
