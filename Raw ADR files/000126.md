# ADR-0005: Vision Framework for Cube Scanning

**Status**: Accepted
**Date**: October 12, 2025
**Deciders**: Architecture Team

## Context

The app requires the ability to scan a physical 3x3 cube puzzle using the device camera and accurately detect its current state (colors of all 54 stickers across 6 faces). This involves:

- Face detection and alignment
- Color recognition under varying lighting conditions
- Coordinate mapping of 9 stickers per face
- Real-time feedback during scanning
- Validation of cube state consistency

Available approaches:

1. **Apple Vision Framework + CoreML**: On-device ML with custom model
2. **OpenCV**: Computer vision library with color detection algorithms
3. **Custom ARKit + Image Processing**: AR-based cube tracking and color sampling
4. **Third-party APIs**: Cloud-based vision services (Google Vision, AWS Rekognition)

Key considerations:

- Accuracy requirements (high success rate in good lighting conditions)
- Performance (real-time or near-real-time feedback)
- Privacy (on-device processing)
- Lighting robustness
- Development complexity

## Decision

**We will use Apple's Vision framework combined with a custom CoreML model for cube face detection, edge recognition, and color classification.**

Architecture:

- **Vision Framework**: Face/rectangle detection, alignment
- **CoreML Model**: Color classification for individual stickers
- **Custom Post-Processing**: Validation, error correction, state construction

## Alternatives Considered

### OpenCV

**Pros**:

- Mature, proven computer vision library
- Extensive algorithm implementations
- Cross-platform (useful if Android version built later)
- Good documentation and community

**Cons**:

- C++ library requires bridging to Swift
- Increases binary size
- Manual integration and maintenance
- Not optimized for Apple Neural Engine
- More complex color calibration needed

**Why not chosen**: Vision framework provides equivalent capabilities with better iOS integration and hardware acceleration ([Vision Framework documentation](https://developer.apple.com/documentation/vision)).

### Custom ARKit + Image Processing

**Pros**:

- 3D tracking of cube in space
- Potential for real-time overlay guidance
- Natural AR experience

**Cons**:

- Significantly more complex implementation
- Higher computational overhead (running AR session)
- Overkill for static cube scanning
- Greater battery drain
- Requires good lighting and feature-rich environment

**Why not chosen**: Over-engineered for the scanning use case; ARKit better suited for future AR features (solution overlay) rather than static scanning.

### Cloud-Based Vision APIs (Google Vision, AWS Rekognition)

**Pros**:

- Powerful pre-trained models
- No on-device model training required
- Continuous improvement from provider

**Cons**:

- Violates privacy requirement (camera images sent to cloud)
- Requires internet connectivity
- Network latency impacts user experience
- API costs scale with usage
- Vendor lock-in
- Cannot customize for cube-specific scenarios

**Why not chosen**: Conflicts with [ADR-0002](./ADR0002-on-device-processing.md) (on-device processing); unacceptable privacy implications.

### Manual Color Sampling (No ML)

**Pros**:

- Simple implementation
- No model training
- Lightweight

**Cons**:

- Very sensitive to lighting conditions
- Poor accuracy without calibration
- Requires manual white balance
- Struggles with non-standard cube colors
- No robustness to shadows or reflections

**Why not chosen**: Insufficient accuracy; poor user experience in varied lighting.

### Third-Party Cube Detection SDKs

**Pros**:

- Potentially faster integration
- Pre-optimized for 3x3 cube puzzles

**Cons**:

- Limited options available
- Unknown privacy practices
- Less control over accuracy improvements
- Licensing costs or restrictions
- Potential supply-chain security concerns

**Why not chosen**: Prefer first-party frameworks for privacy and control; no compelling third-party options identified.

## Consequences

### Positive

1. **Privacy-First**: All image processing on-device; images never leave device
2. **Hardware Acceleration**: Neural Engine optimized for CoreML inference ([CoreML Performance](https://developer.apple.com/documentation/coreml/optimizing_your_model_for_on-device_execution))
3. **Native Integration**: Seamless Swift API; SwiftUI camera integration
4. **Offline Operation**: No network required; consistent with [ADR-0002](./ADR0002-on-device-processing.md)
5. **Real-Time Performance**: Frame-by-frame processing capability at camera framerate
6. **Customizable**: Train custom CoreML model specific to 3x3 cube puzzle characteristics
7. **Small Footprint**: CoreML model size depends on architecture; typically compact
8. **Future-Proof**: Apple continues investing in Vision and CoreML frameworks

### Negative

1. **Model Training Required**: Must create or find training dataset for cube colors
2. **Lighting Sensitivity**: Requires good lighting for accurate color detection
3. **Tuning Needed**: Color classification thresholds need calibration
4. **iOS-Specific**: Model training tools and framework specific to Apple ecosystem
5. **Edge Cases**: Unusual cube brands or worn stickers may require special handling
6. **No Pre-Built Solution**: Must implement cube-specific logic (face detection, sticker grid mapping)

### Neutral

1. **CoreML Model Updates**: Model improvements require app updates (not dynamic)
2. **Accuracy Trade-Offs**: Balance model complexity vs. inference speed
3. **User Guidance**: May need on-screen guides to help users position cube correctly

## Rationale

The decision prioritizes **privacy, performance, and native integration** while maintaining high accuracy.

### Key Factors

#### Privacy Alignment

- Camera images processed entirely on-device
- Aligns with ADR-0002 (on-device processing)
- No cloud dependencies or data transmission
- Builds user trust

#### Performance Characteristics

- Vision framework optimized for real-time detection ([Vision Framework documentation](https://developer.apple.com/documentation/vision))
- CoreML uses Neural Engine for hardware acceleration ([Neural Engine documentation](https://developer.apple.com/documentation/coreml/core_ml_api/using_a_neural_network_with_aneuralnetworkmodel))
- Performance targets to be validated through implementation:
  - Rectangle/face detection: Real-time processing capability
  - Color classification: Responsive per-face processing
  - Full 6-face scan: Complete within seconds (user-dependent)

#### Accuracy Targets

With proper model training and testing:

- Face detection: High accuracy expected (rectangle detection is well-established in Vision framework)
- Color classification: Target high accuracy in good lighting conditions
- Full cube state: Target high first-try success rate
- All metrics to be established through experimentation and user testing

#### Development Efficiency

```swift
// Example Vision + CoreML integration
let faceDetectionRequest = VNDetectRectanglesRequest { request, error in
    guard let results = request.results as? [VNRectangleObservation] else { return }
    // Process detected face
}

let colorClassificationRequest = VNCoreMLRequest(model: cubeColorClassifier) { request, error in
    guard let results = request.results as? [VNClassificationObservation] else { return }
    // Extract color predictions
}
```

Clean API with minimal boilerplate.

#### Ecosystem Fit

- Native Swift framework
- Xcode tooling for CoreML model management
- Automatic optimization for device hardware
- Consistent updates with iOS releases

### Face Detection Strategy

```swift
// Detect cube face as rectangle
let rectangleRequest = VNDetectRectanglesRequest()
rectangleRequest.minimumAspectRatio = 0.8  // Nearly square
rectangleRequest.maximumAspectRatio = 1.2
rectangleRequest.minimumConfidence = 0.7   // To be tuned through experimentation
rectangleRequest.minimumSize = 0.3         // To be tuned for optimal UX
```

### Color Classification Model

**Input**:

- Cropped sticker image (resolution to be determined based on accuracy/performance trade-offs)
- Normalized RGB values

**Output**:

- 6-class probability distribution: [white, yellow, red, orange, blue, green]
- Confidence score

**Training Data Requirements** (to be determined through experimentation):

- Sufficient images per color class for accurate classification
- Varied lighting conditions (indoor, outdoor, artificial, natural)
- Multiple cube brands and color variations
- Augmentation: brightness, contrast, rotation, perspective transforms

**Model Architecture** (to be determined through experimentation):

- Lightweight CNN (consider MobileNetV3 or similar efficient architecture)
- Target: Fast inference suitable for real-time scanning
- Model size: Compact to minimize app size impact

### Scanning Flow

1. **Initialize Camera**: Request permission, configure AVCaptureSession
2. **Real-Time Detection**: Run rectangle detection on each frame
3. **User Guidance**: Overlay grid, show detected face, prompt for alignment
4. **Capture Face**: When face is stable and well-aligned, capture frame
5. **Extract Stickers**: Divide detected rectangle into 3×3 grid
6. **Classify Colors**: Run CoreML model on each of 9 sticker regions
7. **Validate**: Check confidence scores, prompt to re-scan if low
8. **Repeat**: Guide user to scan remaining 5 faces
9. **Construct State**: Combine 6 faces into CubeState
10. **Final Validation**: Verify cube state is legal (8 corners, 12 edges, correct counts)

### Error Handling & Recovery

| Error Condition | Recovery Strategy |
|----------------|-------------------|
| Face not detected | Show alignment guide, improve lighting prompt |
| Low color confidence | Re-scan specific face |
| Illegal cube state | Indicate which face likely has error, re-scan |
| Poor lighting | Suggest moving to better lit area, show lighting quality indicator |
| Glare/reflections | Suggest changing angle, detect specular highlights |

### User Experience Enhancements

```swift
// Real-time feedback
struct ScanOverlayView: View {
    @Binding var detectedFace: VNRectangleObservation?
    @Binding var alignmentScore: Double

    var body: some View {
        ZStack {
            // Camera preview
            CameraPreviewView()

            // Detected face outline
            if let face = detectedFace {
                RectangleOverlay(observation: face)
                    .stroke(alignmentColor, lineWidth: 3)
            }

            // 3x3 grid guide
            GridOverlay()

            // Alignment indicator
            AlignmentMeter(score: alignmentScore)

            // Instructions
            Text("Align cube face with grid")
                .padding()
                .background(.ultraThinMaterial)
        }
    }
}
```

### Performance Optimization

- **Frame Throttling**: Process subset of frames to reduce CPU load (rate to be determined through testing)
- **Region of Interest**: Only analyze center region of frame (where cube should be)
- **Batch Inference**: Explore batching multiple stickers in single CoreML inference for efficiency
- **Async Processing**: Use dedicated serial queue for Vision requests

### Testing Strategy

- **Unit Tests**: Color classification accuracy on labeled test set
- **Integration Tests**: Full scanning flow with sample images
- **Device Tests**: Test on minimum device (iPhone 12) under various lighting
- **Edge Cases**: Non-standard cube brands, worn stickers, extreme lighting
- **User Testing**: Real users scan various cubes in natural environments
