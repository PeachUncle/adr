# TASK-016: Wire chat and dynamic widgets
> Source: tasks/tasks.md

## Context
- Implement ChatView component that calls POST /chat and renders assistant replies
- Read response.route_hint and dispatch correct follow-up fetches for dynamic widgets
- Maintain message history with loading, success, and error states
- Show compact facts panel when present
- Support PriceWidget, NewsWidget, and ShortlistWidget hydration

## Options Considered
- **Option A**: Monolithic ChatView with embedded widget rendering (Pros: Simple structure; Cons: Hard to maintain, tight coupling)
- **Option B**: Modular approach with separate widget components (Pros: Reusable, maintainable, testable; Cons: More files)
- **Option C**: Single component with conditional rendering (Pros: Fewer files; Cons: Large component, harder to test)

## Decision
- **Chosen approach**: Option B - Modular approach with separate widget components
- **Rationale**: Better separation of concerns, reusable components, easier testing and maintenance

## Impacts
- **Performance**: Efficient with debouncing (30-second cache) and request ID preservation
- **Complexity**: Moderate - Well-structured component hierarchy with clear responsibilities
- **Security/Privacy**: Good - Request IDs preserved for tracing, no sensitive data exposed
- **Compatibility**: High - Uses existing API client and follows established patterns
- **Risks & Mitigations**: 
  - Risk: Widget loading states might confuse users; Mitigation: Clear loading indicators and error handling
  - Risk: Debouncing might show stale data; Mitigation: 30-second cache with clear indicators
