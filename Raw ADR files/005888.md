# Title

Independant module compilation

# Status

Accepted

# Context

The kernel needs a way to compile each application in an independant way. This allows for a more modular design in a whole.

# Decision

The build tool is updated to allow definition of specific **object lists** for each binary to produce: one list for the **kernel** code and one list per **partition**.

```C
PART_0_LIST := lib/libc drv/uart tests
PART_1_LIST := lib/libc drv/uart tests/apps
PART_2_LIST := lib/libc drv/uart tests/threads
...
CORE_LIST := kernel platform arch drv/uart lib/libc
```

Each list is given to the [build](../../tools/make/build.mk) script in order to produce the corresponding **binary file**.

Each partition is compiled and **statically** mapped with its own [linker script](../../tools/linker/). Each partition uses a **32KB** address space, the only difference is the memory offset they use.

```C
           │               │
           │       .       │
           │       .       │
           │       .       │
           │               │
0x80102000 ├───────────────┤
           │               │
           │     part_2    │
           │               │
0x80101000 ├───────────────┤
           │               │
           │     part_1    │
           │               │
0x80100000 ├───────────────┤
           │               │
           │   part_table  │
           │               │
0x800FF000 ├───────────────┤
           │               │
           │    syscalls   │
           │               │
0x800FE000 ├───────────────┤
           │               │
           │               │
           │     kernel    │
           │               │
           │               │
0x80000000 └───────────────┘
```

The entry point of each partition is a **_partition_runtime** routine. This routine **initializes code segments** to be able to execute the partition code. It also expects to find a **main** routine which is the partition entry point for the user.

Also, the **_partition_runtime** restores the return address as we expect to return to **task_runtime** when the processor exits at the end of the partition code.

```C
        │                                            
        │                                            
 ┌──────▼───────┐                                    
 │ task_runtime │                                    
 └──────┬───────┘                                    
        │                                            
        │          ┌────────────────────┐            
        └──────────► _partition_runtime │            
                   └──────────┬─────────┘            
                              │                      
                              │              ┌──────┐
                              └──────────────► main │
                                             └───┬──┘
                                                 │   
                   ┌────────────────────┐        │   
                   │ _partition_runtime ◄────────┘   
                   └──────────┬─────────┘            
                              │                      
 ┌──────────────┐             │                      
 │ task_runtime ◄─────────────┘                      
 └──────┬───────┘                                    
        │                                            
        ▼                                            
```

The **_partition_runtime** is always mapped at the same address which is given to the kernel through the [partition table](./adr-013.md) when the task is created. The kernel uses this entry point to initialize the stack and jump to the partition code.

On the other hand, when the partition code needs to call kernel code, it does it through **syscalls**. For this first implementation, syscalls are statically mapped: this is a big security issue as this design is subject to **return-to-libc** attack and should not be used in a stable release. 

But this is convenient for a first release as we just define syscalls address in a linker script :

```C
ax_task_create = 0x800fe000;
ax_task_get = 0x800fe008;
ax_task_destroy = 0x800fe010;
ax_task_yield = 0x800fe018;
...
```

Partitions can then call kernel routine through these calls:

```C
               │               │    
               │       .       │    
               │       .       │    
               │       .       │    
               │               │    
    0x80102000 ├───────────────┤    
               │               │    
               │     part_2    │    
               │               │ ◄─┐
    0x80101000 ├───────────────┤   │
               │               │   │
               │     part_1    │   │
┌──            │               │   │
│   0x80100000 ├───────────────┤   │
│              │               │   │
│              │   part_table  │   │
│              │               │   │
│   0x800FF000 ├───────────────┤   │
└─►            │               │   │
               │    syscalls   │   │
┌──            │               │   │
│   0x800FE000 ├───────────────┤   │

               │     kernel    │    
               │               │    
               │               │
```

# Consequences

Partitions are compiled and mapped with a custom ABI, we should use something as **.elf** format (or a simplified version such as in [Fuschia](https://fuchsia.dev/fuchsia-src/concepts/kernel/vdso)). We should also use a **loader** to map partitions in volatile memory.

This should allow to avoid **return-to-libc** attacks and also allow **dynamic linking**.

Linker scripts could be generated automatically depending on how many partitions we have to compile.

As all partitions are statically mapped, all libraries are included in each partition. If dynamic linking is implemented, this could help to reduce binary sizes as library code could be shared.
