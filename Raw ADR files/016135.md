# ADR-002: Kubernetes with Kustomize Overlays

**Date:** December 2024  
**Status:** Accepted  
**Deciders:** scAIe Engineering Team

## Context

cAIl needs to support multiple deployment environments:
- **Development**: Local testing with hot-reload
- **Staging**: Pre-production validation
- **Production**: High-availability deployment

Requirements:
- Consistent configuration across environments
- Easy promotion from staging to production
- Environment-specific secrets and resources

## Decision

Use **Kustomize** with overlay pattern:

```
deploy/k8s/
├── base/                 # Shared configuration
│   ├── kustomization.yaml
│   ├── namespace.yaml
│   ├── backend.yaml
│   ├── frontend.yaml
│   └── ...
└── overlays/
    ├── dev/              # Development tweaks
    │   └── kustomization.yaml
    ├── staging/          # Staging configuration
    │   └── kustomization.yaml
    └── prod/             # Production HA
        └── kustomization.yaml
```

### Base Configuration
- All common resources
- Default image tags
- Shared labels

### Overlay Customizations

| Aspect | Dev | Staging | Prod |
|--------|-----|---------|------|
| Replicas | 1 | 2 | 3 |
| Namespace | cail-dev | cail-staging | cail |
| Log Level | DEBUG | INFO | INFO |
| Resources | Minimal | Moderate | Full |

## Deployment

```bash
# Development
kubectl apply -k deploy/k8s/overlays/dev

# Staging
kubectl apply -k deploy/k8s/overlays/staging

# Production
kubectl apply -k deploy/k8s/overlays/prod
```

## Consequences

### Positive
- DRY configuration
- GitOps-friendly
- Built into kubectl (no extra tools)
- Clear promotion path

### Negative
- Learning curve for Kustomize patches
- Debugging overlay conflicts can be tricky

## Alternatives Considered

1. **Helm Charts**: Rejected - overkill for single-tenant deployment
2. **Plain YAML per environment**: Rejected - duplication nightmare
3. **Terraform**: Rejected - not ideal for K8s resources
