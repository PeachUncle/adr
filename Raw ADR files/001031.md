# ADR-0003: Deterministic Length Control via LengthController

**Status**: Accepted ✅
**Date**: 2026-01 (Implemented), 2026-01-12 (Documented)
**Deciders**: Project Team
**Technical Story**: Length adjustment reliability improvement

---

## Context

Korean SOP applications have strict character count requirements: **950-1000 characters including whitespace**.

Early implementations used LLM-based length adjustment:

```python
# Old approach
prompt = f"Adjust this text to exactly 1000 characters: {text}"
adjusted = llm.generate(prompt)
```

**Problems**:
- **Unpredictable**: LLM might produce 950, 1020, or 1100 chars
- **Multiple Retries**: Required 3-5 iterations (expensive)
- **Success Rate**: Only 60-70% hit target after 5 tries
- **Semantic Drift**: Repeated LLM calls changed meaning

The lack of determinism made length control a reliability bottleneck.

---

## Decision

Implement **LengthController** with rule-based primary strategy and LLM fallback:

### Architecture

```python
class LengthController:
    def adjust(text, evidence, question_type, constraints):
        for iteration in range(MAX_ITERATIONS=2):
            delta = calc_delta(len(text))

            if delta > 0:  # Too short - expand
                text = rule_based_expansion(text, evidence)
                if still_short:
                    text = llm_expansion(text, evidence)

            elif delta < 0:  # Too long - compress
                text = rule_based_compression(text)
                if still_long:
                    text = llm_compression(text)

            if in_range(len(text)):
                return success(text)

        return failure_with_reason(text)
```

### Rule-Based Compression Patterns

Priority-ordered removal patterns:

```python
REMOVABLE_PATTERNS = [
    # 1. Unnecessary modifiers
    (r'(?:매우|정말|굉장히|상당히)\s+', '', 'Intensity adverbs'),

    # 2. Self-assessment phrases
    (r'(?:~라고 생각합니다|~라고 봅니다)', '~입니다', 'Self-evaluation'),

    # 3. Meta expressions
    (r'(?:개인적으로|솔직히|사실)\s*', '', 'Meta phrases'),

    # 4. Duplicate connectors
    (r'(?:그리고|또한)\s+(?:그리고|또한)\s+', '또한 ', 'Duplicate connectors'),

    # 5. Verbose background
    (r'(?:어릴 때부터|학창 시절부터)[^.]*?(?=\s*이러한|\s*그래서)', '', 'Verbose background'),
]
```

### Rule-Based Expansion Strategy

1. **Slot Detection**: Find expansion-capable positions
   ```python
   # After experience mentions
   "경험이 있습니다" → slot for detail insertion
   "관심을 갖게 되었습니다" → slot for motivation detail
   "활용하여" → slot for technical detail
   ```

2. **Evidence Mining**: Extract concrete details from KB
   ```python
   # Prefer sentences with numbers
   "3D reconstruction 정확도 15% 향상" ✅
   "많은 연구를 수행" ❌ (vague)
   ```

3. **Natural Insertion**: Add seamlessly
   ```python
   # Before
   "연구 경험이 있습니다."

   # After
   "연구 경험이 있습니다. 특히 3D reconstruction 정확도를 15% 향상시켰습니다."
   ```

### LLM Fallback

Only called when:
- Rule-based methods insufficient (>20 char delta remaining)
- No suitable expansion slots detected
- Evidence extraction fails

**Constraints on LLM**:
```
1. Preserve core claims and evidence
2. No meaningless modifiers (매우, 정말)
3. Maintain tone (합니다/입니다)
4. No first-person pronouns
```

## Consequences

### Positive

✅ **95%+ Success Rate**: Hit 950-1000 in ≤2 iterations
✅ **Predictable**: 2-iteration maximum (vs 5+ with LLM-only)
✅ **Faster**: Rule-based is instant (<1ms)
✅ **Cost-Effective**: LLM fallback rarely needed (20% cases)
✅ **Semantic Preservation**: Rules don't change meaning
✅ **Debuggable**: Clear log of which rules applied

### Negative

⚠️ **Rule Maintenance**: Patterns need updates for edge cases
⚠️ **Korean-Specific**: Rules tuned for Korean text structure
⚠️ **Evidence Dependency**: Expansion quality depends on KB richness

### Neutral

🔵 **Fallback Exists**: LLM available when rules insufficient
🔵 **Configurable**: Can adjust MAX_ITERATIONS, patterns

## Alternatives Considered

### Alternative 1: Pure LLM Approach
**Approach**: Keep prompting LLM until correct length

**Pros**:
- No rule maintenance
- Handles edge cases naturally

**Cons**:
- Unpredictable (60-70% success)
- Expensive (5+ API calls)
- Semantic drift over iterations

**Rejected Because**: Empirical testing showed 30-40% failure rate after 5 iterations.

---

### Alternative 2: Character-Level Truncation/Padding
**Approach**: Simply cut at 1000 chars or pad with spaces

**Pros**:
- 100% success hitting character count
- Instant, zero cost

**Cons**:
- Breaks sentences mid-word
- Padding looks unprofessional
- Doesn't optimize content

**Rejected Because**: Quality unacceptable for submission documents.

---

### Alternative 3: Word-Level Statistical Model
**Approach**: Train model to predict word importance, remove low-importance words

**Pros**:
- Data-driven approach
- Could learn optimal patterns

**Cons**:
- Requires large training corpus
- Korean word segmentation complexity
- Maintenance burden (retraining)

**Rejected Because**: Rule-based approach achieves 95%+ success without ML overhead.

## Implementation Details

### Calculation Strategy

```python
def calc_delta(current_length: int) -> int:
    """
    Returns:
      +N: Need to add N chars (too short)
      -N: Need to remove N chars (too long)
       0: Within range
    """
    TARGET_MIN = 950
    TARGET_MAX = 1000

    if current_length < TARGET_MIN:
        return TARGET_MIN - current_length  # Positive
    elif current_length > TARGET_MAX:
        return TARGET_MAX - current_length  # Negative
    return 0
```

### Compression Workflow

```
1. Apply removable patterns (regex-based)
   → Remove ~50-150 chars typically

2. Check if sufficient
   → Yes: Return compressed text
   → No: Continue

3. LLM compression (preserve core, remove fluff)
   → Reduce remaining delta

4. Check again
   → Success: Return
   → Failure: Return with failure report
```

### Expansion Workflow

```
1. Detect expansion slots
   → Find positions after experience/motivation/skill mentions

2. Extract details from evidence
   → Prefer quantitative, specific content

3. Insert details naturally
   → "특히 [detail]." pattern

4. Check if sufficient
   → Yes: Return expanded text
   → No: LLM expansion as fallback
```

### Failure Analysis

When MAX_ITERATIONS exhausted without success:

```python
def analyze_failure(original, final, final_length):
    if final_length < TARGET_MIN:
        deficit = TARGET_MIN - final_length
        return f"Deficit: {deficit} chars. Insufficient evidence or expansion slots."

    elif final_length > TARGET_MAX:
        excess = final_length - TARGET_MAX
        return f"Excess: {excess} chars. Compressible content exhausted."
```

## Testing Strategy

### Unit Tests (test_patches.py)

```python
class TestLengthController(unittest.TestCase):
    def test_calc_delta(self):
        # Too short: positive delta
        assert ctrl._calc_delta(800) > 0

        # Too long: negative delta
        assert ctrl._calc_delta(1100) < 0

        # In range: zero delta
        assert ctrl._calc_delta(970) == 0

    def test_compression_patterns(self):
        text = "매우 정말 굉장히 좋은 경험이었습니다."
        compressed, _ = ctrl._compress_text(text, 20)

        # Modifiers should be removed
        assert len(compressed) < len(text)
```
