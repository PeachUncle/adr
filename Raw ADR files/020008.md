# ADR-004: Scope Reduction - Remove Search, Badges, and Delete Features

## Status

Accepted

## Context

The initial design included channel search, unread badges, and message deletion features. However, these add significant complexity and are not core to the MVP goal of rebuilding the UI with Shadcn components.

## Decision

We will remove the following features from scope:

1. Channel search functionality
2. Unread message badges
3. Message deletion (including admin/owner permissions)

## Rationale

### Channel Search - REMOVED

**Why Remove:**

- Adds state management complexity (search query, filtered results)
- Requires debouncing for performance
- Need to handle empty search states
- Not critical for MVP with small channel counts

**Impact:**

- Users must scroll through channel list
- Acceptable for small-to-medium channel counts (<50)

### Unread Badges - REMOVED

**Why Remove:**

- Requires tracking read/unread state per user per channel
- Need database schema changes (last_read_at timestamps)
- Complex logic for marking channels as read
- Real-time updates for badge counts across all users

**Impact:**

- Users can't see which channels have new messages
- Must check channels manually
- Common pattern in simple chat apps

### Message Deletion - REMOVED

**Why Remove:**

- Complex permission logic (owner vs admin vs regular user)
- UI state management (show/hide delete buttons)
- Confirmation dialogs and error handling
- Jest tests would need significant updates
- Channel #1 protection logic

**Impact:**

- Users cannot delete their messages
- Admins cannot moderate content via UI
- Simpler, cleaner message display

## Scope Boundaries

### IN SCOPE (MVP)

✅ Mobile-first responsive layout  
✅ Channel list navigation  
✅ Real-time message display  
✅ Message sending with keyboard shortcuts  
✅ Channel creation (existing prompt flow)  
✅ User authentication and logout  
✅ Empty channel states  
✅ Toast error notifications

### OUT OF SCOPE (Future Phases)

❌ Channel search and filtering  
❌ Unread message indicators  
❌ Message deletion and moderation  
❌ File uploads and attachments  
❌ @mentions and notifications  
❌ Emoji reactions  
❌ Message threading

## Implementation Impact

### Simplified Components

```jsx
// ChannelListHeader - No search input
<div className="p-4 border-b">
  <h2 className="text-lg font-semibold">Channels</h2>
  <Button onClick={onNewChannel}>
    <Plus className="h-4 w-4" />
  </Button>
</div>

// ChannelButton - No unread badge
<button className={cn("...", isActive && "bg-accent")}>
  <Hash className="h-4 w-4" />
  <span>{channel.slug}</span>
</button>

// MessageItem - No delete button
<div className="space-y-1">
  <div className="flex items-baseline gap-2">
    <span>{author}</span>
    <span>{timestamp}</span>
  </div>
  <p>{message.content}</p>
</div>
```

### Reduced Testing Surface

- No search functionality tests
- No unread badge state tests
- Skip message deletion tests in Jest suite
- Focus on core message display and sending

## Consequences

### Positive

- **Faster Development**: ~40% reduction in implementation time
- **Simpler Architecture**: Fewer state management concerns
- **Easier Testing**: Reduced test surface area
- **Lower Bug Risk**: Fewer features = fewer potential issues
- **Cleaner UI**: Less visual clutter, focus on core functionality

### Negative

- **Reduced Functionality**: Users lose some convenience features
- **Manual Channel Discovery**: No search means scrolling through lists
- **No Moderation Tools**: Admins can't delete inappropriate messages
- **Less Polish**: Feels less feature-complete than original

### Mitigation Strategies

- **Channel Organization**: Keep channel list sorted alphabetically
- **Clear Naming**: Encourage descriptive channel names
- **Future Roadmap**: Document removed features for Phase 2
- **User Feedback**: Gather feedback on missing features post-launch

## Future Considerations

### Phase 2 Candidates

1. **Channel Search**: Add search input with debounced filtering
2. **Unread Badges**: Implement read state tracking
3. **Message Actions**: Add delete, edit, react functionality
4. **Advanced Features**: File uploads, @mentions, threading

### Technical Debt

- Component architecture supports adding these features later
- Database schema may need updates for unread tracking
- Permission system already exists for future moderation features
