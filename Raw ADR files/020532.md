# ADR-001: Progressive Web App Over Native Mobile App

## Status
**Accepted** (2025-12-23)

## Context
Need to deliver mobile interface for testing FPP controllers. Two main approaches:
1. **Native apps** (iOS Swift + Android Kotlin/Java)
2. **Progressive Web App** (HTML/CSS/JS)

Key considerations:
- Single developer
- Cross-platform support (iOS + Android)
- Fast development timeline (MVP in 1 week)
- Local network access requirements
- No app store distribution needed

## Decision
**Build as a Progressive Web App (PWA)**

## Consequences

### Positive
- **Cross-platform**: Single codebase works on iOS and Android
- **No app store**: Avoid App Store/Play Store review delays and fees
- **Fast development**: Leverage web skills, no native SDK learning curve
- **Easy deployment**: Static file hosting (GitHub Pages, local file)
- **Instant updates**: No app store approval for bug fixes
- **Lower barrier**: Users install via browser "Add to Home Screen"
- **Offline-first**: Service workers provide offline prop list

### Negative
- **Limited hardware access**: Can't use BLE, NFC, or advanced sensors (not needed for this use case)
- **iOS install friction**: "Add to Home Screen" less discoverable than App Store
- **Performance**: Slightly slower than native (acceptable for UI-heavy app)
- **Push notifications**: Limited (not required for this app)

### Risks & Mitigations
| Risk | Mitigation |
|------|------------|
| iOS Safari PWA limitations | Test early on iOS, use progressive enhancement |
| Network API restrictions | HTTP fetch works fine for local network access |
| Storage quotas (IndexedDB) | Monitor storage usage, implement cleanup if > 80% |

## Alternatives Considered

### Alternative 1: Native iOS App (Swift)
**Pros:**
- Best iOS performance and UX
- Full hardware access
- App Store discoverability

**Cons:**
- iOS only (excludes Android users)
- Requires macOS + Xcode for development
- App Store review delays (3-7 days)
- Swift learning curve
- Distribution complexity

**Why rejected:** Single platform, high development overhead, unnecessary for local network HTTP calls.

### Alternative 2: Native Android App (Kotlin)
**Pros:**
- Best Android performance
- Google Play discoverability
- Full hardware access

**Cons:**
- Android only (excludes iOS users)
- Play Store review
- Kotlin learning curve
- Need separate iOS version

**Why rejected:** Same as iOS - unnecessary complexity for HTTP-based app.

### Alternative 3: React Native
**Pros:**
- Cross-platform with single codebase
- Large ecosystem
- Native-like performance

**Cons:**
- Heavier than PWA (bundle size, dependencies)
- Still requires native SDKs and simulators
- More complex build/deployment
- App store distribution still required

**Why rejected:** Adds complexity without delivering value over PWA for this use case.

### Alternative 4: Flutter
**Pros:**
- Cross-platform
- Good performance
- Single Dart codebase

**Cons:**
- New language (Dart)
- Larger bundle size than PWA
- App store distribution
- More complex than web

**Why rejected:** Learning curve and distribution complexity outweigh benefits.
