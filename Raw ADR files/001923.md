# Kong as API Gateway

* Status: accepted
* Date: 2025/03/03

## Context and Problem Statement

We need to decide whether to use Kong as an API Gateway for our project. Kong is a popular open-source API gateway that provides features such as authentication, rate limiting, and logging.

## Decision Drivers

* Client requirements

## Considered Options

* Kong

## Decision Outcome

Chosen option: Kong. We use Kong as an API Gateway because it provides the features required by the client.

### Positive Consequences

* Simplifies the implementation of authentication and authorization
* Provides rate limiting and logging capabilities

### Negative Consequences

* Requires additional configuration and setup
* Introduces a dependency on Kong for API gateway functionality
* May require additional monitoring and maintenance efforts

## Annex I: Manual for Setting Up and Using the Kong API Gateway

### 1. Setup Kong 
In the `./kong` directory, execute:    

```sh
make all
```

This command generates two containers (one for Kong and one for your database) and configures a service along with the Kong paths. In addition, it activates the following plugins:  
- `auth-key`  
- `AC`  
- `logs`  

### 2. Configure consumers  

#### a. Create consumer  
Execute the following request:

```sh
curl -i -X POST http://localhost:8001/consumers/ \
  --data "username=user1"
```

#### b. Create authentication key (API Key) for the consumer
Execute the following request:

```sh
curl -i -X POST http://localhost:8001/consumers/user1/key-auth
```

Expected response: 

```json
{
  "key": "abcd1234abcd1234"
}
```

#### c. Assign consumer to a group
Execute the following request:  

```sh
curl -i -X POST http://localhost:8001/consumers/user1/acls \
  --data "group=users"
```

### 3. Make requests  

Once the consumer has an API Key, it can make requests to the routes defined in Kong, as long as it belongs to the appropriate group (in this case, `users`).   

To make a request, the API Key must be included in the `apikey` header.    

Example of a `GET` request using `curl`:  

```sh
curl -i -X GET http://localhost:8003/api/v1/questions/ \
  -H "apikey: abcd1234abcd1234"
```

> **Note:** The `apikey` header contains the generated key for the consumer `user1`.  

If the consumer does not belong to the authorized group (`users` in this case), Kong will return an authorization error.
