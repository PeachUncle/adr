# TASK-014: Tests and ops for self-hosted LLM path
> Source: tasks/tasks.md

## Context
- Create comprehensive unit tests for OllamaClient, IntentService, and ChatOrchestrator
- Implement API tests for /classify and /chat endpoints with error scenarios
- Add observability with JSON logs, metrics counters, and latency tracking
- Document self-hosted LLM setup process for new developers

## Options Considered
- **Option A**: Mock all external dependencies (Pros: Fast tests, no external requirements; Cons: May not catch integration issues)
- **Option B**: Use real Ollama for some tests (Pros: More realistic; Cons: Slower, requires Ollama running)
- **Option C**: Hybrid approach with mocks for unit tests and real services for integration tests (Pros: Best of both worlds; Cons: More complex test setup)

## Decision
- **Chosen approach**: Option A - Mock all external dependencies for unit tests
- **Rationale**: Ensures tests run without external dependencies, are fast, and focus on testing business logic rather than external service integration

## Impacts
- **Performance**: Unit tests run in milliseconds without external dependencies
- **Complexity**: Moderate - Comprehensive mocking setup but clear test structure
- **Security/Privacy**: Improved - All tests run locally without external API calls
- **Compatibility**: High - Tests work in any environment without setup requirements
- **Risks & Mitigations**: 
  - Risk: Tests may not catch integration issues; Mitigation: Separate integration tests with real services
  - Risk: Mock complexity grows; Mitigation: Use factory patterns and shared fixtures
