# ✅ Decision Revised: Draft Mode for Public v1.0.0

**Date:** 2025-12-20  
**Status:** User feedback led to better decision

---

## 🎯 What Happened

### Initial Decision (REVISED)
- Keep strict exact version matching for v1.0.0
- Simple, ship what we have
- Iterate based on feedback

### User's Critical Feedback
> "I don't want to have to explain: 'oh yeah ... this is called v1.0.0 ... but actually there are tons of limitations and we consider fixes only if people complain'. I'd like external v1.0.0 to be a well rounded release with close to zero known issues."

### Why User Is RIGHT ✅

**I missed the key distinction:**
- **Internal v1.0.0** (M9) = Testing baseline, NOT PUBLIC
- **Public v1.0.0** (M10) = First impression to users!
- These are NOT the same thing!

**Public v1.0.0 implications:**
- First impression sets the tone
- Can't have known limitations
- "v1.0.0" means polished, not "basic but works"
- Hard to walk back ("why didn't you include this?")

---

## ✅ Revised Decision

### For Public v1.0.0: Implement Draft Mode

**Why:**
1. **First impressions matter** - Public v1.0.0 is our debut
2. **Known pain point** - We're aware of DX friction, why not fix it?
3. **User expectation** - "v1.0.0" should feel complete
4. **Competitive** - npm/cargo have this, users expect it
5. **Timeline acceptable** - +1-2 days worth better launch

**What It Adds:**
```yaml
metadata:
  mode: draft  # "draft" or "release", defaults to "release"

dependencies:
  - package: prompt-gen.common
    version: "^1.0.0"  # ✅ OK in draft, ❌ ERROR in release
```

## 💡 Key Insights

### 1. Internal ≠ Public Versioning

From VERSIONING_FINAL_STRATEGY.md:
- Internal v1.0.0 = Testing baseline (M9)
- Internal v1.1.0 = Full feature set
- **Public v1.0.0 = First public release (M10)**

Internal v1.0.0 can have limitations (it's for testing).  
Public v1.0.0 cannot (it's our debut).

### 2. "v1.0.0" Means Different Things

**Internally:** "Core features working, blockers fixed"  
**Publicly:** "Polished, complete, production-ready"

We need to deliver the **public** meaning, not the **internal** one!

### 3. Proactive > Reactive

**Reactive approach:**
- Ship strict-only
- Wait for complaints
- Add draft mode in v1.1.0
- **Result:** "Why didn't you include this in v1.0.0?"

**Proactive approach:**
- Implement draft mode before launch
- Address known limitation proactively
- Ship polished v1.0.0
- **Result:** "Wow, v1.0.0 is complete!"

### 4. Timeline Impact is Acceptable

**+1-2 days to M9 completion:**
- M10 is weeks 3-4 (plenty of time)
- Better to ship polished than fast
- First impression matters more than speed
