# ADR-005: Observability Strategy for Safe AI Platforms

**Status**: Accepted
**Date**: December 2024
**Author**: Vincent
**Implementation**: [MonitorX](https://github.com/BugVanquisher/MonitorX) + integrations with Atlas, Hyperion, Sentinel

---

## Context

Operating a GenAI platform requires answering questions that traditional APM can't:

**Traditional APM Questions**:
- Is the service up?
- What's the latency?
- Are there errors?

**AI Platform Questions**:
- Is the model safe? (safety block rate, false positive rate)
- Is the model drifting? (output quality over time)
- Are we under attack? (adversarial pattern detection)
- What's the actual cost? (token-level accounting)
- Which tier is catching what? (tiered defense effectiveness)

### Requirements

From operating Gmail Shield and Provisioned Throughput:

1. **Real-time**: Know about attacks within seconds
2. **Multi-dimensional**: Safety + Performance + Cost metrics
3. **Actionable**: Alerts that tell you what to do
4. **Historical**: Trend analysis for capacity planning
5. **Correlated**: Connect user complaints to system metrics

## Implementation in MonitorX

### Unified Metrics Collector

```python
# monitorx/collector/unified.py

class UnifiedMetricsCollector:
    """
    Collect and correlate metrics from all Aether components.

    Design Decision: Correlation by request_id
    - Each request gets unique ID at Atlas
    - ID propagated through Sentinel → Hyperion → back
    - Enables end-to-end tracing

    Storage: InfluxDB for time-series
    - Safety metrics: 30-day retention
    - Performance metrics: 7-day high-res, 90-day aggregated
    - Cost metrics: 365-day retention (billing)
    """

    def __init__(self, influx_client):
        self.influx = influx_client

    async def collect_inference_metric(
        self,
        model_id: str,
        request_id: str,
        latency_ms: float,
        tokens: int,
        safety_verdict: str,
        safety_tier: int,
        batch_size: int,
        cached: bool,
        tags: dict = None
    ):
        """
        Record unified metric for single inference.
        """
        point = Point("inference") \
            .tag("model", model_id) \
            .tag("safety_verdict", safety_verdict) \
            .tag("safety_tier", str(safety_tier)) \
            .tag("cached", str(cached)) \
            .field("latency_ms", latency_ms) \
            .field("tokens", tokens) \
            .field("batch_size", batch_size) \
            .field("request_id", request_id) \
            .time(datetime.utcnow())

        if tags:
            for k, v in tags.items():
                point = point.tag(k, str(v))

        await self.influx.write(point)

        # Check thresholds and alert
        await self._check_thresholds(model_id, latency_ms, safety_verdict)

    async def _check_thresholds(self, model_id, latency_ms, safety_verdict):
        """
        Check against model-specific thresholds.
        """
        config = await self.get_model_config(model_id)

        if latency_ms > config.thresholds.latency:
            await self.alert_service.send(
                level="warning",
                message=f"High latency for {model_id}: {latency_ms}ms",
                model=model_id,
                metric="latency"
            )

        # Anomaly detection for safety
        if safety_verdict == "block":
            recent_block_rate = await self._get_recent_block_rate(model_id)
            baseline_block_rate = await self._get_baseline_block_rate(model_id)

            if recent_block_rate > baseline_block_rate * 2:
                await self.alert_service.send(
                    level="critical",
                    message=f"Anomalous block rate for {model_id}: {recent_block_rate:.1%} vs baseline {baseline_block_rate:.1%}",
                    model=model_id,
                    metric="safety_block_rate"
                )
```

### ML-Aware Alerting

```python
# monitorx/alerting/ml_alerts.py

class MLAwareAlertService:
    """
    Alerting with ML-specific context and intelligence.

    Key Differences from Standard Alerting:
    1. Model-specific thresholds (different models have different norms)
    2. Trend detection (gradual drift vs. sudden spike)
    3. Correlated alerts (latency spike + safety spike = attack?)
    4. Cooldown periods (avoid alert fatigue during known events)
    """

    def __init__(self):
        self.channels = []
        self.alert_history = AlertHistory()
        self.cooldown_manager = CooldownManager()

    async def evaluate_and_alert(self, metric_name: str, value: float, context: dict):
        """
        Evaluate metric against intelligent thresholds.
        """
        model_id = context.get("model_id")

        # Get adaptive threshold
        threshold = await self._get_adaptive_threshold(model_id, metric_name)

        if value <= threshold.ok:
            return  # All good

        # Determine severity
        if value > threshold.critical:
            severity = "critical"
        elif value > threshold.warning:
            severity = "warning"
        else:
            return

        # Check for correlated alerts
        correlated = await self._find_correlated_alerts(model_id, metric_name)

        # Build alert
        alert = Alert(
            severity=severity,
            metric=metric_name,
            value=value,
            threshold=threshold,
            model_id=model_id,
            correlated_alerts=correlated,
            suggested_actions=self._suggest_actions(metric_name, severity, correlated)
        )

        # Check cooldown
        if await self.cooldown_manager.should_suppress(alert):
            return

        # Send to channels
        await self._dispatch_alert(alert)

    async def _get_adaptive_threshold(self, model_id: str, metric_name: str) -> Threshold:
        """
        Get threshold that adapts to model's baseline.

        Example: If model normally has 5% block rate,
        alert at 10% (2x baseline), not fixed 20%.
        """
        baseline = await self._get_baseline(model_id, metric_name, days=7)
        stddev = await self._get_stddev(model_id, metric_name, days=7)

        return Threshold(
            ok=baseline + stddev,
            warning=baseline + 2 * stddev,
            critical=baseline + 3 * stddev
        )

    def _suggest_actions(self, metric_name: str, severity: str, correlated: List) -> List[str]:
        """
        Suggest concrete actions based on alert context.
        """
        actions = []

        if metric_name == "safety_block_rate":
            if severity == "critical":
                actions.append("Check for coordinated attack in Sentinel logs")
                actions.append("Review recent pattern additions")
            if any(a.metric == "latency" for a in correlated):
                actions.append("Block rate + latency spike = possible DoS attack")

        elif metric_name == "latency_p95":
            actions.append("Check GPU utilization in Hyperion")
            actions.append("Review batch queue depth")
            if severity == "critical":
                actions.append("Consider scaling Hyperion replicas")

        elif metric_name == "quota_utilization":
            actions.append("Notify customer of approaching limit")
            actions.append("Review for unusual usage patterns")

        return actions
```

### Dashboard: Safety Operations Center

```python
# monitorx/dashboard/safety_ops.py

"""
Streamlit dashboard for safety operations.

Key Views:
1. Real-time attack detection
2. Tiered defense effectiveness
3. False positive tracking
4. Historical trends
"""

import streamlit as st

def safety_operations_dashboard():
    st.title("🛡️ Safety Operations Center")

    # Real-time metrics
    col1, col2, col3, col4 = st.columns(4)

    with col1:
        block_rate = get_current_block_rate()
        baseline = get_baseline_block_rate()
        delta = (block_rate - baseline) / baseline * 100
        st.metric("Block Rate", f"{block_rate:.1%}", f"{delta:+.1f}%")

    with col2:
        fp_rate = get_false_positive_rate()
        st.metric("False Positive Rate", f"{fp_rate:.2%}")

    with col3:
        tier1_pct = get_tier_distribution()[1]
        st.metric("Tier 1 Catch Rate", f"{tier1_pct:.0%}")

    with col4:
        mttr = get_mean_time_to_respond()
        st.metric("Mean Time to Mitigate", f"{mttr:.0f} min")

    # Attack timeline
    st.subheader("Attack Timeline")
    attack_data = get_attack_timeline(hours=24)
    st.line_chart(attack_data)

    # Active alerts
    st.subheader("Active Alerts")
    alerts = get_active_alerts()
    for alert in alerts:
        with st.expander(f"🚨 {alert.severity.upper()}: {alert.message}"):
            st.write(f"**Model**: {alert.model_id}")
            st.write(f"**Metric**: {alert.metric} = {alert.value}")
            st.write(f"**Threshold**: {alert.threshold}")
            st.write("**Suggested Actions**:")
            for action in alert.suggested_actions:
                st.write(f"- {action}")
            if st.button("Resolve", key=alert.id):
                resolve_alert(alert.id)

    # Pattern effectiveness
    st.subheader("Pattern Effectiveness")
    patterns = get_pattern_stats()
    st.dataframe(patterns[["pattern", "catches_24h", "false_positives", "effectiveness"]])
```

## Consequences

### Benefits

1. **Visibility**: Complete view across safety, performance, cost
2. **Actionability**: Alerts include suggested actions
3. **Correlation**: Connect symptoms across components
4. **Adaptive**: Thresholds adjust to each model's baseline

### Trade-offs

1. **Complexity**: Multiple metric types, storage backends
   - Mitigation: Unified collector abstracts complexity
   - Benefit: Right storage for right data (time-series vs. logs)

2. **Storage Cost**: High-cardinality metrics are expensive
   - Mitigation: Aggregation, retention policies
   - Benefit: Detailed data when needed for investigation

3. **Alert Fatigue**: ML systems are noisy
   - Mitigation: Adaptive thresholds, cooldowns, correlation
   - Benefit: Alerts that matter, not noise

## Alternatives Considered

### 1. Standard APM Only (Datadog, New Relic)

**Rejected because**:
- No ML-specific metrics (safety, drift)
- No adaptive thresholds
- Expensive at scale

### 2. Logs-Only Observability

**Rejected because**:
- No real-time aggregation
- Hard to trend over time
- Expensive to query at scale

### 3. Per-Component Observability

**Rejected because**:
- No correlation across components
- Duplicate dashboards
- Inconsistent alerting
