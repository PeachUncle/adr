# ADR-006: Component Architecture - Atomic Design with Clear Separation

## Status

Accepted

## Context

The existing chat UI has a monolithic Layout component that handles sidebar, channels, messages, and user info. We need a more modular architecture that separates concerns, improves testability, and makes components reusable.

## Decision

We will implement an atomic design approach with clear component boundaries and single responsibilities.

## Component Hierarchy

```
ChatLayout (Organism)
├── ChannelSidebar (Molecule)
│   ├── ChannelListHeader (Molecule)
│   ├── ChannelList (Molecule)
│   │   └── ChannelButton (Atom)
│   └── UserFooter (Molecule)
├── MobileSheet (Molecule)
│   └── [Same content as ChannelSidebar]
└── MainChatArea (Molecule)
    ├── ChannelHeader (Molecule)
    ├── MessageList (Molecule)
    │   ├── MessageItem (Atom)
    │   └── EmptyChannelState (Atom)
    └── MessageInput (Molecule)
```

## Design Principles

### Single Responsibility

Each component has one clear purpose:

- **ChatLayout**: Responsive layout and state management
- **ChannelList**: Display and navigate channels
- **MessageList**: Display messages with auto-scroll
- **MessageInput**: Compose and send messages

### Props Down, Events Up

- Parent components pass data down via props
- Child components communicate up via callback props
- No direct component-to-component communication

### Composition Over Inheritance

- Small, focused components that compose together
- Reusable atoms (ChannelButton, MessageItem)
- Flexible molecules (ChannelList, MessageList)

## Component Specifications

### Atoms (Single Purpose, No Dependencies)

#### ChannelButton

```typescript
interface ChannelButtonProps {
  channel: Channel;
  isActive: boolean;
  onSelect: () => void;
}
```

- Renders single channel with Hash icon
- Handles active state styling
- No business logic, pure presentation

#### MessageItem

```typescript
interface MessageItemProps {
  message: Message;
}
```

- Displays author, timestamp, content
- No actions or state management
- Pure presentation component

#### EmptyChannelState

```typescript
interface EmptyChannelStateProps {
  channelName: string;
}
```

- Welcome message for empty channels
- Static content, no interactions

### Molecules (Composed Functionality)

#### ChannelList

```typescript
interface ChannelListProps {
  channels: Channel[];
  activeChannelId: number;
  onChannelSelect: (channelId: number) => void;
}
```

- Manages list of ChannelButton components
- Handles ScrollArea for overflow
- Determines active state for each button

#### MessageList

```typescript
interface MessageListProps {
  messages: Message[];
  channelName: string;
}
```

- Manages list of MessageItem components
- Handles auto-scroll behavior
- Shows EmptyChannelState when needed

#### MessageInput

```typescript
interface MessageInputProps {
  onSubmit: (message: string) => Promise<void>;
}
```

- Manages input state and validation
- Handles keyboard shortcuts
- Manages loading and error states

### Organisms (Complete Features)

#### ChatLayout

```typescript
interface ChatLayoutProps {
  channels: Channel[];
  activeChannelId: number;
  user: User;
  onLogout: () => void;
  onNewChannel: () => void;
  children: React.ReactNode;
}
```

- Manages responsive layout (desktop sidebar vs mobile Sheet)
- Coordinates between sidebar and main content
- Handles Sheet open/close state

## Data Flow Architecture

### Top-Down Data Flow

```
ChannelsPage (useStore hook)
├── channels: Channel[]
├── messages: Message[]
├── user: User
└── activeChannelId: number

↓ Props

ChatLayout
├── channels → ChannelList → ChannelButton
├── user → UserFooter
└── activeChannelId → ChannelList (for active state)

MainChatArea
├── messages → MessageList → MessageItem
└── onSubmit → MessageInput
```

### Event Flow (Bottom-Up)

```
ChannelButton.onSelect()
→ ChannelList.onChannelSelect()
→ ChatLayout.handleChannelSelect()
→ router.push() + setSheetOpen(false)

MessageInput.onSubmit()
→ ChannelsPage.addMessage()
→ Supabase API call
→ Real-time subscription updates messages
```

```

│   ├── ChannelButton.js
│   ├── MessageItem.js
│   └── EmptyChannelState.js
├── molecules/

└── organisms/

```

## Consequences

### Positive

- **Testability**: Small components are easier to test in isolation
- **Reusability**: Atoms can be reused in different contexts
- **Maintainability**: Clear boundaries make changes predictable
- **Debugging**: Easier to isolate issues to specific components
- **Performance**: Can optimize individual components independently

### Negative

- **More Files**: 10 components vs 1 monolithic Layout
- **Props Drilling**: Some data passes through multiple levels
- **Complexity**: More moving parts to coordinate

### Mitigation

- **Clear Naming**: Component names indicate their purpose
- **TypeScript**: Interfaces document expected props
- **Documentation**: Each component has clear responsibility
- **Testing**: Unit tests for atoms, integration tests for molecules (see [ADR-014: Testing Strategy](./adr-014-testing-strategy.md))

## Alternative Considered: Flat Structure

We considered putting all components in `components/chat/` without subdirectories, but the atomic organization makes the architecture clearer and helps developers understand component relationships.
