# Design: Fuse Projection and Quantization Operations

## Context
The current implementation performs projection and quantization as separate operations, creating an intermediate `rotated_vectors` Matrix that consumes significant memory and requires an additional memory pass. Investigation reveals this intermediate can be eliminated while maintaining code clarity and testability.

## Goals / Non-Goals

### Goals
- Eliminate intermediate `rotated_vectors` Matrix (save 33-50% memory)
- Maintain isolated, testable helper functions
- Preserve SIMD optimizations
- Keep centroid for query processing
- No performance regression
- Single-pass projection + quantization

### Non-Goals
- Not changing the mathematical correctness
- Not making functions less testable
- Not removing modularity
- Not optimizing beyond fusion (separate effort)

## Decisions

### Decision 1: Fused projectAndQuantize Function

**Current (Unfused) Flow:**
```
Step 1: Project (O(N*D*d))
  For each vector v (D dimensions):
    For each output dim j:
      rotated[j] = dot(P[:,j], v)    // Store in Matrix
  
Step 2: Quantize (O(N*d))
  For each vector rotated (d dimensions):
    For each dim j:
      hypercube[j] = rotated[j] >= 0 ? +scale : -scale
    corrective_2 = dot(rotated, hypercube)
```
**Memory**: N×D (input) + N×d (rotated) + N×d (hypercube) = N×(D+2d)

**New (Fused) Flow:**
```
Step: Project + Quantize (O(N*D*d))
  For each vector v (D dimensions):
    For each output dim j:
      proj_val = dot(P[:,j], v)           // Compute but don't store
      hypercube[j] = proj_val >= 0 ? +scale : -scale
      corrective_2 += proj_val * hypercube[j]
```
**Memory**: N×D (input) + N×d (hypercube) = N×(D+d)

**Savings**: N×d Matrix eliminated (33% for d=64, D=128)

### Algorithm: Fused projectAndQuantize

```zig
fn projectAndQuantize(
    normalized_vectors: Matrix,    // N × D (unit norm)
    projection: Matrix,            // D × d (orthogonal)
    allocator: Allocator,
) !struct { hypercube: Matrix, corrective_2: []f32 } {
    const N = normalized_vectors.rows;
    const D = normalized_vectors.cols;
    const d = projection.cols;
    
    // Allocate outputs
    var hypercube = try Matrix.init(allocator, N, d);
    var corrective_2 = try allocator.alloc(f32, N);
    
    const scale = 1.0 / @sqrt(@as(f32, @floatFromInt(d)));
    
    // Process each vector
    for (0..N) |i| {
        const v = getRow(normalized_vectors, i);
        const h = getRow(hypercube, i);
        
        corrective_2[i] = 0.0;
        
        // For each output dimension
        for (0..d) |j| {
            // Project: compute dot(P[:,j], v)
            var proj_val: f32 = 0.0;
            
            // SIMD-optimized dot product
            if (isPowerOfTwo(D) and D >= 8) {
                proj_val = simdDotProduct(P[:,j], v);
            } else {
                for (0..D) |k| {
                    proj_val += projection.get(k, j) * v[k];
                }
            }
            
            // Quantize: binarize and map to hypercube
            h[j] = if (proj_val >= 0.0) scale else -scale;
            
            // Accumulate corrective factor
            corrective_2[i] += proj_val * h[j];
        }
    }
    
    return .{ .hypercube = hypercube, .corrective_2 = corrective_2 };
}
```

**Complexity**: O(N*D*d) - same as unfused, but:
- Fewer memory allocations
- Better cache locality (process each vector completely before next)
- Eliminate intermediate matrix read/write

### Decision 2: Simplified PreprocessedData

**Current:**
```zig
pub const PreprocessedData = struct {
    rotated_vectors: Matrix,     // N × d - REMOVED
    corrective_factors: []f32,   // N values - KEPT
    centroid: []f32,             // D dimensions - KEPT
    allocator: Allocator,
};
```

**New:**
```zig
pub const PreprocessedData = struct {
    corrective_factors: []f32,   // N values (||v-centroid||)
    centroid: []f32,             // D dimensions (for queries)
    allocator: Allocator,
    
    pub fn deinit(self: *PreprocessedData) void {
        self.allocator.free(self.corrective_factors);
        self.allocator.free(self.centroid);
    }
};
```

**Rationale:**
- Centroid needed for query vector preprocessing
- corrective_factors needed for distance computation
- rotated_vectors only intermediate, never reused

### Decision 4: Maintain Function Isolation

Keep these functions unchanged and independently testable:
- `binarizeAndMapToHypercube()` - for testing quantization logic
- `dotProduct()` - for testing SIMD correctness
- `computeCentroid()` - for testing mean computation
- `meanCenterAndNormalize()` - for testing normalization

New testable function:
- `projectAndQuantize()` - fusion can be tested independently

### SIMD Optimization Strategy

Fused function maintains SIMD in critical paths:

1. **Projection Dot Product** (bottleneck):
```zig
// Power-of-2 input dimensions >= 8
const VecSize = 8;
const Vec = @Vector(VecSize, f32);
var vec_sum = @as(Vec, @splat(0.0));

for (0..D by VecSize) |k| {
    const p_vec: Vec = getProjectionColumn(projection, j, k);
    const v_vec: Vec = v[k..][0..VecSize].*;
    vec_sum += p_vec * v_vec;
}

proj_val = @reduce(.Add, vec_sum);
```

2. **Quantization** (already optimized):
- Uses comparison and select (stays the same)

3. **Accumulation** (scalar - not bottleneck):
- `corrective_2 += proj_val * h[j]` is simple scalar

## Memory Layout Comparison

### Before Fusion (Per Vector):
```
Input:     [f32; D]          Original normalized vector
Rotated:   [f32; d]          Projected (intermediate) ← ELIMINATED
Hypercube: [f32; d]          Quantized final
Corrective1: f32             Norm before projection
Corrective2: f32             Dot product
Centroid:  [f32; D]          Shared across all
```
**Total per vector**: D + d + d + 1 + 1 = D + 2d + 2 floats

### After Fusion (Per Vector):
```
Input:     [f32; D]          Original normalized vector
Hypercube: [f32; d]          Quantized final
Corrective1: f32             Norm before projection
Corrective2: f32             Dot product
Centroid:  [f32; D]          Shared across all
```
**Total per vector**: D + d + 1 + 1 = D + d + 2 floats

**Savings**: d floats per vector = 4d bytes
- For d=64: 256 bytes per vector
- For d=128: 512 bytes per vector
- For SIFT-1M: 512 MB savings total

## Risks / Trade-offs

### Risk: Slightly More Complex Fusion Code
- **Mitigation**: Well-documented, tested independently
- **Impact**: Low - algorithm is straightforward

### Trade-off: Cannot Inspect rotated_vectors
- **Context**: Needed for debugging/visualization?
- **Decision**: User confirmed not needed
- **Impact**: None

### Risk: Harder to Debug
- **Mitigation**: Keep unfused helpers for testing
- **Mitigation**: Comprehensive unit tests
- **Impact**: Low

### Trade-off: API Breaking Change
- **Impact**: quantizeVectors signature changes
- **Mitigation**: Update all call sites (only internal)
- **Justification**: Better API design
