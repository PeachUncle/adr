# ADR-0003: List Sheets CLI Behavior

- Status: Accepted
- Date: 2025-12-08

## Context

We have a tested internal loader (`odsview.container` + `odsview.workbook`)
that can open a plain `.ods` file and enumerate sheet names via
`Workbook.sheets`. However, the CLI currently exposes only help/usage
behavior and does not yet provide any user-visible viewing capability.

We want a minimal, well-specified first feature that:

- Demonstrates end-to-end value to users.
- Exercises the loader in a realistic way.
- Fits the "read-only, SSH-friendly" scope of the project.

Listing sheet names for a given `.ods` file is a natural first behavior:
small surface area, clearly testable, and orthogonal to decisions about
row/column rendering, truncation, and search.

## Decision

Introduce a `--list-sheets` flag to the `odsview` CLI with the following
behavior:

- Invocation form: `odsview --list-sheets FILE.ods`.
- When `--list-sheets` is provided, a single positional `FILE` argument
  is **required**.
- The CLI loads the workbook via `load_workbook(FILE)` and prints each
  sheet name on its own line to `stdout` in order.
- On success, the process exits with code `0`.
- Errors (missing file, unreadable or invalid `.ods`, loader failure)
  result in:
  - A clear diagnostic message on `stderr`.
  - A non-zero exit code (`1` for runtime/IO errors, `2` for usage
    errors such as missing `FILE`).

This feature remains strictly **read-only** and does not change or write
any files.

## Rationale

- **Minimal yet useful**: Listing sheets is immediately helpful when
  exploring spreadsheets over SSH and requires no rendering/truncation
  policy decisions.
- **Incremental**: Reuses the existing `load_workbook` and
  `Workbook.sheets`, giving us end-to-end coverage without overcommitting
  to a full table-view contract.
- **Clear contracts**: The behavior, exit codes, and streams are easy to
  specify and test.
- **Alignment with scope**: This fits squarely within the "read-only
  terminal viewer" scope defined in ADR-0001.

## Consequences

- **CLI interface**:
  - The `odsview` CLI gains a `--list-sheets` flag.
  - The combination `--list-sheets` without a `FILE` positional is
    treated as a usage error (exit code `2`).
  - Other future viewing modes (e.g. table rendering) can be added as
    separate flags/options without changing this behavior.
- **Implementation**:
  - `odsview.cli` will call `load_workbook` and iterate
    `Workbook.sheets`, printing each name to `stdout`.
  - Errors from the loader (e.g. file not found, invalid container) will
    be caught and surfaced as `stderr` messages with exit code `1`.
- **Testing**:
  - New tests will invoke `python -m odsview.cli --list-sheets` against
    the existing fixture `tests/fixtures/simple.ods` and assert that:
    - Exit code is `0`.
    - `stdout` contains the expected sheet names.
  - Additional tests will cover error cases such as missing `FILE`.

Future work (table rendering, filtering, encryption handling) will be
captured in separate ADRs and must not change the semantics of
`--list-sheets` without an explicit superseding ADR.
