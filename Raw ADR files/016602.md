# ADR-002: Refactor Money Type for SQLite Compatibility

## Status

Accepted

## Context

After migrating from ETS to SQLite (ADR-001), we encountered serialization issues with the AshMoney.Types.Money type:

1. **Serialization Error**: `Money.Ecto.Map.Type.dump/1` is undefined when trying to save Money values to SQLite
2. **Type Incompatibility**: AshMoney expects specific Ecto types that aren't available with SQLite adapter
3. **Migration Blocker**: This prevents the application from storing any financial transactions
4. **Complex Type Storage**: SQLite doesn't natively support composite types like Money (amount + currency)

## Decision

We will refactor the Money type storage to use separate fields for amount and currency values:

- Store amount as `:decimal` type (e.g., `amount_value`)
- Store currency as `:atom` type with constraints (e.g., `amount_currency`)
- Maintain the same pattern for converted amounts

## Consequences

### Positive

- **SQLite Compatibility**: Decimal and atom types work natively with SQLite
- **Simpler Storage**: Each field maps directly to a database column
- **Easier Debugging**: Can inspect money values directly in database
- **Migration Simplicity**: Standard column types in migrations
- **Flexibility**: Can add currency-specific validations per field

### Negative

- **API Changes**: All code creating transactions must use new field names
- **Type Safety**: Lost the type safety of the Money struct at database level
- **Validation Complexity**: Need to ensure amount and currency are always set together
- **Display Logic**: Must reconstruct Money-like display formatting manually
- **Test Updates**: All tests need updating to use new field structure

### Neutral

- **Performance**: Minimal difference in query performance
- **Storage Size**: Similar storage requirements (two columns vs one composite)

## Implementation

### Before (with Money type):

```elixir
attribute :amount, AshMoney.Types.Money, allow_nil?: false
attribute :converted_amount, AshMoney.Types.Money

# Usage
Transaction.create(%{amount: Money.new(50.00, :EUR)})
```

### After (separate fields):

```elixir
attribute :amount_value, :decimal, allow_nil?: false
attribute :amount_currency, :atom, constraints: [one_of: [:EUR, :KRW]]
attribute :converted_amount_value, :decimal
attribute :converted_amount_currency, :atom, constraints: [one_of: [:EUR, :KRW]]

# Usage
Transaction.create(%{amount_value: Decimal.new("50.00"), amount_currency: :EUR})
```

### Migration Steps:

1. Update Transaction resource attributes
2. Modify create/update actions to handle separate fields
3. Update currency conversion logic
4. Create helper functions for Money-like operations
5. Update all tests and seeds
6. Add validation to ensure amount_value and amount_currency are set together

## Future Considerations

- When migrating to PostgreSQL, consider using composite types or JSON columns
- Could create a custom Ecto type that handles the serialization properly
- May want to add a virtual attribute that reconstructs Money struct for display
