# ADR 005: API Endpoint URL Structure

## Status

Accepted

## Context

When implementing the frontend-backend communication, we encountered an issue with the API endpoint URLs. The frontend was making requests to `/api/upload` and `/api/query`, but the backend was exposing these endpoints without the `/api` prefix, resulting in 404 errors.

We had two options to resolve this mismatch:
1. Modify the backend to add the `/api` prefix to all routes
2. Modify the frontend to remove the `/api` prefix from the URLs

## Decision

We've decided to modify the frontend to use the correct API endpoint URLs without the `/api` prefix. This approach was chosen because:

1. It was simpler to implement and required fewer changes
2. The backend routes were already established and working correctly
3. Changing the backend route structure might have required more extensive testing and validation

The specific changes made were:
- Updated `UploadPage.tsx` to use `http://localhost:8000/upload` instead of `http://localhost:8000/api/upload`
- Updated `AnalyticsPage.tsx` to use `http://localhost:8000/query` instead of `http://localhost:8000/api/query`

## Consequences

### Positive

- **Resolved 404 Errors**: The frontend can now successfully communicate with the backend API
- **Minimal Changes**: Only required changes to two frontend files
- **No Backend Restructuring**: Avoided potential issues with changing the backend API structure

### Negative

- **Inconsistent with API Best Practices**: Many APIs use an `/api` prefix to distinguish API endpoints from other routes
- **Potential Future Confusion**: Developers might expect the `/api` prefix as it's a common convention

## Implementation Details

The implementation involved:

1. Identifying all API endpoint URLs in the frontend code
2. Updating these URLs to match the actual backend routes
3. Testing to ensure proper communication between frontend and backend

## Notes

In the future, if we decide to standardize on using an `/api` prefix for all API endpoints, we should update both the frontend and backend code together to maintain consistency.
