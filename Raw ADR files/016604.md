# ADR-004: Fix Authentication Routes and LiveView Configuration

## Status

Accepted

## Context

After migrating to SQLite (ADR-001), the authentication routes were returning 404 errors and LiveView mount conflicts were occurring:

1. **Incorrect URLs**: The home page was using `/auth/user/register` instead of the correct `/register` path
2. **LiveView Mount Conflict**: `AshAuthentication.Phoenix.LiveSession` was conflicting with custom mount handlers
3. **Route Configuration**: The sign-in routes had incorrect `on_mount` configuration causing runtime errors

## Decision

We will fix the authentication configuration to use AshAuthentication's default patterns:

1. Update all authentication URLs to use the correct paths
2. Remove conflicting `on_mount` configurations from the router
3. Fix LiveUserAuth mount functions to avoid assign conflicts

## Implementation

### URL Corrections

```html
<!-- Before -->
<a href="/auth/user/register">Sign Up</a>
<a href="/auth/user/sign_in">Sign In</a>

<!-- After -->
<a href="/register">Sign Up</a>
<a href="/sign-in">Sign In</a>
```

### Router Configuration

```elixir
# Before - with conflicting on_mount
sign_in_route register_path: "/register",
              reset_path: "/reset",
              auth_routes_prefix: "/auth",
              on_mount: [{SharedLedgerWeb.LiveUserAuth, :live_no_user}],
              overrides: [...]

# After - removed on_mount to avoid conflicts
sign_in_route register_path: "/register",
              reset_path: "/reset",
              auth_routes_prefix: "/auth",
              overrides: [...]
```

### LiveUserAuth Fixes

```elixir
# Before - trying to assign current_user
def on_mount(:live_no_user, _params, _session, socket) do
  if socket.assigns[:current_user] do
    {:halt, Phoenix.LiveView.redirect(socket, to: ~p"/")}
  else
    {:cont, assign(socket, :current_user, nil)}
  end
end

# After - let AshAuthentication handle assigns
def on_mount(:live_no_user, _params, _session, socket) do
  if socket.assigns[:current_user] do
    {:halt, Phoenix.LiveView.redirect(socket, to: ~p"/")}
  else
    {:cont, socket}
  end
end
```

## Consequences

### Positive

- **Working Authentication**: Users can now access registration and sign-in pages
- **Correct Routes**: All authentication URLs are properly configured
- **No Mount Conflicts**: LiveView mount handlers work without conflicts
- **Framework Compliance**: Using AshAuthentication's intended patterns

### Negative

- **Breaking Change**: Any bookmarked authentication URLs will need updating
- **Less Custom Control**: Relying more on AshAuthentication defaults

### Neutral

- **Framework Dependency**: More tightly coupled to AshAuthentication's LiveView patterns
- **Documentation**: Need to update any documentation referencing old URLs

## Testing

Authentication flow was validated using MCP Tidewave:

- User registration works correctly
- Sign-in with password authentication succeeds
- Tokens are properly generated in metadata
