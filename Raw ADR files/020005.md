# ADR-001: UI Framework Choice - Shadcn UI with Default Styling

## Status

Accepted

## Context

The existing chat UI uses custom SCSS styling with Tailwind CSS, which requires maintenance overhead and custom design decisions. We need to rebuild the UI with a consistent, accessible, and maintainable approach that reduces time-to-market.

## Decision

We will use Shadcn UI components with default styling only, following the "ship defaults first" philosophy.

## Rationale

### Chosen: Shadcn UI + Radix Primitives + Tailwind CSS

- **Accessibility**: Built-in WCAG 2.1 AA compliance via Radix primitives
- **Consistency**: Unified design language across all components
- **Maintenance**: No custom component library to maintain
- **Performance**: Tree-shakeable components, only import what's used
- **Developer Experience**: Well-documented, TypeScript-first
- **Keyboard Navigation**: All interactions keyboard accessible by default
- **Focus Management**: Proper focus trapping in modals/sheets

### Rejected Alternatives

**Custom Component Library**

- ❌ High maintenance overhead
- ❌ Need to implement accessibility from scratch
- ❌ Inconsistent design decisions over time
- ❌ Longer development time

**Material-UI (MUI)**

- ❌ Larger bundle size
- ❌ More opinionated styling (harder to customize later)
- ❌ Different design philosophy than existing app

**Chakra UI**

- ❌ Different component API patterns
- ❌ Less TypeScript-first approach
- ❌ More complex theming system

## Consequences

### Positive

- Zero custom styling reduces development time by ~60%
- Automatic accessibility compliance
- Consistent hover states, focus indicators, and animations
- Easy to upgrade (just update Shadcn components)
- Mobile-responsive by default

### Negative

- Less visual uniqueness (looks like other Shadcn apps)
- Harder to implement brand-specific design later
- Dependency on Shadcn's design decisions

### Mitigation

- Phase 2 can customize Shadcn theme variables for branding
- Component structure allows easy styling updates later
- Focus on functionality first, visual customization second

## Implementation Notes

- Install via `npx shadcn-ui@latest init`
- Only add components we actually use
- Use default variants (no custom styling)
- Leverage Tailwind utility classes for spacing/layout only
