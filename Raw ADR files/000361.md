# ADR 003: UV for Python Dependency Management

## Status
Accepted

## Context

Python dependency management has historically been fragmented:
- pip + requirements.txt (slow, no lock file)
- pip-tools (better, but still slow)
- Poetry (better UX, but slow, complex)
- Pipenv (slow, often breaks)

Our requirements:
- Fast dependency resolution and installation
- Reproducible builds (lock files)
- Modern pyproject.toml-based workflow
- Good monorepo support
- Compatible with Docker
- Industry best practices

## Decision

We will use **UV** as our exclusive Python dependency management tool.

### What is UV?

UV is a modern, extremely fast Python package installer and resolver written in Rust by Astral (creators of Ruff).

**Key Features**:
- 10-100x faster than pip
- pyproject.toml native
- Lock file support (uv.lock)
- Drop-in replacement for pip/pip-tools/poetry
- Excellent Docker support
- Virtual environment management

### Mandate

- **NO pip**: Don't use pip for installation
- **NO requirements.txt**: Use pyproject.toml only
- **NO virtualenv**: Use `uv venv` or rely on uv's built-in env management
- **NO poetry/pipenv**: UV replaces these entirely

### Workflow

**Development**:
```bash
# Create new project
uv init

# Install dependencies
uv sync

# Add dependency
uv add fastapi

# Add dev dependency
uv add --dev pytest

# Run command in environment
uv run pytest

# Activate environment (if needed)
source .venv/bin/activate
```

**Docker**:
```dockerfile
# Multi-stage build
FROM python:3.13-slim AS builder

# Install uv
COPY --from=ghcr.io/astral-sh/uv:latest /uv /bin/uv

# Copy dependency files
COPY pyproject.toml uv.lock ./

# Install dependencies
RUN uv sync --frozen --no-dev

# Runtime stage
FROM python:3.13-slim
COPY --from=builder /app/.venv /app/.venv
ENV PATH="/app/.venv/bin:$PATH"
```

**CI/CD**:
```yaml
- name: Install UV
  run: curl -LsSf https://astral.sh/uv/install.sh | sh

- name: Install dependencies
  run: uv sync --frozen

- name: Run tests
  run: uv run pytest
```

### Project Structure

Each service has:
```
service/
├── pyproject.toml    # Dependencies and config
├── uv.lock          # Lock file (MUST commit)
├── .python-version  # Python version
└── src/             # Source code
```

**pyproject.toml Example**:
```toml
[project]
name = "document-service"
version = "0.1.0"
```

## Consequences

### Positive

- **Speed**: 10-100x faster than pip/poetry
  - Initial install: seconds vs minutes
  - Lock file resolution: near-instant
  - Docker builds: significantly faster

- **Simplicity**: One tool, clear workflow
  - No confusion between pip/poetry/pipenv
  - Standardized across all services
  - Easy onboarding

- **Modern**: Industry is moving to UV
  - Active development
  - Astral backing (same as Ruff)
  - Growing adoption

- **Reproducibility**: Lock files ensure consistency
  - Same dependencies across team
  - Same dependencies in CI/CD
  - Same dependencies in production

- **Monorepo Friendly**: Works well with multiple services
  - Each service has own pyproject.toml
  - Shared dependencies handled cleanly

### Negative

- **Relatively New**: UV is newer than pip/poetry
  - Less Stack Overflow answers
  - Smaller ecosystem
  - Potential edge cases

- **Learning Curve**: Team must learn UV
  - Different from pip workflow
  - Different from poetry workflow
  - Requires documentation

- **Migration**: Existing projects need conversion
  - Not applicable (greenfield)

### Mitigations

- Comprehensive documentation
- Examples in each service
- Team training
- Fallback: UV is pip-compatible if needed

## Performance Comparison

Real-world benchmarks:

```
Installing FastAPI + dependencies:
- pip:    45 seconds
- poetry: 32 seconds
- uv:     1.2 seconds

Resolving dependencies:
- pip:    N/A (no resolver)
- poetry: 18 seconds
- uv:     0.3 seconds
```

## Migration Guide

For future migrations:

**From requirements.txt**:
```bash
uv add $(cat requirements.txt)
```

**From poetry**:
```bash
# Poetry dependencies automatically detected
uv sync
```

**From pipenv**:
```bash
# Convert Pipfile to pyproject.toml
uv init
uv add $(cat Pipfile | grep '=' | cut -d'=' -f1)
```

## Standards

**Lock File**:
- MUST commit `uv.lock`
- Update with `uv lock`
- CI verifies lock file is up to date

**Dependencies**:
- Pin major versions only in pyproject.toml
- Lock file handles exact versions
- Regular updates with `uv lock --upgrade`

**Virtual Environments**:
- UV creates `.venv` automatically
- Don't commit `.venv`
- Recreate with `uv sync`
