# ADR-001: Docusaurus for Textbook Delivery

## Status
**Accepted** | 2025-11-29

## Context

The hackathon challenge requires:
1. Write a book using a suitable documentation platform
2. Deploy to GitHub Pages
3. Demonstrate Spec-Kit Plus + Claude Code workflow

We need a platform that:
- Renders markdown beautifully with code syntax highlighting
- Supports multiple sidebars (textbook chapters + methodology showcase)
- Provides excellent developer experience for content authoring
- Integrates seamlessly with GitHub Pages
- Supports modern web features (search, responsive design, dark mode)
- Is actively maintained and has strong community support

## Decision

We will use **Docusaurus** (v3.x with TypeScript) as the textbook delivery platform.

### Docusaurus Configuration
```typescript
- title: 'Physical AI & Humanoid Robotics'
- url: https://ahtishamyousaf.github.io
- baseUrl: /physical-ai-textbook/
- organizationName: ahtishamyousaf
- projectName: physical-ai-textbook
```

### Key Features Utilized
1. **Dual Sidebars**:
   - `textbookSidebar`: 10 chapters organized in 3 parts
   - `methodologySidebar`: Spec-driven workflow showcase

2. **Syntax Highlighting**: Python, Bash, YAML, XML, C++, JSON (ROS 2 stack)

3. **Markdown Extensions**: Mermaid diagrams, admonitions, code blocks with tabs

4. **SEO & Performance**: Static site generation, meta tags, sitemap

5. **GitHub Integration**: Edit links, auto-deployment via GitHub Actions

## Alternatives Considered

### 1. GitBook
**Pros**:
- Beautiful default theme
- Strong documentation focus
- Good search functionality

**Cons**:
- ❌ Proprietary platform (hosted, not GitHub Pages)
- ❌ Free tier limitations
- ❌ Less control over customization
- ❌ Vendor lock-in concerns

**Verdict**: Rejected due to hosting requirements and cost

### 2. MkDocs with Material Theme
**Pros**:
- Python-based (aligned with ROS 2 stack)
- Material Design looks professional
- Good plugin ecosystem

**Cons**:
- ❌ Less flexible sidebar configuration
- ❌ Limited React component integration
- ❌ Smaller community than Docusaurus
- ❌ Slower build times for large sites

**Verdict**: Rejected due to sidebar limitations

### 3. mdBook (Rust-based)
**Pros**:
- Fast builds
- Simple, focused on books
- Used by Rust documentation

**Cons**:
- ❌ Limited customization options
- ❌ No multi-sidebar support
- ❌ Fewer themes and plugins
- ❌ Less suitable for methodology showcase

**Verdict**: Rejected due to limited features

### 4. VuePress
**Pros**:
- Vue.js-based (similar to Docusaurus but Vue)
- Good plugin system
- Static site generation

**Cons**:
- ❌ Smaller community than Docusaurus
- ❌ Less active development
- ❌ Fewer ready-made themes
- ❌ React ecosystem alignment better for future AI components

**Verdict**: Rejected in favor of Docusaurus ecosystem

### 5. Jupyter Book
**Pros**:
- Excellent for code-heavy content
- Native Jupyter notebook integration
- Good for data science/robotics

**Cons**:
- ❌ Overkill for markdown-first textbook
- ❌ Harder to customize presentation
- ❌ Not optimized for multi-sidebar architecture
- ❌ Methodology showcase would be awkward

**Verdict**: Rejected as overkill for our use case

## Rationale

Docusaurus wins because:

1. **Hackathon Alignment**:
   - GitHub Pages deployment is first-class (official guide)
   - Docusaurus is explicitly designed for documentation/books
   - Strong hackathon credibility (used by Meta, Facebook, Jest, etc.)

2. **Dual-Purpose Architecture**:
   - Easily supports two sidebars (textbook + methodology)
   - Textbook content and workflow showcase can coexist cleanly
   - Flexibility for future expansion (blog, API docs, interactive components)

3. **Developer Experience**:
   - TypeScript support for type safety
   - Hot reload during development
   - Excellent error messages
   - CLI tools for scaffolding

4. **ROS 2 / Robotics Fit**:
   - Syntax highlighting for Python, C++, YAML, Bash, XML (all ROS 2 stack)
   - Mermaid diagram support (architecture diagrams, state machines)
   - Admonitions for warnings, tips, safety notes
   - Code tabs for Python vs C++ examples

5. **Community & Ecosystem**:
   - 50k+ GitHub stars, active development
   - Large plugin ecosystem
   - Extensive documentation
   - Used by major projects (React, Redux Toolkit, Jest, Docusaurus itself)

6. **Spec-Kit Plus Integration**:
   - Easy to render PHRs as markdown pages
   - ADRs can be displayed in docs/methodology/adr-index
   - Constitution can be rendered directly
   - Workflow diagrams using Mermaid

7. **Performance & SEO**:
   - Static site generation (fast loading)
   - Automatic sitemap generation
   - Meta tags for social sharing
   - Lighthouse scores typically 95+

8. **GitHub Pages Compatibility**:
   - Official GitHub Actions integration
   - No configuration hacks needed
   - baseUrl support for `/repo-name/` paths
   - Asset optimization out of the box

## Consequences

### Positive
- ✅ Students get professional, responsive textbook site
- ✅ Methodology showcase has dedicated navigation
- ✅ Search functionality works out of the box
- ✅ Dark mode respects user preferences
- ✅ Mobile-friendly for on-the-go learning
- ✅ Easy for contributors to add chapters (markdown files)
- ✅ Deployment is automated (GitHub Actions)

### Negative
- ⚠️ Node.js dependency (requires npm/yarn for local builds)
- ⚠️ React knowledge helpful for advanced customization
- ⚠️ Initial learning curve for Docusaurus-specific features
- ⚠️ Build time increases with more content (mitigated by incremental builds)

### Neutral
- ℹ️ Locked to Docusaurus v3.x for stability
- ℹ️ Migration to other platforms would require content transformation
- ℹ️ Some features require plugins (search, analytics)

## Implementation Notes

### Directory Structure
```
physical-ai-textbook/              # Docusaurus site root
├── docs/
│   ├── intro.md
│   ├── methodology/               # Spec-Driven workflow showcase
│   │   ├── spec-driven-workflow.md
│   │   ├── phr-gallery.md
│   │   ├── adr-index.md
│   │   └── constitution.md
│   ├── chapter-01/
│   │   └── intro-physical-ai.md
│   └── chapter-02-10/...
├── static/
│   └── img/                       # Images, diagrams
├── src/
│   └── components/                # React components (future)
├── docusaurus.config.ts           # Main configuration
├── sidebars.ts                    # Sidebar definitions
└── package.json
```

### Deployment Flow
```
1. Push to main branch
2. GitHub Actions triggers build
3. npm ci && npm run build
4. Deploy to gh-pages branch
5. Live at https://ahtishamyousaf.github.io/physical-ai-textbook/
```
