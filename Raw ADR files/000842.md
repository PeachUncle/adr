# ADR-011: External System Integration Strategy

## Status
**Accepted** | October 7, 2025

## Context

BahariWatch requires integration with multiple external systems to fulfill its mission of detecting and preventing illegal fishing in Kenya's coastal regions. The primary integration challenge involves consuming vessel tracking data from Global Fishing Watch (GFW), which aggregates AIS (Automatic Identification System) and VMS (Vessel Monitoring System) feeds. Additionally, the system needs to integrate with notification services (SMS/Email) and potentially government enforcement databases.

### Business Drivers
- **Real-time Detection:** Community reports must be correlated against current vessel positions to identify suspicious activities
- **Data Completeness:** Kenya's own VMS has been largely inoperable (Sh16 million unpaid maintenance), creating dependency on external data sources
- **Coverage Gaps:** Small/unregistered boats lack transponders, requiring multiple data sources for comprehensive monitoring
- **Enforcement Efficiency:** Timely alerts to enforcement agencies depend on reliable external system integration

### Technical Constraints
- **External API Characteristics:**
  - **Rate Limits:** GFW API enforces 50,000 daily requests, 1,550,000 monthly (non-commercial use)
  - **Latency:** RESTful API with network latency (international data centers)
  - **Data Freshness:** AIS data available from 2017 to ~5 days ago; SAR detections 2017 to ~3 months ago
  - **Authentication:** Bearer token authentication required for all requests
  - **Concurrency Limits:** 4Wings Report API supports only 1 concurrent report per user (429 error on concurrent requests)
  - **Error Scenarios:** 401 (Unauthorized), 422 (Validation Error), 429 (Too Many Requests), 500 (Internal Server Error)

- **System Requirements:**
  - Must support offline operation (community reports) then sync when connectivity available
  - Must handle intermittent external API failures gracefully
  - Must correlate spatial-temporal data (GPS coordinates + timestamps) between community reports and vessel tracks
  - Must maintain audit trail of all external system interactions for compliance

### Architecture Characteristics Affected
- **Reliability:** External system failures must not cascade to core reporting functionality
- **Performance:** API rate limits could bottleneck matching operations during high-volume periods
- **Security:** API tokens must be protected; data transmission must be encrypted
- **Maintainability:** Integration logic should be isolated to minimize coupling
- **Testability:** Must be able to test without consuming actual API quotas

### Integration with Other ADRs
- **ADR-001 (Microservices):** External integrations implemented as separate AIS Integration Service
- **ADR-002 (Event-Driven):** Uses async messaging to decouple from core services
- **ADR-003 (Database):** Caches external API responses to reduce redundant calls
- **ADR-008 (Security):** API tokens stored in secure vault (e.g., AWS Secrets Manager)

---

## Decision

We will implement an **Adapter Pattern with Circuit Breaker and Caching Strategy** for integrating with Global Fishing Watch API and other external systems.

#### 2. **Global Fishing Watch API Integration**

**Primary Endpoints Used:**

a) **Vessels API:** Retrieve vessel identity and characteristics
   - Endpoint: `GET /v3/vessels/search`
   - Use Case: Identify vessel details from community report descriptions
   - Cache TTL: 24 hours (vessel identity changes infrequently)

b) **4Wings API - Reports:** Generate fishing effort reports for specific regions
   - Endpoint: `POST /v3/4wings/report`
   - Use Case: Analyze historical fishing patterns in hotspot regions
   - Cache TTL: 1 hour (regional patterns change slowly)

c) **Events API:** Retrieve vessel events (encounters, loitering, port visits, fishing)
   - Endpoint: `GET /v3/events`
   - Use Case: Correlate community reports with known fishing events
   - Cache TTL: 30 minutes (events are near-real-time critical)

d) **Insights API:** Get vessel risk indicators (IUU lists, AIS off events)
   - Endpoint: `POST /v3/vessels/{vesselId}/insights`
   - Use Case: Prioritize alerts based on vessel risk profile
   - Cache TTL: 6 hours (risk assessments update periodically)

#### 3. **Resilience Patterns**

**A. Circuit Breaker Implementation**

State Machine:
- **CLOSED:** Normal operation, requests pass through
- **OPEN:** Too many failures (threshold: 5 failures in 60 seconds), reject requests immediately
- **HALF_OPEN:** After timeout (30 seconds), allow 1 test request

```python
class CircuitBreaker:
    def __init__(self, failure_threshold=5, timeout=30, reset_timeout=60):
        self.failure_threshold = failure_threshold
        self.timeout = timeout  # seconds to stay OPEN
        self.reset_timeout = reset_timeout  # window for counting failures
        self.state = "CLOSED"
        self.failure_count = 0
        self.last_failure_time = None
        self.opened_at = None
    
    def call(self, func, *args, **kwargs):
        if self.state == "OPEN":
            if time.time() - self.opened_at >= self.timeout:
                self.state = "HALF_OPEN"
            else:
                raise CircuitBreakerOpenError("GFW API circuit breaker is OPEN")
        
        try:
            result = func(*args, **kwargs)
            if self.state == "HALF_OPEN":
                self.reset()
            return result
        except ExternalAPIException as e:
            self.record_failure()
            raise
    
    def record_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        
        if self.failure_count >= self.failure_threshold:
            self.state = "OPEN"
            self.opened_at = time.time()
            # Publish CircuitBreakerOpened event to alert monitoring
            publish_event("AISIntegrationService.CircuitBreakerOpened")
```

**C. Rate Limiting (Token Bucket Algorithm)**

```python
class RateLimiter:
    def __init__(self, max_requests=50000, window=86400):  # 50k per day
        self.max_requests = max_requests
        self.window = window  # seconds (86400 = 24 hours)
        self.tokens = max_requests
        self.last_refill = time.time()
        self.lock = threading.Lock()
    
    def acquire(self, tokens=1) -> bool:
        with self.lock:
            self._refill()
            if self.tokens >= tokens:
                self.tokens -= tokens
                return True
            else:
                # Log rate limit exhaustion
                logger.warning(f"GFW API rate limit exhausted. Tokens: {self.tokens}")
                return False
    
    def _refill(self):
        now = time.time()
        elapsed = now - self.last_refill
        tokens_to_add = (elapsed / self.window) * self.max_requests
        self.tokens = min(self.max_requests, self.tokens + tokens_to_add)
        self.last_refill = now
```

#### 4. **Caching Strategy (Redis)**

**Cache Keys Pattern:**
```
gfw:vessel:{vessel_id}:identity          TTL: 86400s (24h)
gfw:events:{vessel_id}:{start}:{end}     TTL: 1800s (30m)
gfw:report:{region_hash}:{date}          TTL: 3600s (1h)
gfw:insights:{vessel_id}                 TTL: 21600s (6h)
```

**Cache Invalidation:**
- **Time-based:** TTL expiration (automatic)
- **Event-based:** Manual invalidation on `VesselDataUpdated` events from GFW webhooks (if available)

**Cache-Aside Pattern:**
```python
def get_vessel_data(vessel_id: str) -> VesselData:
    # 1. Check cache
    cache_key = f"gfw:vessel:{vessel_id}:identity"
    cached = redis_client.get(cache_key)
    if cached:
        return VesselData.parse_raw(cached)
    
    # 2. Fetch from API (with circuit breaker + rate limiting)
    if not rate_limiter.acquire():
        raise RateLimitExceededError("GFW API daily quota exhausted")
    
    vessel_data = circuit_breaker.call(
        fetch_vessel_data_from_gfw, vessel_id
    )
    
    # 3. Store in cache
    redis_client.setex(
        cache_key, 
        86400,  # 24 hour TTL
        vessel_data.json()
    )
    
    return vessel_data
```

#### 5. **Fallback Strategies**

**Priority Cascade:**

1. **Primary:** Global Fishing Watch API
2. **Fallback 1:** Cached data (even if stale beyond TTL)
3. **Fallback 2:** Manual verification flag for enforcement (no auto-match)
4. **Fallback 3:** Log for later batch processing when API recovers

**Degraded Mode Operations:**
```python
class DegradedModeHandler:
    def handle_gfw_outage(self, report: Report):
        # 1. Use stale cache (ignore TTL)
        vessel_data = get_from_cache_ignore_ttl(report.region)
        if vessel_data:
            return generate_low_confidence_match(report, vessel_data)
        
        # 2. Flag for manual review
        report.requires_manual_verification = True
        publish_event(ReportFlaggedForManualReview(report.id))
        
        # 3. Queue for batch processing
        queue_for_batch_processing(report)
        
        # 4. Alert monitoring (PagerDuty/Slack)
        alert_monitoring("GFW API unavailable, operating in degraded mode")
```

#### 6. **Error Handling Matrix**

| Error Code | Retry? | Fallback | Alert | User Impact |
|------------|--------|----------|-------|-------------|
| **401 Unauthorized** | No | N/A | Critical (token expired) | Report accepted but matching delayed |
| **422 Validation Error** | No | Log & Skip | Warning | Report accepted, match attempt logged |
| **429 Too Many Requests** | Yes (exponential backoff) | Use cache | Info | Temporary delay in matching |
| **500 Internal Server Error** | Yes (3 attempts) | Circuit breaker opens | Warning | Report queued for retry |
| **Timeout (>30s)** | Yes (3 attempts) | Circuit breaker opens | Warning | Report queued for retry |
| **Network Error** | Yes (3 attempts) | Circuit breaker opens | Critical (if persistent) | Degraded mode activated |

## Rationale

### Why This Decision Over Alternatives?

#### Alternative 1: Direct Synchronous API Calls
**Rejected because:**
- No resilience against external API failures
- Rate limit violations would cascade failures
- No caching = wasteful API quota consumption
- Tight coupling between matching logic and external APIs

#### Alternative 2: Periodic Batch Processing (Cron Jobs)
**Rejected because:**
- Violates "near real-time" requirement (alerts within minutes)
- Inefficient for sparse community reports
- Still needs same resilience patterns
- Poor user experience (long delay between report and alert)

#### Alternative 3: Direct VMS Integration (Kenya Government)
**Rejected because:**
- Kenya's VMS is inoperable (Sh16M unpaid maintenance)
- Limited to vessels with transponders (misses small boats)
- Bureaucratic delays in data access approvals
- May revisit as **supplementary** data source in future

### Trade-Off Analysis

| Dimension | Adapter + Circuit Breaker (Chosen) | Direct Sync Calls | Batch Processing | Direct VMS |
|-----------|-----------------------------------|-------------------|------------------|------------|
| **Reliability** | ↑ High (isolated failures) | ↓ Low (cascading failures) | → Moderate | ↓ Low (system inoperable) |
| **Performance** | ↑ Fast (caching + async) | ↓ Slow (network latency) | ↓ Very slow (delay in hours) | ↑ Fast (direct access) |
| **Cost Efficiency** | ↑ Optimal (cache reduces API calls) | ↓ Wasteful (redundant calls) | ↑ Good (fewer calls) | ↑ Good (no API fees) |
| **Complexity** | ↓ Higher (circuit breaker, cache) | ↑ Simple (direct call) | → Moderate | ↓ High (government integration) |
| **Data Freshness** | ↑ Near real-time (5-30 min) | ↑ Near real-time | ↓ Stale (hours delay) | ↑ Real-time (if operational) |
| **Rate Limit Risk** | ↑ Managed (token bucket) | ↓ High risk | ↑ Low risk | N/A |

## Architecture Characteristics Impact

### Reliability: ↑ Significantly Positive
- **Circuit breaker** prevents cascading failures (GFW outage doesn't crash matching service)
- **Caching** provides degraded-mode operation with stale data
- **Retry logic** handles transient network failures
- **Fallback adapters** ensure notifications reach enforcement even if primary provider fails

### Performance: ↑ Positive
- **Cache hit rate** expected 60-70% (vessel identity/regional patterns repeat)
- **Async processing** decouples matching from API latency (report submission completes in <500ms)
- **Rate limiting** prevents quota exhaustion, ensuring consistent performance
- **Potential bottleneck:** GFW API latency (200-500ms per request) mitigated by caching

### Security: ↑ Positive
- **API tokens** stored in secrets manager (AWS Secrets Manager / HashiCorp Vault)
- **TLS/HTTPS** for all external API calls
- **No PII exposure:** GFW receives only GPS coordinates, no fisher identity
- **Audit logging:** All API calls logged with request/response for compliance

### Maintainability: ↑ Positive
- **Adapter pattern** isolates external API changes (GFW API v3→v4 migration contained)
- **Clear boundaries:** AIS Integration Service owns all external integrations
- **Testable:** Mock adapters for unit tests, stub GFW API for integration tests
- **Observability:** Circuit breaker state changes emit events for monitoring

### Testability: ↑ Positive
- **Mock GFW adapter** for unit tests (no API quota consumed)
- **WireMock server** for integration tests (simulate 429, 500 errors)
- **Chaos engineering:** Inject circuit breaker state changes to test degraded mode
- **Test coverage target:** 85% for resilience logic (circuit breaker, retry, fallback)

### Deployability: → Neutral
- **Additional component:** Redis cache server (DigitalOcean Managed Redis recommended)
- **Environment variables:** GFW API token, rate limits configurable per environment
- **Rolling deployments:** AIS Integration Service updates don't affect core reporting
- **Blue-green testing:** Validate GFW integration in staging before production

### Scalability: ↑ Positive
- **Horizontal scaling:** Multiple AIS Integration Service instances share Redis cache
- **Rate limit distribution:** Token bucket algorithm supports distributed rate limiting (Redis-based)
- **Cache efficiency:** Reduces GFW API calls by 60-70%, staying within 50k daily limit
- **Bottleneck analysis:** 50k daily limit = 34 requests/min sustained; with caching, supports ~100 reports/min

### Cost: ↑ Positive
- **GFW API:** Free (non-commercial use, stay within 50k daily limit)
- **Redis cache:** ~$15-25/month (DigitalOcean Managed Redis 1GB)
- **Notification costs:** Twilio SMS ~$0.05/SMS; Africa's Talking ~$0.008/SMS (Kenya rates)
- **Avoided cost:** Paying for Kenya VMS maintenance (Sh16M = ~$120k avoided)

## Consequences

### Positive

1. **Resilient Architecture:** System remains operational even when GFW API is down (degraded mode with cached data)
2. **Cost-Effective:** Caching reduces API calls by 60-70%, staying well within free tier limits
3. **Fast Response:** 200-500ms matching latency (cache hits <50ms)
4. **Future-Proof:** Adapter pattern allows easy addition of new vessel tracking sources (e.g., Spire Maritime, Kpler)
5. **Compliance-Ready:** Audit logs of all external API calls support GDPR/legal requirements
6. **Testable:** Mock adapters enable testing without consuming API quotas

### Negative

1. **Increased Complexity:** Circuit breaker, rate limiter, cache management add operational overhead
2. **Stale Data Risk:** Cache TTLs may serve slightly outdated vessel positions (mitigated by short TTLs for critical data)
3. **Redis Dependency:** Cache failure degrades performance (mitigated by fallback to direct API calls)
4. **Monitoring Burden:** Must track circuit breaker state, cache hit rates, rate limit consumption
5. **Initial Development Time:** Estimated 2 weeks to implement full resilience patterns (vs 3 days for direct API calls)

### Neutral

1. **GFW API Dependency:** Still dependent on external service availability (no domestic alternative currently viable)
2. **Rate Limit Constraint:** 50k daily limit sufficient for pilot (1000 users) but may need negotiation for scale
3. **Data Licensing:** GFW data is CC BY-NC 4.0; must ensure BahariWatch use remains non-commercial

### Security Implications

### Code Example: Complete Integration Flow
```python
# AIS Integration Service - Main Processing Logic

from typing import List, Optional
from datetime import datetime, timedelta
import httpx
from pybreaker import CircuitBreaker

class GFWAdapter:
    def __init__(self, base_url: str, api_token: str):
        self.base_url = base_url
        self.headers = {"Authorization": f"Bearer {api_token}"}
        self.client = httpx.AsyncClient(timeout=30.0)
        self.circuit_breaker = CircuitBreaker(
            fail_max=5,
            timeout_duration=30,
            reset_timeout=60
        )
        self.rate_limiter = RateLimiter(max_requests=50000, window=86400)
        self.cache = RedisCache()
    
    async def get_vessels_in_region(
        self, 
        lat: float, 
        lon: float, 
        radius_km: float,
        timestamp: datetime
    ) -> List[VesselPosition]:
        """
        Get vessels within radius of GPS coordinates at given time.
        
        Args:
            lat, lon: Center point GPS coordinates
            radius_km: Search radius in kilometers
            timestamp: Time of community report
        
        Returns:
            List of vessels detected in region
        """
        # 1. Check cache
        cache_key = self._build_cache_key(lat, lon, radius_km, timestamp)
        cached_vessels = await self.cache.get(cache_key)
        if cached_vessels:
            logger.info(f"Cache hit for region ({lat}, {lon})")
            return cached_vessels
        
        # 2. Check rate limit
        if not self.rate_limiter.acquire():
            logger.warning("GFW API rate limit exhausted")
            # Fallback: Use stale cache (ignore TTL)
            stale_vessels = await self.cache.get_stale(cache_key)
            if stale_vessels:
                return stale_vessels
            raise RateLimitExceededError("Daily API quota exhausted, no cached data")
        
        # 3. Call API via circuit breaker
        try:
            vessels = await self.circuit_breaker.call(
                self._fetch_vessels_from_gfw,
                lat, lon, radius_km, timestamp
            )
            
            # 4. Cache result
            await self.cache.set(
                cache_key, 
                vessels, 
                ttl=1800  # 30 minutes
            )
            
            return vessels
            
        except CircuitBreakerError:
            logger.error("Circuit breaker OPEN, using fallback")
            # Fallback: Return empty list, flag for manual review
            return []
    
    @retry(
        stop=stop_after_attempt(3),
        wait=wait_exponential(multiplier=1, min=2, max=10),
        retry=retry_if_exception_type((httpx.TimeoutException, httpx.ConnectError))
    )
    async def _fetch_vessels_from_gfw(
        self, 
        lat: float, 
        lon: float, 
        radius_km: float,
        timestamp: datetime
    ) -> List[VesselPosition]:
        """
        Internal method to fetch vessels from GFW API.
        Protected by @retry decorator for transient failures.
        """
        # Build bounding box (lat/lon ± radius)
        lat_offset = radius_km / 111.0  # 1 degree lat ≈ 111 km
        lon_offset = radius_km / (111.0 * cos(radians(lat)))
        
        polygon = [
            [lon - lon_offset, lat - lat_offset],
            [lon + lon_offset, lat - lat_offset],
            [lon + lon_offset, lat + lat_offset],
            [lon - lon_offset, lat + lat_offset],
            [lon - lon_offset, lat - lat_offset],
        ]
        
        # GFW 4Wings Report API request
        payload = {
            "region": {
                "geometry": {
                    "type": "Polygon",
                    "coordinates": [polygon]
                }
            },
            "datasets": ["public-global-ais-vessel-presence:latest"],
            "startDate": (timestamp - timedelta(hours=1)).isoformat(),
            "endDate": (timestamp + timedelta(hours=1)).isoformat(),
            "spatialResolution": "HIGH",
            "temporalResolution": "HOURLY"
        }
        
        response = await self.client.post(
            f"{self.base_url}/4wings/report",
            json=payload,
            headers=self.headers
        )
        
        if response.status_code == 429:
            # Too Many Requests (concurrent report limit)
            raise RateLimitError("GFW concurrent request limit hit")
        elif response.status_code >= 500:
            raise ExternalAPIException(f"GFW API error: {response.status_code}")
        
        response.raise_for_status()
        
        # Parse response
        data = response.json()
        vessels = self._parse_vessel_positions(data)
        
        logger.info(f"Fetched {len(vessels)} vessels from GFW API")
        return vessels

# Event Handler in Matching Service
class ReportSubmittedHandler:
    def __init__(self, gfw_adapter: GFWAdapter):
        self.gfw_adapter = gfw_adapter
    
    async def handle(self, event: ReportSubmitted):
        """
        Process ReportSubmitted event:
        1. Query GFW for vessels in region
        2. Calculate spatial-temporal matches
        3. Publish MatchFound events
        """
        try:
            vessels = await self.gfw_adapter.get_vessels_in_region(
                lat=event.latitude,
                lon=event.longitude,
                radius_km=5.0,  # 5km search radius
                timestamp=event.timestamp
            )
            
            if not vessels:
                logger.info(f"No vessels found near report {event.report_id}")
                await self.publish(NoMatchFound(report_id=event.report_id))
                return
            
            # Calculate matches based on proximity and time
            matches = self._calculate_matches(event, vessels)
            
            for match in matches:
                await self.publish(MatchFound(
                    report_id=event.report_id,
                    vessel_id=match.vessel_id,
                    confidence=match.confidence,
                    distance_km=match.distance_km
                ))
        
        except RateLimitExceededError:
            # Queue for batch processing later
            logger.warning(f"Rate limit hit, queuing report {event.report_id}")
            await self.queue_for_batch_processing(event.report_id)
        
        except CircuitBreakerError:
            # Flag for manual review
            logger.error(f"Circuit breaker OPEN, flagging report {event.report_id}")
            await self.publish(ReportFlaggedForManualReview(
                report_id=event.report_id,
                reason="GFW API unavailable"
            ))
```
