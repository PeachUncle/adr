# ADR-0004: QEM Decimation with Color Boundary Penalty

## Status

Accepted

## Date

2025-09-15

## Context

Color baking workflows benefit from mesh simplification to reduce face count while preserving visual fidelity. Traditional decimation algorithms focus purely on geometric error, but multi-color 3D printing requires preserving color boundaries to maintain sharp transitions between material slots.

### Requirements

- Reduce face count for performance and memory efficiency
- Preserve color boundaries critical for multi-material printing
- Maintain geometric quality where color transitions don't occur
- Support both automatic ratio-based and explicit target face count decimation
- Integrate seamlessly with existing heuristic decimation fallback

### Existing Solutions

- **Heuristic region-aware decimation**: Removes faces in uniform color regions based on local variance. Simple and fast but limited geometric awareness.
- **Standard QEM**: Quadric Error Metric provides superior geometric preservation but ignores color information entirely.

## Decision

Implement QEM decimation with color boundary penalty as an alternative to heuristic decimation, controlled by `--decimate-mode` flag.

### Algorithm Design

1. **Quadric Construction**: Build error quadrics per vertex from incident face planes using standard QEM approach
2. **Edge Cost Function**:

   ```python
   cost = geometric_error + color_weight * color_penalty
   ```

   where:
   - `geometric_error`: Standard quadric error for edge collapse
   - `color_penalty`: Binary penalty (0 or 1) applied when edge endpoints have different palette indices
   - `color_weight`: User-configurable multiplier (default: 10.0)

3. **Boundary Preservation**: Optional `--decimate-preserve-boundary` flag completely forbids collapsing edges across color boundaries (infinite penalty)

4. **Collapse Selection**: Brute-force global minimum search across all edges (O(E) per iteration)

### CLI Interface

```bash
# QEM with color awareness
--decimate-mode qem
--decimate-color-weight 15.0      # Penalty multiplier for cross-color edges
--decimate-preserve-boundary      # Completely forbid cross-color collapses

# Fallback to heuristic (default)
--decimate-mode heuristic
```

### Implementation Tradeoffs

#### Chosen: Brute-force global search

- Pros: Simple implementation, guaranteed global minimum per iteration
- Cons: O(E) cost per iteration, slower than priority queue approaches
- Rationale: Meshes in target domain (post-subdivision, <100k faces) are manageable; simplicity preferred for initial implementation

#### Alternative considered: Priority queue

- Pros: O(log E) collapse selection
- Cons: Complex quadric updates, potential for stale priorities
- Deferred: Can optimize later if performance becomes bottleneck

## Consequences

### Positive

- Color boundaries preserved with tunable sensitivity
- Superior geometric quality compared to heuristic decimation
- Deterministic results (consistent edge iteration order)
- Smooth integration with existing pipeline (mode switch)
- Rich stats for monitoring (collapse counts, boundary preservation metrics)

### Negative

- Higher computational cost than heuristic approach
- May produce less aggressive simplification when color_weight is high
- Current implementation lacks vertex compaction (maintains original vertex array size)

### Monitoring

Stats emitted for performance tracking:

- `qem_attempted_collapses`: Total edge collapses considered
- `qem_committed_collapses`: Actual collapses performed  
- `qem_skipped_color_boundary`: Collapses skipped due to color penalty
- `qem_iterations`: Number of decimation iterations

### Future Optimizations

1. **Priority Queue**: Replace brute-force search with heap-based edge selection
2. **Vertex Compaction**: Remove unused vertices after decimation
3. **Adaptive Color Weight**: Automatically tune based on boundary density
4. **Incremental Quadrics**: Update only affected quadrics rather than recomputing

## Alternatives Considered

1. **Modify heuristic decimation**: Add color awareness to existing face removal logic
   - Rejected: Limited geometric quality, harder to tune

2. **Edge length + color hybrid**: Weight edge length by color similarity
   - Rejected: Less principled than QEM foundation

3. **Two-pass approach**: Geometric QEM followed by color-aware refinement
   - Rejected: More complex, harder to balance phases
