# Design Decision: Exact Version Matching for Dependencies

**Date:** 2025-12-20  
**Status:** ✅ DECIDED  
**Decision:** Dependencies MUST use exact version matching (no semver ranges)

---

## Problem Statement

When implementing package dependencies, we need to decide: Should we support flexible version constraints (like npm's `^1.0.0`, `>=1.0.0`, `~1.0.0`) or require exact version matching (`1.0.0`)?

## Core Constraint: Deterministic Rendering

From RFC 0001:
> **Determinism Everywhere:** Rendering the same package with the same seed produces identical output across conforming engines.

And from the Glossary:
> **Deterministic Rendering** | Guarantee that identical seeds, inputs, and **packages** yield identical outputs across compliant engines.

## Analysis

### What Happens with Flexible Constraints?

**Scenario:** Package A depends on `prompt-gen.common ^1.0.0`

This would match:
- ✅ Version 1.0.0
- ✅ Version 1.1.0 (new datatypes added)
- ✅ Version 1.2.0 (weights changed)
- ✅ Version 1.9.9 (rules updated)

**Problem:**
```yaml
# prompt-gen.common v1.0.0
datatypes:
  colors:
    values:
      - text: red
        weight: 1
      - text: blue
        weight: 1
      - text: green
        weight: 1

# prompt-gen.common v1.1.0
datatypes:
  colors:
    values:
      - text: red
        weight: 2  # Changed!
      - text: blue
        weight: 1
      - text: green
        weight: 1
      - text: yellow
        weight: 1  # Added!
```

**Result:**
- Same package A
- Same seed (e.g., 42)
- Different dependency version (1.0.0 vs 1.1.0)
- **Different outputs!** ❌

This violates deterministic rendering.

### Why Exact Versions Solve This

**With exact matching:**
```yaml
dependencies:
  - package: prompt-gen.common
    version: "1.0.0"  # Exact version required
```

- ✅ Only accepts version 1.0.0
- ✅ Same package + same seed = same output
- ✅ Determinism guaranteed
- ✅ Reproducible rendering across engines

## Decision

**We enforce exact version matching for all dependencies.**

### Rationale

1. **Determinism First**: Our core design tenet requires it
2. **Reproducibility**: Users can share packages with confidence
3. **Debugging**: Easier to diagnose issues when versions are fixed
4. **Simplicity**: Less complex resolution logic
5. **Intentionality**: Forces authors to explicitly update versions

### Trade-offs

**Advantages:**
- ✅ Deterministic rendering guaranteed
- ✅ No version resolution conflicts
- ✅ Clear dependency graph
- ✅ Simpler implementation
- ✅ Easier testing

**Disadvantages:**
- ⚠️ Must manually update versions for bug fixes
- ⚠️ Can't automatically benefit from non-breaking updates
- ⚠️ Dependency maintenance burden on authors

**Verdict:** The advantages align with our design tenets. The disadvantages are acceptable trade-offs for determinism.

## Implementation Details

### Version Format
- **Supported:** Semantic versioning `major.minor.patch` (e.g., `1.0.0`, `1.2.3`)
- **Required:** Exact string match
- **Rejected:** `^1.0.0`, `>=1.0.0`, `~1.0.0`, `*`, `latest`

### Error Messages
When versions don't match:
```
Error: Version mismatch
  Package: prompt-gen.common
  Required: 2.0.0 (exact)
  Found: 1.0.0
  Location: ./packages/common.yaml
  
  Suggestion: Update prompt-gen.common to version 2.0.0 
              or change dependency to version: "1.0.0"
  
  Note: Exact version matching is required for deterministic rendering.
  Different versions may produce different outputs with the same seed.
```

### YAML Syntax
```yaml
dependencies:
  - package: prompt-gen.common
    version: "1.0.0"  # Exact version - quotes recommended
    path: "./packages/common.yaml"  # Optional for local packages
  
  - package: test.fantasy
    version: "2.1.0"  # Must match exactly
    path: "../fantasy/package.yaml"
```

## Future Considerations

### Package Lock Files (v1.1.0+)
Could add lock files for transitive dependencies while still enforcing exact matching:
```yaml
# package-lock.yaml
dependencies:
  prompt-gen.common:
    version: 1.0.0
    resolved: ./packages/common.yaml
    dependencies:
      prompt-gen.base:
        version: 1.2.0
        resolved: ./packages/base.yaml
```

### Update Tooling (v1.1.0+)
CLI commands to help with updates:
```bash
rpg deps list           # Show current versions
rpg deps check          # Check for updates
rpg deps update <pkg>   # Update specific package (requires manual approval)
```

### Breaking Change Detection (v1.1.0+)
Validator could warn if updating dependency version:
```
Warning: Dependency version change detected
  Package: prompt-gen.common
  Old: 1.0.0
  New: 1.1.0
  
  This may affect rendering output. Suggested actions:
  1. Test with multiple seeds
  2. Compare outputs before/after
  3. Update your package version if output changes
```

## Summary

**Exact version matching is not a limitation—it's a feature that ensures deterministic rendering.**

When users share a package that depends on `prompt-gen.common 1.0.0`, everyone who renders it will get identical results with the same seed, regardless of what other versions of `prompt-gen.common` exist on their system.

This is the foundation of trust in the RPG ecosystem. 🎯
