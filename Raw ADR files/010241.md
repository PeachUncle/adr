# ADR 004: React for Renderer Process UI

**Status:** Accepted

**Date:** 2025-10-13

**Deciders:** Development Team

## Context

The Latera desktop application needs a UI framework for the renderer process that can:
- Build fast, keyboard-first interfaces similar to Raycast
- Handle complex state management (articles, tags, search, filters)
- Render lists of hundreds of articles efficiently
- Provide smooth animations and transitions
- Support dark/light themes with system preference detection
- Integrate with Electron IPC for main process communication
- Enable rapid development for a side project
- Leverage existing React expertise

UI Requirements:
- Command palette interface for quick actions
- Virtualized list rendering for performance
- Real-time search with debouncing
- Keyboard navigation throughout
- Context menus and tooltips
- Settings panel and preferences
- Article detail view with reader mode

## Decision

We will use **React 18+** with the following supporting libraries:

### Core Stack:
- **React 18**: UI framework with concurrent features
- **TypeScript**: Type safety throughout
- **Vite**: Fast build tool for renderer process
- **React Router**: Navigation (if multi-window needed)

### Supporting Libraries:
- **TanStack Query** (React Query): Server state and cache management
- **Zustand**: Lightweight global state management
- **Radix UI**: Headless accessible components
- **Tailwind CSS**: Utility-first styling
- **Framer Motion**: Smooth animations
- **cmdk**: Command palette component

## Consequences

### Positive

- **Developer Familiarity**: Leverage existing React expertise, minimal learning curve
- **Rich Ecosystem**: Vast library ecosystem for common UI patterns
- **Component Reusability**: Share components with landing page via monorepo
- **Excellent Tooling**: React DevTools, Vite HMR, TypeScript integration
- **Virtual DOM Performance**: Efficient rendering for list updates
- **Concurrent Features**: React 18 transitions and suspense for smooth UX
- **Community Support**: Large community, abundant resources and examples
- **Electron Integration**: Well-documented patterns for Electron + React
- **Testing Ecosystem**: Jest, Testing Library, Playwright for comprehensive testing
- **Hiring/Collaboration**: Easy to find contributors familiar with React

### Negative

- **Bundle Size**: React + ReactDOM ~140KB (gzipped ~45KB) vs lighter alternatives
- **Runtime Overhead**: Virtual DOM diffing has small performance cost
- **Over-Engineering Risk**: React may be overkill for simple UIs (mitigated by component reuse)
- **Build Complexity**: Need bundler configuration (Vite) for Electron
- **Learning Curve for New Patterns**: Hooks, concurrent rendering require understanding
- **Frequent Updates**: React ecosystem changes rapidly, maintenance needed

### Mitigation Strategies

- Use code splitting and lazy loading for route-based chunks
- Implement virtualization for long lists (react-window or TanStack Virtual)
- Memoize expensive computations with `useMemo` and `useCallback`
- Use React DevTools Profiler to identify performance bottlenecks
- Keep bundle size <500KB by auditing dependencies
- Use Preact as potential future optimization if bundle size critical

## Alternatives Considered

### Vue 3
- **Pros**: Smaller bundle (~33KB), simpler reactivity, less boilerplate, easier learning curve
- **Cons**: Less familiar to team, smaller ecosystem than React, fewer Electron examples, less component sharing with Next.js landing page

### Svelte
- **Pros**: Smallest bundle (compiled away), excellent performance, simple syntax, great DX
- **Cons**: Less mature ecosystem, fewer libraries, different paradigm from landing page, smaller community, limited Electron resources

### Solid.js
- **Pros**: Fastest performance, React-like syntax, fine-grained reactivity, small bundle
- **Cons**: Very small ecosystem, minimal libraries, new technology risk, limited Electron examples, different from landing page stack

### Preact
- **Pros**: Tiny bundle (~3KB), React API compatible, fast, good Electron integration
- **Cons**: Some React features missing/different, smaller ecosystem, compat mode adds size, less testing with Electron

### Vanilla JavaScript + Web Components
- **Pros**: No framework overhead, full control, smallest possible bundle
- **Cons**: Manual state management, more code to write, slower development, harder to maintain, no component ecosystem

### Angular
- **Pros**: Full framework, TypeScript-first, dependency injection, comprehensive tooling
- **Cons**: Heavy bundle, over-engineered for desktop app, steep learning curve, different from landing page, slower development

### IPC Communication Pattern

```typescript
// preload/index.ts - Expose safe IPC API
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('electron', {
  articles: {
    getAll: () => ipcRenderer.invoke('articles:getAll'),
    create: (article) => ipcRenderer.invoke('articles:create', article),
    update: (id, data) => ipcRenderer.invoke('articles:update', id, data),
    delete: (id) => ipcRenderer.invoke('articles:delete', id),
  },
  onArticleAdded: (callback) => {
    ipcRenderer.on('article:added', (_, article) => callback(article));
  }
});

// renderer/queries/articles.ts - TanStack Query integration
export const useArticles = () => {
  return useQuery({
    queryKey: ['articles'],
    queryFn: () => window.electron.articles.getAll(),
  });
};
```

### State Management Strategy

**Local UI State**: React hooks (`useState`, `useReducer`)
- Modal open/close
- Input values
- UI toggles

**Server State** (Main Process Data): TanStack Query
- Articles from database
- Settings
- Tags
- Caching, refetching, optimistic updates

**Global UI State**: Zustand
- Theme (dark/light)
- Command palette open/close
- Selected article
- Filter/search state

```typescript
// stores/ui.ts
import { create } from 'zustand';

interface UIStore {
  theme: 'light' | 'dark';
  commandPaletteOpen: boolean;
  setTheme: (theme: 'light' | 'dark') => void;
  toggleCommandPalette: () => void;
}

export const useUIStore = create<UIStore>((set) => ({
  theme: 'dark',
  commandPaletteOpen: false,
  setTheme: (theme) => set({ theme }),
  toggleCommandPalette: () => set((s) => ({
    commandPaletteOpen: !s.commandPaletteOpen
  })),
}));
```

### Performance Optimizations

1. **Virtualized Lists**: Use `@tanstack/react-virtual` for article lists
2. **Code Splitting**: Lazy load settings, article reader, heavy components
3. **Memoization**: Memoize expensive filters and sorts
4. **Debounced Search**: Debounce search input to reduce renders
5. **Optimistic Updates**: Update UI before database write completes
6. **Suspense Boundaries**: Use React Suspense for loading states
7. **Concurrent Rendering**: Use `startTransition` for non-urgent updates

### Component Library Choice: Radix UI

Headless, accessible primitives for:
- Dialog/Modal
- Dropdown Menu
- Popover
- Tooltip
- Tabs
- Checkbox/Radio
- Scroll Area

Benefits:
- Full keyboard navigation
- ARIA attributes built-in
- Unstyled (style with Tailwind)
- Small bundle impact
- Composable

### Styling Approach

**Tailwind CSS** for utility-first styling:
- Rapid development
- Consistent design system
- PurgeCSS for small bundle
- Dark mode with `class` strategy
- JIT mode for custom values

```tsx
// Example component
export const ArticleCard = ({ article }) => {
  return (
    <div className="group rounded-lg border border-gray-200 dark:border-gray-800
                    hover:border-blue-500 transition-colors p-4 cursor-pointer">

                     group-hover:text-blue-500">

      </h3>
      <p className="text-sm text-gray-600 dark:text-gray-400 mt-1">
        {article.description}
      </p>

```

### Build Configuration

**Vite** for renderer process:
- Fast HMR during development
- Optimized production builds
- Built-in TypeScript support
- Electron-friendly configuration

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  base: './', // Relative paths for Electron
  build: {
    outDir: 'dist/renderer',
    rollupOptions: {
      input: './src/renderer/index.html',
    },
  },
});
```

## Notes

- Keep components small and focused (single responsibility)
- Use TypeScript strictly for props, state, and IPC contracts
- Implement error boundaries for graceful error handling
- Use React DevTools Profiler to monitor performance
- Consider Preact as drop-in replacement if bundle size becomes issue
- Share components with landing page via `@latera/ui` package when appropriate
