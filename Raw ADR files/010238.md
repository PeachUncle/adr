# ADR 001: Electron Framework Selection

**Status:** Accepted

**Date:** 2025-10-13

**Deciders:** Development Team

## Context

Latera requires a cross-platform desktop application that can:
- Implement global keyboard shortcuts system-wide
- Detect and capture link URLs from other applications on hover
- Run background processes for link monitoring
- Integrate with native OS features (notifications, system tray)
- Support Windows and macOS from a single codebase
- Provide a fast, keyboard-first UI similar to Raycast

We need to choose a desktop application framework that balances development speed, platform capabilities, and maintainability for a side project.

## Decision

We will use **Electron 27+** as the desktop application framework.

### Key Reasons:

1. **Global System Access**: Electron provides robust APIs for global keyboard shortcuts (`globalShortcut` module) that work consistently across Windows and macOS
2. **Screen & Mouse Integration**: Access to `screen` and `desktopCapturer` APIs needed for hover detection and link extraction
3. **Web Technology Stack**: Leverages React/TypeScript expertise, reducing learning curve
4. **Rich Ecosystem**: Mature tooling (electron-builder, electron-forge) and extensive community support
5. **IPC Architecture**: Well-established patterns for main/renderer communication essential for background monitoring
6. **Development Speed**: Hot reload, Chrome DevTools, and familiar web debugging tools
7. **Side Project Friendly**: Single developer can be productive quickly without learning platform-specific APIs

## Consequences

### Positive

- Fast development iteration with web technologies
- Single codebase for Windows and macOS
- Excellent debugging and profiling tools (Chrome DevTools)
- Large ecosystem of libraries and community solutions
- Familiar stack for React developers
- Easy to prototype and iterate
- Built-in auto-updater support
- Strong documentation and community resources

### Negative

- Larger application bundle size (~150-200MB installed vs ~10-20MB for native)
- Higher memory footprint (~150-250MB idle vs ~30-50MB for native)
- Chromium dependency means security updates tied to Electron releases
- Perception of "bloated" apps in some user communities
- Startup time slightly slower than native (~2-3s vs <1s)
- Node.js and Chromium update maintenance required

### Mitigation Strategies

- Use `asar` packaging and tree-shaking to minimize bundle size
- Implement lazy loading for renderer processes
- Enable context isolation and disable unnecessary Chromium features
- Use efficient IPC patterns to minimize overhead
- Monitor bundle size in CI/CD pipeline
- Target <180MB memory usage idle, <3s startup time

## Alternatives Considered

### Tauri
- **Pros**: Smaller bundle size (~20MB), lower memory usage, uses system WebView, Rust security benefits
- **Cons**: Less mature ecosystem, steeper learning curve (Rust required), WebView inconsistencies across OS versions, limited global shortcut capabilities, smaller community, more complex debugging

### Native (Swift for macOS + C#/WPF for Windows)
- **Pros**: Best performance, smallest bundle, native feel, optimal memory usage
- **Cons**: Two completely separate codebases, requires learning platform-specific languages/frameworks, 2x development time, inconsistent features across platforms, not practical for side project

### Flutter Desktop
- **Pros**: Single codebase, good performance, cross-platform UI
- **Cons**: Limited desktop maturity, weak global shortcut support, less access to low-level system APIs, smaller desktop ecosystem

### Qt/QML
- **Pros**: True native performance, mature framework, cross-platform
- **Cons**: C++ complexity, licensing considerations (commercial apps), limited web technology integration, steeper learning curve

## Notes

- We'll use **electron-builder** for packaging and distribution (see ADR 002)
- Security will be hardened with context isolation, CSP, and disabled node integration in renderers
- Performance benchmarks: Target <3s cold start, <200MB idle memory, <60ms IPC round-trip
- Bundle size target: <100MB installer, <250MB installed
- We'll revisit this decision if Tauri matures significantly or if performance becomes a critical blocker
