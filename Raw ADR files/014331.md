# TASK-017: Wire portfolio and trading screens
> Source: tasks/tasks.md

## Context
- PortfolioPage: GET /{user_id}/portfolio. Render holdings table, totals, and watchlist
- Link tickers to open a details modal that reuses PriceWidget and NewsWidget
- Recommendations surface: GET /recommend/portfolio. Render proposed buys, sells, adds. Provide "apply" actions
- Orders and trades: POST /{user_id}/orders for limit orders. Show pending then confirmed state
- POST /{user_id}/trade for BUY, SELL, CLOSE quick actions. Refresh portfolio after successful action

## Options Considered
- **Option A**: Single monolithic portfolio page (Pros: Simple structure; Cons: Hard to maintain, poor UX)
- **Option B**: Tabbed interface with separate sections (Pros: Organized, scalable; Cons: More complex)
- **Option C**: Modal-based interactions (Pros: Focused UX; Cons: Limited screen space)

## Decision
- **Chosen approach**: Option B - Tabbed interface with separate sections
- **Rationale**: Better organization, scalable design, clear separation of concerns

## Impacts
- **Performance**: Good - Optimistic UI with rollback, efficient state management
- **Complexity**: Moderate - Well-structured component hierarchy with clear responsibilities
- **Security/Privacy**: Good - User-specific data handling, proper error boundaries
- **Compatibility**: High - Uses existing API client and follows established patterns
- **Risks & Mitigations**: 
  - Risk: API failures might break UI; Mitigation: Comprehensive error handling and fallbacks
  - Risk: Conflicting actions; Mitigation: Optimistic UI with rollback on failure
