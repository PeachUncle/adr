# ADR-0003: Orientation Scoring Metrics

Status: Draft  
Date: 2025-09-14  
Related: ADR-0001 (Stack), ADR-0002 (Segmentation)

## Context

We need a deterministic, explainable orientation scoring system to choose a build orientation that balances:

- Print stability (bed contact area / projection footprint)
- Support minimization (overhang area beyond a threshold angle)
- Z-height minimization (reduces layer count / time)
- Optional aesthetic axis alignment (future: user-specified up vector bias)

## Candidate Metrics

1. Height Score: Normalize model height in candidate orientation vs minimal possible height.  
2. Stability Score: Ratio of convex hull footprint area of projected model to its axis-aligned bounding box (AABB) footprint (proxy for contact robustness).  
3. Overhang Penalty: Surface area of triangles whose normals form angle > theta with +Z, weighted by (angle - theta) / (90 - theta).  
4. Inertia Alignment (future): Prefer orientation aligning principal inertia axis with Z for tall slim shapes (optional weight).  

## Decision

Implement composite score:  

```text
score = w_height * H + w_overhang * O + w_stability * (1 - S)
```

Where:  

- H ∈ [0,1] normalized height (0 = minimal achievable, 1 = worst).  
- S ∈ [0,1] stability (1 = maximal footprint efficiency).  
- O ∈ [0,1] normalized overhang penalty (0 = no overhangs beyond threshold, 1 = worst among sampled orientations).  
Weights default: w_height = 0.25, w_overhang = 0.5, w_stability = 0.25 (subject to tuning).  
The best orientation has minimal composite score.

Sampling Strategy:  

- Evaluate 6 axis-aligned orientations from principal component axes (± each eigenvector).  
- Augment with up to N random hemisphere rotations (deterministic via seed) if mesh anisotropy > ε (optional).  

## Rationale

- Deterministic: Fixed seed and discrete candidate set produce stable outputs.  
- Transparent: Each sub-score is independently reportable to CLI JSON for user insight.  
- Extensible: Additional terms (aesthetic, texture alignment) can be added without breaking existing fields.  

## Consequences

- May miss a slightly better arbitrary rotation not aligned with PCA or random samples if N small.  
- Overhang approximation ignores slicer-specific bridging thresholds and cooling effects.  

## Acceptance Criteria

- Orientation function returns: rotation matrix (3x3), quaternion or Euler, and breakdown of H, S, O, composite.  
- For a flat plate model, system prefers plate lying flat (low height, high stability, zero overhang).  
- For a tall column, system chooses vertical orientation unless overhang surfaces penalize it.  

## Future Work

- Integrate support volume estimation via voxelized ray casting.  
- Add user bias vector and weight.  
- Introduce caching keyed by mesh hash + parameter tuple.  
- Implement gradient-based local refinement around best discrete candidate.
