# Architecture Decision Record: K-Anonymity for Privacy-Preserving Analytics

## Status
Accepted

## Date
2024-01-15

## Context
We needed to design district-level analytics that:

- Provides meaningful insights for school administrators
- Protects individual student privacy (FERPA requirement)
- Prevents re-identification through aggregated data
- Enables performance comparisons across schools
- Supports intervention effectiveness tracking
- Complies with FERPA "directory information" restrictions
- Prevents "small group" privacy violations

### The Privacy Problem

Traditional analytics expose individual students:

```sql
-- ❌ PRIVACY VIOLATION
SELECT school_id, COUNT(*), AVG(test_score)
FROM students
GROUP BY school_id;
-- Result: School A has 2 students with avg score 75
-- → Easy to identify individuals
```

###

 Alternatives Considered

1. **No Analytics**
   - Pros: Complete privacy
   - Cons: No insights for improvement, defeats platform purpose

2. **Differential Privacy**
   - Pros: Strong mathematical guarantees, noise-based
   - Cons: Complex implementation, reduces data utility, requires expertise

3. **Aggregation Only**
   - Pros: Simple, familiar
   - Cons: Small groups still reveal individuals

4. **K-Anonymity**
   - Pros: Simple to understand/implement, effective for education data
   - Cons: Can be circumvented with auxiliary information

5. **Data Masking**
   - Pros: Simple
   - Cons: Reduces data utility significantly

## Decision
We have chosen **K-Anonymity** with **k=5** as minimum group size for all analytics aggregations.

## Rationale

### 1. Simple and Understandable
- District administrators understand "groups of at least 5"
- No complex mathematical concepts to explain
- Aligns with FERPA guidance on small numbers
- Easy to audit and verify compliance

### 2. FERPA Alignment
FERPA guidance states:
> "Information from education records must be released in a form that does not permit personal identification of students"
> 
> Small numbers (typically < 5) can enable identification

K-anonymity ensures each data point represents at least k individuals.

### 3. Practical Implementation
```python
# Simple validation
def validate_k_anonymity(student_count: int, k: int = 5) -> bool:
    """Ensure group has minimum size."""
    return student_count >= k

# Database constraint
ALTER TABLE performance_aggregates
ADD CONSTRAINT check_k_anonymity
CHECK (student_count >= k_anonymity);
```

### 4. Flexible Thresholds
Different data types can have different k values:
- **General analytics**: k=5 (default)
- **Sensitive data** (disability, IEP status): k=10
- **Demographic intersections**: k=5 per group

### 5. Query-Time Enforcement
```python
async def aggregate_performance(
    district_id: UUID,
    min_k_anonymity: int = 5,
    **filters
) -> PerformanceAggregate:
    """Aggregate with k-anonymity protection."""
    # Build query with k-anonymity check
    query = (
        select(
            func.count(distinct(Student.id)).label('student_count'),
            func.avg(LearningSession.engagement_score).label('avg_engagement'),
            func.avg(Student.progress_rate).label('avg_progress')
        )
        .join(LearningSession)
        .where(Student.district_id == district_id)
        .group_by(Student.school_id, Student.grade_level)
        .having(func.count(distinct(Student.id)) >= min_k_anonymity)
    )
    
    result = await db.execute(query)
    
    # Additional check
    for row in result:
        if row.student_count < min_k_anonymity:
            raise ValidationError(
                f"Insufficient data for k-anonymity (k={min_k_anonymity})"
            )
    
    return aggregate
```

### 6. Suppression for Small Groups
When groups are too small, suppress the data:

```python
def apply_k_anonymity_suppression(
    aggregates: List[PerformanceAggregate],
    k: int = 5
) -> List[PerformanceAggregate]:
    """Suppress aggregates with insufficient students."""
    return [
        agg for agg in aggregates
        if agg.student_count >= k
    ]
```

## Implementation Details

### Database Models

```python
class PerformanceAggregate(Base):
    """K-anonymous performance aggregation."""
    __tablename__ = "performance_aggregates"
    
    id = Column(UUID, primary_key=True)
    district_id = Column(UUID, ForeignKey("districts.id"), nullable=False)
    school_id = Column(UUID, ForeignKey("schools.id"))
    grade_level = Column(String(5))
    
    # Aggregation metadata
    student_count = Column(Integer, nullable=False)
    k_anonymity = Column(Integer, nullable=False, default=5)
    
    # Aggregated metrics
    avg_engagement_score = Column(Float)
    avg_progress_rate = Column(Float)
    avg_session_count = Column(Float)
    
    # Time period
    period_start = Column(DateTime, nullable=False)
    period_end = Column(DateTime, nullable=False)
    
    # K-anonymity constraint
    __table_args__ = (
        CheckConstraint(
            'student_count >= k_anonymity',
            name='check_k_anonymity'
        ),
    )
```

### Service Layer

```python
class AnalyticsService:
    """Analytics with k-anonymity protection."""
    
    async def aggregate_performance(
        self,
        district_id: UUID,
        period_start: datetime,
        period_end: datetime,
        school_id: Optional[UUID] = None,
        grade_level: Optional[str] = None,
        min_k_anonymity: int = 5
    ) -> PerformanceAggregate:
        """Aggregate performance with k-anonymity."""
        
        # Build base query
        query = (
            select(
                func.count(distinct(Student.id)).label('student_count'),
                func.avg(LearningSession.engagement_score).label('avg_engagement'),
                func.avg(LearningSession.completion_rate).label('avg_completion'),
                func.sum(LearningSession.duration_minutes).label('total_minutes')
            )
            .select_from(Student)
            .join(LearningSession, LearningSession.student_id == Student.id)
            .where(
                Student.district_id == district_id,
                LearningSession.created_at.between(period_start, period_end)
            )
        )
        
        # Apply filters
        if school_id:
            query = query.where(Student.school_id == school_id)
        if grade_level:
            query = query.where(Student.grade_level == grade_level)
        
        # Group by dimensions
        query = query.group_by(Student.school_id, Student.grade_level)
        
        # K-anonymity filter
        query = query.having(func.count(distinct(Student.id)) >= min_k_anonymity)
        
        # Execute query
        result = await self.db.execute(query)
        row = result.one_or_none()
        
        if not row:
            raise ValidationError(
                f"Insufficient data for k-anonymity (minimum {min_k_anonymity} students required)"
            )
        
        # Validate k-anonymity
        if row.student_count < min_k_anonymity:
            raise ValidationError(
                f"K-anonymity violation: {row.student_count} < {min_k_anonymity}"
            )
        
        # Create aggregate
        aggregate = PerformanceAggregate(
            district_id=district_id,
            school_id=school_id,
            grade_level=grade_level,
            student_count=row.student_count,
            k_anonymity=min_k_anonymity,
            avg_engagement_score=row.avg_engagement,
            avg_completion_rate=row.avg_completion,
            total_minutes=row.total_minutes,
            period_start=period_start,
            period_end=period_end
        )
        
        await self.db.add(aggregate)
        await self.db.commit()
        
        return aggregate
```

### API Endpoints

```python
@router.get("/analytics/performance", response_model=PerformanceAggregateResponse)
async def get_performance_metrics(
    period_start: datetime,
    period_end: datetime,
    school_id: Optional[UUID] = None,
    grade_level: Optional[str] = None,
    min_k_anonymity: int = Query(5, ge=5, le=20),  # Configurable, min 5
    current_user: User = Depends(require_role(UserRole.DISTRICT_ADMIN)),
    analytics_service: AnalyticsService = Depends()
):
    """
    Get performance metrics with k-anonymity protection.
    
    **K-Anonymity**: Results are only returned if there are at least
    `min_k_anonymity` students in the group. This protects individual
    student privacy while providing meaningful aggregate insights.
    
    **Parameters:**
    - min_k_anonymity: Minimum group size (default=5, FERPA recommended)
    
    **Returns:**
    - Aggregated metrics only if k-anonymity is satisfied
    - 400 error if insufficient students for anonymity
    """
    try:
        aggregate = await analytics_service.aggregate_performance(
            district_id=current_user.district_id,
            period_start=period_start,
            period_end=period_end,
            school_id=school_id,
            grade_level=grade_level,
            min_k_anonymity=min_k_anonymity
        )
        return aggregate
    except ValidationError as e:
        raise HTTPException(
            status_code=400,
            detail={
                "error": "k_anonymity_violation",
                "message": str(e),
                "min_k_required": min_k_anonymity,
                "recommendation": "Try broader filters or longer time period"
            }
        )
```

### Frontend Handling

```typescript
// Handle k-anonymity errors gracefully
async function fetchPerformanceMetrics(filters: AnalyticsFilters) {
  try {
    const response = await api.get('/analytics/performance', {
      params: filters
    });
    return response.data;
  } catch (error) {
    if (error.response?.data?.error === 'k_anonymity_violation') {
      // Show user-friendly message
      return {
        error: true,
        message: 'Insufficient data for privacy protection. Try selecting a broader group or longer time period.',
        min_required: error.response.data.min_k_required
      };
    }
    throw error;
  }
}
```

## Advanced K-Anonymity Techniques

### 1. Generalization
When k-anonymity can't be satisfied, generalize the data:

```python
# If grade 5 has only 3 students, group with grade 4 → "Grades 4-5"
def generalize_grade_level(grade: str, student_count: int, k: int = 5):
    """Generalize grade level if needed."""
    if student_count >= k:
        return grade  # Specific grade
    else:
        # Generalize to grade band
        grade_num = int(grade) if grade.isdigit() else 0
        band = (grade_num // 2) * 2
        return f"Grades {band}-{band+1}"
```

### 2. Multi-Dimensional K-Anonymity
Ensure k-anonymity across multiple dimensions:

```python
# Check k-anonymity for demographic intersections
def check_multidimensional_k_anonymity(
    student_groups: List[StudentGroup],
    k: int = 5
) -> bool:
    """Verify k-anonymity across all dimensions."""
    for group in student_groups:
        # Check primary dimension
        if group.count < k:
            return False
        
        # Check demographic breakdowns
        for demographic in group.demographics:
            if demographic.count < k:
                # Suppress this demographic breakdown
                demographic.suppressed = True
    
    return True
```

### 3. Temporal K-Anonymity
Ensure k-anonymity over time periods:

```python
# Expand time window if insufficient students
async def aggregate_with_temporal_expansion(
    district_id: UUID,
    start_date: date,
    k: int = 5,
    max_window_days: int = 90
):
    """Expand time window to satisfy k-anonymity."""
    window_days = 7  # Start with 1 week
    
    while window_days <= max_window_days:
        period_start = start_date - timedelta(days=window_days)
        period_end = start_date
        
        count = await get_student_count(district_id, period_start, period_end)
        
        if count >= k:
            return await aggregate_performance(district_id, period_start, period_end)
        
        window_days += 7  # Expand by 1 week
    
    raise ValidationError(f"Cannot achieve k={k} within {max_window_days} days")
```

## Limitations & Trade-offs

### Limitations
1. **Auxiliary Information**: K-anonymity doesn't protect against attackers with external knowledge
2. **Homogeneity Attack**: If all students in a group have same sensitive attribute
3. **Background Knowledge**: Attackers with specific student information can still identify

### Mitigations
1. **L-Diversity**: Ensure diversity in sensitive attributes within groups
2. **T-Closeness**: Ensure distribution of sensitive attributes matches overall distribution
3. **Access Controls**: Limit who can query analytics
4. **Audit Logging**: Track all analytics queries for compliance

### Trade-offs
- ✅ Strong privacy protection
- ⚠️ May suppress valuable insights for small schools
- ⚠️ Requires larger datasets for detailed breakdowns
- ⚠️ Can't provide individual student progress to teachers (use different system)
