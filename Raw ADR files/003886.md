# ADR-002: Tag Taxonomy Strategy

**Status:** Proposed

**Date:** 2026-01-09

**Deciders:** [You]

## Context

When auto-tagging notes, we need to decide how tags are created and managed:
- Should we use a fixed set of predefined tags?
- Should the LLM create tags freely based on content?
- Or a hybrid approach?

This affects:
- Tag consistency (same concept = same tag)
- Discoverability (can users predict what tags exist?)
- Flexibility (can capture unexpected topics?)
- Prompt engineering complexity
- Future fine-tuning potential

## Decision Drivers

* **Consistency:** "career" vs "careers" vs "job" should be the same tag
* **Flexibility:** Don't want to miss emerging themes in your thinking
* **Usability:** Tags should be useful for filtering
* **LLM reliability:** Fewer choices = more consistent outputs
* **Learning goal:** Understand classification prompt design

## Considered Options

1. **Fixed taxonomy** — Predefined list of 20-50 tags
2. **Free-form tags** — LLM generates any tags it sees fit
3. **Hybrid: Categories + Free tags** — Fixed high-level + free-form sub-tags
4. **Emergent then consolidate** — Free-form initially, merge similar tags later

## Analysis

### Option 1: Fixed Taxonomy

```python
ALLOWED_TAGS = [
    "work", "career", "learning", "ideas", "projects",
    "relationships", "health", "finance", "travel", "books",
    "technology", "ai", "philosophy", "creativity", "goals",
    # ... 20-50 total
]

prompt = f"""
Classify this note using ONLY these tags: {ALLOWED_TAGS}
Select 1-5 that apply.
"""
```

**Pros:**
* Guaranteed consistency
* Predictable filtering experience
* Simpler prompt engineering
* Easier evaluation (known set)

**Cons:**
* Misses unexpected topics
* Requires upfront taxonomy design
* May force awkward fits
* Need to update taxonomy over time

### Option 2: Free-Form Tags

```python
prompt = """
Generate 1-5 descriptive tags for this note.
Tags should be lowercase, 1-3 words each.
"""
```

**Pros:**
* Captures any topic
* No upfront design needed
* Adapts to your actual content

**Cons:**
* Inconsistency: "ai" vs "artificial-intelligence" vs "machine-learning"
* Tag explosion over time
* Harder to filter (which tag to choose?)
* LLM may generate useless tags

### Option 3: Hybrid — Categories + Free Tags

```python
CATEGORIES = ["work", "personal", "learning", "ideas", "reference"]

prompt = """
1. Select ONE primary category from: {CATEGORIES}
2. Generate 1-4 additional descriptive tags (free-form)
"""

# Result: category="learning", tags=["llm-engineering", "career", "projects"]
```

**Pros:**
* High-level consistency (always has a category)
* Flexibility for specifics
* Good filtering UX (filter by category, then browse tags)
* Balanced complexity

**Cons:**
* More complex prompt
* Two classification tasks in one call
* Category might not always fit

### Option 4: Emergent Then Consolidate

```python

# Phase 2: Analyze tag distribution, identify synonyms

def normalize_tag(tag):
    synonyms = {
        "ai": ["artificial-intelligence", "machine-learning", "ml"],
        "career": ["job", "work", "employment"],
        # Built from observed data
    }
    # ... normalize
```

**Pros:**
* Learn from actual usage patterns
* Don't over-engineer upfront
* Tags reflect your actual thinking
* Good learning exercise (tag clustering)

**Cons:**
* Messy data initially
* Requires cleanup effort later
* Inconsistent experience during Phase 1
* Technical debt if not addressed

## Recommendation

For a learning project with personal use:

**Start with Option 4 (Emergent)**, then evolve:

**Phase 1:** 
- Free-form tags
- Log all generated tags
- Learn what the LLM produces naturally

**Phase 2:**
- Analyze tag distribution (which are most common?)
- Identify synonyms and consolidate
- Consider adding category layer

**Phase 3+:**
- Stabilize taxonomy based on learnings
- Add normalization/suggestion layer

**Why this approach:**
1. Avoids premature optimization
2. Good learning opportunity (see LLM behavior)
3. Taxonomy emerges from your actual content
4. Can always add constraints later

## Implementation Notes

**Free-form prompt with guidance:**

```python
TAGGING_PROMPT = """
Generate 1-5 tags for this note.

Guidelines:
- Lowercase only
- Single words or short phrases (2-3 words max)
- Use common terms (prefer "ai" over "artificial-intelligence")
- Be specific enough to be useful for filtering
- Avoid generic tags like "note" or "thought"

Return JSON: {"tags": ["tag1", "tag2"], "summary": "...", "confidence": 0.9}
"""
```

**Phase 2 consolidation query:**

```sql
-- Find potential synonyms (tags that rarely co-occur but appear in similar notes)
SELECT t1.name, t2.name, COUNT(*) as co_occurrence
FROM note_tags nt1
JOIN note_tags nt2 ON nt1.note_id = nt2.note_id AND nt1.tag_id < nt2.tag_id
JOIN tags t1 ON nt1.tag_id = t1.id
JOIN tags t2 ON nt2.tag_id = t2.id
GROUP BY t1.name, t2.name
ORDER BY co_occurrence DESC;
```
