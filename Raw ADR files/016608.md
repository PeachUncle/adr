# ADR-009: Adoption of ex_money Library for Currency Management

## Status

Accepted

## Date

2025-09-20

## Context

SharedLedger initially implemented custom currency conversion logic with hardcoded EUR and KRW support. This approach had several limitations:

- Manual exchange rate management
- Custom Money type implementation with potential edge cases
- Hardcoded currency fields in database schemas
- Limited currency formatting capabilities
- No built-in CLDR (Common Locale Data Repository) support

The application needed a more robust, maintainable solution for handling multi-currency transactions in an international context.

## Decision

We adopted the [ex_money](https://github.com/kipcole9/money) library along with [ex_cldr](https://github.com/elixir-cldr/cldr) for comprehensive currency management. This includes:

1. **Library Stack**:
   - `ex_money` for Money type and operations
   - `ex_cldr` for locale and formatting
   - `ex_money_sql` for Ecto integration
   - Custom exchange rate provider with mock/real fallback

2. **Architecture Changes**:
   - Replaced custom Money module with library Money type
   - Removed hardcoded `amount_eur` and `amount_krw` fields
   - Implemented intelligent exchange rate system with environment-based configuration
   - Created `SharedLedger.Cldr` module for centralized configuration

## Consequences

### Positive

- **Industry Standard**: Leveraging battle-tested libraries used in production systems
- **CLDR Compliance**: Proper locale-aware formatting and parsing
- **Extensibility**: Easy to add new currencies without schema changes
- **Maintainability**: Reduced custom code to maintain
- **Accuracy**: Built-in handling of currency precision and rounding rules
- **Testing**: Mock exchange rates for predictable test environments

### Negative

- **Dependency**: Added external dependencies that need maintenance
- **Migration Complexity**: Required careful migration of existing Money data
- **Learning Curve**: Developers need to understand ex_money API
- **Configuration**: More complex initial setup with CLDR compilation

### Neutral

- **Performance**: Library overhead vs custom implementation is negligible
- **Database Storage**: Money stored as composite type (amount + currency)

## Implementation Notes

### Configuration

```elixir
# config/config.exs
config :ex_money,
  default_cldr_backend: SharedLedger.Cldr,
  exchange_rates_retrieve_every: 300_000,
  api_module: Money.ExchangeRates.OpenExchangeRates,
  callback_module: SharedLedger.Currency.ExchangeRates,
  exchange_rates_cache_module: Money.ExchangeRates.Cache.Ets

config :shared_ledger, SharedLedger.Cldr,
  default_locale: "en",
  locales: ["en", "de", "ko"],
  providers: [Money, Number]
```

### Migration Path

1. Add ex_money dependencies
2. Configure CLDR backend
3. Update Money type references
4. Migrate database fields
5. Update formatting functions
6. Remove legacy conversion code

## Alternatives Considered

1. **Continue with Custom Implementation**
   - Pros: Full control, no dependencies
   - Cons: Reinventing the wheel, maintenance burden

2. **Other Libraries (money_lib, currencies)**
   - Pros: Potentially simpler API
   - Cons: Less comprehensive, no CLDR support

3. **Decimal-only with Manual Currency Tracking**
   - Pros: Simple, no library needed
   - Cons: No type safety, manual everything
