# ADR-001: Voice Pipeline Architecture v8.4

**Date:** December 2024  
**Status:** Accepted  
**Deciders:** scAIe Engineering Team

## Context

cAIl needs a voice pipeline that can handle real-time conversations with:
- Natural language understanding
- Low latency responses
- Seamless handoff to human agents for scheduling

Previous versions (v8.2, v8.3) had issues with:
- Mock data in production flows
- Inconsistent handoff to Chatwoot
- No proper waiting mechanism during external API calls

## Decision

Implement **Pipeline v8.4 "Real Operations"** with:

### 1. Smart Wait Loop
When waiting for external systems (n8n/Cal.com scheduling), use Redis pub/sub:
- Store call mapping: `cail:call_mapping:{chatwoot_conv_id}` → `call_id`
- Wait for response: `cail:scheduling:{call_id}:response`
- Play natural filler phrases every 10 seconds
- Timeout after 90 seconds with graceful fallback

### 2. Chatwoot Silent Sync
All conversations are synchronized to Chatwoot in the background:
- No user interaction required
- Provides audit trail
- Enables human takeover if needed
- Triggers n8n workflows for scheduling

### 3. Single Pipeline Version
Remove v8.2 and v8.3 pipelines. Redirect all calls to v8.4:
- `v8.4_real` is the only active pipeline
- `v8.3_local` redirects to v8.4
- Legacy handlers kept for rollback only

## Consequences

### Positive
- No mock data in production
- Consistent user experience
- Clear handoff flow
- Easier debugging with single pipeline

### Negative
- Requires Redis for Smart Wait
- Dependent on Chatwoot/n8n availability
- 90-second timeout may frustrate users

## Alternatives Considered

1. **Direct Cal.com integration**: Rejected - too tightly coupled
2. **WebSocket real-time updates**: Rejected - complexity not justified
3. **Polling Chatwoot API**: Rejected - higher latency and API limits
