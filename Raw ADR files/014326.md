# TASK-012: Intent service for backend categories
> Source: tasks/tasks.md

## Context
- Create IntentService to classify user queries into specific backend categories
- Use OllamaClient for LLM-based classification with regex fallback
- Support 10 intent categories with field extraction (tickers, user_id, query, trade_action, quantity, price)
- Provide robust fallback when LLM returns invalid JSON

## Options Considered
- Option A: Pure LLM classification (Pros: Accurate, Cons: Unreliable JSON output)
- Option B: Pure regex classification (Pros: Reliable, Cons: Less accurate for complex queries)
- Option C: Hybrid LLM + regex fallback (Pros: Best accuracy with reliability, Cons: More complex)

## Decision
- Chosen approach: Hybrid IntentService with LLM primary and regex fallback
- Uses OllamaClient for primary classification with temperature 0.1 for stability
- Implements sophisticated regex fallback with keyword mapping and ticker extraction
- Pydantic model validation ensures consistent output format

## Impacts
- Performance: LLM classification ~500ms, regex fallback ~10ms
- Complexity: Medium complexity with dual-path classification logic
- Security/Privacy: No additional security concerns, uses existing Ollama setup
- Compatibility: Works with or without LLM availability
- Risks & Mitigations: 
  - Risk: LLM returns non-JSON responses
  - Mitigation: Robust regex fallback with keyword mapping and ticker extraction
