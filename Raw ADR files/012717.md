Abstract:: Writing EPs currently requires scanning through contracts to deciding if they are relevant to any Spec Objects implicated in the EP. The list of contracts at risk when interacting with any Spec Object should be centralized.

## Motivation
> Description of the goals achieved by this Enhancement Proposal and argument that this is the minimal alteration of the Production Spec that would achieve those goals. From PEP 1: "It should clearly explain why the existing language specification is inadequate to address the problem that the PEP solves."

Writing EPs currently requires scanning through contracts to deciding if they are relevant to any Spec Objects implicated in the EP. This is both error-prone and laborious.

## Rationale
> Explanation of major design decisions, including comparison to alternative designs and related work, e.g. how the problem is solved in other software or systems.

The original implementation intended to avoid being too verbose or duplicating information. Another possibility that existed at the outset was placing contracts with the associated spec objects directly, but this didn't allow for contracts that governed relations between SOs or even ones that governed multiple SOs. Two intermediate solutions are to
- List the Contracts that SOs' instances should obey alongside the Properties in a new area under the SO heading.
- List the SOs that should obey a Contract in the Contract's section.
The former makes it slightly easier to write EPs, but introduces risk that a contract will be edited without binding SOs to obey it.

## Contracts at Risk
> Description of how Contracts of any involved Spec Objects were maintained.

No contracts directly bind the Spec Object "Spec Object" or Spec Object Contract which are all that is edited directly here other than SOC 1.
The only section of the DOP that goes into any detail about the content edited here is the "Consistency" section, which does not state precisely how SOs and SOCs are related.

## Spec Changes
> Alterations to Objects, Contracts or Workflows that will achieve the goal of the EP.

##### Spec Object Contract
Add the following property:
- *Bound Spec Objects.* A List of Spec Objects whose instances could possibly fail to obey the contract.

#### Docs Overview Page describes the system accurately
Add the following text:
**Bound SOs.** All spec objects.

##### Scope of Master Branch
Add the following text:
**Bound SOs.** Master Branch.

##### Editing rules for Notes
Add the following text:
**Bound SOs.** System, Snapshot, Living, Daily, Entry, and Area Notes
