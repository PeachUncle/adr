## Context

The trading system requires a multi-agent framework to implement the 3-tier hierarchical agent architecture specified in the V5 strategy documentation. The system must support:

1. **3-State Machine**: MARKET_SCANNING → POSITION_ACTIVE → POSITION_DEFENSE (+ RECOVERY_MODE sub-state)
2. **Hierarchical Agents**: 3 levels (Orchestrator, Stock Selection, Strategy Execution) + Service agents
3. **Communication Patterns**: Command/Query (sync), Delegation (async), Proposal/Approval (async)
4. **State Persistence**: Operational state (Redis) + Permanent memory (Cloud SQL)
5. **Event-Driven Execution**: VIX-based dynamic scheduling, real-time Greeks updates
6. **ML Integration**: Market regime classifier, ensemble entry system
7. **GCP Integration**: BigQuery analytics, Cloud SQL, Redis (Memorystore)

**Requirements**:
- Async-first execution model
- Built-in state machine support
- Native GCP service integration
- State persistence and checkpointing
- Tool/function calling for broker API integration
- Structured agent communication
- Production-ready monitoring and observability

---

## Decision

**Adopt Google Agent Development Kit (ADK)** as the primary agentic framework for implementing the multi-agent trading system.

---

## Rationale

### Why Google ADK

**1. Native GCP Integration**
- First-class support for GCP services (BigQuery, Cloud SQL, Memorystore Redis, Vertex AI)
- No additional API wrappers or authentication complexity
- Integrated monitoring via Google Cloud Operations Suite
- Matches existing infrastructure decisions (ADR-004 BigQuery, ADR-006 IB Gateway)

**2. State Machine Native**
- Built-in support for complex state graphs
- Conditional routing based on dynamic thresholds (Risk Budget, Greeks, VIX)
- Sub-state management (RECOVERY_MODE within POSITION_DEFENSE)
- State persistence with checkpointing
- Handles circular transitions (POSITION_DEFENSE adjustment loops)

**3. Agent Orchestration**
- Hierarchical agent coordination (Level 1 → Level 2 → Level 3)
- Multiple communication patterns (sync/async/proposal-approval)
- Built-in message passing and event handling
- Agent-to-agent delegation
- Service agent pattern support

**4. Production Readiness**
- Enterprise-grade reliability and performance
- Built-in monitoring and telemetry
- Error handling and retry mechanisms
- Logging and observability integration
- Security and authentication built-in

**5. Tool Integration**
- Function/tool calling for broker API (Interactive Brokers Gateway)
- Model Context Protocol (MCP) support for external tools (ADR-011)
- Structured data validation (matches Pydantic requirement)
- API integration patterns

**6. ML/AI Integration**
- Vertex AI integration for ML models (Market Regime Classifier)
- Model versioning and deployment
- A/B testing support (ensemble entry system)
- Fallback mechanism support

**7. Async Execution**
- Async-first design (matches AsyncPG, Redis async requirements)
- Non-blocking agent execution
- Concurrent task processing
- Event-driven triggers (VIX updates, Greeks calculations)

### State Machine Definition (ADK State Graph)

```python
from google.adk import Agent, StateGraph, State, Transition

# Define states
states = {
    "MARKET_SCANNING": State(
        name="MARKET_SCANNING",
        agent=stock_selection_agent,
        transitions=[
            Transition(
                to="POSITION_ACTIVE",
                condition=lambda ctx: ctx["trade_validated"] and ctx["risk_approved"],
                action=execute_entry
            )
        ]
    ),
    "POSITION_ACTIVE": State(
        name="POSITION_ACTIVE",
        agent=position_monitoring_agent,
        transitions=[
            Transition(
                to="MARKET_SCANNING",
                condition=lambda ctx: ctx["profit_target_hit"] or ctx["time_exit"],
                action=close_position
            ),
            Transition(
                to="POSITION_DEFENSE",
                condition=lambda ctx: ctx["risk_budget_consumption"] > 0.60,
                action=initiate_defense
            )
        ]
    ),
    "POSITION_DEFENSE": State(
        name="POSITION_DEFENSE",
        agent=defensive_adjustment_agent,
        sub_states=["RECOVERY_MODE"],
        transitions=[
            Transition(
                to="POSITION_ACTIVE",
                sub_state="RECOVERY_MODE",
                condition=lambda ctx: ctx["adjustment_successful"],
                action=update_recovery_target
            ),
            Transition(
                to="MARKET_SCANNING",
                condition=lambda ctx: ctx["recovery_complete"] or ctx["forced_exit"],
                action=close_position
            )
        ]
    )
}

# Create state graph
trading_state_machine = StateGraph(
    states=states,
    initial_state="MARKET_SCANNING",
    persistence=StateGraphPersistence(
        redis_url="redis://memorystore-instance:6379",
        cloudsql_connection="project:region:instance"
    )
)
```

### Communication Patterns

```python
from google.adk import Agent, Message, MessageType

class PortfolioOrchestrator(Agent):
    """Level 1: Master coordinator agent"""

    async def delegate_stock_selection(self):
        """Delegation pattern (async)"""
        message = Message(
            type=MessageType.DELEGATE,
            recipient="stock_selection_agent",
            payload={"task": "find_opportunity", "vix_regime": self.vix_regime},
            response_required=True,
            timeout=300  # 5 minutes
        )
        response = await self.send_async(message)
        return response

    async def validate_risk(self, trade_proposal):
        """Command/Query pattern (sync)"""
        message = Message(
            type=MessageType.QUERY,
            recipient="risk_management_agent",
            payload={"trade": trade_proposal},
            response_required=True,
            timeout=10
        )
        response = await self.send_sync(message)
        return response

    async def handle_defensive_proposal(self, proposal):
        """Proposal/Approval pattern (async)"""
        # Strategy agent sends proposal
        if self.evaluate_proposal(proposal):
            approval = Message(
                type=MessageType.APPROVAL,
                recipient=proposal.sender,
                payload={"approved": True, "authorization": self.get_auth_token()},
                response_required=False
            )
            await self.send_async(approval)
        else:
            rejection = Message(
                type=MessageType.REJECTION,
                recipient=proposal.sender,
                payload={"rejected": True, "reason": "Portfolio heat exceeded"},
                response_required=False
            )
            await self.send_async(rejection)
```

### Tool Integration (MCP Support)

```python
from google.adk import Tool, MCPTool

class IronCondorAgent(Agent):
    """Level 3: Iron Condor strategy execution agent"""

    def __init__(self):
        super().__init__(name="iron_condor_agent")

        # Register MCP tools (ADR-012)
        self.register_tool(MCPTool(
            name="get_options_chain",
            mcp_server="ib_gateway_mcp",
            function="fetch_options_chain",
            description="Fetch options chain data from Interactive Brokers"
        ))

        self.register_tool(MCPTool(
            name="calculate_greeks",
            mcp_server="greeks_calculation_mcp",
            function="compute_greeks",
            description="Calculate Greeks for options positions"
        ))

        self.register_tool(MCPTool(
            name="execute_trade",
            mcp_server="trade_execution_mcp",
            function="submit_order",
            description="Submit order to Interactive Brokers"
        ))

    async def analyze_opportunity(self, symbol: str) -> dict:
        """Use MCP tools to analyze trading opportunity"""
        # Fetch options chain via MCP
        options_chain = await self.use_tool(
            "get_options_chain",
            {"symbol": symbol, "dte_range": [30, 45]}
        )

        # Calculate Greeks via MCP
        greeks = await self.use_tool(
            "calculate_greeks",
            {"options_chain": options_chain}
        )

        return {"chain": options_chain, "greeks": greeks}
```

### State Persistence

```python
from google.adk import StatePersistence
from google.cloud import sql, memorystore

class TradingSystemPersistence:
    """Dual persistence: Redis (operational) + Cloud SQL (permanent)"""

    def __init__(self):
        # Operational state (Redis Memorystore)
        self.redis_persistence = StatePersistence(
            backend="redis",
            connection_string="redis://memorystore:6379",
            ttl=86400  # 24 hours
        )

        # Permanent state (Cloud SQL)
        self.sql_persistence = StatePersistence(
            backend="cloudsql",
            connection_string="postgresql://user:pass@cloudsql-proxy/trading_db",
            checkpoint_interval=60  # 1 minute
        )

    async def save_state(self, agent_id: str, state: dict):
        """Save to both Redis (fast) and Cloud SQL (permanent)"""
        await self.redis_persistence.save(agent_id, state)
        await self.sql_persistence.checkpoint(agent_id, state)

    async def load_state(self, agent_id: str) -> dict:
        """Load from Redis first, fallback to Cloud SQL"""
        state = await self.redis_persistence.load(agent_id)
        if state is None:
            state = await self.sql_persistence.load(agent_id)
        return state
```

## Monitoring and Observability

### Google Cloud Operations Integration

```python
from google.adk import Agent
from google.cloud import monitoring_v3, logging

class MonitoredAgent(Agent):
    """Base agent with Cloud Operations integration"""

    def __init__(self, name: str):
        super().__init__(name=name)

        # Cloud Monitoring (metrics)
        self.monitoring_client = monitoring_v3.MetricServiceClient()

        # Cloud Logging (structured logs)
        self.logging_client = logging.Client()
        self.logger = self.logging_client.logger(f"agent-{name}")

    async def execute_task(self, task: dict):
        """Instrumented task execution"""
        start_time = time.time()

        try:
            result = await self._execute_task_impl(task)

            # Record success metric
            self.record_metric(
                "agent.task.success",
                value=1,
                labels={"agent": self.name, "task_type": task["type"]}
            )

            # Structured log
            self.logger.log_struct({
                "severity": "INFO",
                "agent": self.name,
                "task_type": task["type"],
                "duration_ms": (time.time() - start_time) * 1000,
                "status": "success"
            })

            return result

        except Exception as e:
            # Record failure metric
            self.record_metric(
                "agent.task.failure",
                value=1,
                labels={"agent": self.name, "error_type": type(e).__name__}
            )

            # Error log
            self.logger.log_struct({
                "severity": "ERROR",
                "agent": self.name,
                "task_type": task["type"],
                "error": str(e),
                "traceback": traceback.format_exc()
            })

            raise
```

**Key Metrics**:
- `agent.task.duration` - Task execution time (ms)
- `agent.task.success` - Successful task completions
- `agent.task.failure` - Failed task attempts
- `agent.state.transition` - State machine transitions
- `agent.message.sent` - Inter-agent messages sent
- `agent.message.received` - Inter-agent messages received
- `agent.tool.call` - MCP tool invocations

**Dashboards**:
- Agent health and uptime
- State machine transition flow
- Communication pattern visualization

## Consequences

### Positive

1. **Native GCP Integration**: Seamless integration with BigQuery, Cloud SQL, Memorystore Redis
2. **Production Ready**: Enterprise-grade monitoring, logging, error handling built-in
3. **State Machine Native**: Complex state graphs with sub-states handled natively
4. **Reduced Development Time**: Pre-built components for agent coordination, persistence, communication
5. **Scalability**: Cloud Run auto-scaling for service agents
6. **Maintainability**: Structured agent framework reduces custom code
7. **Security**: GCP IAM integration, service accounts, Secret Manager support
8. **Tool Integration**: MCP support (ADR-012) for broker API abstraction

### Negative

1. **Framework Lock-In**: Committed to Google ADK ecosystem
2. **Learning Curve**: Team must learn ADK-specific patterns and APIs
3. **GCP Dependency**: Strongly coupled to Google Cloud Platform
4. **Documentation**: ADK is newer, less community documentation than LangChain
5. **Migration Cost**: Switching frameworks in future would be expensive

### Mitigation Strategies

**Lock-In Mitigation**:
- Keep business logic separate from ADK framework code
- Use adapter pattern for ADK-specific functionality
- Document all ADK dependencies for potential migration

**Learning Curve Mitigation**:
- Allocate 2 weeks for team training on Google ADK
- Build comprehensive internal documentation
- Create agent templates for common patterns

**GCP Dependency Mitigation**:
- Use environment variables for all GCP resource references
- Design agents to be cloud-agnostic at business logic level
- Consider multi-cloud strategy in future ADR if needed

## Alternatives Considered

### LangGraph (LangChain)
**Pros**: Mature ecosystem, strong community, state machine support
**Cons**: Manual GCP integration, no native monitoring, requires custom tooling
**Verdict**: Strong alternative, but lacks GCP native advantages

### CrewAI
**Pros**: Easy to learn, hierarchical agents, task delegation
**Cons**: Limited state machine support, no GCP integration, paid tiers for features
**Verdict**: Too simplistic for complex state management requirements

### Custom (AsyncIO + Redis)
**Pros**: Maximum control, no framework overhead, exact specification match
**Cons**: High development cost, manual monitoring setup, reinventing agent patterns
**Verdict**: Not justified given Google ADK availability

### AutoGen (Microsoft)
**Pros**: Strong multi-agent patterns, Azure integration
**Cons**: Azure-centric (conflicts with GCP choice), limited state machine support
**Verdict**: Incompatible with GCP infrastructure decisions
