# ADR-001: Technology Stack Selection

**Status:** Accepted
**Date:** January 2026
**Author:** Chris Therriault

---

## Context

Secure Reader requires a technology stack that supports:
1. High-security document processing
2. AI/LLM integration with multiple providers
3. Fast development iteration
4. Future confidential computing capability
5. White-label deployment for enterprise customers

---

## Decision

### Backend Services

| Component | Technology | Rationale |
|-----------|------------|-----------|
| API Gateway | Python + FastAPI | Async, type-safe, LLM ecosystem |
| Document Processor | Rust | Memory safety, performance, WASM |
| AI Service | Python + LangChain | LLM ecosystem, rapid iteration |
| Policy Engine | Python | Business logic flexibility |

### Frontend

| Component | Technology | Rationale |
|-----------|------------|-----------|
| Web App | React + TypeScript | Type safety, ecosystem |
| Styling | Tailwind CSS | Rapid UI development |
| State | React Query | Server state management |

### Infrastructure

| Component | Technology | Rationale |
|-----------|------------|-----------|
| Phase 1 | Render | Fast deployment, low cost |
| Phase 3+ | Azure + AWS | Enterprise compliance |
| Database | PostgreSQL | ACID, JSON support |
| Object Storage | S3/R2 | Scalable document storage |

### LLM Providers

| Priority | Provider | Model | Use Case |
|----------|----------|-------|----------|
| 1 | Anthropic | Claude Haiku | Cost-effective queries |
| 2 | Anthropic | Claude Sonnet | Complex reasoning |
| 3 | Google | Gemini Flash | Fallback |
| 4 | Azure OpenAI | GPT-4 | Enterprise option |

---

## Alternatives Considered

### Go instead of Rust for Document Processor

**Rejected because:**
- Rust provides stronger memory safety guarantees
- WASM compilation better supported
- Performance advantage for crypto operations
- Better fit for security-critical code

### Node.js instead of Python for AI Service

**Rejected because:**
- LangChain/LiteLLM ecosystem is Python-first
- Guardrails AI is Python-only
- Team has stronger Python expertise for AI
- Async performance adequate for our use case

### Next.js instead of Vite/React

**Rejected because:**
- Don't need SSR for this application
- Simpler deployment as static assets
- Lower complexity for white-label embedding

### GCP instead of Azure for Enterprise

**Rejected because:**
- Azure has better confidential computing (SEV-SNP)
- Azure AI Foundry more mature
- Target customers prefer Azure/AWS

---

## Consequences

### Positive

- Strong security posture with Rust for critical paths
- Rapid AI development with Python ecosystem
- Flexible LLM provider switching
- Clear path to enterprise deployment

### Negative

- Multi-language codebase adds complexity
- Team must maintain Rust expertise
- Python performance may require optimization

### Neutral

- Standard enterprise technology choices
- Well-documented migration path
