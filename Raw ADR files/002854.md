# Proposal: add-header-to-renderer

## Why
The current implementation causes visible screen flicker during game loop refresh because UI elements (header, prompt, status messages) are printed separately via shell echo commands before/after the renderer outputs the field visualization. Each separate terminal write operation can cause visible blinking, degrading the user experience. By consolidating all UI rendering into a single Kitty Graphics Protocol output, we eliminate the blinking and provide a smoother, more professional visual experience.

## Objective
Move all game UI text rendering (header, input prompt, status messages) from shell scripts into the Go renderer to eliminate screen blinking caused by separate print operations.

## Problem Statement
Currently, multiple UI elements are printed by shell scripts before or after calling the renderer, creating multiple separate output operations:
1. Shell prints header text via `echo` (title, tick, score, seeds)
2. Shell prints input prompt via `echo` ("Press 'r' to run script...")
3. Go renderer outputs field image via Kitty Graphics Protocol
4. Shell prints status messages during script execution (planted, watered, harvested)

This separation causes visible screen flicker/blinking because the terminal updates happen at different times. The issue is particularly noticeable during the main game loop refresh cycle where the prompt is re-printed every iteration.

**Current implementation locations:**
- `lib/display.sh:9` - `print_header()` function definition
- `lib/display.sh:27` - `print_status()` function definition
- `game.sh:89` - Header printed in main loop
- `game.sh:94` - Input prompt printed in main loop
- `lib/game_api.sh:20` - Header printed in `sync_render()`
- `lib/game_api.sh:58,74,122` - Status messages during game operations

## Proposed Solution
Integrate all UI text rendering into the Go renderer so that header, field, prompt, and status messages are rendered as a single atomic output operation:

1. Pass complete header/banner text as `--header` flag (shell script handles formatting)
2. Pass optional status message and input prompt text as flags
3. Renderer generates complete UI with text overlays on the output image:
   - Header/banner at top (pre-formatted text from shell)
   - Field visualization in center
   - Status message area (if provided)
   - Input prompt at bottom
4. Remove `print_header()`, `print_status()`, and inline echo calls from shell scripts
5. Single Kitty Graphics Protocol output includes complete UI

**Design Decision**: Use `--header` for complete formatted header text instead of individual `--tick`, `--score`, `--seeds` flags. This gives shell scripts full control over header formatting and makes the renderer simpler (just render text, don't format it).

## Benefits
- **Eliminates blinking**: Single atomic terminal output operation for entire UI
- **Better visual consistency**: All UI elements rendered together with unified styling
- **Cleaner separation**: All rendering logic consolidated in renderer
- **Performance**: Reduces terminal I/O operations from multiple to one
- **Better UX**: Smoother visual experience without text/image separation

## Scope
### In Scope
- Add CLI flags to renderer for UI text:
  - `--header`: Complete formatted header/banner text
  - `--status`: Status message
  - `--prompt`: Input prompt
- Implement text rendering in Go renderer for:
  - Header/banner at top (rendered as-is from flag)
  - Input prompt at bottom
  - Status message area
- Update game loop to format and pass complete header text to renderer
- Update game loop to pass prompt text to renderer
- Update sync_render to pass status messages to renderer
- Remove `print_header()` and status echo calls from shell scripts
- Update field-rendering and game-loop-core specs

### Out of Scope
- Changes to game state structure or JSON format
- Modifications to tick daemon or crop update logic
- ASCII fallback rendering (keeps current behavior)
- Terminal compatibility beyond Kitty protocol

## Dependencies
- Requires existing field-rendering capability
- Depends on game-loop-core for state values
- No breaking changes to existing APIs

## Risks and Mitigations
- **Risk**: Renderer becomes more complex with text rendering
  - **Mitigation**: Use existing gg graphics library which supports text
- **Risk**: Error handling for missing state values
  - **Mitigation**: Provide sensible defaults (tick=0, score=0, seeds=0)
- **Risk**: Visual layout may need adjustment
  - **Mitigation**: Use similar ANSI color scheme, maintain readability

## Success Criteria
- No visible screen blinking during game loop refresh
- Header displays correct real-time values with proper formatting
- Shell scripts have full control over header text formatting
- Input prompt appears at bottom of render output
- Status messages from game operations (plant, water, harvest) display correctly
- Single Kitty Graphics Protocol output per render contains all UI elements
- All existing tests pass
- Visual appearance matches or improves current design
- Smooth transitions when status messages appear/disappear
- Renderer remains simple and flexible for future UI changes
