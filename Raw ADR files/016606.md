# ADR-006: Dynamic Currency Conversion Architecture

## Status

Accepted

## Context

After implementing ADR-002 (separate amount/currency fields), we identified a fundamental limitation with the stored `converted_amount` approach:

1. **Single Conversion Limitation**: The `converted_amount_value` and `converted_amount_currency` fields implied only one conversion could be stored
2. **Multi-Currency Support Need**: The application needs to display conversions to multiple currencies (EUR, KRW, USD, JPY, GBP, CHF, CAD, AUD)
3. **Storage Inefficiency**: Pre-calculating and storing conversions for all possible target currencies would be wasteful
4. **Flexibility Requirements**: UI components need to display different conversion currencies based on context
5. **Real-time Rates**: Future exchange rate updates would require batch recalculation of stored conversions

## Decision

We will refactor from stored conversions to dynamic on-demand conversion calculations using Ash calculations:

- **Remove**: `converted_amount_value` and `converted_amount_currency` stored attributes
- **Add**: Dynamic calculation `amount_in` that accepts a target currency parameter
- **Add**: Convenience calculations `amount_in_eur` and `amount_in_krw` for common conversions
- **Use**: AshMoney.Types.Money as the return type for calculations to maintain type safety

## Consequences

### Positive

- **Multi-Currency Support**: Can convert to any supported currency on-demand
- **Storage Efficiency**: Only store original amount/currency, calculate conversions when needed
- **Flexibility**: UI can request specific currency conversions dynamically
- **Real-time Ready**: Future exchange rate updates automatically apply to all conversions
- **Type Safety**: Calculations return proper Money structs with currency information
- **Maintainability**: No need to maintain conversion consistency in database

### Negative

- **Performance**: Conversions calculated on each request (mitigated by fast decimal arithmetic)
- **Query Complexity**: Need to explicitly load calculations when needed
- **Migration Effort**: Required updating all existing code using converted_amount fields

### Neutral

- **API Complexity**: Similar complexity - explicit loading vs accessing stored fields
- **Test Coverage**: Required updating tests but maintained comprehensive coverage

## Implementation

### Before (stored conversions):

```elixir
# Database storage
attribute :amount_value, :decimal, allow_nil?: false
attribute :amount_currency, :atom
attribute :converted_amount_value, :decimal
attribute :converted_amount_currency, :atom

# Usage - limited to one conversion
transaction = Transaction.create(%{
  amount_value: Decimal.new("100.00"),
  amount_currency: :EUR
  # converted_amount automatically calculated and stored
})
```

### After (dynamic conversions):

```elixir
# Database storage - only original values
attribute :amount_value, :decimal, allow_nil?: false
attribute :amount_currency, :atom

# Dynamic calculations
calculate :amount_in, AshMoney.Types.Money do
  argument :currency, :atom, default: :EUR
  # Converts to any target currency on-demand
end

calculate :amount_in_eur, AshMoney.Types.Money
calculate :amount_in_krw, AshMoney.Types.Money

# Usage - flexible multi-currency conversion
transaction = Transaction.create(%{
  amount_value: Decimal.new("100.00"),
  amount_currency: :EUR
})

# Load specific conversions on-demand
Ash.load!(transaction, :amount_in_krw)  # Get KRW conversion
Ash.load!(transaction, amount_in: [currency: :USD])  # Get USD conversion
```

## Technical Details

### Calculation Implementation

```elixir
calculate :amount_in, AshMoney.Types.Money do
  argument :currency, :atom do
    constraints [one_of: [:EUR, :KRW, :USD, :JPY, :GBP, :CHF, :CAD, :AUD]]
    default :EUR
  end

  calculation fn records, %{arguments: %{currency: target_currency}} ->
    Enum.map(records, fn record ->
      if record.amount_value && record.amount_currency do
        money = Money.new(record.amount_currency, record.amount_value)

        if record.amount_currency == target_currency do
          money
        else
          case ConversionService.convert(money, target_currency) do
            {:ok, converted} -> converted
            {:error, _} -> nil
          end
        end
      else
        nil
      end
    end)
  end
end
```

### UI Integration Pattern

```elixir
# Load transactions with conversions
transactions =
  Transaction
  |> Ash.Query.filter(account_id == ^account_id)
  |> Ash.read!(authorize?: false)
  |> Ash.load!([:amount_in_eur, :amount_in_krw], authorize?: false)

# Display logic shows "opposite" currency
def format_converted_amount(transaction) do
  case transaction.amount_currency do
    :EUR -> format_amount(transaction.amount_in_krw.amount, :KRW)
    :KRW -> format_amount(transaction.amount_in_eur.amount, :EUR)
    _ -> "N/A"
  end
end
```
