# ADR-003: ORM vs Raw SQL

## Status
**Status:** Approved

## Context and Problem Statement
Our system will require heavy use of the database for CRUD operations and so will need to perform well under significant user load. We are choosing between using an ORM library or raw SQL statements through the MySQL library. Our decision needs to consider performance, maintainability, scalability and the ease of development.

## Decision Drivers
The decision drivers for choosing the most appropriate solution include:
- **Maintainability**: The solution must simplify code management and updates in the long term.
- **Ease of Development**: The solution should streamline common database operations and be relatively easy to understand.
- **Scalability**: The solution should accommodate complex queries where required and be able to handle expanding system requirements.
- **Performance**: The solution should balance abstraction with query performance.

## Options Considered
- **Sequelize (Chosen)**: A Node.js-based ORM with features for defining models, handling associations, and abstracting database queries.
- **Other ORMs**: Considered options like TypeORM or Knex.js that also provide abstractions for database interactions.
- **Raw SQL**: Writing direct SQL queries without any abstraction, offering maximum control and performance.
- **Hybrid Approach**: Using raw SQL for complex operations while leveraging an ORM for basic CRUD operations.

## Decision Outcome
We have decided to use the ORM **Sequelize** as it provides a good balance between abstraction and control.

## Consequences
### Positive Outcomes:
- **Maintainability**: Code becomes easier to understand and update, with centralized model definitions and consistent patterns for CRUD operations.
- **Productivity**: Simplifies common tasks like defining relationships, migrations, and validation, reducing the development overhead.
- **Cross-Database Compatibility**: Sequelize supports multiple database dialects (MySQL, PostgreSQL, etc.), making it easier to migrate databases if needed.
- **Scalability**: With Sequelize, complex queries can be constructed either through its API or raw SQL injections when required using its Sequelize literal method.

### Negative Outcomes:
- **Performance Overhead**: Abstracted queries may not be as optimized as hand-written raw SQL in certain use cases.
- **Learning Curve**: Developers unfamiliar with Sequelize or ORMs in general may require initial training.
- **Abstraction Limitations**: Handling highly specific queries or non-standard database features might require fallback to raw SQL.
  ## Mitigation Strategy
  The majority of our queries will be standard CRUD operations therefore will not require hand-written SQL. In the cases where this is needed we can still use Sequelize to query the database using raw SQL. To help with the learning curve, Sequelize functions in our code will be accompanied with descriptive comments. Futhermore, the Sequelize documentation is also very in-depth which will help with training.

## Confirmation
To validate our decision, feedback will be gathered from the team to determine how difficult the Sequelize code is to understand and where more training may be required. We will also perform load testing on both Sequelize and raw SQL statements to determine the performance impact.

## Pros and Cons

### Pros
- **Simplicity**: Reduces boilerplate code for common operations.
- **Association Handling**: Built-in support for relationships (one-to-many, many-to-many) simplifies model management.
- **Migration Tools**: Facilitates schema changes with built-in migration support.
- **Community and Documentation**: A robust ecosystem with extensive guides, plugins, and active community support.
- **Prepared Statements**: Built-in query methods sanitise inputs to help protect against SQL injection attacks and validate inputs.

### Cons
- **Performance Trade-offs**: Abstracted queries might not be as efficient as raw SQL.
- **Debugging Complexity**: ORM-generated queries can sometimes be harder to debug than explicit SQL.
- **Complex Query Limitations**: Requires raw SQL for highly specialized database queries.
