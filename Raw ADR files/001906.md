# ADR-002: UX AI Auditor JSON Response Format for Frontend Integration

**Status:** Accepted  
**Date:** 2024-01-15  
**Author:** UX AI Auditor Team  

## Context

Frontend applications need to consume UX/UI analysis results from the UX AI Auditor API to display insights, scores, and recommendations to users. The API must provide a consistent, well-structured JSON format that enables rich frontend visualizations while maintaining flexibility for different analysis types.

## Decision

We will use a standardized JSON response format that includes:
- Overall analysis scores with descriptions
- Hierarchical sections containing categorized findings
- Quick wins for immediate actionable improvements
- Metadata about the analysis execution

## Consequences

**Positive:**
- Consistent data structure across all analysis types
- Easy to parse and render in frontend applications
- Supports progressive disclosure of information
- Enables sorting/filtering by severity and categories

**Negative:**
- Fixed structure may require API versioning for major changes
- Large responses for comprehensive analyses may require pagination

## Quick Start

```javascript
// Analyze a website
const response = await fetch('https://api.example.com/api/v2/api/analyze_direct', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'your-api-key-here'  // Required in production
  },
  body: JSON.stringify({
    url: 'https://example.com',
    analysis_type: 'ux_auditor',
    output_format: ['json']
  })
});

const result = await response.json();
console.log(result.overall_score.value); // 7.5
console.log(result.sections.length); // Number of analysis sections
```

## Authentication

**API Key Required in Production**

In production environments, all API endpoints (except `/health`) require authentication using an API key. The API key can be provided in three ways:

### 1. Header Authentication (Recommended)
```bash
curl -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/health"
```

### 2. Authorization Bearer Token
```bash
curl -H "Authorization: Bearer your-api-key-here" \
  "http://localhost:8000/api/v2/api/health"
```

### 3. Query Parameter
```bash
curl "http://localhost:8000/api/v2/api/health?apiKey=your-api-key-here"
```

**Environment Configuration:**
- **Development**: API key validation is disabled (`ENV=development`)
- **Production**: API key validation is enforced (`ENV=production`)
- **API Key**: Set via `API_KEY` environment variable

## API Endpoints

### 1. Direct Analysis (Blocking)
**Endpoint:** `POST /api/v2/api/analyze_direct`  
**Description:** Performs analysis synchronously and returns results immediately  
**Response Time:** 30-120 seconds depending on analysis type

```javascript
POST /api/v2/api/analyze_direct
Content-Type: application/json

{
  "url": "https://example.com",
  "analysis_type": "ux_auditor",  // Options: "all", "ux_auditor", "ui_tester", "seo_auditor", "competitive"
  "output_format": ["json"]        // Options: ["json", "markdown", "html"]
}
```

**cURL Example:**
```bash
curl -X POST "http://localhost:8000/api/v2/api/analyze_direct" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-api-key-here" \
  -d '{
    "url": "https://ihtys.menu",
    "analysis_type": "ux_auditor",
    "output_format": ["json"]
  }'
```

### 2. Asynchronous Analysis
**Endpoint:** `POST /api/v2/api/analyze`  
**Description:** Starts analysis in background, returns analysis ID  
**Use Case:** For long-running analyses or when you want to show progress

```javascript
// Start analysis
POST /api/v2/api/analyze
{
  "url": "https://example.com",
  "analysis_type": "ux_auditor"
}

Response:
{
  "analysis_id": "abc-123-def",
  "status": "pending",
  "url": "https://example.com"
}

// Check status
GET /api/v2/api/analysis/{analysis_id}
```

**cURL Examples:**

**Start Analysis:**
```bash
curl -X POST "http://localhost:8000/api/v2/api/analyze" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-api-key-here" \
  -d '{
    "url": "https://ihtys.menu",
    "analysis_type": "ux_auditor",
    "output_format": ["json"]
  }'
```

**Response:**
```json
{
  "analysis_id": "5a7af51e-798f-4c01-9a4d-4651a5aa1c82",
  "status": "pending",
  "url": "https://ihtys.menu"
}
```

**Check Analysis Status:**
```bash
curl -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/analysis/5a7af51e-798f-4c01-9a4d-4651a5aa1c82"
```

### 3. Analysis Management Endpoints

**List All Analyses:**
```bash
# Get all analyses
curl -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/analyses"

# Get analyses with pagination
curl -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/analyses?limit=10&offset=0"

# Filter by status
curl -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/analyses?status=completed"
```

**Delete Analysis:**
```bash
curl -X DELETE \
  -H "X-API-Key: your-api-key-here" \
  "http://localhost:8000/api/v2/api/analysis/5a7af51e-798f-4c01-9a4d-4651a5aa1c82"
```

## JSON Response Structure

### Complete Response Schema

```typescript
interface AnalysisResponse {
  // Analysis metadata
  success: boolean;
  analysis_id: string;
  report_id: string;
  url: string;
  analyzer_type: string;
  
  // Main analysis results
  overall_score: OverallScore;
  sections: Section[];
  quick_wins: QuickWin[];
  
  // Execution metadata
  token_usage: TokenUsage;
  execution_time_ms: number;
  turns: number;
  tool_usage: ToolUsage[];
  
  // Raw analysis text (optional)
  raw_analysis?: string;
}

interface OverallScore {
  value: number;        // 1-10 score
  description: string;  // Russian language description
}

interface Section {
  id: string;           // Unique section identifier
  title: string;        // Section title (e.g., "Навигация и структура")
  score: number;        // 1-10 score for this section
  findings: Finding[];  // Array of issues found
}

interface Finding {
  id: string;
  title: string;
  severity: "critical" | "high" | "medium" | "low";
  description: string;
  recommendation: string;
  business_impact: string;
}

interface QuickWin {
  id: string;
  title: string;
  effort: "low" | "medium" | "high";
  impact: "low" | "medium" | "high";
  recommendation: string;
}
```
