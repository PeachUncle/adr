# Decision: Minimal methods + ivars (v0)

This document records the first “real VM” execution features needed to make progress on CRuby bootstraptests beyond literals.

Target tests motivating this step:

- `vendor/ruby/ruby/bootstraptest/test_yjit_rust_port.rb` (`Setivar test`, `Getivar with an extended ivar table`)

## Decision

Implement a minimal method system and instance-variable storage in the VM, with compiler lowering directly from Prism nodes.

This is intentionally **not** a full Ruby object model yet; it is a stepping stone that keeps the bytecode VM architecture while enabling more bootstrap coverage.

### Methods (v0)

- `def foo ... end` compiles the method body into a nested `Bytecode` function, and emits `DEFINE_METHOD`.
- Calls compile to `CALL`, with an explicit receiver (or `GET_SELF` for implicit receiver).
- VM stores a **global method table** keyed by method name → function index.
  - Method lookup currently **ignores receiver class** (no per-class method tables, visibility, inheritance, singleton methods, or `super`).
  - This is sufficient for bootstrap snippets that define and call uniquely named methods.

### Instance variables (v0)

- `@name` compiles to `IVAR_GET(name_const)`.
- `@name = expr` compiles to `IVAR_SET(name_const)`.
- VM stores ivars in:
  - a `main_ivars` map when `self` is the top-level object
  - an `objects[id]` map for `Value::Object(id)`

### `attr_accessor` (compiler lowering)

- `attr_accessor :a` is lowered by the compiler into method definitions for:
  - `a` → returns `@a`
  - `a=` → sets `@a`
- This lowering is currently **global** (matches the v0 global method table), and is intended only to satisfy early bootstrap coverage.

### `Klass.new` (compiler lowering)

- For `ConstantReadNode.new(...)` (except `Object.new`), the compiler lowers to:
  - `NEW_OBJECT; DUP; CALL initialize; POP`
- This avoids requiring constant lookup/class objects at this stage while still exercising call frames and ivar semantics.

## Consequences / known incompatibilities

- No real `class` semantics: class bodies are executed only for their side effects (method definitions), and do not bind a constant to a class object.
- No constant table: `ConstantReadNode`/`ConstantWriteNode` are not generally supported yet.
- No blocks/`yield`, closures, or keyword args.
- No per-class method dispatch; future work must replace the global method table with a real class/module object model.

## Follow-ups

1. Introduce a real class/module object model + constant table.
2. Move method lookup to per-class tables and add inheritance.
3. Implement blocks and `yield` (needed for `each`, `map`, `times`, `Ractor.new {}` bootstrap tests).
4. Replace `ConstantReadNode.new` lowering with runtime dispatch of `Class#new` once classes exist.
