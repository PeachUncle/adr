# Ingress for secure teams bot

Research options to enable secure access to a teams bot from the internet.

## Context and Problem Statement

A Teams bot running in an isolated VNET only alowing IP/FQDN ingress/egress traffic from the appropriate Teams and Azure Bot Services. The solution must be secure, cost-effective, and require minimal friction to implement, maintain, and extend. The solution must consider a simplistic architecture which would allow for crews to adapt to their customers resources and environment needs.

## Decision Drivers

- Secure
- Least amount of friction to implement
- Cost-effective solution for the use case
- Scalable
- Least amount of rework/friction to replace with other service(s) as needed

## Considered Options

- Azure Firewall
- Azure Front Door
- Azure Load Balancer + NAT Gateway
- Azure Application Gateway
- Azure Application Gateway + API Management (Internal)
- API Management (External)

### Azure Firewall

Azure Firewall is a cloud-native network security service designed for protecting Azure Virtual Network resources. It offers threat intelligence-based filtering, allowing automatic blocking of malicious IPs and domains. Azure Firewall operates at both the network (Layer 3), transport (Layer 4), and application (Layer 7) levels, supporting rules based on FQDNs (fully qualified domain names) and protocols.

Features:

- Threat Intelligence: Integration with Microsoft Threat Intelligence, which blocks known malicious IPs and domains.
- Application and Network Rules: Supports both application (Layer 7) and network (Layer 4) filtering.
- FQDN Filtering: Can filter outbound traffic based on fully qualified domain names, even in non-HTTP/S scenarios.
- TLS Inspection: Inspects encrypted traffic for enhanced security.
- Logging and Monitoring: Integrated with Azure Monitor, enabling logging and diagnostic data for better visibility.

### Azure Front Door

Azure Front Door is a global HTTP(S) load balancer and content delivery network (CDN) that provides high-performance web application delivery. It’s designed for scenarios where low latency and high availability across multiple regions are crucial. Azure Front Door can optimize the routing of web traffic, and it includes a built-in web application firewall (WAF) for advanced security.

Features:

- Global Load Balancing: Routes traffic to the nearest available region, optimizing for performance and availability.
- WAF: Offers Layer 7 protection with customizable rules for blocking common web threats.
- SSL Offloading: Reduces the load on backend services by handling SSL decryption.
- URL Path-Based Routing: Routes requests to specific backends based on URL paths.
- Caching: Provides caching capabilities to speed up content delivery for static assets.
- Session Affinity: Routes user sessions consistently to the same backend.

### NAT Gateway

NAT Gateway (Network Address Translation) in Azure provides secure, scalable outbound internet access for Azure Virtual Networks. It enables resources in a private subnet to reach external services without exposing the subnet to inbound connections from the internet.

Features:

- High Scalability: Supports thousands of connections per second, designed for high-traffic applications.
- Static IP: Ensures consistent IP addresses for outbound traffic.
- Secure Outbound Connectivity: Only enables outbound internet access without inbound access, reducing the attack surface.
- Simplified Management: Automatically scales without requiring extensive configuration.

### Azure Load Balancer

Azure Load Balancer provides a Layer 4 (TCP/UDP) balancing solution, designed for distributing network traffic across multiple VMs or services within a region. It's commonly used to achieve high availability and redundancy for backend services.

Features:

- Internal and Public Load Balancing: Can balance traffic both within virtual networks and to the internet.
- Health Probes: Monitors the health of instances, ensuring that traffic is only directed to healthy backends.
- Automatic Scaling: Integrates with Virtual Machine Scale Sets for automatic scaling of backend instances.
- Port Forwarding and NAT Rules: Supports forwarding traffic to specific ports on backend VMs.
- Session Persistence: Offers “Source IP affinity” to maintain session continuity across connections.

### Azure Load Balancer with NAT Gateway

This combination enables a Layer 4 load balancer with outbound connectivity capabilities, using NAT Gateway for consistent outbound IP addresses. This setup allows for secure and scalable outbound internet traffic while still benefiting from load balancing.

Features:

- Load Balancing: Balances traffic among multiple backend instances using Layer 4 (TCP/UDP).
- Outbound NAT: Manages outbound internet traffic with consistent, static IP addresses.
- Secure Connectivity: Outbound connections use NAT Gateway, enhancing security by not exposing instances to inbound internet access.
- Multi-Zone Support: Ensures high availability by distributing traffic across multiple availability zones.

### Application Gateway (App Gateway)

Azure Application Gateway is a robust Layer 7 load balancer, offering advanced routing, security, and session management features for web applications. It supports SSL offloading and integrates a Web Application Firewall (WAF) for better security against common threats.

Features:

- WAF: Protects web applications against common exploits like SQL injection, XSS, and others.
- SSL Offloading: Offloads SSL decryption to the gateway to reduce backend load.
- URL Path-Based Routing: Routes requests to different backends based on URL paths, ideal for microservices.
- Multi-Site Hosting: Hosts multiple applications behind a single gateway, with separate routing rules for each.
- Autoscaling: Automatically scales based on traffic load, ensuring availability and cost efficiency.

### API Management (APIM)

Azure API Management (APIM) is an API gateway service that allows organizations to publish, secure, transform, and monitor APIs. It offers a developer portal, analytics, and various API security policies to control and streamline API consumption.

Features:

- Developer Portal: Enables self-service API documentation and onboarding for developers.
- Policy Engine: Configures policies such as rate limiting, caching, transformation, and authentication.
- Analytics and Monitoring: Tracks usage, errors, and performance metrics, integrating with Azure Monitor.
- Multiple Environment Support: Allows deployment of APIs in internal, external, and hybrid modes.
- API Versioning and Revision: Supports versioning to manage different API versions effectively.

### API Management (APIM) Internal Mode

APIM Internal Mode is similar to standard APIM but operates within a private virtual network, allowing only internal traffic. This mode is optimal for API endpoints that don’t need to be publicly accessible.

Features:

- Internal-Only API Access: Restricts API consumption to resources within the virtual network.
- Integration with VNET: Allows secure connections to Azure resources within the same VNET.
- Full APIM Feature Set: Supports the same management, monitoring, and policy features as standard APIM.
- Enhanced Security: Keeps APIs internal, reducing exposure to the public internet.

### API Management (APIM) External Mode

APIM External Mode is designed to expose APIs over the internet, accessible to both internal and external clients. This mode is ideal for public APIs or APIs serving clients outside the Azure virtual network.

Features:

- Public API Access: Allows public access to APIs, suitable for external customers.
- Policy and Security Management: Controls access through API keys, IP whitelisting, and rate limiting.
- Developer and Management Portal: Offers a user-friendly portal for API documentation, testing, and onboarding.
- Geo-Redundancy: Provides high availability and resilience across multiple Azure regions.
- Analytics and Reporting: Provides insights into API usage, performance, and error tracking.

### App Gateway with APIM Internal Mode

This setup combines Application Gateway’s advanced Layer 7 load balancing and WAF capabilities with APIM in Internal Mode, allowing organizations to secure internal APIs with high performance.

Features:

- Layer 7 Security: Protects APIs with WAF, SSL offloading, and Layer 7 routing rules.
- VNET Integration: Ensures that API traffic stays within the virtual network.
- Internal Access Control: APIM Internal Mode restricts API access to internal clients only.
- URL-Based Routing for APIs: Enables complex routing scenarios based on the API path, HTTP headers, or query strings.

## Comparing Options

The Azure Application Gateway + API Management (Internal) option would not be suitable for the project. To inject APIM in a VNET, the Premium V1 SKU will be necessary, which costs ~$2800/mo per unit. The Premium V2 SKU has not been released and Standard V2 would not accommodate the VNET injection requirement. Given there is no need for any traditional API Management features (policies, products/subscriptions, dev portal, etc.), the cost incurred by APIM is not worth the ability to allow public traffic to an Azure App Service.

The API Management (External) option would also not be suitable for the same reasons. APIM (External) would require Premium V1, which carries the same cost constraints. The APIM team has released Standard V2 which allows for VNet integration (no injection), which would be a cheaper option than Premium V1, but still costs ~$700/mo per unit. Again, given there is no need for any traditional API Management features (policies, products/subscriptions, dev portal, etc.), it does not make sense to utilize API Management to allow public access to an Azure App Service given the cost versus alternatives.

Azure Firewall offers the ability to allow access to the Azure App Service at a cheaper cost (<~$100/mo) and would be a suitable option given the current architecture. While the current architecture does not include multiple App Services, Azure Firewall is not a load balancer and may not be the best option if there would be future additional deployments and load balancing requirements. If multiple App Services were needed, it would require Azure Firewall to have multiple public IP addresses to allow routing to the correct App Service or each App Service would have to be configured on different ports.
The Firewall offers security features that are necessary and would be utilized in a WAF aligned architecture.

Both Azure Front Door and Azure Application Gateway are layer 7 load balancers that offer built in Web Application Firewalls. Azure Front Door would require the Premium SKU to enable Private Link, WAF, etc. but does not include additional charges for the Firewall and would cost ~$330/mo. Application Gateway would cost < ~$100/mo, though it would include additional charges for its WAF that is linked above. Azure Front Door and Azure Application Gateway would each be suitable options that go beyond Azure Firewall to allow public access to the App Service and should be especially considered if there may be additional load balancing requirements. It is important to note that Azure Firewall would require the creation of a custom domain and certificate to allow for HTTPS traffic, which would be an additional step to consider. Azure Front Door would be able to handle these concerns automatically.

## TLS Considerations

Implementing any of the specified architectural options necessitates strategies for TLS/SSL, certificates, and DNS. These strategies should address SSL offloading/termination, certificate issuance and renewal, and DNS management. It is essential that all strategies and configurations align with the existing network architecture, policies, and procedures, and these factors must be thoroughly considered when selecting the appropriate Azure Service(s).

## Decision Outcome

Azure Front Door was chosen because it delivers the essential capabilities needed to allow for future flexibility and implementation. The key deciding factors for choosing Front Door came down to the following capabilities: Web Application Firewall (WAF), certificate management, public DNS, and SSL offloading. Being able to leverage existing Front Door capabilities verses implementing alternatives will greatly simplify onboarding and adoption. While these capabilities will significantly simplify and streamline the overall experience, it should be acknowledged they do come with a slight cost increase over a few of the alternatives options.
