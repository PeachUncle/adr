# ADR-005: Ash-Phoenix Form Integration and Authentication Patterns

## Status

Accepted (Revised after implementation experience)

## Context

During the authentication implementation, we encountered multiple integration challenges between Ash Framework and Phoenix LiveView that required specific solutions:

1. **Phoenix.HTML.FormData Protocol Issue**: Ash.Changeset doesn't implement the Phoenix.HTML.FormData protocol
2. **LiveSession Conflicts**: AshAuthentication's LiveSession strictly manages `current_user` assign
3. **Domain Duplication**: Had two User models in different domains causing conflicts
4. **SQLite Limitations**: ALTER COLUMN operations not supported, causing migration failures
5. **Secrets Module**: Function clause errors after domain reorganization

## Decision

### 1. Domain Organization

Keep authentication components in a single domain:

```elixir
# ✅ CORRECT - Single source of truth
SharedLedger.Identity
├── User          # All user authentication logic
└── Token         # JWT token management

SharedLedger.Accounts
├── Account       # Shared expense accounts (NOT user accounts)
└── AccountMember # Membership relationships

# ❌ WRONG - Duplicate User models
SharedLedger.Accounts.User  # DELETE THIS
SharedLedger.Identity.User  # KEEP ONLY THIS
```

### 2. Form Handling Patterns

We adopt three distinct patterns based on use case:

#### Pattern A: Simple Forms with Plain Maps

```elixir
# For basic forms without complex validation
def mount(_params, _session, socket) do
  {:ok, assign(socket, :form, to_form(%{}, as: :user))}
end

def handle_event("submit", %{"user" => params}, socket) do
  User
  |> Ash.Changeset.for_action(:create, params)
  |> Ash.create()
  |> case do
    {:ok, user} ->
      {:noreply, redirect(socket, to: ~p"/dashboard")}
    {:error, changeset} ->
      errors = Ash.Error.to_error_messages(changeset.errors)
      {:noreply, assign(socket, :errors, errors)}
  end
end
```

#### Pattern B: Complex Forms with AshPhoenix.Form

```elixir
# For forms requiring Ash validations
def mount(_params, _session, socket) do
  form = AshPhoenix.Form.for_action(User, :register_with_password, %{})
  {:ok, assign(socket, :form, form)}
end
```

#### Pattern C: Authentication with AshAuthentication Components

```elixir
# Let AshAuthentication handle everything
# router.ex
sign_in_route register_path: "/register",
              reset_path: "/reset",
              auth_routes_prefix: "/auth"
# No custom LiveViews needed!
```

### 3. LiveSession and current_user Management

**CRITICAL RULE**: Never modify `current_user` in custom on_mount callbacks.

```elixir
# ❌ WRONG - Causes "Cannot set assign current_user" error
def on_mount(:live_user_optional, _params, _session, socket) do
  if socket.assigns[:current_user] do
    {:cont, socket}
  else
    {:cont, assign(socket, :current_user, nil)}  # THIS CAUSES ERROR!
  end
end

# ✅ CORRECT - Let AshAuthentication manage current_user
def on_mount(:live_user_optional, _params, _session, socket) do
  {:cont, socket}  # Just continue, don't touch current_user
end

def on_mount(:live_user_required, _params, _session, socket) do
  if socket.assigns[:current_user] do
    {:cont, socket}
  else
    {:halt, Phoenix.LiveView.redirect(socket, to: ~p"/sign-in")}
  end
end

def on_mount(:live_no_user, _params, _session, socket) do
  if socket.assigns[:current_user] do
    {:halt, Phoenix.LiveView.redirect(socket, to: ~p"/")}
  else
    {:cont, socket}  # Don't assign nil!
  end
end
```

### 4. Router Configuration

Keep authentication routes outside protected LiveSession:

```elixir
scope "/", SharedLedgerWeb do
  pipe_through :browser

  # Authentication routes - OUTSIDE LiveSession
  auth_routes AuthController, SharedLedger.Identity.User, path: "/auth"
  sign_out_route AuthController

  sign_in_route register_path: "/register",
                reset_path: "/reset",
                auth_routes_prefix: "/auth"
                # NO on_mount here for auth routes!

  # Protected routes - INSIDE LiveSession
  ash_authentication_live_session :authenticated_routes,
    on_mount: {SharedLedgerWeb.LiveUserAuth, :live_user_required} do
    live "/dashboard", DashboardLive, :index
    live "/accounts/:id", AccountLive.Show, :show
  end
end
```

### 5. Secrets Module Configuration

Must reference the correct User module:

```elixir
defmodule SharedLedger.Secrets do
  use AshAuthentication.Secret

  def secret_for(
        [:authentication, :tokens, :signing_secret],
        SharedLedger.Identity.User,  # Must match your User module location!
        _opts,
        _context
      ) do
    Application.fetch_env(:shared_ledger, :token_signing_secret)
  end
end
```

### 6. SQLite Migration Workarounds

SQLite doesn't support ALTER COLUMN, requiring special handling:

```bash
# Development workaround
mix ash.codegen --dev

# Or reset database if no data to preserve
mix ecto.drop && mix ecto.create && mix ecto.migrate

# For production, plan schema carefully from start
```

Field design considerations:

```elixir
# ❌ WRONG - SQLite can't handle composite types
attribute :amount, Money

# ✅ CORRECT - Separate fields
attribute :amount_value, :decimal
attribute :amount_currency, :atom, constraints: [one_of: [:EUR, :KRW]]
```

## Testing Strategy

### Order is Critical

1. **Backend First** (IEx/Tidewave)

```elixir
# Test the Ash action works
User
|> Ash.Changeset.for_action(:register_with_password, %{
    email: "test@example.com",
    password: "SecurePass123!",
    password_confirmation: "SecurePass123!"
  })
|> Ash.create()
```

2. **Compilation Check**

```bash
mix compile --warnings-as-errors
mix format  # ALWAYS format after changes
```

3. **UI Testing** (Playwright)

```javascript
await page.goto("http://localhost:4000/register");
await page.fill('[name="user[email]"]', "test@example.com");
// Complete flow testing
```

## Consequences

### Positive

- Clear integration patterns prevent common errors
- No LiveSession conflicts with proper on_mount handling
- Single source of truth for User model
- Predictable authentication flow
- SQLite compatibility with workarounds

### Negative

- Cannot use Ash.Changeset directly with to_form/1
- Cannot customize current_user assignment
- SQLite requires database resets for schema changes
- Must understand three different form patterns

### Neutral

- Testing must follow specific order (backend → UI)
- Developers need to understand both Ash and Phoenix patterns
- Documentation crucial for team onboarding

## Common Pitfalls and Solutions

| Problem               | Error Message                                | Solution                                     |
| --------------------- | -------------------------------------------- | -------------------------------------------- |
| Duplicate User models | Table already exists                         | Keep User in Identity domain only            |
| Form protocol error   | "FormData not implemented for Ash.Changeset" | Use plain maps or AshPhoenix.Form            |
| LiveSession conflict  | "Cannot set assign current_user"             | Never modify current_user in on_mount        |
| SQLite migration      | "ALTER COLUMN not supported"                 | Use --dev or reset database                  |
| Secrets error         | "no function clause matching"                | Update Secrets module with correct User path |
