# ADR-003: Azure Key Vault as Single Source of Truth

!!! info "ADR Metadata"
    **Status**: ✅ Accepted  
    **Date**: 2025-10-09  
    **Deciders**: Platform Team, Security Team, Compliance Team  
    **Last Updated**: 2025-10-09

## Context

Our organization needs a centralized, secure, and compliant secret storage solution that serves as the Single Source of Truth (SSoT) for all secrets across our infrastructure. Current state includes:

!!! warning "Current Challenges"
- 📊 Multiple secret storage locations (HashiCorp Vault, Kubernetes Secrets, environment variables)
- 🛡️ Inconsistent access controls and audit capabilities
- 📜 Compliance requirements (BIO, NIS2) demanding centralized secret management
- ☁️ Integration with existing Azure infrastructure and identity management## Decision

!!! success "Selected Solution"
    We will use **Azure Key Vault** as the Single Source of Truth for all organizational secrets.

### Key Vault Configuration
!!! info "Azure Key Vault Setup"
    - **Vault Type**: Azure Key Vault (Standard tier with Premium upgrade path)
    - **Access Model**: Azure RBAC for management, Vault access policies for applications
    - **Networking**: Private endpoints with restricted public access
    - **Geographic Distribution**: Primary region (West Europe) with backup procedures

## Rationale

!!! tip "Why Azure Key Vault"
    
    **1. Enterprise Grade Security**
    
- 🔒 Hardware Security Module (HSM) backed
- 📜 FIPS 140-2 Level 2 validated
- 🔒 Encryption at rest and in transit    **2. Compliance and Governance**
    
- 🔍 Built-in audit logging
- 📜 Compliance certifications (SOC, ISO 27001, FedRAMP)
- 📋 Integration with Azure Policy and Governance    **3. Operational Excellence**
    
- ❤️ 99.9% SLA with geo-redundancy
- 💾 Automatic backup and disaster recovery
- 📚 Versioning and soft-delete capabilities    **4. Azure Native Integration**
    
- ☁️ Seamless integration with Azure AD/Entra ID
- ☸️ Workload Identity support for Kubernetes
- 📊 Integration with Azure Monitor and Sentinel    **5. Cost Effectiveness**
    
- 💰 Pay-per-operation model
- 🖥️ No infrastructure overhead
- 📉 Reduced operational complexity!!! warning "Why Not Alternatives"
    - **HashiCorp Vault**: Higher operational overhead, licensing costs, infrastructure management
    - **AWS Secrets Manager**: Vendor lock-in to AWS, additional cloud complexity
    - **Custom Solution**: Security risks, compliance challenges, development overhead

## Implementation Architecture

### Key Vault Structure
```yaml title="Key Vault Organization"
itl-secrets-{environment}
├── certificates/
│   ├── tls-certificates
│   └── signing-certificates
├── keys/
│   ├── encryption-keys
│   └── signing-keys
└── secrets/
    ├── application-secrets/
    │   ├── {app-name}-database-password
    │   ├── {app-name}-api-key
    │   └── {app-name}-connection-string
    ├── infrastructure-secrets/
    │   ├── cluster-ca-cert
    │   └── service-account-keys
    └── generated-secrets/
        ├── {app-name}-session-secret
        └── {app-name}-encryption-key
```

### Access Control Model

!!! note "Management Access (Azure RBAC)"
    - **Key Vault Administrator**: Platform team members
    - **Key Vault Secrets Officer**: Automated deployment pipelines
    - **Key Vault Reader**: Security and compliance teams

## Security Configuration

!!! warning "Network Security"
    - 🔐 **Private Endpoints**: All access through private endpoints
    -  **Firewall Rules**: Allow only known IP ranges and Azure services
    -  **Virtual Network Integration**: Connected to hub-spoke network topology

!!! tip "Access Policies"
    -  **Principle of Least Privilege**: Minimal required permissions
    -  **Time-Limited Access**: Temporary elevated access for emergency operations
    -  **Conditional Access**: MFA required for human access

!!! info "Audit and Monitoring"
    -  **Diagnostic Settings**: All operations logged to Azure Monitor
    -  **Alerting**: Real-time alerts on suspicious access patterns
    - 🔒 **SIEM Integration**: Logs forwarded to Azure Sentinel

## Operational Procedures

!!! note "Secret Lifecycle Management"
    
    **Creation**
    1. Secrets created via automation (Terraform, ARM templates)
    2. Immediate encryption with Azure-managed keys
    3. Version control for all secret definitions

    **Rotation**
    1. Automated rotation using Azure Functions or Logic Apps
    2. Coordinated updates through External Secrets Operator
    3. Zero-downtime rotation procedures

    **Deletion**
    1. Soft-delete enabled (90-day retention)
    2. Purge protection for production environments
    3. Audit trail maintained for all deletions

!!! tip "Backup and Recovery"
    -  **Cross-Region Backup**: Automated backup to secondary region
    -  **Point-in-Time Recovery**: Ability to restore to specific versions
    -  **Disaster Recovery**: Documented procedures for regional failures

## Consequences

!!! tip "Positive Outcomes"
    - 🔒 **Centralized Security**: Single location for all security policies
    -  **Compliance**: Built-in compliance with major frameworks
    - ⚙️ **Operational Simplicity**: Reduced secret sprawl and management overhead
    -  **Enterprise Features**: Versioning, soft-delete, audit trails
    -  **High Availability**: Enterprise-grade SLA and redundancy

!!! warning "Negative Consequences"
    -  **Vendor Lock-in**: Tied to Azure ecosystem
    -  **Cost**: Per-operation pricing can add up at scale
    -  **Regional Dependency**: Requires Azure presence in required regions
    -  **Learning Curve**: Team needs Azure Key Vault expertise

!!! danger "Risks and Mitigations"
    **Risk**: Azure Key Vault regional outage  
    **Mitigation**: Multi-region deployment, cached secrets for critical applications
    
    **Risk**: Access policy misconfiguration  
    **Mitigation**: Infrastructure as Code, automated testing, least privilege principles
    
    **Risk**: Cost escalation  
    **Mitigation**: Monitoring, optimization, appropriate refresh intervals

## Migration Strategy

!!! note "Phased Implementation"
    **Phase 1**: Infrastructure Setup
    
    - Deploy Azure Key Vault with security configuration
    - Implement access policies and monitoring
    - Test External Secrets Operator integration

    **Phase 2**: Pilot Migration
    
    - Migrate 2-3 non-critical applications
    - Validate operational procedures
    - Refine monitoring and alerting

    **Phase 3**: Production Migration
    
    - Migrate critical applications with maintenance windows
    - Implement automated rotation for dynamic secrets
    - Complete audit and compliance validation

    **Phase 4**: Legacy Cleanup
    
    - Decommission old secret storage systems
    - Update documentation and training
    - Implement governance policies
