# ADR-002: Use uv as Primary Package Manager

**Date**: 2025-10-06  
**Status**: Accepted  
**Author**: Nik Jois

## Context

The project needs a fast, reliable package manager for dependency management, virtual environments, and reproducible builds. Python offers several options: pip, poetry, pipenv, pdm, and uv.

## Decision

We will use uv as the primary package manager, with fallback support for pip, hatch, and tox.

## Rationale

### uv Advantages

1. **Performance**
   - Written in Rust (10-100x faster than pip)
   - Parallel downloads
   - Efficient caching
   - Fast virtual environment creation

2. **Standards Compliance**
   - PEP 517/518/621 compatible
   - Works with standard pyproject.toml
   - No proprietary lock file formats
   - Drop-in pip replacement

3. **Developer Experience**
   - Intuitive CLI (`uv sync`, `uv run`)
   - Automatic virtual environment management
   - Excellent error messages
   - Cross-platform (Linux, macOS, Windows)

4. **Lock Files**
   - Automatic dependency locking
   - Reproducible builds
   - Fast conflict resolution

5. **Integration**
   - Works with existing tools (pytest, mypy, etc.)
   - Compatible with pip requirements files
   - CI/CD friendly

### Alternatives Considered

**pip**
- Pros: Standard, universal
- Cons: Slow, no built-in locking, manual venv management

**poetry**
- Pros: Popular, feature-rich
- Cons: Slow dependency resolution, proprietary lock format, complex

**pipenv**
- Pros: Combines pip + venv
- Cons: Slow, inconsistent behavior, less maintained

**pdm**
- Pros: PEP 582 support, fast
- Cons: Smaller community, less tooling support

## Consequences

### Positive

- 10-100x faster dependency installation
- Automatic lock file generation
- Simpler workflow for developers
- Better CI/CD performance
- Standards-compliant

### Negative

- Relatively new (less mature than pip/poetry)
- Team needs to learn new commands (mitigated: similar to pip)
- Additional installation step (mitigated: single curl command)

### Neutral

- Still maintain pyproject.toml (standard)
- Can fallback to pip if needed
- Lock file is uv-specific but not required

## Implementation

1. Document uv installation in README
2. Provide uv-based setup instructions
3. Maintain fallback instructions for pip, hatch, tox
4. Use uv in CI/CD pipelines
5. Generate uv.lock for reproducibility

Example commands:

```bash
# Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# Setup project
uv venv -p 3.11
uv sync

# Run commands
uv run pytest
uv run opengov-hydraulicsplanning --help
```

## Validation

Success criteria:
- Faster installation times in CI/CD
- Reproducible builds across environments
- Developer satisfaction
- No breaking changes for non-uv users

## Migration Path

For existing users:
1. Install uv
2. Run `uv sync` (creates lock file)
3. Continue using uv for all operations
4. Or continue using pip/hatch/tox (still supported)
