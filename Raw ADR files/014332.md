# TASK-018: Frontend integration tests for intent flows
> Source: tasks/tasks.md

## Context
- Add Playwright or Cypress tests for /chat integrated flows (backend running)
- Test all intent categories: STOCK_RECOMMENDATION, PORTFOLIO_RECOMMENDATION, SHORTLIST, FETCH_NEWS, FETCH_NEWS_TICKER, FETCH_STOCK_PRICE, USER_PORTFOLIO, USER_TRADE, USER_ORDER
- One error path: ambiguous prompt → UI shows a clear error banner
- Seed test user data or stub minimal backend fixtures
- Use data-testid attributes for stable selectors

## Options Considered
- **Option A**: Cypress testing (Pros: Popular, good documentation; Cons: Slower, less stable)
- **Option B**: Playwright testing (Pros: Fast, stable, multi-browser; Cons: Newer, less community)
- **Option C**: Jest + React Testing Library (Pros: Fast unit tests; Cons: Limited integration testing)

## Decision
- **Chosen approach**: Option B - Playwright testing
- **Rationale**: Better performance, multi-browser support, more stable selectors, excellent debugging tools

## Impacts
- **Performance**: Excellent - Fast test execution with parallel runs
- **Complexity**: Moderate - Well-structured test files with clear organization
- **Security/Privacy**: Good - Tests run in isolated browser contexts
- **Compatibility**: High - Multi-browser testing (Chrome, Firefox, Safari, Mobile)
- **Risks & Mitigations**: 
  - Risk: Flaky tests due to timing; Mitigation: Proper waits and timeouts
  - Risk: Backend dependencies; Mitigation: Generous timeouts for LLM processing
