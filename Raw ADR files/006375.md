# ADR-001: Use Baileys for WhatsApp Integration

**Status**: Accepted

**Date**: 2024-09-20

**Deciders**: Development Team

**Tags**: whatsapp, integration, api

## Context

ParentLog needs to capture WhatsApp messages from family members to build a timeline of child memories. WhatsApp provides several integration options:

1. **Official WhatsApp Business API**: Enterprise-grade, requires business verification, costs money
2. **Baileys (unofficial library)**: Open-source, free, uses WhatsApp Web protocol
3. **Web scraping**: Unreliable, against WhatsApp ToS
4. **Manual export**: Requires user intervention, not real-time

Our requirements:
- **Real-time message capture**: Messages must appear within seconds
- **Low cost**: MVP budget is minimal (prefer free tier solutions)
- **Personal/family use**: Not commercial messaging
- **Simple authentication**: QR code pairing acceptable
- **No business verification**: Don't want to go through WhatsApp Business approval

## Decision

We will use **Baileys** (https://github.com/WhiskeySockets/Baileys), an open-source TypeScript library that implements the WhatsApp Web protocol.

## Alternatives Considered

### Option 1: Official WhatsApp Business API
**Pros:**
- Officially supported by Meta
- Reliable and stable
- Compliant with WhatsApp ToS
- Access to advanced features

**Cons:**
- Requires business verification process (weeks)
- Costs money after free tier
- Overkill for personal/family use
- Complex setup and approval workflow
- Rate limits designed for customer service, not personal chat

### Option 2: Baileys (Chosen)
**Pros:**
- Free and open-source
- Works with personal WhatsApp accounts
- No approval process needed
- QR code pairing (familiar to users)
- Active community and maintenance
- TypeScript support (matches our stack)
- Real-time message events

**Cons:**
- Unofficial API (uses reverse-engineered WhatsApp Web protocol)
- Risk of WhatsApp banning accounts (mitigated with conservative rate limits)
- Could break if WhatsApp changes protocol
- No official support
- Session management complexity

### Option 3: Web Scraping
**Pros:**
- No API needed

**Cons:**
- Unreliable (WhatsApp Web UI changes frequently)
- Against WhatsApp Terms of Service
- Can't capture messages in real-time
- Requires browser automation (complex, resource-intensive)
- High risk of account ban

## Consequences

### Positive
- **Fast implementation**: Can prototype and test quickly
- **Zero cost**: No API fees or subscription required
- **Personal accounts**: Users can connect existing WhatsApp numbers
- **Real-time capture**: Messages arrive instantly via event listeners
- **TypeScript integration**: Smooth integration with Next.js and Node.js stack
- **QR code pairing**: Familiar authentication flow for users

### Negative
- **Risk of breaking changes**: WhatsApp could update protocol
- **Account ban risk**: Must implement conservative rate limits
- **Unofficial status**: No guarantees or SLA
- **Session management**: Must handle credential persistence carefully
- **Compliance uncertainty**: Unclear if personal use violates ToS
- **Scaling limitations**: Each user needs dedicated Baileys instance

### Neutral
- **Community support**: Active GitHub issues and discussions available
- **Library maintenance**: Regular updates from maintainers
- **Documentation**: Adequate but not official

## Risk Mitigation Strategies

1. **Rate Limiting**: Implement conservative rate limits (60 messages/min)
2. **Personal Use Only**: Document that ParentLog is for personal/family use
3. **Graceful Degradation**: Design system to handle connection drops
4. **Session Persistence**: Store credentials in database for automatic reconnection
5. **Monitoring**: Log connection status and watch for ban indicators
6. **Version Pinning**: Pin Baileys version in production, test updates carefully
7. **Exit Strategy**: Design architecture to allow switching to official API if needed
