# ADR-003: Vanilla JavaScript Over Framework (React/Vue/Svelte)

## Status
**Accepted** (2025-12-23)

## Context
Need to build UI for prop selection and test pattern control. Options:
1. **Vanilla JS** (no framework, pure DOM manipulation)
2. **React** (component-based, virtual DOM)
3. **Vue** (progressive framework)
4. **Svelte** (compile-time framework)

Key considerations:
- Bundle size (phone network constraints)
- Development speed
- Maintainability for single developer
- Build complexity

## Decision
**Use Vanilla JavaScript with no framework**

## Consequences

### Positive
- **Zero dependencies**: No npm, no bundler, no build step
- **Tiny bundle**: ~10KB (minified) vs. 50KB+ (React + ReactDOM)
- **Fast load**: < 100ms initial load on 3G
- **Simple deployment**: Single HTML file + CSS + JS
- **No build step**: Edit → Save → Refresh
- **Full control**: No framework abstractions or magic
- **Learning value**: Reinforce fundamentals

### Negative
- **More boilerplate**: Manual DOM manipulation, event listeners
- **No reactivity**: Must manually update UI on state change
- **Less structure**: No enforced component model
- **Reimplementation**: Build own router, state management (if needed)

### Neutral
- **Development speed**: Slower initial setup, faster iteration (no rebuilds)
- **Maintainability**: Simple enough that vanilla JS is fine

### Risks & Mitigations
| Risk | Mitigation |
|------|------------|
| Code becomes spaghetti | Use modules (ES6), clear separation of concerns |
| State management chaos | Simple object store, explicit update functions |
| DOM manipulation bugs | Test thoroughly, use data attributes for selection |

## Alternatives Considered

### Alternative 1: React
**Pros:**
- Declarative UI updates
- Component reusability
- Large ecosystem
- Familiar to most developers

**Cons:**
- 50KB+ bundle (React + ReactDOM minified)
- Requires build step (Babel, Webpack/Vite)
- JSX complexity
- Overkill for simple CRUD UI

**Why rejected:** Bundle size and build complexity not justified for this app.

### Alternative 2: Vue
**Pros:**
- Simpler than React
- Good documentation
- Progressive adoption

**Cons:**
- ~30KB bundle
- Still requires build step for SFC
- Learning curve for single-file components

**Why rejected:** Similar to React - unnecessary complexity.

### Alternative 3: Svelte
**Pros:**
- Compile-time (smaller runtime)
- Reactive by default
- Simpler syntax than React

**Cons:**
- Still requires build step
- Less mature than React/Vue
- Learning curve

**Why rejected:** Build step still present, unnecessary for simple UI.

### Alternative 4: Alpine.js
**Pros:**
- Minimal (15KB)
- No build step
- Declarative syntax in HTML

**Cons:**
- Still a dependency
- Less control than vanilla
- Magic attributes can be confusing

**Why rejected:** Vanilla JS is only ~5KB more code, full control, zero deps.

## Implementation Pattern

### Module Structure
```javascript
// app.js - Main entry
// state.js - Global state management
// ui.js - DOM manipulation helpers
// api.js - FPP API client
// storage.js - IndexedDB wrapper
```

### State Management
```javascript
// Simple observer pattern
const state = {
  props: [],
  selectedProp: null,
  controllers: []
};

const listeners = [];
function setState(updates) {
  Object.assign(state, updates);
  listeners.forEach(fn => fn(state));
}

function subscribe(fn) {
  listeners.push(fn);
}
```

### Component Pattern (Without Framework)
```javascript
function renderPropList(props) {
  const container = document.getElementById('prop-list');
  container.innerHTML = props.map(prop => `
    <div class="prop-item" data-id="${prop.id}">
      <h3>${prop.name}</h3>
      <p>${prop.controller_name}</p>
    </div>
  `).join('');

  // Event delegation
  container.addEventListener('click', (e) => {
    const item = e.target.closest('.prop-item');
    if (item) {
      const propId = item.dataset.id;
      selectProp(propId);
    }
  });
}
```
