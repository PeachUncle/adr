# ADR-0006: AI Fallback System

## Status
Proposed (Not Yet Implemented)

## Date
2025-12-17

## Context
When the primary AI provider (e.g., local LM Studio) is unavailable, the
application currently shows an error with a Retry button. Users have expressed
the need for automatic failover to a backup AI provider.

Current error handling:
- Catches `ConnectionException`
- Shows provider-agnostic error with server/model info
- Displays "Fallback AI not configured" placeholder
- Provides Retry button

## Proposed Decision

### Configuration Structure
```php
// config/ai.php
return [
    'providers' => [
        'primary' => env('AI_PRIMARY_PROVIDER', 'local'),
        'fallback' => env('AI_FALLBACK_PROVIDER', 'claude'),
    ],
    'fallback_enabled' => env('AI_FALLBACK_ENABLED', false),

    'local' => [
        'url' => env('AI_LOCAL_URL', 'http://localhost:1234'),
        'model' => env('AI_LOCAL_MODEL', 'qwen/qwen3-vl-30b'),
    ],
    'claude' => [
        'api_key' => env('CLAUDE_API_KEY'),
        'model' => env('CLAUDE_MODEL', 'claude-sonnet-4-20250514'),
    ],
];
```

### AiService Changes
```php
class AiService
{
    private array $providers = [];

    public function __construct(AiProviderFactory $factory)
    {
        $this->providers['primary'] = $factory->make(config('ai.providers.primary'));

        if (config('ai.fallback_enabled')) {
            $this->providers['fallback'] = $factory->make(config('ai.providers.fallback'));
        }
    }

    public function chat(string $systemPrompt, string $userMessage, ?string $purpose = null): AiResponse
    {
        $usedProvider = 'primary';

        try {
            $response = $this->providers['primary']->chat($systemPrompt, $userMessage);
        } catch (ConnectionException $e) {
            if (!isset($this->providers['fallback'])) {
                throw $e;
            }

            $usedProvider = 'fallback';
            $response = $this->providers['fallback']->chat($systemPrompt, $userMessage);
        }

        // Log includes which provider was used
        $this->logCompletion($usedProvider, ...);

        return new AiResponse($response, $usedProvider);
    }
}
```

### Response Object
```php
class AiResponse
{
    public function __construct(
        public string $content,
        public string $provider,  // 'primary' or 'fallback'
        public bool $usedFallback,
    ) {
        $this->usedFallback = $provider === 'fallback';
    }
}
```

### UI Indicator
When fallback is used, show indicator:
```html
@if($aiResponse->usedFallback)
    <div class="bg-yellow-50 border border-yellow-200 rounded p-2 text-sm">
        Primary AI unavailable. Results from fallback provider (Claude).
    </div>
@endif
```

## Rationale

### Why config-based enable/disable?
- Fallback may incur costs (Claude API)
- User controls when fallback is acceptable
- Can disable during development to test primary reliability

### Why provider chain vs. single fallback?
Starting with single fallback for simplicity. A full chain (try A, then B,
then C) adds complexity without clear benefit yet.

### Why return provider info?
Users should know which AI generated the response:
- Different providers may have different quality
- Cost implications
- Debugging and optimization

## Implementation Steps
1. Create `ClaudeProvider` implementing `AiProvider`
2. Create `AiProviderFactory` for instantiation
3. Update `AiService` with fallback logic
4. Create `AiResponse` value object
5. Update views to show fallback indicator
6. Update error UI to show fallback status

## Alternatives Considered

### Circuit Breaker Pattern
More sophisticated: track failure rate, open circuit after N failures,
periodically retry primary.

Deferred. Simple try/fallback is sufficient for current scale.

### Background Health Checks
Ping providers periodically, route to healthy one.

Deferred. Adds complexity. Try-and-fail is acceptable latency-wise.

## Consequences
- Users get AI results even when primary is down
- May incur API costs during outages
- Clear indication when fallback is used
- Logging captures which provider handled each request
- Foundation for more sophisticated failover in future
