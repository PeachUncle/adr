# ADR-013: Mobile Tab Bar Navigation Strategy

## Status

~~Accepted~~ **Superseded by [ADR-015: Unified Sidebar Navigation](./adr-015-unified-sidebar-navigation.md)**

## Context

The application has evolved from a single-context chat interface to a multi-context platform supporting Chat, Docs, AI, and More sections. The existing mobile navigation strategy (ADR-002) uses Sheet components for entity navigation within the chat context, but doesn't address switching between different application contexts.

Users need to:
1. Switch between different contexts (Chat, Docs, AI, More) on mobile
2. Navigate within each context (channels, documents, conversations)
3. Maintain context persistence across sessions
4. Access role-based features in the More section

The current Sheet-based navigation works well for entity lists (channels, documents) but doesn't provide an intuitive way to switch between application contexts on mobile devices.

## Decision

We will implement a **hybrid mobile navigation strategy** combining:

1. **Bottom Tab Bar** for context switching between Chat, Docs, AI, and More
2. **Sheet Navigation** (from ADR-002) for entity lists within each context

This approach uses both "Mobile-First with Sheet" (ADR-002) and "Mobile-First Bottom Navigation" patterns for different navigation levels.

## Rationale

### Chosen: Hybrid Navigation (Bottom Tabs + Sheets)

**Bottom Tab Bar for Context Switching:**
- ✅ Industry standard for multi-section mobile apps (Instagram, WhatsApp Business, Slack)
- ✅ Persistent visibility of all available contexts
- ✅ Single tap to switch contexts (no menu drilling)
- ✅ Clear visual hierarchy separating contexts from entities
- ✅ Supports role-based context visibility (More menu options)

**Sheet Navigation for Entity Lists:**
- ✅ Maintains ADR-002 benefits for entity navigation
- ✅ Consistent with existing chat interface
- ✅ Handles variable-length lists (channels, documents)
- ✅ Preserves screen real estate for content

### Key Distinction from ADR-002

ADR-002 rejected "Bottom Navigation (Mobile)" for **entity navigation** (channel lists), which remains valid. This ADR introduces bottom navigation for **context switching** - a fundamentally different use case:

- **Context Switching**: Fixed set of 4 contexts (Chat, Docs, AI, More)
- **Entity Navigation**: Variable lists (channels, documents, conversations)

### Rejected Alternatives

**Single Sheet for Everything**
- ❌ Poor information architecture (contexts mixed with entities)
- ❌ Requires multiple navigation levels in one interface
- ❌ No persistent context awareness

**Hamburger Menu for Contexts**
- ❌ Hidden navigation reduces discoverability
- ❌ Extra taps required for context switching
- ❌ Doesn't match multi-context app mental model

**Top Tab Bar**
- ❌ Conflicts with page headers and navigation
- ❌ Harder to reach on large mobile screens
- ❌ Less common pattern for primary navigation

## Implementation Details

### Mobile Navigation Hierarchy

```
Bottom Tab Bar (Context Level)
├── Chat Tab → Sheet with Channel List
├── Docs Tab → Sheet with Document List  
├── AI Tab → Sheet with Conversation List
└── More Tab → Sheet with Menu Options
```

### Component Structure

```jsx
// Mobile Tab Bar (≤768px)
<MobileTabBar 
  activeContext="chat"
  onContextChange={setActiveContext}
  user={user}
  isOwner={isOwner}
>
  <Sheet open={isSheetOpen} onOpenChange={setIsSheetOpen}>
    <SheetContent>
      {activeContext === 'chat' && <ChannelList />}
      {activeContext === 'docs' && <DocumentList />}
      {activeContext === 'ai' && <ConversationList />}
      {activeContext === 'more' && <MoreMenu />}
    </SheetContent>
  </Sheet>
</MobileTabBar>

// Desktop Sidebar (≥768px) - unchanged from ADR-002
<aside className="hidden md:flex md:w-64 flex-col border-r">
  <ContextTabs />
  <EntityList />
</aside>
```

### Context Persistence

```javascript
// Save active context to localStorage
useEffect(() => {
  localStorage.setItem('lastContext', activeContext)
}, [activeContext])

// Restore on mount with fallback
const [context, setContext] = useState(
  localStorage.getItem('lastContext') || 'chat'
)
```

### Role-Based Navigation

```javascript
// More menu shows different options based on user role
const isAdmin = user.email?.includes("+supaadmin@");
const moreMenuItems = [
  { label: 'Help', action: 'external' },
  { label: 'About', action: 'modal' },
  ...(isAdmin ? [{ label: 'Settings', action: 'navigate' }] : []),
  { label: 'Logout', action: 'function' }
];
```

## Consequences

### Positive

- **Intuitive Navigation**: Bottom tabs match user expectations for multi-context apps
- **Efficient Context Switching**: Single tap between Chat, Docs, AI, More
- **Preserved Entity Navigation**: Sheet pattern remains for lists within contexts
- **Context Persistence**: Users return to their last active context
- **Role-Based Access**: More menu adapts to user permissions
- **Consistent Desktop Experience**: No changes to desktop navigation

### Negative

- **Increased Complexity**: Two navigation patterns to maintain
- **Screen Space**: Bottom tabs reduce content area by ~60px
- **Learning Curve**: Users must understand two-level navigation hierarchy

### Technical Implications

- **State Management**: Context and entity selection managed separately
- **URL Routing**: Context switching may not change URL (Sheet navigation does)
- **Performance**: Tab switching is instant (no network requests)
- **Accessibility**: Both tab bar and sheets must support keyboard navigation

## Testing Strategy

- **Context Switching**: Verify tabs switch contexts without network calls
- **Entity Navigation**: Ensure sheets work within each context
- **Persistence**: Test localStorage save/restore across sessions
- **Role-Based Access**: Verify More menu adapts to user permissions
- **Accessibility**: Keyboard navigation through tabs and sheets
- **Touch Targets**: All tabs meet 44px minimum requirement

See [ADR-014: Testing Strategy](./adr-014-testing-strategy.md) for comprehensive testing patterns and implementation details.

## Superseded By

This decision has been superseded by [ADR-015: Unified Sidebar Navigation](./adr-015-unified-sidebar-navigation.md) as of January 2025.

**Reason for Supersession:**
- Bottom tab bar created dual navigation patterns (mobile tabs + desktop sidebar)
- Shadcn sidebar-07 provides unified responsive navigation
- 45% code reduction by consolidating navigation logic
- Better desktop experience with collapsible sidebar
- Simpler state management (no context switching)

**Migration Path:**
See [Sidebar Migration Specification](../../.kiro/specs/sidebar-migration/) for implementation details.

**Date Superseded:** January 2025

## Compatibility with ADR-002

This ADR **extends** rather than **supersedes** ADR-002:

- **ADR-002 Pattern**: Sheet navigation for entity lists (channels, documents)
- **ADR-013 Pattern**: Bottom tab navigation for context switching
- **Combined Result**: Two-level navigation hierarchy optimized for different use cases

Both patterns work together to create a comprehensive mobile navigation strategy that scales from single-context (chat) to multi-context (platform) applications.
