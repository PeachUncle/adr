## Context

The project's architecture is composed of multiple pay-per-use cloud services on GCP, as well as third-party APIs with subscription costs. To ensure financial viability and prevent unexpected expenses, a formal strategy is required for monitoring, analyzing, and optimizing these operational costs. The goal is to maintain the system's performance and reliability while adhering to a defined budget.

## Decision

We will implement a multi-faceted cost management strategy centered around **Google Cloud's native billing and cost management tools**, supplemented by specific architectural and operational best practices.

1.  **Centralized Monitoring**: **Google Cloud Billing reports** will be the single source of truth for all infrastructure cost analysis. We will create a custom dashboard specifically for this project to visualize spending trends.

2.  **Budgeting and Alerting**: A formal monthly budget will be set for the GCP project. **Billing alerts** will be configured to automatically notify the development team via email and Pub/Sub when spending reaches 50%, 90%, and 100% of the budgeted amount.

3.  **Cost Attribution**: **Resource labels** will be applied to all GCP resources (e.g., `service: market-analysis-agent`, `environment: production`). This will allow us to break down costs by agent/service in the billing reports, identifying which components are the most expensive.

4.  **Architectural Optimization**: The following cost-optimization principles will be enforced:
    *   **Serverless First**: Continue to prioritize serverless, scale-to-zero services (Cloud Run, Pub/Sub, Vertex AI Training) for all intermittent workloads.
    *   **Aggressive Caching**: The `MarketAnalysisAgent` **must** implement robust caching (using Redis) for the results of expensive queries (BigQuery) and third-party API calls (Finnhub, Alpha Vantage) to minimize redundant computation and data egress.
    *   **Right-Sizing**: All provisioned resources (Cloud SQL, Redis) will be initially deployed with the smallest viable instance size and only scaled up if performance monitoring indicates a bottleneck.

5.  **Regular Reviews**: A **monthly cost review meeting** will be held to analyze the billing report, investigate any anomalies, and identify new opportunities for optimization.

## Rationale

1.  **Proactive Management**: This strategy moves from a reactive "check the bill at the end of the month" approach to a proactive, continuous process of monitoring and optimization.
2.  **Data-Driven Decisions**: By using detailed billing reports and resource labels, we can make informed, data-driven decisions about where to focus optimization efforts, rather than guessing.
3.  **Native Tooling**: Leveraging Google Cloud's built-in billing tools is the most cost-effective and deeply integrated solution. It requires no additional software and provides the most accurate and granular data.
4.  **Accountability**: Formalizing the process with budgets, alerts, and regular reviews creates clear accountability for managing operational costs.

## Consequences

-   **Implementation**:
    *   A monthly budget and a series of billing alerts must be configured in the Google Cloud Console.
    *   A standardized set of resource labels must be defined and consistently applied to all resources managed by our Terraform configuration (ADR-019).
    *   The `MarketAnalysisAgent`'s caching logic becomes a critical component not just for performance, but for cost management. Its effectiveness must be monitored.
-   **Operational Overhead**: The monthly cost review will add a small but important recurring task to the team's operational responsibilities.
-   **Third-Party Costs**: This ADR primarily covers GCP infrastructure costs. Costs for third-party APIs (Finnhub, Alpha Vantage) must be monitored separately through their respective billing dashboards.

## Alternatives Considered

-   **Third-Party Cloud Cost Management Tools (e.g., CloudZero, Harness)**: These are powerful platforms that can provide deeper insights and automated optimization recommendations. However, for the current scale of the project, they are an unnecessary expense. Google Cloud's native tools are more than sufficient to meet our needs.
-   **Manual Cost Tracking**: Relying on developers to manually track their resource usage. This was rejected as it is not scalable, is prone to human error, and provides no centralized oversight or automated alerting.

## Implementation Strategy

### Phase 1: Billing Configuration and Baseline (Week 1)
**Deliverables**:
- Configure Google Cloud Billing account and link to project
- Set up billing export to BigQuery for detailed cost analysis
- Define monthly budget based on projected usage ($200/month initial target)
- Configure billing alerts at 50%, 90%, and 100% thresholds
- Create baseline cost report for current infrastructure

**Dependencies**: GCP project with billing enabled, BigQuery dataset for billing export

### Phase 2: Resource Labeling Strategy (Week 1-2)
**Deliverables**:
- Define resource labeling taxonomy (env, service, cost-center, owner)
- Update Terraform configuration to apply labels to all resources
- Implement label validation in CI/CD pipeline (reject unlabeled resources)
- Apply labels to existing resources retroactively
- Document labeling standards for developers

**Dependencies**: Phase 1 completion, ADR-019 (Terraform IaC)

### Phase 3: Cost Monitoring Dashboard (Week 2-3)
**Deliverables**:
- Create custom billing dashboard in Data Studio or Looker
- Implement cost breakdown views (by service, by agent, by environment)
- Create trend analysis charts (daily, weekly, monthly costs)
- Add cost anomaly detection alerts (>20% spike from baseline)
- Document dashboard usage for monthly reviews

**Dependencies**: Phase 2 completion, billing data exported to BigQuery

### Phase 4: Cost Optimization Implementation (Week 3-4)
**Deliverables**:
- Implement Redis caching in MarketAnalysisAgent to reduce BigQuery queries
- Configure Cloud Run concurrency limits to optimize instance usage
- Right-size Cloud SQL and Redis instances based on actual usage
- Implement lifecycle policies for GCS buckets (delete old logs after 90 days)
- Configure committed use discounts for predictable workloads (if applicable)

**Dependencies**: Phase 3 completion, usage metrics from Cloud Monitoring

- Storage: 5-8% of total

### Cost Optimization Strategies

1. **Aggressive BigQuery Caching**: Implement Redis caching for MarketAnalysisAgent query results with 1-hour TTL. Reduces BigQuery scanning from 200GB to 40GB/month (80% reduction, saves $80/month).

2. **Partitioned and Clustered Tables**: Partition BigQuery tables by date, cluster by symbol. Reduces query costs by 70-80% through improved query pruning.

3. **Cloud Run Concurrency Tuning**: Increase Cloud Run concurrency from default 80 to 200 per instance. Reduces instance count by 60%, saves $10-15/month.

4. **Right-Sized Databases**: Start with smallest Cloud SQL instance (db-f1-micro) and Redis instance (1GB Basic). Scale up only when CPU >80% or memory >90% for sustained periods.

5. **GCS Lifecycle Policies**: Delete log files after 90 days, move infrequent access data to Nearline storage class after 30 days. Reduces storage costs by 40%.

6. **Third-Party API Optimization**: Implement request deduplication and caching to minimize redundant API calls. Negotiate volume discounts with providers.

7. **Scheduled Shutdown**: Shut down non-production environments (dev, staging) outside business hours (nights, weekends). Saves 50-60% on non-prod costs.

## Risk Assessment

| Risk | Severity | Likelihood | Impact | Mitigation |
|------|----------|------------|--------|------------|
| Unexpected cost spike | High | Medium | Budget overrun, service disruption if funds exhausted | Configure billing alerts at multiple thresholds, implement cost anomaly detection, set up automatic budget caps with notifications |
| BigQuery cost explosion | High | Medium | Single misconfigured query scans TB of data, incurs $100+ charge | Implement query cost estimation before execution, set maximum bytes billed limits, require code review for new BigQuery queries |
| Third-party API overage charges | Medium | Low | API rate limit exceeded, unexpected overage fees | Implement request counting and rate limiting, set up usage alerts from providers, negotiate hard caps with vendors |
| Resource label inconsistency | Low | High | Inability to attribute costs to specific services or owners | Enforce labeling via Terraform validation, automated label compliance checks, monthly label audit |
| Zombie resources | Medium | Medium | Unused resources continue incurring costs (test instances, old snapshots) | Regular resource inventory audits, automated cleanup scripts, tagging resources with expiration dates |
| Lack of cost visibility | Medium | Medium | Teams unaware of cost impact of decisions, gradual cost creep | Monthly cost review meetings, cost attribution reports sent to stakeholders, developer training on cost-conscious practices |
| Budget insufficient for scaling | High | Low | Unable to scale system to handle increased trading volume | Include 30% buffer in budget, define scaling cost model, establish process for budget increase approval |

## Monitoring and Success Criteria

### Key Metrics

| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| Total Monthly Cost | <$250 | Google Cloud Billing reports |
| Cost Per Trade Executed | <$2 | Total monthly cost / number of trades |
| BigQuery Cost Efficiency | <$100/month | BigQuery billing breakdown |
| Cost Variance from Budget | <10% | Actual vs budgeted spend comparison |
| Unlabeled Resource Percentage | <5% | Resource inventory audit |

### Alerting Thresholds

**Critical**:
- Monthly spend exceeds 100% of budget
- Daily cost spike >$50 (200% of daily average)
- Single BigQuery query costs >$10
- Third-party API cost exceeds monthly limit

**Warning**:
- Monthly spend at 90% of budget with >5 days remaining
- Daily cost increase >50% from 7-day average
- BigQuery monthly costs >$80 (approaching $100 target)
- Any service cost increases >30% month-over-month
- More than 10% of resources unlabeled

**Info**:
- Monthly spend at 50% of budget (mid-month checkpoint)
- Weekly cost summary report generated
- Cost optimization opportunity identified (automated analysis)
- Monthly cost review meeting scheduled

### Success Criteria

**Functional Requirements**:
- Billing alerts configured and tested for 50%, 90%, 100% thresholds
- Resource labels applied to all GCP resources (100% compliance)
- Billing data exported to BigQuery for analysis
- Cost monitoring dashboard accessible to all stakeholders
- Monthly cost review process documented and scheduled

**Performance Requirements**:
- Billing alert delivery latency <5 minutes
- Cost dashboard data freshness <24 hours
- Cost anomaly detection latency <2 hours

**Cost Requirements**:
- Total infrastructure costs remain below $250/month
- BigQuery costs optimized to <$100/month (50% reduction from unoptimized baseline)
- Cost per trade <$2 (enables profitability at target win rate)

**Operational Requirements**:
- Monthly cost review meeting held with stakeholders
- Cost optimization recommendations generated quarterly
- Developer training on cost-conscious practices completed
- Cost attribution reports distributed to team monthly

### Risk Factors

1. **BigQuery Cost Variability**: Medium complexity - Query costs depend on data scanned, which varies with table size and query patterns. Risk: Unexpected cost spikes from inefficient queries. Mitigation: Implement query cost estimation, set maximum bytes billed limits, regular query pattern audits.

2. **Third-Party API Cost Control**: Low complexity - API costs are subscription-based with predictable limits. Risk: Overage charges if rate limits exceeded. Mitigation: Implement rate limiting in code, negotiate hard caps with vendors, monitor usage against limits.

3. **Cost Attribution Accuracy**: Low complexity - Resource labels enable accurate cost attribution. Risk: Unlabeled resources misattributed, unclear cost ownership. Mitigation: Enforce labeling via Terraform validation, monthly label compliance audits.

4. **Budget Planning Accuracy**: Medium complexity - Initial budget based on estimates, actual costs may vary. Risk: Budget too low (constrains operations) or too high (inefficient). Mitigation: Start with conservative budget, review and adjust monthly based on actual usage, maintain 30% buffer.

5. **Cost Optimization Trade-offs**: Medium complexity - Optimizations may impact performance or functionality. Risk: Over-optimization degrades user experience or system reliability. Mitigation: Test optimizations in dev/staging first, monitor performance metrics alongside cost metrics, maintain balance between cost and quality.
