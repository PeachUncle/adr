# ADR-003: YooMoney Self-Employed Person Information Display

**Status:** Proposed  
**Date:** 2024-12-27  
**Author:** Development Team  

## Context

The YooMoney payment integration team has requested the addition of mandatory information for self-employed persons on our website. This requirement stems from both YooMoney's compliance policies and recent changes in Russian legislation regarding self-employed advertising disclosures.

### Current Situation

1. **YooMoney Integration**: We are integrating YooMoney as a payment processor for our UX/UI analysis services
2. **Self-Employed Status**: The business operates under self-employed person (самозанятый) status in Russia
3. **Missing Compliance Info**: Currently, our website lacks the required self-employed person disclosures

### Legal Requirements Analysis

#### Federal Law Changes (September 2023)
- **New Requirement**: Self-employed persons must include TIN (ИНН) and full name (ФИО) in all advertising
- **Scope**: Applies to advertising of goods and services by self-employed individuals
- **Penalty**: Fines and potential advertising restrictions for non-compliance

#### YooMoney Requirements
YooMoney requires self-employed merchants to display:
- **Full Name (ФИО)**: Complete legal name as registered
- **TIN (ИНН)**: Tax identification number
- **Contact Information**: Email or postal address
- **Self-Employment Status**: Optional but recommended for transparency

#### Website vs. Advertising Distinction
- **Advertising**: Social media posts, paid ads, marketplace listings (mandatory TIN/name display since Sept 2023)
- **Website**: Company information display (not strictly mandatory but highly recommended for trust and compliance)

### Current Technical State

- **Frontend**: Next.js 15 application with TypeScript
- **Styling**: Tailwind CSS with DaisyUI components
- **Authentication**: NextAuth.js integration
- **Database**: PostgreSQL with Prisma ORM
- **Payment Integration**: YooMoney integration in progress

## Decision

We will implement a **comprehensive self-employed information disclosure system** that satisfies YooMoney requirements while maintaining user trust and legal compliance.

### Core Decision Points

1. **Information Display**: Add required self-employed information to website footer and dedicated pages
2. **Privacy-First Approach**: Display only legally required information, implement privacy protection measures
3. **Multi-Location Strategy**: Place information in footer, about/contact pages, and legal sections
4. **User Trust Focus**: Frame disclosure as transparency and legitimacy demonstration
5. **Mobile-Responsive**: Ensure proper display across all device types

### Security and Privacy Considerations

#### 1. Email Protection

```typescript
// src/utils/privacy.ts
export function protectEmail(email: string): string {
  if (!email.includes('@')) return email;
  
  const [local, domain] = email.split('@');
  if (local.length <= 2) return email;
  
  const protectedLocal = local[0] + '*'.repeat(local.length - 2) + local[local.length - 1];
  return `${protectedLocal}@${domain}`;
}


```

## Implementation Details

### Environment Variables

The project uses `@t3-oss/env-nextjs` for type-safe environment variable validation. Self-employed variables are defined in `src/env.js`:

```javascript
// src/env.js - Server schema
server: {
  // ... existing variables
  SELF_EMPLOYED_FULL_NAME: z.string(),
  SELF_EMPLOYED_TIN: z.string(), 
  SELF_EMPLOYED_EMAIL: z.string().email(),
}
```

**Environment file (.env.local):**
```bash
# Required - application will fail to start without these

SELF_EMPLOYED_TIN="644112920982"
SELF_EMPLOYED_EMAIL="denuly54@gmail.com"
```

**Benefits of env validation:**
- Type safety with Zod schemas
- Email validation for contact email
- Required variables ensure proper configuration
- Runtime validation in development
- Build fails fast if environment is misconfigured

## Risk Mitigation Strategies

### Privacy Protection
1. **Email Masking**: Display email in protected format (user***@domain.com)
2. **Contact Form**: Provide contact form as alternative to direct email
3. **Spam Protection**: Implement CAPTCHA and rate limiting

### Security Measures
1. **Environment Variables**: Store sensitive info in env vars, not code
2. **Access Logging**: Monitor who accesses legal information pages
3. **Regular Updates**: Periodic review of displayed information
4. **Secure Hosting**: Ensure website security to protect all information

### Legal Protection
1. **Legal Review**: Have lawyer review all displayed information
2. **Regular Updates**: Monitor law changes affecting self-employed
3. **Documentation**: Keep records of compliance measures
4. **Professional Consultation**: Regular consultation with tax advisor
