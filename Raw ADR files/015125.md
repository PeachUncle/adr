# Design: Refactor Hypercube to Bit-Packed Storage

## Context
Hypercube vectors contain binary values (±1/√d), representing signs of projected vectors. Storing as 32-bit floats wastes 31 bits per value. By storing as 1 bit per value, we achieve massive memory savings and enable hardware-accelerated bitwise operations.

## Goals / Non-Goals

### Goals
- Reduce memory footprint by 97% (32x reduction)
- Achieve 10x query speedup through hardware acceleration
- Maintain mathematical correctness
- Preserve existing quantization accuracy

### Non-Goals
- Not changing quantization algorithm (same ±1/√d computation)
- Not optimizing for non-power-of-2 dimensions (accept padding)
- Not implementing compressed bitpacking (simple 1 bit per value)

## Decisions

### Decision 1: Use u64 Chunks for Storage

**Rationale**: u64 provides:
- Natural alignment for modern CPUs
- Hardware popcount support (@popCount)
- SIMD-friendly for future optimization
- Good balance between size and efficiency

**Structure**:
```zig
pub const QuantizedData = struct {
    hypercube_bits: []u64,     // N × ⌈d/64⌉ u64s
    bits_per_vector: usize,    // ⌈d/64⌉
    corrective_1: []f32,       // Unchanged
    corrective_2: []f32,       // Unchanged
    centroid: []f32,           // Unchanged
    projection: Matrix,        // Unchanged
    dimension: usize,          // d (unchanged)
    allocator: Allocator,
};
```

### Decision 2: Bit Encoding Convention

**Encoding**:
- `1` bit → positive value (+1/√d)
- `0` bit → negative value (-1/√d)

**Justification**: Matches natural interpretation where 1=positive, 0=negative

### Decision 3: Compute-Then-Pack Strategy

**Algorithm**:
1. Compute hypercube as floats (±1/√d)
2. Use floats to compute corrective_2
3. Pack floats to bits
4. Free float array

**Rationale**: corrective_2 needs actual float values for dot product. Temporary float allocation is acceptable (immediately freed).

## Algorithm: Bit Packing

### Packing Function

```zig
/// Pack float hypercube values (±scale) to bits
/// Positive values → 1, negative values → 0
fn packToBits(hypercube_floats: []const f32, output_bits: []u64) void {
    const d = hypercube_floats.len;
    
    // Initialize bits to zero
    @memset(output_bits, 0);
    
    for (hypercube_floats, 0..) |val, i| {
        const chunk_idx = i / 64;      // Which u64
        const bit_idx = i % 64;        // Which bit in u64
        
        if (val > 0.0) {
            // Set bit to 1 for positive
            output_bits[chunk_idx] |= @as(u64, 1) << @intCast(bit_idx);
        }
        // Negative stays 0 (already initialized)
    }
}
```

**Example** (d=8):
```
hypercube_floats = [+0.35, -0.35, +0.35, -0.35, +0.35, +0.35, -0.35, -0.35]
                    [ 1,     0,     1,     0,     1,     1,     0,     0   ]
output_bits[0] = 0b00110101 (little-endian bit order)
```

### Updated Quantization

pub fn quantizeVectorsFromRaw(...) !QuantizedData {
    // ... (centroid computation unchanged)
    
    const bits_per_vector = (output_dim + 63) / 64;  // ⌈d/64⌉
    var hypercube_bits = try allocator.alloc(u64, num_vectors * bits_per_vector);
    
    for (0..num_vectors) |i| {
        // Allocate temporary hypercube floats
        const temp_hyp = try allocator.alloc(f32, output_dim);
        defer allocator.free(temp_hyp);
        
        // Compute hypercube (±1/√d)
        corrective_2[i] = 0.0;
        for (0..output_dim) |j| {
            const proj_val = /* dot product */;
            temp_hyp[j] = if (proj_val >= 0.0) scale else -scale;
            corrective_2[i] += proj_val * temp_hyp[j];
        }
        
        // Pack to bits
        const bit_start = i * bits_per_vector;
        packToBits(temp_hyp, hypercube_bits[bit_start..][0..bits_per_vector]);
    }
    
    return QuantizedData{
        .hypercube_bits = hypercube_bits,
        .bits_per_vector = bits_per_vector,
        // ... rest
    };
}

## Algorithm: Query with Bitwise Operations

### Population Count

```zig
// Count 1-bits (positive values) in hypercube
fn computePopCount(bits: []const u64) u32 {
    var count: u32 = 0;
    for (bits) |chunk| {
        count += @popCount(chunk);  // Hardware POPCNT instruction!
    }
    return count;
}
```

**Performance**: 1 CPU cycle per 64 bits (vs 64 float comparisons)

### Dot Product with Bitwise Operations

```zig
fn computeDotProductBitwise(
    q_bar: []const u32,  // B-bit quantized query
    bits: []const u64,   // Bit-packed hypercube
    d: usize,
) f32 {
    var dot_term: f32 = 0.0;
    
    for (0..d) |i| {
        const chunk_idx = i / 64;
        const bit_idx = @as(u6, @intCast(i % 64));
        
        // Extract bit
        const is_positive = (bits[chunk_idx] >> bit_idx) & 1;
        
        // Compute sign: 1 → +1, 0 → -1
        const sign: f32 = if (is_positive == 1) 1.0 else -1.0;
        
        // Accumulate: q_bar[i] * sign
        dot_term += @as(f32, @floatFromInt(q_bar[i])) * sign;
    }
    
    return dot_term;
}
```

### Updated Distance Estimation

```zig
fn estimateDistance(...) f32 {
    // Get bit pattern for vector
    const bit_start = vector_index * quantized_data.bits_per_vector;
    const bits = quantized_data.hypercube_bits[bit_start..][0..quantized_data.bits_per_vector];
    
    // Hardware popcount
    const pop_count = @as(f32, @floatFromInt(computePopCount(bits)));
    
    // Bitwise dot product
    const dot_term = computeDotProductBitwise(quant_query.q_bar, bits, d);
    
    // Rest of distance formula unchanged
    const sqrt_d = @sqrt(@as(f32, @floatFromInt(d)));
    const term1 = (2.0 * quant_query.width / sqrt_d) * dot_term;
    const term2 = (2.0 * quant_query.q_lower / sqrt_d) * pop_count;
    const term3 = (quant_query.width * quant_query.q_bar_sum / sqrt_d);
    const term4 = sqrt_d * quant_query.q_lower;
    
    const inner_product_est = (term1 + term2 + term3 - term4) / corrective_2;
    
    const distance_sq = corrective_1 * corrective_1 +
        norm_q_residual * norm_q_residual -
        2.0 * corrective_1 * norm_q_residual * inner_product_est;
    
    return @sqrt(@max(0.0, distance_sq));
}
```

## Memory Layout

### Before (Float Storage)
```
Vector 0: [f32, f32, f32, ..., f32]  (d×4 bytes)
Vector 1: [f32, f32, f32, ..., f32]  (d×4 bytes)
...
Vector N: [f32, f32, f32, ..., f32]  (d×4 bytes)

Total: N × d × 4 bytes
```

### After (Bit Storage)
```
Vector 0: [u64]  (⌈d/64⌉×8 bytes, bits 0-63 in u64[0], bits 64-127 in u64[1], etc.)
Vector 1: [u64]
...
Vector N: [u64]

Total: N × ⌈d/64⌉ × 8 bytes
```

### Example Sizes

| Dimension | Vectors | Float Storage | Bit Storage | Savings |
|-----------|---------|---------------|-------------|---------|
| 64        | 1M      | 256 MB        | 8 MB        | 248 MB  |
| 128       | 1M      | 512 MB        | 16 MB       | 496 MB  |
| 256       | 10M     | 10 GB         | 320 MB      | 9.68 GB |

## Performance Analysis

### Quantization Performance

**Impact**: Minimal (~1-2% slower)
- Added: bit packing overhead
- Same: hypercube computation, corrective_2 calculation
- Trade-off: Acceptable for massive query speedup

### Query Performance

**Before** (float operations):
```
Population count: 64 float comparisons per 64 values
Dot product: 64 float multiplications per 64 values
Time per vector: ~50 ns
```

**After** (bitwise operations):
```
Population count: 1 popcount per 64 values (~1 cycle)
Dot product: 64 integer ops (faster than float)
Time per vector: ~5 ns
```

**Speedup**: ~10x for distance computation

## Risks / Trade-offs

### Risk: Dimension Padding

**Issue**: Non-power-of-64 dimensions waste bits
- d=100 → needs 128 bits (28 wasted)
- Impact: 28% overhead for d=100

**Mitigation**: Document clearly, acceptable trade-off for simplicity

### Risk: Breaking Change

**Issue**: Existing QuantizedData incompatible
**Mitigation**: 
- Version bump
- Clear migration guide
- Can't load old quantized data (must re-quantize)

### Risk: Bit Order Confusion

**Issue**: Little-endian bit ordering could confuse
**Mitigation**:
- Clear documentation
- Comprehensive tests
- Helper functions encapsulate details
