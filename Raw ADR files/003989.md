# ADR-006: Dynamic Permission Requests for Privacy

Date: 2025-10-30

## Status
Accepted

## Context

StepDown emphasizes privacy as a core value. Traditional Android apps declare all permissions in the manifest, which users see at install time. Even if permissions aren't used immediately, this creates privacy concerns and reduces trust.

Our requirements:
- No network access unless user explicitly enables backup
- No permission prompts at install time
- Clear user understanding of why permissions are needed
- Compliance with Play Store privacy policies

Android permission model:
- **Normal permissions**: Granted automatically (e.g., INTERNET, VIBRATE)
- **Dangerous permissions**: Require user approval (e.g., CAMERA, LOCATION)
- **Special permissions**: Require system settings navigation (e.g., SCHEDULE_EXACT_ALARM on API 31+)

StepDown needs:
- `SCHEDULE_EXACT_ALARM` (API 31+): For reliable alarm timing
- `POST_NOTIFICATIONS` (API 33+): To show notifications
- `INTERNET`: Only when backup is enabled
- `RECEIVE_BOOT_COMPLETED`: To reschedule alarms after reboot

## Decision

We will use a **dynamic permission request strategy** where permissions are requested contextually when the user enables features that require them.

### Permission Request Strategy

**1. SCHEDULE_EXACT_ALARM (API 31+)**
- Request: On app first launch during onboarding
- Rationale shown: "StepDown needs exact alarm scheduling to send daily reminders at consistent times"
- Fallback: Use inexact alarms if denied (with user warning)

**2. POST_NOTIFICATIONS (API 33+)**
- Request: On app first launch during onboarding
- Rationale shown: "StepDown needs notification permission to remind you of your daily schedule"
- Fallback: Silent mode (no notifications, user must open app)

**3. INTERNET**
- Declared: NOT in manifest initially
- Request: Only when user toggles "Enable Backup" in Settings
- Rationale shown: "Backup requires internet access to sync with Google Drive. No data is sent without your explicit action."
- Fallback: Backup disabled if denied

**4. RECEIVE_BOOT_COMPLETED**
- Declared: In manifest (normal permission, auto-granted)
- No user prompt needed

### Manifest Configuration

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Normal permissions - no prompt -->
    <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
    <uses-permission android:name="android.permission.VIBRATE" />

    <!-- Special permissions - prompt with rationale -->
    <uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"
                     android:maxSdkVersion="32" />

    <!-- API 33+ notification permission -->
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

    <!-- INTERNET permission NOT declared here -->
    <!-- Added dynamically when user enables backup -->
</manifest>
```

### Implementation

#### Permission Request Flow

```kotlin
class OnboardingActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Request permissions sequentially during onboarding
        lifecycleScope.launch {
            requestExactAlarmPermission()
            requestNotificationPermission()
        }
    }

    private suspend fun requestExactAlarmPermission() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            val alarmManager = getSystemService(AlarmManager::class.java)

            if (!alarmManager.canScheduleExactAlarms()) {
                // Show rationale dialog
                showDialog(
                    title = "Reliable Reminders",
                    message = "StepDown needs exact alarm scheduling to send daily reminders at consistent times (5-6 PM).\n\nThis helps you stick to your reduction schedule.",
                    positiveButton = "Allow" to {
                        val intent = Intent(Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM).apply {
                            data = Uri.parse("package:$packageName")
                        }
                        startActivity(intent)
                    },
                    negativeButton = "Skip" to {
                        // Continue with inexact alarms
                        showWarning("Reminders may be delayed by up to 30 minutes")
                    }
                )
            }
        }
    }

    private fun requestNotificationPermission() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
            if (ContextCompat.checkSelfPermission(this, Manifest.permission.POST_NOTIFICATIONS)
                != PackageManager.PERMISSION_GRANTED) {

                // Show rationale dialog
                showDialog(
                    title = "Enable Notifications",
                    message = "StepDown sends a daily notification to remind you of your schedule. Without notifications, you'll need to open the app manually.",
                    positiveButton = "Allow" to {
                        ActivityCompat.requestPermissions(
                            this,
                            arrayOf(Manifest.permission.POST_NOTIFICATIONS),
                            REQUEST_POST_NOTIFICATIONS
                        )
                    },
                    negativeButton = "Skip" to {
                        // Enable silent mode
                        preferences.edit().putBoolean("silent_mode", true).apply()
                    }
                )
            }
        }
    }
}
```

#### Dynamic INTERNET Permission (Backup)

```kotlin
class SettingsFragment : PreferenceFragmentCompat() {
    override fun onPreferenceTreeClick(preference: Preference): Boolean {
        if (preference.key == "enable_backup") {
            val switch = preference as SwitchPreference

            if (switch.isChecked) {
                // User enabled backup
                requestInternetPermissionForBackup()
            } else {
                // User disabled backup
                revokeInternetPermission()
            }
            return true
        }
        return super.onPreferenceTreeClick(preference)
    }

    private fun requestInternetPermissionForBackup() {
        // Show detailed rationale
        MaterialAlertDialogBuilder(requireContext())
            .setTitle("Enable Cloud Backup")
            .setMessage(
                "Cloud backup will sync your event log to Google Drive.\n\n" +
                "• Data is stored in your private app folder\n" +
                "• Only you can access it\n" +
                "• Requires internet permission\n" +
                "• Only syncs when you're online\n\n" +
                "No data is sent without your explicit action."
            )
            .setPositiveButton("Continue") { _, _ ->
                // Dynamically add INTERNET permission
                // (Note: This is conceptual - Android doesn't truly support runtime INTERNET permission)
                // In practice, we declare it in manifest but check user preference before using
                enableBackupFeature()
            }
            .setNegativeButton("Cancel") { _, _ ->
                // Revert toggle
                findPreference<SwitchPreference>("enable_backup")?.isChecked = false
            }
            .show()
    }

    private fun enableBackupFeature() {
        // Check if Google Play Services available
        if (isGooglePlayServicesAvailable()) {
            // Request Drive API scopes
            val signInOptions = GoogleSignInOptions.Builder(GoogleSignInOptions.DEFAULT_SIGN_IN)
                .requestScopes(Scope(DriveScopes.DRIVE_APPFOLDER))
                .build()

            val client = GoogleSignIn.getClient(requireContext(), signInOptions)
            startActivityForResult(client.signInIntent, REQUEST_SIGN_IN)
        } else {
            showError("Google Play Services required for backup")
        }
    }
}
```

## Consequences

### Positive

1. **Privacy-first UX**: Users see zero permissions at install time
2. **Trust building**: Transparent about why each permission is needed
3. **Context clarity**: Permission requests appear when user enables feature
4. **Play Store compliance**: Demonstrates minimal permission usage
5. **User control**: Users can revoke permissions and understand impact
6. **Marketing advantage**: "Zero permissions at install" is a selling point

### Negative

1. **Complex implementation**: More code than declaring all permissions upfront
2. **User friction**: Some users may deny permissions and lose functionality
3. **Support burden**: Users may not understand why features don't work after denying permissions
4. **Testing complexity**: Must test all permission states (granted/denied/never ask again)

### Risks

1. **User confusion about INTERNET permission**
   - *Risk*: Users don't understand why backup needs internet
   - *Mitigation*: Clear explanation in dialog, link to privacy policy
   - *Likelihood*: Low (most users understand cloud backup requires internet)

2. **Alarm permission denial breaks core functionality**
   - *Risk*: User denies SCHEDULE_EXACT_ALARM, app loses primary feature
   - *Mitigation*: Fallback to inexact alarms + WorkManager
   - *Degraded experience*: Notifications may be delayed up to 30 minutes
   - *Likelihood*: Low (most users want reliable reminders)

3. **Notification permission denial on API 33+**
   - *Risk*: User denies POST_NOTIFICATIONS, no way to remind them
   - *Mitigation*: Persistent in-app banner: "Enable notifications for daily reminders"
   - *Fallback*: In-app only mode (no background notifications)
   - *Likelihood*: Medium (some users are notification-averse)

4. **Google Play Services unavailable for backup**
   - *Risk*: Device without Google Play (e.g., Huawei, custom ROMs)
   - *Mitigation*: Disable backup feature with clear message
   - *Alternative*: Future consideration for alternative backup (e.g., local file export)
   - *Likelihood*: Low (target mainstream devices)

## Permission State Handling

### Permission Denied

```kotlin
override fun onRequestPermissionsResult(
    requestCode: Int,
    permissions: Array<out String>,
    grantResults: IntArray
) {
    when (requestCode) {
        REQUEST_POST_NOTIFICATIONS -> {
            if (grantResults.isEmpty() || grantResults[0] != PackageManager.PERMISSION_GRANTED) {
                // Permission denied
                if (ActivityCompat.shouldShowRequestPermissionRationale(this, Manifest.permission.POST_NOTIFICATIONS)) {
                    // User denied but didn't select "Don't ask again"
                    showSnackbar("Notifications are disabled. You can enable them in Settings anytime.")
                } else {
                    // User selected "Don't ask again" or denied twice
                    showSnackbar("To enable notifications, go to Settings > Apps > StepDown > Permissions")
                }

                // Enable silent mode
                preferences.edit().putBoolean("silent_mode", true).apply()
            }
        }
    }
}
```

### Permission Revoked After Granted

```kotlin
class AlarmScheduler(private val context: Context) {
    fun scheduleAlarm() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            val alarmManager = context.getSystemService(AlarmManager::class.java)

            if (!alarmManager.canScheduleExactAlarms()) {
                // Permission was revoked
                Log.w("StepDown", "SCHEDULE_EXACT_ALARM permission revoked")

                // Fallback to inexact alarm
                scheduleInexactAlarm()

                // Notify user
                NotificationManager.showPermissionRevokedNotification(
                    "Exact alarm permission was revoked. Reminders may be delayed."
                )
                return
            }
        }

        // Permission granted, proceed
        scheduleExactAlarm()
    }
}
```

## Testing Strategy

### Permission Test Matrix

| API Level | Permission | Granted | Denied | Never Ask Again |
|-----------|------------|---------|--------|-----------------|
| 26-30 | SCHEDULE_EXACT_ALARM | N/A | N/A | N/A |
| 31-32 | SCHEDULE_EXACT_ALARM | ✅ Exact alarms | ⚠️ Inexact fallback | ⚠️ Inexact fallback |
| 33+ | POST_NOTIFICATIONS | ✅ Notifications | ⚠️ Silent mode | ⚠️ Silent mode + banner |
| All | INTERNET (backup) | ✅ Backup works | ❌ Backup disabled | ❌ Backup disabled |

### Automated Tests

@Test
fun whenNotificationPermissionDenied_enablesSilentMode() {

    // Verify silent mode enabled
    assertTrue(getPreferences().getBoolean("silent_mode", false))

fun whenAlarmPermissionDenied_usesInexactAlarm() {
    // Deny permission (API 31+)
