# 5. Use Kiro as the Only UI for Kiro Forge

Date: 2025-11-18

## Status

Accepted

## Context

Kiro Forge is a developer productivity framework that enables teams to bootstrap projects with curated coding standards through steerings and hooks. Available as an MCP (Model Context Protocol) server, it provides centralized management of reusable steering-hook packs that can be synced across developer environments.

The kiro-forge platform serves multiple personas:

- Developers who bootstrap projects and apply steerings
- Architects who create and version steering packs
- DevOps Leads who distribute updates and manage the central repository
- Engineering Managers who track adoption and compliance metrics
- Security Engineers who embed compliance checks
- Traditional productivity platforms require multiple interfaces:

This creates the same fragmentation problem that Kiro Forge aims to solve for development workflows. Each interface requires separate learning, authentication, and context switching—undermining the unified developer experience.

Since Kiro Forge is built as an MCP server and leverages Kiro's native capabilities (steerings and hooks), the question arises: should we build traditional UIs for managing Kiro Forge, or use Kiro itself as the only interface?

## Decision

We will use Kiro as the only UI for all interactions with Kiro Forge across all personas and use cases.

All steerings, operations, analytics queries, and platform management will occur through Kiro's conversational interface via the Kiro Forge MCP server. No separate web dashboards, admin consoles, or CLI tools will be built.

## Consequences

### Positive:

- Dogfooding the Product Model
- Accelerated Development / we can develop faster
- Kiro Forge uses Kiro to manage itself, validating the steering-hook productivity model it promotes
- Demonstrates the power of conversational interfaces for complex workflows
- Builds confidence in the MCP server architecture
- Unified Developer Experience
- Single interface for consuming and managing steering packs
- No context switching between development and platform management
- Consistent interaction model across all personas
- No need to build and maintain web dashboards, admin portals, or CLI tools
- Focus engineering effort on core MCP server functionality
- Faster time-to-market for Phase 1 (MCP server read/write)
- Natural Interaction Patterns

#### Example prompts

- "Bootstrap an ETL project with data quality steerings"
- "Create an IaC steerings with CDK best practices from the current project"
- "Show me web development steerings for React"
- "Sync latest security steerings to all teams"

## Negative:

- Lack of Graphical Analytics Dashboards

- No visual dashboards for tracking adoption trends, compliance scores, and violation patterns
- Engineering managers and executives may prefer graphical representations over conversational queries

- Optional Future Enhancement: Comprehensive analytics dashboards can be implemented post-MVP / hackathon using Amazon QuickSight, providing visual insights for stakeholders who require graphical representations while maintaining Kiro as the primary interface
