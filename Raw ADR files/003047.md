# ADR-0000: Initial Project Structure and Adoption of Cathedral Engineering Manifesto

*   **Date:** 2024-07-29
*   **Status:** Accepted

## Context

This is the inaugural Architectural Decision Record for the "Cathedral Engine" project. The project aims to reimplement functionalities similar to an existing "Claude" system, but in Rust, and with integrations for multiple AI provider APIs (Google, Anthropic, Grok, Open Router). A core requirement is to follow a specific, rigorous architectural and documentation methodology.

## Decision

1.  **Adoption of the "Grand Unifying Manifesto: The Canon of Cathedral Engineering":** The project will strictly adhere to the principles, laws, and practices outlined in this manifesto. This includes its directives on documentation (Master Atlas, Sectional Blueprints, ADRs), directory structure, modularity, coding practices (TDD, Flat Logic, DRY, True Names), and the overall philosophy of building a "digital cathedral."

2.  **Initial Project Initialization:**
    *   The project is initialized as a Rust binary application using `cargo new cathedral_engine --bin`.
    *   Core dependencies identified and added to `Cargo.toml` include: `tokio`, `reqwest`, `serde`, `serde_json`, `thiserror`, `anyhow`, `tracing`, `tracing-subscriber`, `treesitter`, `tree-sitter-rust`, `tree-sitter-markdown`, and `fs_extra`.
    *   The `src/` directory will contain `main.rs` (entry point) and `lib.rs` (for shared library code).
    *   The `ARCHITECTURE.md` file is established as the "Master Atlas."
    *   This `docs/adr/` directory is established for recording ADRs.

3.  **Top-Level Modular Structure (Preliminary):** As outlined in `ARCHITECTURE.md`, the initial high-level modules are planned as directories within `src/`: `api_clients`, `context_engine`, `indexing_engine`, `diff_engine`, `tool_executor`, `memory_store`, `orchestration_layer`, `common_types`, `cli`, and `config`.

## Consequences

*   **Development Process:** The development process will be characterized by meticulous planning, documentation, and adherence to the Manifesto's coding rituals (e.g., TDD, refactoring for flat logic).
*   **Documentation Overhead:** There is an explicit commitment to maintaining comprehensive documentation, which will require ongoing effort.
*   **Structural Rigidity:** The architectural laws provide a strong framework. Deviations will require formal ADRs.
*   **Clarity and Maintainability:** The adherence to these principles is expected to result in a highly organized, understandable, and maintainable codebase, suitable for long-term development and evolution.
*   **Learning Curve:** Team members (currently the AI Architect) must be fully conversant with the Manifesto.
