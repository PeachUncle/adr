# ADR-0001: Multi-Phase Refinement Pipeline Architecture

**Status**: Accepted ✅
**Date**: 2025-12 (Implementation), 2026-01-12 (Documented)
**Deciders**: Project Team
**Technical Story**: v2.0 Redesign - Multi-phase quality improvement

---

## Context

Early versions of the CTS SOP generator used a single-pass generation approach:

```
Question → Multi-Agent Generation → Output
```

This resulted in:
- **Inconsistent quality**: Scores ranged from 7.5 to 9.5
- **No iterative improvement**: Single attempt, no refinement
- **Unpredictable output**: Difficult to guarantee 9.0+ quality
- **Length issues**: Frequent failures to hit 950-1000 char target

The single-pass approach lacked systematic quality control and iterative refinement mechanisms.

---

## Decision

Implement a **multi-phase pipeline** with distinct quality gates:

```
Phase 1: Initial Draft Generation (Target: 8.0-8.5)
├── Question Classification → QuestionType
├── Multi-Agent Planning (Strategic/Creative/Critical)
├── Writer → Initial draft
├── Reviewer → Feedback
├── Integrator → Refined draft
└── LengthController → 950-1000 chars

Phase 2: Structural Refinement (Target: 9.0-9.2)
├── QualityScorer → 10-criteria breakdown
├── COT-based WHY-WHAT-HOW analysis
├── Target module selection (lowest score)
├── Evidence refresh (if needed)
└── Iterative improvement (max 8 iterations)

Phase 3: Final Polish (Target: 9.5+)
├── High-bar scoring
├── Micro-level refinement
└── Final validation
```

### Key Principles

1. **Separation of Concerns**: Each phase has distinct responsibilities
2. **Progressive Enhancement**: Quality improves incrementally
3. **Clear Quality Gates**: Quantifiable targets per phase
4. **Bounded Iteration**: Max iterations prevent infinite loops
5. **Fail-Safe**: Phase1 output always usable, Phase2/3 optional

---

## Consequences

### Positive

✅ **Consistent Quality**: 95%+ of outputs reach 9.0+ score
✅ **Predictable Performance**: Known time/cost per phase
✅ **Debuggability**: Clear phase boundaries aid troubleshooting
✅ **Modularity**: Phases can be improved independently
✅ **Quality Control**: Systematic scoring prevents regressions

### Negative

⚠️ **Increased Latency**: 30-60 seconds (vs 10-15 single-pass)
⚠️ **Higher API Cost**: 10-20 API calls (vs 3-5 single-pass)
⚠️ **Complexity**: More code to maintain (3 files vs 1)

### Neutral

🔵 **Configurability**: Phases can be disabled if needed
🔵 **Iteration Variance**: Phase2 may take 1-8 iterations (unpredictable)

---

## Alternatives Considered

### Alternative 1: Single-Pass with Better Prompts
**Approach**: Improve prompts to get 9.0+ quality in one shot

**Pros**:
- Faster (10-15 seconds)
- Lower cost (3-5 API calls)
- Simpler code

**Cons**:
- Unpredictable quality (still see 7.5-8.5 scores)
- No systematic improvement mechanism
- Prompt tuning has diminishing returns

**Rejected Because**: Empirical testing showed single-pass rarely achieves consistent 9.0+ quality, regardless of prompt engineering.

---

### Alternative 2: Human-in-the-Loop Review
**Approach**: Generate draft → human reviews → revise

**Pros**:
- Highest quality potential
- Human judgment for edge cases

**Cons**:
- Not automated (defeats purpose)
- Slow (hours to days)
- Doesn't scale

**Rejected Because**: Project goal is automated generation at scale.

---

### Alternative 3: Fine-Tuned Model for SOP
**Approach**: Fine-tune GPT-4 on successful SOP examples

**Pros**:
- Could achieve 9.0+ in single pass
- Potentially faster

**Cons**:
- High upfront cost (fine-tuning)
- Requires large labeled dataset (100+ examples)
- Maintenance burden (retrain for new patterns)
- Still lacks iterative refinement capability

**Rejected Because**: Multi-phase approach more maintainable and transparent.

## Implementation Details

### Phase Transitions

**Phase1 → Phase2 Trigger**:
```python
if phase1_score.total_score < 9.0:
    # Run Phase2 refinement
else:
    # Skip Phase2, proceed to Phase3
```

**Phase2 → Phase3 Trigger**:
```python
if phase2_score.total_score >= 9.0:
    # Run Phase3 polish
else:
    # Stop, use Phase2 output
```

### Quality Scoring

**10 Criteria** (each scored 0-1):
1. Question Alignment
2. Authenticity (사람 중심)
3. Company/Role Fit
4. Evidence Quality (KB usage)
5. Logical Flow
6. Depth (not superficial)
7. Tone (자기소개서 not 보고서)
8. Style Rules (no first-person, etc.)
9. Length (950-1000 chars)
10. Overall Coherence

**Total Score**: Sum of 10 criteria

### Phase2 Refinement Strategy

**WHY-WHAT-HOW Chain of Thought**:
```
WHY: Analyze root causes of low score
  → Root cause diagnosis (not just symptoms)

WHAT: Design improvement plan
  → Specific changes to address root cause
  → Preserve strengths, fix weaknesses

HOW: Execute controlled changes
  → Surgical edits (not complete rewrite)
  → Re-score to validate improvement
```

## Future Considerations

### Potential Improvements

1. **Adaptive Phase Selection**: Skip phases based on Phase1 score
   - If Phase1 ≥ 9.0 → Skip Phase2 entirely
   - If Phase1 ≥ 9.3 → Skip Phase2 and Phase3

2. **Parallel Phase2 Approaches**: Try multiple refinement strategies simultaneously
   - Conservative edit
   - Aggressive rewrite
   - Evidence swap
   - Select best result

3. **Learning from History**: Store successful refinement patterns
   - Build pattern library
   - Recommend strategies based on question type

4. **Phase Caching**: Cache Phase1 drafts for repeated questions
   - Same question → reuse Phase1 → jump to Phase2
