# ADR-001: Use Textual for Terminal User Interface

**Date**: 2025-10-06  
**Status**: Accepted  
**Author**: Nik Jois

## Context

The project requires a professional, accessible Terminal User Interface (TUI) for hydraulics calculations and AI agent interactions. The TUI must be:
- Keyboard-driven and accessible
- Cross-platform (Linux, macOS, Windows)
- Modern and visually appealing
- Easy to extend with new features

## Decision

We will use Textual as the TUI framework.

## Rationale

### Textual Advantages

1. **Modern Python Framework**
   - Built on asyncio for responsive UI
   - Type-safe with full type annotations
   - Active development and community

2. **Rich Feature Set**
   - Built-in widgets (buttons, inputs, tables, tabs)
   - CSS-like styling
   - Keyboard shortcuts and bindings
   - Screen navigation

3. **Accessibility**
   - Screen reader compatible
   - Full keyboard navigation
   - ARIA-compliant widgets

4. **Developer Experience**
   - Clean, declarative API
   - Hot reload during development
   - Excellent documentation
   - Testing utilities

5. **Performance**
   - Efficient rendering
   - Low resource usage
   - Smooth animations

### Alternatives Considered

**urwid**
- Pros: Mature, stable
- Cons: Callback-based API, less modern, limited styling

**blessed/prompt_toolkit**
- Pros: Lightweight
- Cons: More low-level, requires more boilerplate

**npyscreen**
- Pros: Simple for basic UIs
- Cons: Limited features, not actively maintained

**Rich only (no TUI framework)**
- Pros: Already a dependency
- Cons: Would need to build TUI infrastructure from scratch

## Consequences

### Positive

- Professional, modern TUI with minimal code
- Rapid development of new screens
- Consistent look and feel
- Easy to test and maintain
- Great developer experience

### Negative

- Additional dependency (mitigated: lightweight and pure Python)
- Learning curve for team (mitigated: excellent docs)
- Tied to Textual's release cycle

### Neutral

- Requires Python 3.8+ (already our minimum is 3.11)
- Terminal-only (web UI would be separate)

## Implementation

1. Add textual to dependencies
2. Create `tui/` module structure
3. Implement base app with screen navigation
4. Create screens for:
   - Calculations
   - AI Agents
   - Data workflows
   - Settings
5. Add keyboard shortcuts
6. Implement theme support

## Validation

Success criteria:
- TUI launches without errors
- All screens accessible via keyboard
- Responsive on different terminal sizes
- Works on Linux, macOS, Windows
- Users find it intuitive
