# Project management tools

* Status: proposed
* Deciders: Oihana Elizagoyen, Xabier Mikel Gutierrez and Aimar Uriarte
* Date: 2025/02/16

## Context and problem statement

We need to choose the best tool for managing the project's tasks, communication, and overall workflow. The tool selected should integrate well with our team’s existing practices and be sustainable for the duration of the project (around 10 years).

## Decision drivers

* **Familiarity and ease of use** – The team should be comfortable with the tool to avoid significant training and to ensure quick adoption.
* **Longevity and support** – The tool should be widely used and well-supported to ensure availability over the long term.
* **Functionality** – The tool should provide features that help track tasks, issues, and communicate efficiently.

## Considered options

* **Trello**
* **Document (e.g., Google Docs or similar)**
* **Slack**
* **Jira**
* **Azure Boards**
* **GitHub Issues + Projects**

## Decision outcome

Chosen option: **GitHub Issues + Projects**

### Justification:

GitHub Issues + Projects was chosen because it leverages our existing knowledge of GitHub and offers powerful tools for managing tasks and issues. With our student accounts, we benefit from premium features at no cost. GitHub is widely used and supported, ensuring its availability throughout the life of the project. Additionally, it provides seamless integration with commits and other workflows (e.g., closing issues via commits), which is a significant advantage for our development process.

### Positive consequences

* Streamlines task management and version control in a single platform.
* Widely used and supported globally, ensuring long-term sustainability.
* The team is already familiar with GitHub, reducing onboarding time and increasing efficiency.
* Integrates directly with GitHub repositories, allowing for automatic updates to issues and projects.

### Negative consequences

* Overloading one platform with both project management and code-related tasks may lead to some organizational complexity.
* While it's useful for managing issues and tasks, it might not have the depth of functionality of other dedicated project management tools like Jira or Azure Boards.

## Pros and Cons of the Options

### Trello

* Good, because it provides an intuitive and visual way to manage tasks.  
* Good, because it supports collaboration with easy drag-and-drop task management.  
* Bad, because it lacks deep integration with GitHub and version control workflows.  
* Bad, because it can become difficult to manage large-scale projects efficiently.  

### Document (Google Docs or similar)

* Good, because it is simple and accessible to everyone.  
* Good, because it allows for flexible documentation and planning.  
* Bad, because it lacks automation and issue-tracking features.  
* Bad, because it is not optimized for agile or structured task management.  

### Slack

* Good, because it enhances team communication and integrates with various tools.  
* Good, because it allows quick updates and discussions.  
* Bad, because it is not designed for structured task management.  
* Bad, because information can get lost in chat history without proper organization.  

### Jira

* Good, because it provides robust project tracking and agile methodologies.  
* Good, because it has extensive features for issue tracking and sprint planning.  
* Bad, because it has a steep learning curve for new users.  
* Bad, because it may be overkill for a small team.  

### Azure Boards

* Good, because it integrates well with Microsoft tools and supports agile workflows.  
* Good, because it has built-in support for backlog management and sprint planning.  
* Bad, because it is complex and requires an Azure ecosystem for full functionality.  
* Bad, because it is less familiar to the team.  

### GitHub Issues + Projects

* Good, because it integrates project management and issue tracking with version control.  
* Good, because it is widely used, ensuring long-term support.  
* Good, because the team is already familiar with the platform, reducing the learning curve.  
* Bad, because managing project tasks and code changes in the same platform could become overwhelming without proper organization.
