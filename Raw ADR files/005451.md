# ADR-032: API Integration Architecture

**Date**: 2025-10-16  
**Status**: Accepted  
**Decision Makers**: System Architect, Trading Operations Lead, Infrastructure Team  
**Consulted**: Interactive Brokers Support, Alpha Vantage Support  
**Informed**: Development Team, QA Team, Risk Management

---

## Context

The multi-agent trading system requires robust integration with multiple external APIs for market data, options pricing, order execution, and news/sentiment analysis. The system must handle real-time data streams, maintain high availability through failover mechanisms, and ensure cost-effective API usage while meeting stringent latency and reliability requirements.

### Business Drivers

- **Real-Time Market Data**: Sub-second latency for trading decisions
- **High Availability**: 99.9% uptime through multi-tier failover
- **Cost Optimization**: Minimize API costs through caching and intelligent usage
- **Regulatory Compliance**: Audit trail for all API interactions
- **Operational Resilience**: Graceful degradation when APIs are unavailable

### Technical Constraints

- **Primary Data Source**: Interactive Brokers (IB) Gateway (real-time, free)
- **Secondary Source**: Alpha Vantage (delayed 15min, $0-50/month)
- **Tertiary Source**: Finnhub (delayed backup, $0-25/month)
- **Maximum Latency**: <100ms for market data, <200ms for order execution
- **Rate Limits**: IB no limit, Alpha Vantage 5 req/sec, Finnhub 60 req/min
- **Availability Target**: 99.9% during market hours (9:30 AM - 4:00 PM ET)

---

## Decision

We will implement a **three-tier API integration architecture** with automatic failover, intelligent caching, and comprehensive monitoring:

### 1. Interactive Brokers Gateway Integration (Primary)

- **Deployment**: Cloud Run container running IB Gateway 10.19+
- **Connection**: Persistent TWS API connection with credentials from Secret Manager
- **Market Data**: Real-time Level 1 data (quotes, trades, Greeks)
- **Execution**: Direct order submission with real-time fills
- **Cost**: $0/month (included with brokerage account)
- **Latency**: <100ms market data, <200ms order execution
- **Availability**: 99.5% (IB infrastructure dependency)

### 2. Alpha Vantage Integration (Secondary)

- **API**: REST API with Premium tier (125 requests/day)
- **Use Cases**: News sentiment, delayed quotes (15min), fundamental data
- **Caching**: Redis with 24-hour TTL (85%+ hit rate target)
- **Cost**: $50/month for Premium tier
- **Latency**: <2 seconds for API calls, <50ms for cached data
- **Failover**: Activated when IB connection lost >30s or data stale >60s

### 3. Finnhub Integration (Tertiary)

- **API**: WebSocket + REST for delayed market data
- **Use Cases**: Backup quotes, options data, earnings calendar
- **Cost**: $0-25/month (Free or Starter tier)
- **Latency**: <5 seconds for delayed data
- **Failover**: Activated when both IB and Alpha Vantage unavailable

### 4. Failover & Circuit Breaker

- **Automatic Failover**: Primary → Secondary (30s timeout) → Tertiary (5% error threshold)
- **Circuit Breaker**: Trading halt if all sources unavailable >5 minutes
- **Health Monitoring**: Continuous connection checks, data staleness detection
- **Manual Override**: Trading desk can force specific data source

### Credential Management Requirements (8 requirements)

- **REQ-API-CRED-001**: Google Secret Manager for all API keys (IB, Alpha Vantage, Finnhub)
- **REQ-API-CRED-002**: Credential rotation support (90-day rotation policy, zero-downtime)

### Error Handling Requirements (10 requirements)

- **REQ-API-ERROR-001**: Connection timeout handling (5s timeout, 3 retries with exponential backoff)
- **REQ-API-ERROR-002**: HTTP error classification (4xx client errors, 5xx server errors, network errors)
- **REQ-API-ERROR-003**: Retry strategy (idempotent requests retry automatically, non-idempotent require confirmation)
- **REQ-API-ERROR-004**: Circuit breaker pattern (open after 5 consecutive failures, half-open after 60s)
- **REQ-API-ERROR-005**: Error logging (structured logs with error code, message, request context, stack trace)
- **REQ-API-ERROR-006**: Alert notifications (PagerDuty for critical errors, Slack for warnings)
- **REQ-API-ERROR-007**: Graceful degradation (use cached data when API unavailable, flag as stale)
- **REQ-API-ERROR-008**: User-facing error messages (actionable errors, avoid exposing internal details)
- **REQ-API-ERROR-009**: Error rate monitoring (track error rate by API, alert if >5% over 5 minutes)
- **REQ-API-ERROR-010**: Dead letter queue (failed requests to Pub/Sub DLQ for manual review)

### Failover & High Availability Requirements (11 requirements)

- **REQ-API-FAILOVER-001**: Three-tier architecture (Primary IB → Secondary AV → Tertiary Finnhub)
- **REQ-API-FAILOVER-002**: Automatic failover triggers (connection loss >30s, data stale >60s, error rate >5%)
- **REQ-API-FAILOVER-003**: Health check monitoring (continuous checks every 10s, 3 failures trigger failover)
- **REQ-API-FAILOVER-004**: Failover notification (alert trading desk, log to BigQuery, Slack notification)
- **REQ-API-FAILOVER-005**: Fallback to secondary (Alpha Vantage within 30s, use cached data during transition)
- **REQ-API-FAILOVER-006**: Fallback to tertiary (Finnhub within 60s if AV also fails)
- **REQ-API-FAILOVER-007**: Circuit breaker activation (trading halt if all sources down >5 minutes)
- **REQ-API-FAILOVER-008**: Automatic recovery (reconnect to primary when available, validate data quality)
- **REQ-API-FAILOVER-009**: Manual override capability (trading desk can force specific source)
- **REQ-API-FAILOVER-010**: Failover metrics tracking (count, duration, source used, performance impact)
- **REQ-API-FAILOVER-011**: Failover testing (monthly DR drill, automated synthetic failover tests)

### Health Check Requirements (6 requirements)

- **REQ-API-HEALTH-001**: Connection status endpoint (/health GET returns 200 if all sources reachable)
- **REQ-API-HEALTH-002**: Latency monitoring (p50, p95, p99 latencies per API, alert if p95 >500ms)
- **REQ-API-HEALTH-003**: Error rate tracking (errors per API, per endpoint, alert if >5% over 5 min)
- **REQ-API-HEALTH-004**: Data freshness check (timestamp of last successful data fetch, alert if >2 min stale)
- **REQ-API-HEALTH-005**: Rate limit status (current usage vs limit, alert at 80% threshold)
- **REQ-API-HEALTH-006**: Cloud Monitoring dashboard (real-time metrics, historical trends, SLO tracking)

### Rate Limiting Requirements (7 requirements)

- **REQ-API-RATE-001**: Token bucket algorithm (configurable rate, burst capacity)
- **REQ-API-RATE-002**: Per-API rate limits (IB 50/sec, AV 5/sec, Finnhub 60/min)
- **REQ-API-RATE-003**: Request queuing (queue requests when at limit, FIFO processing)
- **REQ-API-RATE-004**: Priority queues (critical requests bypass rate limits, non-critical queued)
- **REQ-API-RATE-005**: Rate limit metrics (current rate, queue depth, dropped requests)

## Consequences

### Positive

✅ **High Availability**: 99.9% uptime through three-tier failover  
✅ **Cost Efficiency**: $50-75/month total API costs with intelligent caching  
✅ **Low Latency**: <100ms market data, <200ms order execution  
✅ **Operational Resilience**: Graceful degradation when sources fail  
✅ **Audit Trail**: Complete logging for regulatory compliance  
✅ **Scalability**: Cloud Run auto-scaling handles traffic spikes  

### Negative

⚠️ **Complexity**: Three data sources require coordination and testing  
⚠️ **IB Dependency**: Primary source has 99.5% availability (0.5% downtime)  
⚠️ **Delayed Fallback Data**: Secondary/tertiary have 15-minute delay  
⚠️ **Cost**: $600-900/year for Alpha Vantage Premium  
⚠️ **Cache Staleness**: Redis cache may serve stale data during outages  

### Risks

🔴 **IB Gateway Outage**: Primary source down requires immediate failover  
🔴 **All Sources Down**: Circuit breaker halts trading (manual intervention)  
🔴 **API Rate Limits**: Exceeding limits degrades service  
🔴 **Cache Invalidation**: Stale cache data may cause incorrect decisions  
🔴 **Credential Compromise**: API key theft could disrupt service  

### Mitigation

1. **Monthly DR Drills**: Test failover scenarios, measure recovery time
2. **Rate Limit Monitoring**: Alert at 80% threshold, adaptive throttling
3. **Cache Validation**: Timestamp checks, data freshness alerts
4. **Credential Rotation**: Automated 90-day rotation, Secret Manager audit logs
5. **Redundant Caching**: Multi-region Redis for cache availability
