# ADR-001: LangGraph for Agent Routing and State Management

## Status
**Accepted** - January 2024

## Context

The Marina system needs to route user conversations to specialized therapeutic agents based on:
- Affective state classification (anxiety, low-mood, delirium, etc.)
- Safety risk assessment (crisis intervention)
- Context complexity (escalation to commercial LLMs)
- Conversation history and user profile

Key requirements:
1. **Stateful Conversations**: Maintain conversation context across multiple turns
2. **Durable State**: Sessions must survive service restarts and failures
3. **Complex Routing Logic**: Multi-factor decision making with hysteresis
4. **Auditability**: Complete trace of routing decisions for therapeutic oversight
5. **Scalability**: Support multiple concurrent conversations
6. **Fault Tolerance**: Graceful handling of component failures

## Decision

We will use **LangGraph** as the primary orchestration framework for agent routing and conversation state management, with PostgreSQL as the persistence backend through `PostgresCheckpointer`.

### Architecture Components:

1. **LangGraph State Machine**
   - Nodes for each processing stage (classification, safety, routing, response)
   - Edges with conditional logic for routing decisions
   - Built-in retry and error handling mechanisms

2. **PostgreSQL Checkpointing**
   - Persistent conversation threads with full state history
   - Automatic checkpoint creation after each turn
   - Recovery capability from any checkpoint

3. **Agent Interfaces**
   - Standardized agent interface for all therapeutic agents
   - Pluggable agent architecture for easy extension
   - Context passing through LangGraph state

## Rationale

### Why LangGraph?

**Pros:**
- **Built for LLM Workflows**: Designed specifically for complex LLM-based applications
- **Durable Execution**: Native support for checkpointing and recovery
- **Visual Debugging**: Graph visualization for complex routing logic
- **Scalable**: Supports distributed execution and multiple workers
- **Flexible**: Easy to modify routing logic without code restructuring
- **Observability**: Built-in tracing and monitoring capabilities

**Alternatives Considered:**
- **Celery**: Good for task queues but lacks stateful conversation management
- **Apache Airflow**: Overkill for real-time conversation routing
- **Custom State Machine**: Would require building checkpointing and recovery from scratch
- **Step Functions**: Vendor lock-in and limited customization for our use case

### Why PostgreSQL Checkpointing?

**Pros:**
- **ACID Guarantees**: Ensures conversation state consistency
- **Vector Support**: pgvector extension for memory retrieval integration
- **Familiar Technology**: Team expertise and operational knowledge
- **Backup/Recovery**: Mature backup and disaster recovery procedures
- **Performance**: Excellent performance for read-heavy workloads

**Alternatives Considered:**
- **Redis**: Fast but lacks durability guarantees
- **MongoDB**: JSON-native but lacks ACID for multi-document updates
- **File-based**: Simple but doesn't scale and lacks concurrent access


### Graph Structure
```python
def create_routing_graph():
    workflow = StateGraph(ConversationState)
    
    # Add nodes
    workflow.add_node("classify_state", classify_affective_state)
    workflow.add_node("assess_safety", assess_safety_risk)
    workflow.add_node("build_context", build_conversation_context)
    workflow.add_node("route_agent", route_to_agent)
    workflow.add_node("escalate", escalate_to_commercial)
    workflow.add_node("generate_response", generate_agent_response)
    workflow.add_node("post_process", post_turn_analysis)
    
    # Add conditional edges
    workflow.add_conditional_edges(
        "assess_safety",
        lambda state: "crisis" if state.safety_assessment.risk_level == "high" else "continue",
        {
            "crisis": "route_agent",
            "continue": "classify_state"
        }
    )
    
    workflow.add_conditional_edges(
        "route_agent", 
        should_escalate,
        {
            "escalate": "escalate",
            "local": "generate_response"
        }
    )
    
    return workflow.compile(
        checkpointer=PostgresCheckpointer(connection_string)
    )
```

## Consequences

### Positive:
1. **Simplified Complexity**: LangGraph handles state transitions, checkpointing, and error recovery
2. **Developer Productivity**: Visual debugging and standard patterns reduce development time
3. **Reliability**: Built-in durability and recovery mechanisms
4. **Scalability**: Support for horizontal scaling with shared checkpointer
5. **Auditability**: Complete state transition history for compliance and debugging
6. **Maintainability**: Clear separation of routing logic from business logic

### Negative:
1. **Framework Dependency**: Tight coupling to LangGraph framework evolution
2. **Learning Curve**: Team needs to learn LangGraph concepts and patterns
3. **Performance Overhead**: Additional latency from checkpointing on every turn
4. **Debugging Complexity**: Distributed state can make debugging more challenging

### Mitigation Strategies:
1. **Framework Risk**: Maintain abstraction layer over LangGraph for potential future migration
2. **Performance**: Implement async checkpointing and optimize database queries
3. **Debugging**: Invest in comprehensive logging and monitoring
4. **Team Training**: Dedicated LangGraph training and documentation

## Performance Impact

### Expected Latencies:
- **Checkpoint Save**: ~50ms per turn (PostgreSQL write)
- **State Retrieval**: ~20ms (PostgreSQL read with indexes)
- **Graph Execution**: ~100ms overhead (in-memory processing)
- **Total Overhead**: ~170ms added to base processing time

### Optimization Strategies:
1. **Connection Pooling**: Use pgbouncer for database connections
2. **Async Processing**: Non-blocking checkpointing where possible
3. **Batch Operations**: Batch multiple state updates
4. **Indexing**: Optimize database indexes for checkpoint queries

## Monitoring and Observability

### Key Metrics:
- **Checkpoint Success Rate**: >99.9%
- **State Transition Latency**: <100ms p95
- **Recovery Success Rate**: >99.5%
- **Graph Execution Errors**: <0.1%

### Alerting:
- Checkpoint failure rate >0.1%
- Graph execution timeout >1%
- Recovery failure rate >0.5%
- Database connection pool exhaustion

## Future Considerations

1. **Multi-region Deployment**: Consider PostgreSQL streaming replication
2. **Event Sourcing**: Potential evolution to full event sourcing pattern
3. **Graph Optimization**: Opportunities for parallel node execution
4. **Custom Checkpointer**: Possible custom implementation for performance optimization

*This ADR establishes LangGraph as the foundational technology for Marina's conversational AI routing system, providing the reliability and scalability needed for therapeutic applications.*
