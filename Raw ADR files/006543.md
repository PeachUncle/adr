# Decision: Implementation of Adaptive Workflow Using Claude Code Native Features

Date: 2025-11-17

## Context

ADR 0008 established an adaptive two-phase planning workflow for development with Claude Code. However, the ADR focused on the conceptual workflow pattern without specifying implementation mechanics. The challenge: how to implement this workflow using Claude Code's native capabilities rather than building custom tooling.

Recent research into Claude Code's feature set revealed several powerful native capabilities that align perfectly with ADR 0008's requirements:
- **Skills**: Auto-activated capabilities based on context
- **Sub-agents**: Specialized agents (Plan, Explore) for focused tasks
- **Plan Mode**: Built-in read-only exploration phase
- **Hooks**: Event-driven automation with blocking capabilities
- **Slash Commands**: Explicit workflow control points

The decision point: Should we implement ADR 0008's workflow using these native features, or build custom tooling?

## Approach

Implement the adaptive two-phase planning workflow using six Claude Code native components:

### 1. Task Backlog Management
**Implementation**: `.claude/commands/backlog.md` slash command
- Maintains project-level task list in `.claude/backlog.md`
- Commands: `add`, `list`, `select`
- Selecting a task triggers automatic entry into planning phase

### 2. Adaptive Planning Skill
**Implementation**: `.claude/skills/adaptive-workflow/SKILL.md`
- Auto-activates when user requests feature implementation
- Enforces ADR 0008's two-phase pattern
- Phase 1: Uses Plan Mode for read-only exploration and roadmap creation
- Phase 2: Per-task re-assessment with approval checkpoints

### 3. Plan Mode Integration
**Implementation**: `.claude/commands/plan-feature.md`
- Explicit command to enter planning phase
- Uses Plan Mode for codebase exploration
- Creates TodoWrite roadmap before implementation
- Leverages Explore sub-agent for thorough analysis

### 4. Pre-Implementation Re-assessment
**Implementation**: `.claude/commands/reassess.md`
- Runs before each subtask execution
- Checks current codebase state against plan assumptions
- Two paths: Quick confirmation or detailed adjustment explanation
- Waits for explicit approval before proceeding

### 5. Approval Hooks
**Implementation**: `.claude/hooks/pre-edit-approval.sh`
- PreToolUse hook for Edit/Write operations
- Warns before file modifications
- Optional blocking for critical operations
- Registered in `.claude/settings.local.json`

### 6. Enhanced Commit Workflow
**Implementation**: Enhanced `.claude/commands/commit.md`
- Only executes after explicit user approval
- Follows ADR 0008's approval checkpoint pattern
- Integrates with existing commit command structure

## Usage Flow

**Setup Phase:**
1. User: `/backlog add "Feature description"`
2. User: `/backlog select 1`

**Phase 1 - Planning:**
3. Skill auto-activates → Plan Mode
4. Claude explores codebase using Explore sub-agent
5. Creates TodoWrite roadmap
6. User reviews and approves
7. Exit Plan Mode

**Phase 2 - Execution Loop (per subtask):**
8. Claude: `/reassess` (automatic)
9. Explains approach, waits for approval
10. Implements code
11. Marks todo completed
12. Summarizes changes
13. User: "commit this"
14. Claude: `/commit`
15. Repeat for next subtask

## Decision Rationale

Using Claude Code's native features provides:

1. **Auto-activation over manual triggers**: Skills detect appropriate contexts and activate the workflow automatically
2. **Built-in safety**: Plan Mode's read-only guarantee prevents accidental edits during exploration
3. **Specialized intelligence**: Plan and Explore sub-agents are optimized for their specific tasks
4. **Minimal custom code**: Leverage battle-tested native features instead of building from scratch
5. **Team compatibility**: Standard Claude Code features work across all team members
6. **Future-proof**: Native features receive updates and improvements from Anthropic

Goal: Maximum workflow power with minimum custom implementation complexity.

## Trade-offs

**Benefits:**
- Zero custom tooling infrastructure needed
- Skills provide seamless workflow activation
- Sub-agents handle exploration and planning optimally
- Plan Mode enforces read-only safety during planning
- Hooks enable programmatic approval checkpoints
- Native features are well-documented and supported

**Costs:**
- Initial setup requires creating multiple configuration files
- Team members need to learn Claude Code's feature system
- Skill activation logic may need tuning for project-specific patterns
- Hook implementation requires bash scripting knowledge
- More sophisticated than simple markdown checklists

**Impact:**
- Development workflow: Extends ADR 0008 with concrete implementation
- Team onboarding: Requires understanding Claude Code's feature system
- Maintenance: Native features reduce long-term maintenance burden
- Adaptability: Skills and hooks can be refined as workflow evolves
- Related ADRs: Implements ADR 0008, extends ADR 0001's workflow system
