# Decision: Exceptions v0 (bootstrap-only)

## Context

Early bootstraptests require:

- `begin ... rescue ... end` expressions
- rescue modifiers (`expr rescue fallback`)
- `SyntaxError`/`ArgumentError` style control-flow for failing operations

At this stage the VM does not yet have:

- call frames / backtraces
- a real Class/Module system
- `ensure` / `retry` / non-local flow controls

## Decision

Implement a minimal exception substrate sufficient for bootstraptest literals:

- Runtime representation:
  - `Value::Exception { class: ExceptionClass, message: String }`
  - `ExceptionClass` enum currently includes `StandardError` and `SyntaxError`
- Bytecode support:
  - `PUSH_RESCUE { handler_ip, mask }`: pushes a rescue handler record capturing `handler_ip` and current operand stack depth
  - `POP_RESCUE`: pops the most recent handler record (normal non-exceptional path)
  - `RAISE`: pops an exception and unwinds to the nearest handler whose `mask` matches the exception class
  - `EXCEPTION_MESSAGE`: extracts `e.message` from `Value::Exception`
- Unwinding model:
  - The VM keeps an explicit `rescue_stack`.
  - `RAISE` pops handlers until it finds one with a compatible mask.
  - On match, it truncates the operand stack back to the saved depth and pushes the exception value, then jumps to `handler_ip`.
  - If no handler matches, `RAISE` becomes an uncaught runtime error.
- Rescue matching:
  - Use a simple bitmask (currently `StandardError=0x1`, `SyntaxError=0x2`) so bytecode can encode “catch sets” without dynamic type objects.

## Rationale

- Keeps exception state explicit (no hidden side channels) and makes it easy to evolve into proper exception tables later.
- Fits naturally with a stack-based bytecode interpreter.
- Provides enough surface area to compile `begin/rescue` in a structured way, instead of hard-coding bootstraptest cases in the CLI.

## Follow-ups

- Replace `ExceptionClass` enum with real exception objects once Class/Module exists.
- Add `ensure` and proper unwinding tables (not just a stack) once call frames are introduced.
- Add backtraces and span-aware error reporting.
