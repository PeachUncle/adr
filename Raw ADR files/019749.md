# ADR-004: Rust over Go

**Status**: Accepted  
**Date**: 2025-10-31  
**Deciders**: Core Team

## Context

VEGA is a performance-critical distributed database. Language choice impacts:
- Latency (p50, p95, p99)
- Throughput
- Resource efficiency (CPU, memory)
- Developer productivity

Main contenders: **Rust** vs **Go**

## Decision

Use **Rust** for VEGA implementation.

## Rationale

### Rust Advantages for VEGA

1. **Predictable Latency**
   - **No GC pauses**: Critical for p99 latency
   - Deterministic memory management
   - Real-time workloads feasible

2. **Zero-Cost Abstractions**
   - High-level code compiles to optimal machine code
   - No runtime overhead (unlike Go's runtime)
   - Tight control over memory layout

3. **Memory Safety Without GC**
   - Ownership system prevents:
     - Use-after-free
     - Double-free
     - Data races (at compile time!)
   - Safer than C/C++, faster than Go

4. **Performance**
   - Native speed (no interpreter/JIT)
   - SIMD optimizations
   - Cache-friendly data structures

5. **Concurrency**
   - `async`/`await` with Tokio (similar to Go's goroutines)
   - Compile-time data race prevention
   - No hidden overhead

6. **Ecosystem**
   - `rocksdb`: High-quality bindings
   - `tokio`: Production-ready async runtime
   - `raft-rs`: Raft implementation
   - `prost`: Protobuf support

### Go Advantages (Why We Didn't Choose It)

1. **Faster Development**
   - Simpler syntax
   - Faster compile times
   - Easier for new contributors

2. **Mature Ecosystem**
   - More libraries
   - Larger talent pool
   - Better tooling (some areas)

3. **Goroutines**
   - Built-in lightweight concurrency
   - Easy to use

**BUT**: GC pauses are a dealbreaker for p99 latency targets.

## Trade-offs

### Rust Challenges
- ❌ **Steeper learning curve**: Ownership, lifetimes, borrowing
- ❌ **Slower initial development**: Fighting the borrow checker
- ❌ **Longer compile times**: Especially incremental builds
- ❌ **Smaller community**: Compared to Go/Java/Python

### Mitigations
- **Learning curve**: Invest in team training, pair programming
- **Development speed**: Leverage strong typing for refactoring confidence
- **Compile times**: Use `sccache`, split into crates
- **Community**: Growing fast, great docs (The Rust Book)

## Performance Comparison

### Latency (p99)
| Language | Point Read | Point Write | Notes |
|----------|------------|-------------|-------|
| Rust | ~2-3ms | ~5-10ms | No GC pauses |
| Go | ~5-15ms | ~10-20ms | GC pauses visible |

### Throughput
| Language | Ops/sec/core | Notes |
|----------|--------------|-------|
| Rust | 80-100k | Near C++ levels |
| Go | 50-70k | GC overhead |

### Memory
| Language | Overhead | Control |
|----------|----------|---------|
| Rust | Minimal | Full control |
| Go | GC overhead | Less control |

## Alternatives Considered

### 1. Go (Rejected)
- **Pros**: Faster development, simpler, good concurrency
- **Cons**: GC pauses hurt p99 latency, less control
- **When**: Good for control planes, not data planes

### 2. C++ (Rejected)
- **Pros**: Maximum performance, no GC
- **Cons**: Memory safety issues, harder to maintain, slower development
- **When**: If Rust didn't exist, we'd use C++

### 3. Java (Rejected)
- **Pros**: Mature ecosystem, good libraries
- **Cons**: GC pauses, higher memory overhead, JVM startup time
- **When**: Enterprise applications, not latency-critical systems

### 4. Zig (Considered)
- **Pros**: No hidden control flow, simple, fast
- **Cons**: Immature ecosystem, less safety than Rust
- **Decision**: Monitor, revisit in 2-3 years

## Examples from Industry

### Rust in Production Databases
- **TiKV** (TiDB): Storage engine in Rust
- **Materialize**: Streaming database in Rust
- **TerminusDB**: Graph database in Rust
- **Neon**: Serverless Postgres in Rust

### Go in Production Databases
- **CockroachDB**: Written in Go
- **etcd**: Raft-based KV store in Go
- **InfluxDB**: Time-series DB in Go

**Note**: CockroachDB team has mentioned GC tuning challenges for latency.

## Consequences

### Positive
- ✅ Predictable, low latency (no GC)
- ✅ Memory-safe by default
- ✅ High performance (near C++)
- ✅ Growing ecosystem
- ✅ Future-proof (Rust adoption increasing)

### Negative
- ❌ Slower initial development
- ❌ Harder to hire (smaller talent pool)
- ❌ Longer compile times
- ❌ Steeper learning curve

### Risk Mitigation
- **Hiring**: Train developers, remote hiring
- **Onboarding**: Strong docs, pair programming
- **Compile times**: Use `sccache`, incremental compilation
- **Complexity**: Design patterns, community support
