Summary
- Sprint-004 focuses on production readiness: ship the privacy-safe metrics pipeline, finalize performance/error budgets, workerize heavy flows, and close release/testing/documentation gates for existing tools.

Decision
- Schedule: proposed 2026-02-03 → 2026-02-14; maintain the two-week cadence; no new tools unless needed to unblock existing flows.
- Metrics/observability:
  - Add `/api/tools/metrics` with a strict Zod schema; accept only synthetic data (tool slug, action type, duration ms, size bucket, success/error category, workerUsed, offline/online, sample id).
  - Sampling: dev 100%, prod 10% until stable; drop on failure; never capture payloads or user-identifying data.
  - Surface budgets: console warnings in dev when budgets are exceeded; optional admin-only dashboard later (out-of-scope for this sprint).
- Performance/resilience:
  - Workerize markdown-to-pdf and large format conversions; keep synchronous small-paths; add fallbacks to main-thread execution and aria-live progress updates.
  - Enforce the 10MB cap and >5MB progress messaging across tools; preserve offline-friendly behavior and graceful degradation without `DATABASE_URL`.
  - Publish per-tool budgets (render and action) aligned with Sprint-003 targets; treat regressions as blockers until resolved.
- UI kit/docs:
  - Finish `@/components/ui` audit (FileUpload, ImportPanel, ToolPageTemplate, MultiSelect); ensure `useId` + aria labels, remove placeholders, and export needed parts.
  - Refresh `DEVELOPER_CHEAT_SHEET.md` and add playbook snippets for metrics/workerization patterns.
- QA gates:
  - Expand unit + Playwright smokes for workerized flows and metrics plumbing; keep `npm run validate` and `npm run qa:translations` required for sign-off.

Rationale
- Production-ready metrics and budgets prevent silent regressions before adding more tools and preserve the privacy promise.
- Workerization and UI kit hardening keep interactions responsive while maintaining accessibility and offline behavior.
- Documentation and tests accelerate future contributors and reduce onboarding time.

Out of scope
- New tool creation or major redesign.
- Server-dependent analytics beyond the lightweight `/api/tools/metrics`.
- Raising the 10MB ceiling or collecting payload-level data.

Risks/Mitigations
- Privacy drift from metrics: constrain schema to synthetic fields; sampling + drop-on-fail.
- Worker regressions: maintain main-thread fallback and tests for both paths.
- Schedule risk from docs/tests load: prioritize metrics + workerization first; defer optional dashboards.

Next steps
- Capture per-tool budgets and owners in the checklist; implement `/api/tools/metrics` endpoint + client sampling.
- Workerize markdown-to-pdf/format-converter heavy paths with fallbacks and progress UX.
- Complete UI kit audit + docs, then run `npm run validate` and `npm run qa:translations`.
